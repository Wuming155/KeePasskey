## P3 低危问题、特性接线与体验优化（1 项）

### ISSUE-P3-472：标准解锁页主密码行「未聚焦 + 空值」态无任何文案——无标签 + 48dp 上限下占位提示不可见

- **核实时间点**：2026-10-04；**核实方式**：JVM 预览渲染读数（`preview-exports/` 通路，**非设备读数**）+ 像素扫描——`UnlockContentPreview`（STANDARD、未聚焦、空值）导出图 1080×2400 的主密码行带（y 430~700）内，暗像素（R+G+B < 600）只落在 leading 锁图标（x 148~188）与 trailing 眼睛图标（x 883~942）两簇，**x ∈ (188, 883) 区间 0 暗像素** ⇒ 该行无任何文案；对照 M3 源码：占位符可见性由 `placeholderOpacity` 决定，`label == null` 时 `showExpandedLabel = false` ⇒ `UnfocusedEmpty → 1f`（**本应可见**）⇒ 渲染读数与源码规则矛盾，机制未坐实。
- **背景**：§436 把主密码字段改为「无浮动标签（`label = null`）+ 扁平行内嵌 + 主体高度压到 48dp」（`SecurePasswordField` 的 `embeddedFlat` 形态），提示文案改由 `placeholder`（`unlock_master_password_hint` =「输入主密码以解锁」）承担。若该提示在未聚焦态确实不呈现，标准解锁页这一行就只剩左右两枚图标——本屏是解锁主路径，用户看不出这里是主密码输入（可发现性受损）。**两条候选机制（均未坐实）**：① 占位符的标签 / 聚焦门控（与实际解析到的 M3 版本行为相关：`gradle/libs.versions.toml` 声明 `material3 = 1.5.0-alpha28`，本次复核所读源码为缓存内 `1.5.0-alpha27`，alpha28 源码未缓存故未逐字核）；② 48dp 高度上限与 `supportingText` 槽的最小高度（`MinSupportingTextLineHeight`，见 `ISSUE-P3-457` 的槽位契约）互相挤压，字段正文区被裁掉。**本条目不预设缺陷定性**——JVM 预览渲染器与真机可能不一致（该通路不得写成设备读数），须真机先行确认。
- **验收标准**：  
  ① 真机确认（标准解锁页、未聚焦、空值）：该行是否呈现「输入主密码以解锁」。可见 ⇒ 判为 **JVM 预览渲染器限界**并登记限界表（**不得**据此改生产代码）；同为空白 ⇒ 确认缺陷；  
  ② 确认缺陷后择一并留痕：字面量标签回归（`label` 非空）/ 占位提示改为常显的提示行 / 解除 48dp 上限（任一方案须说明与 §436 走查回执①「紧凑档」口径的相容性，**不得**直接移除 48dp 上限而不核该回执）；  
  ③ 聚焦 / 未聚焦两态预览补齐（`ISSUE-P3-340` 口径），使该行在导出图上可直接查；  
  ④ 全量 test 绿 + `python tools/doc/gate_readings.py` 全 PASS；批次文档留痕。
