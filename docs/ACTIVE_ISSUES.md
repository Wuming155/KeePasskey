## P2 中危缺陷与协议/测试缺口

### ISSUE-P2-620：进程重建后旧 PendingIntent 可混用另一域的密码请求

- **核实**：2026-10-15，当前工作区静态调用链、独立复核及 [Android 官方 PendingIntent 契约](https://developer.android.com/reference/android/app/PendingIntent)；中危、置信度中，**需要进一步验证真实 Credential Manager 保留窗口**。
- **位置**：`CredentialPendingIntents.kt:89-96`、`CredentialResponseAssembler.kt:346-359`、`PasswordFillActivity.kt:129-139,191-206,237-243`。
- **触发与后果**：系统仍持有域 A 的旧候选，提供者普通进程死亡后，新进程从 1000 重发同码，为同浏览器域 B 创建同组件、仅 extras 不同的入口；`FLAG_UPDATE_CURRENT` 可更新旧 token。落地页只比较系统包名，随后用新版 entry/domain 自洽校验；用户点旧项并完成验证后，A 请求可能收到 B 口令。未证明无交互窃取；force-stop 不可替代普通死亡。
- **建议与验收**：为每条入口设置跨进程唯一且参与 `filterEquals` 的请求标识（如随机 `Intent.data`），交付前绑定最终系统 origin/package/条目，保持系统所需可变标志。用独立持有者和真实两域 CM 流程验证旧请求不能收到新域秘密，保留 PID、系统回执与非空设备测试 XML；Autofill 同形计数器与旧 `AutofillId` 接受条件另行验证，不据此认定同样泄露。

### ISSUE-P2-621：回滚状态写失败后，后续同步可采纳旧版本

- **核实**：2026-10-15，当前同步采纳、缓存比较、错误返回及锁定/重开链静态追踪；中危、置信度中，**需要进一步验证本地故障注入**。
- **位置**：`SyncEngineAdoptionSettlement.kt:26-34`、`SyncEngineSupport.kt:75-84`、`SyncRollbackGuard.kt:134-162,193-211`、`SyncContentChangeDetector.kt:59-83`、`SyncCycleRemoteOutcomes.kt:145-165`。
- **触发与后果**：同进程成功同步 A 后锁库并重开未改过的 A，进程内文件 checkpoint 仍在而内存同步参考为空；采用远端 B 并保存、提交 B 缓存/基线后，rollback 写入或改名失败。周期返回 Error，但进程与缓存继续存在；下一轮本地 B 对缓存 B 判未变，远端重放 A 因守卫 `current=A` 判 Unchanged，可再次保存并丢失 B 更新。需本地持久化故障，未证明远端能诱发该故障。
- **反证边界**：普通进程重建会在开库前清同步缓存且没有进程内 checkpoint，基线缺失时保守走冲突；**不报告仅靠进程死亡即可静默回滚**。正常高水位提交后 A 会进入 recent 并被拒绝；已有状态缺失/不可解析及 32 项窗口限界不等于本次部分提交状态。
- **建议与验收**：为正式库、缓存基线和高水位建立可恢复的代际/事务状态，高水位失败后禁止继续自动采用旧远端。定点注入 B 基线提交后的 rollback 写/rename 失败，再重放 A，确认拒绝或显式恢复/冲突而非直接覆盖；普通进程重建另列对照。

### ISSUE-P2-624：同步收尾检查点可能误记尚未上传的新版本

- **核实**：2026-10-15，当前上传结算、独立保存、锁库清缓存与重开采纳链静态追踪及定点独立复核；中危、置信度中，**需要进一步验证调度注入**。
- **位置**：`SyncCycleRunner.kt:126-130`、`SyncLocalFileCheckpoint.kt:56-64`、`SyncUploadSettlement.kt:36-45`、`SyncCycleRemoteOutcomes.kt:90-97,145-153`；条目保存运行于 `VaultEntryWriteCoordinator.kt:60-66` 的 Default 调度。
- **触发与后果**：本轮 A 已结算为收敛后，另一保存恰在检查点打开文件前把 B 写入正式库；检查点记录当前 B，但云端仍 A。同进程锁库清缓存/内存同步基线后重开干净 B，远端若为合法 C，错误检查点会把差异判作纯远端更新并采纳 C，B 尚未上传。新一轮的快照已是 B，因此同期编辑守卫不能识别上轮误记；不依赖混合读文件。
- **建议与验收**：检查点绑定实际确认修订、库/目标身份及稳定文件写入回执；在共享数据库提交边界复核修订，不能一致取样时不登记。仅扩大同步 mutex 不能阻止使用另一把锁的保存。用 barrier 固定 A 结算后、摘要读前提交 B，再锁库重开并提供 C，确认 B 保留待合并。

### ISSUE-P2-625：同步网络等待可使安全锁定延期数分钟

- **核实**：2026-10-15，当前同步挂锁、自动锁定与请求超时/重试源码及独立基线复核；中危、置信度高，未做慢网设备复现。
- **位置**：`SyncCoordinator.kt:245-252`、`SyncCycleRunner.kt:126-135`、`AutoLockSessionGuard.kt:128-143`、`AutoLockHoldoff.kt:21-52`、`SyncNetworkOptions.kt:37-42`、`TransientHttpRetry.kt:52-68`。
- **触发与后果**：取得同步 mutex 前即增加长任务挂锁计数，直到整个网络周期结束才释放；熄屏/后台超时锁定只返回 Deferred。单 call 上限 300 秒、至多 3 次尝试，但没有周期总预算或挂锁 deadline；慢响应可使安全锁定延期数分钟，排队调用也可延长挂锁。明文暴露另需设备/应用仍可被人访问，云端不能直接读库；finally 和单请求超时构成反证，不称永久不锁。
- **建议与验收**：网络使用独立密文快照，挂锁缩至必要本地提交段；明确安全锁定最长延期，能取消/暂停后续明文工作并可靠清理主凭据，合并重复触发。以慢 HTTPS、熄屏、后台超时和同步排队验证锁定完成时间及文件保全。

### ISSUE-P2-626：前台同步收尾仍在主线程读取整库摘要

- **核实**：2026-10-15，前台 viewModelScope 调用链和检查点文件读取源码及独立复核；中危、置信度高，未测帧、ANR 或功耗。
- **位置**：`VaultListViewModel.kt:166-171`、`VaultListSyncController.kt:67-70`、`SyncCycleRunner.kt:126-130`、`SyncLocalFileCheckpoint.kt:62-64,77-90`。
- **触发与后果**：前台同步成功后回到调用线程，普通 `record()` 经 FileInputStream/SHA-256 遍历整库；内部装配的 IO 调度不覆盖该收尾。大库/慢存储可阻塞 UI；不据此认定 Worker 也在主线程或已发生 ANR。
- **建议与验收**：检查点读取自行切 IO，并与 ISSUE-P2-624 的修订绑定共同设计；优先复用可信写入回执摘要。线程/StrictMode 验证须覆盖成功收尾，另测大库磁盘读取量及帧延迟。

### ISSUE-P2-627：锁库或进程冷启时周期同步在联网前直接失败

- **核实**：2026-10-15，WorkManager 执行体、周期入口和设置文案静态追踪；中危、置信度高，未实跑锁定态周期任务。
- **位置**：`PeriodicSyncWorker.kt:32-47`、`SyncCycleRunner.kt:134-136`；设置文案 `strings.xml` 的 `sync_periodic_sub`。
- **触发与后果**：启用周期同步后，任务运行时若库已锁定或进程新建，`databaseFlow` 为空，直接返回未解锁错误，尚未构造 Provider 或探测远端；Worker 对所有结果返回 success。周期任务不能在常见锁定状态完成所述后台云端变更检查，解封云凭据无需用户认证也不能消除此依赖。
- **建议与验收**：将密文待传队列/元数据探测与需解锁的 KDBX 合并分离，按库持久化修订及条件写基线；锁定时仅执行无需明文的工作，合并留待解锁。未支持前明确限定文案，锁定跳过与真实鉴权失败分开表示；不得为后台同步长期保留主密钥。以锁库/冷启后真实请求和解锁后收敛验收。

### ISSUE-P3-622：开库失败可留下未被会话接管的明文附件缓存

- **核实**：2026-10-15，当前普通/子库加载、附件落盘及异常清理源码复核；低危、置信度高，未做设备磁盘复现。
- **位置**：`SessionOpener.kt:254-285`、`ChildReadOnlySession.kt:147-164`、`InnerHeaderReader.kt:85-99`、`KdbxFile.kt:284-290`；对照 `SessionExternalParser.kt:29-44` 的按次记录清理。
- **触发与后果**：大附件已写入 `cacheDir/attachments` 后，后续字段/XML/终止块认证失败；直接调用方仅返回错误，没有撤销本次 spill，`InnerHeader.clearSensitive` 只擦随机流密钥。残余受 app 私有目录隔离，锁定/关闭/冷启动会清；普通根库重试前会清旧缓存，重复累积只在子库等没有全局重置的路径讨论。不能据此认定普通其他应用可读取。
- **建议与验收**：统一记录每次解析创建的存储键，失败/取消按次撤销，成功后明确转移所有权；不要全局清理而误删活动根库附件。以虚构大附件和晚失败/取消验证实际磁盘残余，并保留已有根库附件为不得删除的对照。

### ISSUE-P3-623：CSV 导出的库字段可被电子表格当作公式

- **核实**：2026-10-15，当前导入到导出的静态追踪及 [LibreOffice 公式导入选项](https://help.libreoffice.org/latest/en-US/text/shared/00/00000208.html)核对；低危、置信度高，未运行表格公式或外联验证。
- **位置**：`KdbxCsvExporter.kt:81-95,106-144` 的 String/CharArray 两种写入；`BrowserCsvImporter.kt:130-143` 仅告警而保留字段；`SettingsExportController.kt:139-152` 有效保护明文导出授权。
- **触发与后果**：不可信条目字段以 `=` 等公式前缀进入库，用户确认导出 CSV 后，在允许公式求值的表格软件中打开。当前仅转义列分隔符/引号/换行，无法保证单元格按文本解释；具体内容伪造、外联或泄露取决于下游策略，不能描述为自动泄露。
- **建议与验收**：明确区分原值交换与表格安全导出，后者强制单元格文本语义，并向原样 CSV 使用者提示公式风险；不得静默改写互操作密码。用无外联算术公式验证指定软件/选项下按文本导入，同时对拍原值导出再导入保持秘密不变。

### ISSUE-P3-629：字段级“采纳云端”无法表达云端字段删除

- **核实**：2026-10-15，冲突字段词汇、UI 决策、合并和上传链静态追踪及独立复核；低危、置信度高，属于当前策略/交互限局，删除语义需产品裁决。
- **位置**：`KdbxMerger.kt:245-255,277-285`、`SyncConflictResolution.kt:128-136,87-101`；反证 `KdbxMergerFieldResolutionTest.kt:105-120`。
- **触发与后果**：云端合法 KDBX 已删除字段，本地仍有该字段，用户逐字段选择云端；缺键分支直接 continue，保留本地值并上传。自定义字段已有测试明确锁为 no-op；本仓通常保留标准字段的空值键，标准缺键主要来自外部客户端。整条目采纳云端可以采用删除，不据此报告远程秘密泄漏。

### ISSUE-P3-630：WebDAV Basic 认证的可擦密码中间副本未清零

- **核实**：2026-10-15，认证头构造源码与独立基线复核；低危、置信度高，工程清理缺口，未作堆转储复现。
- **位置**：`WebDavAuthHeader.kt:28-43`。
- **触发与后果**：UTF-8 `passwordBuffer` 复制出的独立 `passwordBytes` 未在 finally 清零，仅擦了 combined 和原 buffer；该副本待 GC 回收。利用需进程内存读取，超出当前云端无密钥威胁模型，因此不算已证明的云同步泄漏漏洞；最终 Basic header 的 String 边界另有声明，不能承诺全堆擦除。
- **建议与验收**：将独立密码字节副本纳入覆盖正常/异常路径的 finally 所有权清理，减少不必要副本；用虚构凭据验证各中间可擦缓冲的清理责任。
