3. **行号一律视为「核实时刻的快照」**：正文内引用的 `文件:行号` 仅作定位提示，实现前须以真实内容为准。

## P2 中危缺陷与协议/测试缺口（1 项）

### ISSUE-P2-88：自动匹配候选的「二次确认」路径确认后仍不写入凭据（`AutofillConfirmActivity`）

- **优先级**：P2（核心流程体验——**已解锁库**的自动匹配候选点「确认填充」后，目标输入框仍为空）
- **当前状态**：**开放项**——与已闭环的 `ISSUE-P2-86` **同源**（同一条认证链路）但**成因不同、修法不同**，故独立跟踪。
- **来源**：`ISSUE-P2-86` 的 2026-09-17 真机验证批次**顺带取得的新证据**（该批次原本只做解锁路径）。
- **核实时间点与核实方式（2026-09-17，真机 Redmi 4X / LineageOS / Android 17 / API 37，serial `1c859bcc7d24`）**：
  - **现象**：自动匹配候选 → 框架拉起 `AutofillConfirmActivity` → 点「确认填充」→ 页面正常结束、无崩溃，
    但**客户端两个输入框始终为空**（客户端自述 `usernameFilled=false passwordFilled=false`）；
  - **本次新做的关键负向实验**：把该路径的认证 `PendingIntent` 同样改为 `FLAG_MUTABLE`、并**去掉**基 Intent 的
    `NEW_TASK|CLEAR_TOP`（即与已验证可用的选择器 / 解锁路径**同构造**）后，真机结果**仍为不写入**，
    框架留痕 `onAuthenticationResult(): empty intent`。
    ⇒ **「PI 可变性 / 基 Intent flags」不是确认路径的决定变量**。
    该改动因而**未被保留**（确认路径的代码与 HEAD 逐字一致，仅加注释）——不做未经证实的、且会扩大攻击面的变更。
- **问题描述（两条路径的数据集形态不同，这是本次诊断的落点）**：
  - **选择器 / 解锁路径**：数据集**不带值**，由活动在用户指认后构造**真实 `Dataset`** 并经
    `AutofillManager.EXTRA_AUTHENTICATION_RESULT` 回传 ⇒ **真机实测可填充**（`ISSUE-P2-86` 已验证）；
  - **确认路径**：数据集**本身已带真实值**（`AutofillDatasetBuilders` 中 `setField(usernameId, …)` 的真值），
    认证 `PendingIntent` 只作**放行门控**；活动结束后仅 `setResult(RESULT_OK, Intent().putExtras(Bundle.EMPTY))`
    ——**不回传数据集**。⇒ 实测不写入。
- **待验假设（**列为待验假设，不得当结论**）**：
  1. 确认结果可能**必须**经 `EXTRA_AUTHENTICATION_RESULT` 回传一个 `Dataset`，框架才会把值应用到目标表单。
     但当前活动**手上没有该数据集的取值**（它只持有 `EXTRA_CREDENTIAL_TITLE` / `EXTRA_ENTRY_ID` / 授权上下文），
     故这条路是**设计级**改动：需把目标框 id 一并下发，由活动在确认后按条目取回凭据并构造 `Dataset`
     （与选择器的 `deliver` 同构）。
  2. 或者，「**带值数据集 + 门控 PI**」这一形态本身不被框架支持，须把候选数据集改写成选择器同构造
     （不带值 + 活动回传）。
  ⇒ 两条假设**须先做单变量实验区分**，不得先改代码后补理由。
- **验收标准**：
  - ① 用**单变量**实验区分上述两条假设，给出**真机原始留痕**；
  - ② 依结论实施修复，且**必须保持**「经用户显式确认才下发明文」这一既有安全属性
    （`TASK-11` / `ISSUE-P1-24` 口径：已解锁分支的每个数据集必须携带 `setAuthentication` 二次确认）；
  - ③ 真机用例断言「确认后凭据写入客户端输入框」，并在**关掉任何『客户端显式重请求』补救**的前提下通过；
  - ④ 若结论为「当前形态不可修复」，则**如实登记为已知行为边界**（`已知工程限界`）并写明用户可见后果。
- **与 `ISSUE-P2-86` 的关系**：`P2-86` 已闭环（解锁路径改为「链入选择器并原样转发认证结果」并经真机验证）。
  本条**不**回退该修法；两条路径的构造不同，**不可互相外推**——**已实测**：把 `P2-86` 的两项构造改动
  套到确认路径上**无效**。
- **依据**：`RESOLVED_LOG.md` §110；`docs/records/自动填充认证链路真机实测记录.md`；
  `app/src/main/java/com/keepasskey/app/autofill/AutofillConfirmActivity.kt`。
