# 敏感缓冲所有权契约

> 本文件是敏感数组和缓冲区的唯一所有权与擦除规范。工程规则只规定通用的敏感数据处理原则；产品已接受的不可擦除残余由 [已知工程限界.md](已知工程限界.md) 登记。
> 新增所有权类别、改变擦除责任或扩大豁免范围，均视为安全契约变更，须同步更新本文件中的规则、登记表和对应测试。

---
## 1. 目的与范围

同一数组可能在多个对象间复制、借用或共享；只看某处是否调用 fill，无法判断该处应不应该擦除。契约因此明确三件事：谁拥有缓冲、跨边界如何交付、哪些公开或非秘密数据可以豁免。

本契约约束明文与密钥材料的数组/缓冲所有权和确定性擦除。生命周期事件是否覆盖所有持有者不在此处重复登记，见 [已知工程限界.md](已知工程限界.md)；不可擦字符串边界也由限界表维护。函数内优先使用字符或字节数组的通用规则见 [工程规则](../../.codebuddy/rules/engineering-rules.md)。

## 2. 四类所有权（唯一分类法）

任何承载**明文或密钥材料**的数组 / 缓冲，在任一时刻**恰好**属于下列四类之一。

### 2.1 类别定义

| 类别 | 名称 | 定义 | 就地 `fill(0)` | 交出后 |
|:--:|---|---|:--:|---|
| **O** | **Owner（独占所有权）** | 本持有者是该缓冲的**唯一**引用者，且其可达性由本持有者独自决定 | ✅ **允许且必为** | 必须**转移**（交出后本方不再持有）或**复制**（各自负责） |
| **B** | **Borrow（借用视图）** | 本持有者可读该缓冲，但**唯一所有者是别人**（本方不决定其生命周期） | ❌ **禁止** | 原样归还 / 只读消费，不得驻留 |
| **S** | **Shared（别名共享）** | 同一实例被**两个及以上逻辑所有者**同时可达（copy-on-write、浅拷贝、列表复用） | ❌ **禁止**（会误伤存活方） | 只能「丢引用」；擦除须经身份集合判定 |
| **P** | **Process-lifetime（进程级）** | 该秘密的生命周期**等于进程**，设计上**不擦、不轮换** | ❌ **禁止** | 不适用 |

### 2.2 判定树（依次问，命中即停）

```
Q1 该秘密是否由进程级密钥派生、且设计上要求「随进程存活」？
     └─ 是 → P（必须登记到 §4 的 P 类清单；禁止新增）
Q2 是否存在第二个持有者，能在本持有者释放之后**继续读取**该缓冲？
     └─ 是 → S（典型：data class 浅拷贝共享数组、copy-on-write 共享 ProtectedString、
              `KdbxDatabase.copy()` 复用同一 `binaries` 列表）
Q3 交出者是否**保留引用**并期望自己仍可继续使用（读或写）？
     └─ 是 → B（典型：KdbxAttachment 内存附件的 data 借用视图、
              InnerRandomStreamCipher 对 streamKey 的只读消费）
Q4 否则 → O
```

> **判定优先序的理由**：`S` 必须在 `B` 之前问。若先问 Q3，会把双方共享的浅拷贝误判为借用，从而放弃擦除义务；反过来若把 `B` 误判为 `O`，会擦掉仍由他方使用的字节。

### 2.3 P 类（进程级）的既有实例与边界

既有 P 类实例是 `InMemoryCipher` 的进程密钥。它服务可跨树共享的 `ProtectedString`，不能在单个会话结束时擦除或轮换；接受理由与残余边界见[已知工程限界](已知工程限界.md) §2.2。未经重新评估不得为它增加局部擦除入口。

## 3. 规范性规则（R1 ~ R6）

> 本节是**可判定的**条款：每条都给出「违例形态」，供 §8 的机检面与代码评审引用。

### R1 — 就地擦除只对 O 类合法
**唯 O 类**允许 `fill(0)`。对 B 类的返回值、对 S 类的实例做就地清零**一律为违例**。

- 违例形态：`attachment.data.fill(0)`（B；内存附件的 `data` 是借用视图，
  `KdbxAttachment.kt:38-48`）；`oldRoot.clearSensitiveData()`（S；新树共享未修改子树引用，
  `KdbxGroup.kt:96-97` 明令禁止）。
- 正例：`KdbxAttachment.clear()`（`KdbxAttachment.kt:83-85`）只擦**本实例持有的** `inlineData`。

### R2 — 跨边界交付必须显式声明三种方式之一
交出缓冲时，必须（在 KDoc 与该方法的签名/命名上）声明为 **转移（transfer）/ 借用（borrow）/
复制（copy）** 之一；**默认是不转移**。

- **转移**：交出后本方**不得**再读、再擦（擦除责任随之转移）。落地形态：交出 `ownedSecrets`。
- **借用**：接收方只读且不驻留，**不得**擦除；KDoc 必须写「严禁修改或清零」。
- **复制**：接收方持独立副本、自负擦除责任；交出方保留自己的副本与责任。
- 违例形态：返回数组后又在 `finally` 中擦同一实例；需要交付独立结果时先复制，再擦除原数组。`CredentialIntermediateWipeTest` 锁定该责任边界。

### R3 — O 类的擦除必须挂在**确定性钩子**上
允许的钩子只有四种：`Closeable.close()` / `use { }` / 会话终止三事件（锁定 / 换库 / 退出）/
函数 `finally`。**禁止**以「等 GC」作为擦除手段。

- 落地形态：流实例自持副本由 `close()` 擦（`CbcStreams.kt:184-195`；
  `CbcDecryptingInputStream.kt:49-58` 的契约说明）；会话级由 `DatabaseSession.lock()` /
  `close()` / 换库前置释放统一触发（`KdbxDatabase.kt:62-74`）。
- 违例形态：把缓冲存进字段、却没有任何一个钩子会遍历到它。

### R4 — 函数内局部 O 缓冲：`finally` 擦除 + 不得外泄
函数内创建的 O 缓冲必须在 `finally` 中擦除，且**不得** `return`、不得写入字段、
不得传给非「转移」接收者。

- 正例：`HmacBlockStream.kt:363-382`（末块明文切片写出后清零，满块则留给 `close()` 收口）；
  `ProtectedString.useChars` / `useUtf8`（`ProtectedString.kt:129-151`）——把「借出 + 擦回」
  封成一个作用域，调用方无法忘记。
- 违例形态：`val copy = x.copyOf(); use(copy); return`（无 `finally`）。

### R5 — 会话级 O 缓冲的擦除必须经**统一收口点**
会话级秘密（凭据、派生密钥、整树、附件字节）只能由**已登记的收口点**擦除，
不得由各组件各自 `fill`（否则必然出现「补一处、漏一处」）。

- 收口点清单见 §4；新增会话级秘密必须**同时**登记其收口点，否则视为未完成。
- 反面形态（已登记为限界，非本条违例）：散落在各解析/序列化路径的**函数内局部** O 缓冲，
  由 R4 约束，不经 R5。

### R6 — 豁免必须落在 §5 清单内
未被 §5 清单收录的数据**一律推定为秘密**，必须指定所有权类别与擦除责任。
新增豁免须在 §5 追加一行并给出「为何不由密文 / 公开信息推导」的理由。

## 5. 非秘密数据豁免清单

不在本清单中的内容默认按秘密处理。豁免只表示该值本身不承担密钥或明文载荷语义，不代表可以写入日志或公开给无关调用方。

| # | 豁免类别 | 理由 | 失效条件 |
|:--:|---|---|---|
| E1 | `KdbxAttachment.contentHash()`、`InnerHeader` 附件内容哈希、`HealthCheckEngine` 重用索引哈希 | 仅用于内容去重或身份等值判定，不进入密钥派生 | 任一摘要被用作密钥材料、KDF 输入或认证凭据时重新分类 |
| E2 | AES KDF `seed`；Argon2 `salt`、`associatedData` | KDBX 外层头部 VariantDictionary 中明文参数 | 格式改为保密存储时重新分类 |
| E3 | `KdbxHeader.masterSeed`、`encryptionIv`、`cipherUuid`、`compression`、`innerRandomStreamId` | KDBX 外层明文头字段 | 对应字段改为保密字段时重新分类 |
| E4 | Salsa20 固定 8 字节 nonce、`InnerRandomStreamId.NONE` 常量 | 固定协议值，不由库秘密派生 | 任一值改为按库生成时重新分类 |
| E5 | 同步响应 `etag`、`contentLength`、`lastModifiedMillis` | 远端公开响应的结构元数据，不含数据库载荷 | 任一值成为唯一安全裁决依据时重新评估 |
| E6 | `InnerHeader.BinaryItem.flags` / `size`；`HmacBlockStream` 的 `blockIndex`、`blockSize`、`currentBlockSize`、`filled`；`WipableByteArrayOutputStream.count` | 仅表示保护标志、块位置或缓冲长度 | 新增标量不自动豁免；任一所列值被证明可推导秘密内容时重新分类 |
| E7 | 数据库 `name`、`description`、UUID；`KdbxTimes.creationTime`、`lastModificationTime`、`lastAccessTime`、`expiryTime`、`expires`、`usageCount`、`locationChanged`；`KdbxGroup.name`、`notes`、回收站标志 | 明确列出的模型展示元数据，不是凭据字段 | 字段语义改为承载凭据时重新分类；用户自行填入凭据仍按秘密处理 |
| E8 | `KdbxAttachment` 落盘路径缓存的 `contentHash` | 与 E1 同一附件内容摘要，用于身份/去重 | 该摘要用途超出 E1 所列条件时重新分类 |

### 5.1 不得豁免的相似数据

口令哈希、复合密钥、派生密钥、密钥文件摘要、HMAC 密钥，以及任何受保护或未受保护字段的明文都按秘密处理。“字段未加密”不等于字段值可公开。

## 6. 池对象身份判定

### 6.1 分类

- 独占的内存池条目属于 O 类；同一个条目实例被多个数据库或会话引用时属于 S 类。
- 附件对池条目的访问是 B 类借用；copyOf() 生成的独立副本由接收方负责。
- 因此共享池不能按内容比较后清理，必须按对象身份排除仍被存活侧引用的实例。

### 6.2 当前规则

二进制池和图标池的清理均遵循对象身份集合判定：清理独占实例，保留仍被活动侧引用的共享实例。现行落点和守卫测试见 §4 的登记表。本节保留为既有 §6.1/§6.2 引用入口。
---

## 7. 验证锚点

### Step 4 — 池清理身份判定

清理二进制池或图标池时必须按对象身份排除存活侧共享实例；对应不变式和测试见 §4、§8.1。

### 7.1 规则对照

所有权交付由 R1–R6 约束；不得以清理共享对象、过早擦除借用方缓冲或等待 GC 替代明确责任。既有测试与本契约的对应关系见 §4 和 §8。

## 8. 测试与机检

### 8.1 契约测试入口

测试类与其锁定的不变式列在 §4。测试本身是行为的权威实现；本文件不重复维护每个测试的场景数量或执行历史。

### 8.2 必须维持的不变式

每个 O 类收口点至少有一条契约测试。测试须覆盖正确擦除及危险负例：不得擦除 B 类借用、仍存活的 S 类共享实例或已交付给调用方的返回值。新增测试必须能区分契约正确与错误实现。
