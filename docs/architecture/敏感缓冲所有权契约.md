# 敏感缓冲所有权契约

适用于主密码、密钥文件、派生密钥、私钥、条目明文及解密附件。平台字符串与介质擦除限制见 [工程边界](已知工程限界.md)。

## 所有权

| 类型 | 约定 | 谁负责清理 |
|---|---|---|
| 独占 | 本持有者决定生命周期 | 持有者在 finally、close 或会话结束时擦除 |
| 借用 | 只读使用他方的缓冲，不驻留、不修改 | 原所有者；借用方不得清零 |
| 共享 | 新旧树或多个对象仍引用同一实例 | 统一收口，按对象身份排除仍存活引用；下线回收经 `ProtectedStringReclamation` 基于 Epoch 分代协调，等待下线时刻在册的读者退出后排空，后续新租约不推迟旧桶；无在册读者时立即擦除；已下线对象严禁重新挂回活动树 |
| 进程级 | 生命周期覆盖进程 | 既有 InMemoryCipher 密钥不随单会话清除，不随意增加此类秘密 |

交付数组时明确是转移、借用还是独立复制。转移后交出方不再读取或清零；复制后各自负责；返回结果前不能在 finally 中擦掉同一数组。

## 清理边界

- 函数内独占缓冲在 finally 清理，流持有的副本由 close 清理；不依赖 GC。
- 会话凭据由凭据缓存统一清理；轮换、锁定、关闭与换库时保证旧独占材料退出。同步 Provider 持有的协议凭据副本在会话终止、换引擎、配置撤销与丢弃待决引擎时经 `SyncEngine.releaseProviderCredentials` 失效；认证头按请求现算，不可擦的 String 只存在单次请求作用域。
- 数据库树、附件池和图标池按实例身份清理，不能按内容相等判断是否共享，也不能清掉新活动树仍引用的 ProtectedString。
- 消费一份树快照的读取面（UI 投影、检索、凭据装配）在消费期间登记单调租约 ID，租约覆盖使用期而非仅取回动作，旧实例归入对应 Epoch 退休桶等待在册读者退出；后续新租约不推迟更早退休桶，无在册读者或锁定/会话终止/换库时立即擦除（锁定为硬边界，旧树读取直接拒绝交付）。未释放读者的待回收实例驻留内存取决于读者生命周期，协调器不设硬上限强清（以杜绝活读被中断），消费方须严格避免持租约跨交互或跨网络等待；内部状态与批量排空由单一 monitor 同步保护，存在锁竞争且清零为 O(N) 循环开销，不宣称无锁或零成本。实测 3000 条目设备采样（emulator-5554 API 36）投影耗时 135~209 ms（中位 154 ms）、并发改树保存 371~426 ms（中位 382 ms），仅代表本测试环境。
- 内存附件的 data 可能是借用视图；对外交付明文附件时提供独立副本，调用方用完擦除。落盘附件由 BinaryStore 生命周期回收。
- 保存链写盘确认成功后，整库序列化缓冲的所有权转移给会话持久化基线（不再克隆第二份）；基线在替换登记、清除、锁定与关闭时擦除，交出方此后不得再读写或清零该数组。留存失败时基线作废并前移修订，不留旧值冒充最新版本。
- 序列化、导入导出、认证编码与签名派生可能产生额外副本，每个独占副本都要有明确清理点，失败和取消路径同样适用。
- 流式解密可采用有界预读：小请求按最小预读块 4 KiB 摊销原生调用，批量读取仍以 64 KiB 封顶，未交付明文只驻留当前一次预读量；交付即归零、close 整段兜底归零，预读不得扩大到吞掉整段载荷。
- Rust 原生秘密用 Zeroizing 或等价确定性擦除机制覆盖正常及提前返回路径；JNI 入参与输出也按各自所有权处理。

## 非秘密与可观测边界

格式公开的盐、IV、算法标识、长度、UUID、同步版本元数据及用于去重的内容摘要，不因数组类型就自动成为密钥；若被用于认证或密钥派生，按秘密重新评估。密码哈希、复合密钥和密钥文件摘要始终按秘密处理。用户字段即使未启用保护位，也不能写入日志。

不可确定擦除的 String 不冒充已清零。展示面遇到已释放字段可安全降级，写盘或交付面必须明确失败，不能把不可读内容转换为空值后保存。

## 验证

保留有判别力的行为测试：成功、失败及取消后独占缓冲被擦除，借用数组不变，共享存活实例不受损，已交付副本仍有效。回收协调的判别性用例包括单调租约分代排空、后续新租约不推迟更早退休桶、合规长租约不被提前硬清、锁定直接清理不等租约、共享存活实例在旧租约释放后仍可读、并发读取不产生半份明文。断言以真实行为和状态迁移为准，不锁定源码私有结构。无需另维护逐类逐用例的登记表或断言源码中必须出现某个清理调用。
