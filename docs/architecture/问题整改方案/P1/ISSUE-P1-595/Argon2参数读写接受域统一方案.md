# ISSUE-P1-595：Argon2参数读写接受域统一方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：本项已实施并于[批次514](../../../../resolved/batches/514-Argon2参数读写接受域统一批次.md)验收闭环。 以下矩阵保留原实施验收要求，实际结果以批次为准。

## 1. 问题与依据

来源为 AUD-07。2026-10-13 直读 `database/src/main/java/com/keepasskey/database/file/KdbxKdfParameterCodec.kt` 的联合预算及动态堆门槛，并核对 `SettingsPreferencesController.setArgon2Parameters`。256 MiB×50 轮等于 12.5 GiB 字节·轮，超过现读侧 8 GiB 上限；本次没有执行该高负载派生，也不声称所有设备能成功写出。

## 2. 目标与边界

UI、写侧和读侧使用同一组可接受参数规则；本设备允许保存的设置在相同预算下必须可重开。不放宽现有防 DoS 门槛，也不保证任意低内存设备都能打开高预算库。

## 3. 实施步骤

1. 将现行边界整理为 database 层的公开窄接口，供 app 设置校验使用；读侧内部 codec 委托该接口。保持 app→database→crypto→core 依赖方向，不让 crypto 反向依赖 database。
2. 单一判据覆盖内存、迭代、并行度、版本、每通道下界、盐长、联合预算及设备可用预算。设备预算通过可注入快照获取，以便确定性测试。
3. 联合预算保持除法判定避免乘法溢出；MiB→bytes 转换也先校验，不能在 Long 溢出后再判范围。
4. 设置控制器在改变会话前校验，UI 动态禁用不合法组合并说明原因；默认选项、算法切换、基准推荐值都走同一判据。
5. KdbxFile 写入口在写任何目标字节和进行 KDF 前再校验，阻止绕过 UI 的调用者写出不可接受产物。失败不得改会话头或正式文件。
6. 更新读侧 KDoc 中「宽于一切合法用户配置」的过时陈述；动态预算作为设备能力限制明确说明，不误称 KDBX 格式标准上限。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 256 MiB×32 / ×33 / ×50 | 固定足够堆预算时，32 边界允许，33/50 在派生前拒绝 |
| 堆预算低于目标内存两倍 | UI 和写侧拒绝，与读侧一致 |
| memory=8×parallelism×1024 的上下邻点 | 各入口结论一致 |
| 超大 Long 输入、非法版本/盐长 | 无溢出旁路，不触发高负载派生 |
| 所有 UI 组合 | 合法组合实际写后重开；非法组合不改变磁盘/会话 |

扩展 `Argon2KdfBoundsMirrorTest`、`KdbxKdfParameterCodecWriteContractTest`，枚举组合的接受域测试与真实派生往返分开。高成本合法组合逐项安排设备预算，未执行项如实保留。

## 5. 顺序与实施验收

与 ISSUE-P2-602 的候选设置事务配套，写入口受 ISSUE-P1-601 保护。先纯边界测试，再真实写读及官方产物对拍；不能以 mock KDF 成功代替往返。若修改 Native 绑定、原生分派或探活，必须按仓库规则完成四层设备测试。
