- 本轮已修改生产代码、测试、产品裁决及状态文档。此处各方案中的拟议状态类型、预算和接口只有在源码中实际落地后才可视为现有契约；各开放项不能因部分实现或测试通过而关闭。
- 开始实施前重新读取当前问题及相关源码，比较本页基线；历史方案、历史验收和编译成功均不能替代当前验收。源码位置以链接文件及函数为准，行号随实现变化。
- 每项交付都记录“实现、编译、JVM、设备、生产路径端到端”的实际状态及未验证项；每个原始触发序列都有正/负对照。对静态推断仍用“需要进一步验证”，不自行提升严重度或声称真实泄漏。
- 用 barrier、受控调度和定点文件故障注入验证竞态，不用概率性 sleep。分别检查正式文件重解析、内存、缓存/基线、rollback 状态、实际远端回执；仅最外层返回值不足以证明一致性。
- 实施时按改动范围选择 JVM 测试，例如 `./gradlew.bat :app:testDebugUnitTest :database:testDebugUnitTest :sync:testDebugUnitTest`，优先运行各方案点名的有意义用例。新增用例名是计划，已有用例也需实际执行后才能报告通过。
- 本轮按用户指示在已连接的 API 37 Redmi 4X 实体机串行运行 Android 用例；测试前确认 KeePasskey 主应用包未安装，避免触碰用户库数据。对应模块执行 `connectedDebugAndroidTest`，检查 tests > 0、failures = 0、errors = 0 并保留非空 XML。后续若设备已有需保留的数据，改用隔离设备。普通进程死亡、冷启、force-stop、会话重建是不同证据，不混用。
- 如实施扩大到 Rust/JNI/Native 加密分派或探活，必须执行 crypto、database、sync、app 四层设备测试。当前文档交付未触及这些实现，也未运行运行时测试。
- 只使用虚构秘密与无外联公式，不向日志写入秘密/敏感站点标识。共享 `ProtectedString`/附件引用遵守所有权；独立 KDBX 客户端端到端对拍后才可宣称互操作。
- 方案/实施文档使用简体中文；文档交付运行 `python tools/doc/check_md_links.py` 及 `git diff --check`，另核对“当前 ID—文件夹—方案—登记链接”一一对应。安全审计/复核报告若被修改，另跑一致性脚本；本轮未改此类报告。
