# ISSUE-P3-605：防截屏政策与现行裁决对齐方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 AUD-17。2026-10-13 对照 `docs/security/Privacy-Policy.md`、PD-47/PD-48、归档 §411 的用户裁决与 `app/src/main/java/com/keepasskey/app/security/FlagSecurePolicy.kt`：现行窗口守卫只看用户开关，政策及旧裁决仍写锁定态强制。代码行为是已接受取舍，本项修文档承诺。

## 2. 目标与边界

公开政策与当前裁决一致，明确旧「锁定态强制」口径已被 2026-10-02 裁决替代。不得借修文档擅自恢复强制防截屏，也不能把窗口守卫开关外推为所有特殊对话框均无独立规则。

## 3. 实施步骤

1. 定向核对 FlagSecureGuard、SecureDialog、TOTP/Passkey 扫码对话框和系统凭据 Activity 的实际策略，形成「常规窗口/特殊对话框」声明边界。
2. 将政策改为：窗口截屏防护按用户开关生效，关闭后解锁页等窗口可被截屏/录屏；保留风险确认与首帧保守防护的真实描述。
3. 在 PD-47、PD-48 中标记「锁定态强制」旧段被 §411 裁决替代；保留各条其余扫码、PRF、字段校验裁决。使用批次编号引用，不改历史归档原文。
4. 统一应用内安全说明、发布文案和其他政策副本；只更正冲突承诺，不重写无关政策。特殊对话框若独立强制，则照实描述其例外。
5. 写清保护局限：开关关闭后的截屏/相册副本无法由应用追溯擦除，首帧临时 FLAG_SECURE 不能等同全程保护。
