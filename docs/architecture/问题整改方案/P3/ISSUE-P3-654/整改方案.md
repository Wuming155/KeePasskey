# ISSUE-P3-654 crypto的PRF与CBC兜底临时秘密副本未确定清零

> 状态：**尚未实施**。核实：2026-10-16（Asia/Shanghai）；基线：`94172d1efca004692b68ea480a1516753087fd70`。
> P3；静态确认缓冲生命周期缺口；置信度：高。仅静态源码确认，未执行产品或运行测试。

## 1. 问题与依据

PRF secretToProtected新建Base64 CharArray交给只读借用构造器后未擦原件；stripWhitespace缩短数组后未擦旧out。CBC堆兜底尾块在head非空时用head+stripped复制到out，但旧head/stripped明文数组未擦。

影响：PRF秘密文本和CBC末段明文的可擦短命副本等待GC。CBC仅堆兜底路径且head非空时成立；不据此推导远程、跨进程读取或密码学算法失效。

- [crypto/src/main/java/com/keepasskey/crypto/passkey/PasskeyPrf.kt](../../../../../crypto/src/main/java/com/keepasskey/crypto/passkey/PasskeyPrf.kt)：原始行124–142。
- [crypto/src/main/java/com/keepasskey/crypto/cipher/CbcDecryptingInputStream.kt](../../../../../crypto/src/main/java/com/keepasskey/crypto/cipher/CbcDecryptingInputStream.kt)：原始行286–300。

1. 用虚构32字节PRF秘密调用编码，再对含空白的Base64秘密解码，观测临时数组生命周期。
2. 让CBC堆兜底在末次缓冲至少两块、合法PKCS7条件下完成，观察head/stripped/out为独立数组。
3. 正常返回和异常路径检查工作数组；返回ProtectedString/out必须仍有效。

反证：有效容器out/ProtectedString及部分原始bytes已有清理；CBC直接缓冲路径不同。没有额外未授权读取堆的攻击链。

## 2. 修复目标与边界

明确命名并清理各独占中间数组，只把一份有效结果移交给输出所有者。

模块：crypto PasskeyPrf/CbcDecryptingInputStream；core ProtectedString借用契约。预期：临时秘密副本按所有权清理，返回结果不被误擦。

不改PRF算法、CBC填充协议或既有直接缓冲分派；不承诺全堆擦除。

## 3. 实施步骤与失败处理

1. secretToProtected保存临时chars并finally清零，保留encoded现有清理。
2. stripWhitespace在copyOf缩短成功后擦旧out，异常同样兜底清理，返回原件时正确转移所有权。
3. CBC head非空拼接后finally擦head/stripped，head为空时不得擦已转移的out；提前异常也覆盖。

失败时所有已分配的独占工作数组在finally中擦除，已交付的输出由其所有者清理。不得为“补清零”擦掉受保护容器或有效输出的唯一数组。

## 4. 验收矩阵

- PRF编码和带空白/非法文本解析的中间缓冲清理，返回容器内容正确。
- CBC合法/坏padding/transform异常、head空与非空、close提前结束，明文与既有向量一致。
- 若改变原生分派或JNI则按AGENTS四层connected实跑，纯堆分支改动按实际受影响测试验证。

以上是拟议验收，当前实现/编译/JVM/设备/端到端均尚未实施；新增或修改的androidTest必须实际运行且XML非空。保持已有算法向量和失败测试。
