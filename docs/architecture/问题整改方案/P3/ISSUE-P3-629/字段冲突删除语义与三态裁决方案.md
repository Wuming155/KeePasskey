# ISSUE-P3-629：字段冲突删除语义与三态裁决方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：本项已实施并于[批次 §524](../../../../resolved/batches/524-字段冲突删除三态与KDBX对拍批次.md)验收闭环。以下矩阵保留原实施验收要求，实际结果和边界见归档批次。

## 1. 问题与依据

当前登记为 P3、置信度高，属于策略与交互缺口。[KdbxMerger.kt](../../../../../sync/src/main/java/com/keepasskey/sync/merge/KdbxMerger.kt) 的 `resolveConflictByFields()` 对远端缺失的标准键和自定义键直接 `continue`；`KdbxMergerFieldResolutionTest` 明确锁定远端缺自定义字段时 no-op。[SyncConflictResolution.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncConflictResolution.kt) 优先采用字段决策，再序列化上传，所以界面选择云端仍可能把本地字段传回去。

本仓通常保留标准字段空键，标准缺键主要来自外部文件。整条目采纳云端已能采用删除；本条不等于远程秘密泄露，也不能把自动合并所有缺失键直接视为删除。

## 2. 目标与产品取舍

推荐在用户显式逐字段选择时区分“保留本地”“采用远端值”“采用远端删除”；字段缺失、存在但为空、存在且有值必须可辨。默认仍保留本地，删除需要界面明确显示并被选择。标准字段缺键是否原样保留还是按模型规范转为空键，先形成产品裁决及互操作要求，不能由 nullable 值隐式决定。

若产品决定暂不支持字段删除，则禁用远端缺失字段的“采纳云端”操作并解释原因，引导用户使用已有整条目入口；不能保持按钮看似生效但实际 no-op。该路径只能按最终明确的产品范围验收，不能同时宣称支持三态删除。

## 3. 实施步骤与失败处理

1. 在现有产品裁决中记录缺失/空值/删除的区别、标准与自定义字段规则、默认选择及历史保留行为。先增加原行为对照测试，保留既有用例资产；修改 no-op 断言时给出新裁决依据。
2. 在合并域引入有类型的字段存在状态和已验证决策，避免 `Map<String, nullable value>` 同时表达缺失与未选择。由冲突快照及用户选择导出保留/设值/删除三态，限制可处理键为该冲突的已知差异键。
3. 在 `KdbxMerger.resolveConflictByFields()` 应用删除：自定义字段按精确键删除；标准字段按裁决删除键或设置规范空值。未选择、未知键与伪造决策拒绝或安全保留，不扩展为条目/历史/附件整体删除。沿用修改时间及历史快照策略。
4. 同步调整 `ConflictResolutionUiState`、`ConflictResolutionViewModel.buildConflictedField()` 和字段行：明确显示“云端已删除”与“空值”，受保护值继续掩码；选择前不把秘密放入 UiState。全选云端时明确包含字段删除，整条目/双方保留入口继续可用。
5. 将决策与原冲突快照、库和远端 ETag 绑定。用户裁决期间本地/远端再次变化时，保留既有校验与 412 重新冲突流程；不得把旧删除决策自动套到新版本同名字段。
6. 仅在成功保存、上传与结算后发布新树；失败保留可重试的冲突上下文。被删除的 `ProtectedString` 可能仍由历史或旧树借用，按所有权契约释放，不能当场清掉共享对象。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 本地有值、云端缺失，分别选本地/云端 | 本地选择保留；云端选择按裁决删除，上传重解析后不复活 |
| 云端字段存在但为空；受保护/普通自定义字段 | 空值与删除在 UI 和产物上可辨，保护语义不丢失 |
| 双方添加/修改/删除及未选择 | 逐字段决策与差异快照一致，不误删无关字段 |
| 标准字段由独立客户端删除 | 读入、裁决、上传及双方重开符合确定的缺键规范 |
| 用户选择后本地修改、远端 ETag 改变 | 旧裁决拒绝或重新冲突，不静默覆盖新字段 |
| 整条取云端、双方保留、历史引用 | 既有入口语义保持，旧历史仍可读且无共享秘密提前擦除 |

扩展 `KdbxMergerFieldResolutionTest`、`ConflictResolutionCustomFieldTest`、`ConflictResolutionViewModelTest`，覆盖真实 UI → 决策 → 条件上传 → 重新解析链。涉及 KDBX 互操作的结论必须用独立实现端到端对拍，仓内自测不能替代。

## 5. 顺序、交付与回退

先产品裁决，再合并域三态、UI 及提交链同批接线。与 [ISSUE-P2-621](../../P2/ISSUE-P2-621/同步采纳代际事务与失败隔离方案.md)、[ISSUE-P2-624](../../P2/ISSUE-P2-624/同步检查点修订绑定方案.md) 联测时复用其结算边界，不同时改写共享提交状态机。

回退时禁用无法正确表达的逐字段云端删除，保留整条目选择；不恢复误导性 no-op。关闭前需有产品决定、合并器、UI、实际上传及互操作五类对应证据。
