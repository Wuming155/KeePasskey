# ISSUE-P3-647 CXF通行密钥导入遗留UTF-8工作字节与JSON副本

> 状态：**尚未实施**。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P3；结论：静态确认缓冲生命周期缺口；置信度：高。本轮只记录审查和方案，不修改业务代码。

## 1. 问题与依据

begin直接把toUtf8Bytes结果传解析器，只擦decoded。scanner每个字符串的ByteSink复制后未擦内部数组；reader不递归清理完整AST，只清已选秘密节点。多凭据、未知字段与失败分支的私钥/PRF/其它秘密副本可留下。

- 审查维度：安全性与权限控制。
- 影响范围：最多4KiB载荷的可擦中间副本驻留到GC，违背本类KDoc和所有权契约；未证明跨进程/远程秘密泄露，不使用真实载荷做复现。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/passkey/PasskeyImportDraftHost.kt](../../../../../app/src/main/java/com/keepasskey/app/passkey/PasskeyImportDraftHost.kt)：原始行 51–55。
- [app/src/main/java/com/keepasskey/app/passkey/ByteJsonScanner.kt](../../../../../app/src/main/java/com/keepasskey/app/passkey/ByteJsonScanner.kt)：原始行 138–150。
- [app/src/main/java/com/keepasskey/app/passkey/PasskeyCxfReader.kt](../../../../../app/src/main/java/com/keepasskey/app/passkey/PasskeyCxfReader.kt)：原始行 44–54。

复现/验证路径：

1. 使用虚构的单凭据、多凭据混装、含未知秘密字段及畸形JSON载荷导入。
2. 在测试观察传入UTF8数组、ByteSink和AST节点。
3. 成功/拒绝/取消后检查工作数组；返回草案仍须持有独立有效副本。

反证和限制：原CharArray、编码器buffer及部分选中key/PRF节点已有清理，载荷大小有限；利用仍需额外内存访问能力。

## 2. 修复目标与边界

解析器只保留显式交付草案的秘密，其余副本在所有终态清理。

涉及模块：app PasskeyImportDraftHost/ByteJsonScanner/PasskeyCxfReader。

预期结果：载荷工作副本清理与草案所有权分离且可验证。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 捕获UTF8工作数组并finally清零，继续尊重read(payload)调用方所有权。
2. ByteSink提供覆盖扩容旧缓冲的清理；scanner成功/失败均有闭合。
3. reader finally递归擦AST，先确认ImportedPasskey私钥/PRF均独立复制。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
