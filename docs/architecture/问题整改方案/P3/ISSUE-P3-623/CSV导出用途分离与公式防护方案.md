# ISSUE-P3-623：CSV 导出用途分离与公式防护方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：已完成（按用户指定的 Python 读写验证边界）。按 PD-86 保留原值 CSV 并新增文本型 XLSX 导出，单测通过；Python `openpyxl` 3.1.5 读取、保存并重载当前 Kotlin 导出器生成的 XLSX 后，`+1+1`、`-1+1`、`=1+1`、`@SUM(1,1)` 均保持字符串单元格。该验收范围覆盖 Python 读写互操作与 OOXML 单元格类型；未声称 Excel/Sheets/LibreOffice 的 UI 导入行为。

## 1. 问题与依据

当前登记为 P3、置信度高。[KdbxCsvExporter.kt](../../../../../database/src/main/java/com/keepasskey/database/csv/KdbxCsvExporter.kt) 的 String/CharArray 写入仅转义 CSV 分隔符、引号和换行。[BrowserCsvImporter.kt](../../../../../app/src/main/java/com/keepasskey/app/data/importer/BrowserCsvImporter.kt) 对公式前缀告警后保留原值；这是互操作边界，不能通过导入时篡改密码来修复导出问题。

用户确认明文导出后，是否求值取决于下游软件及选项。[LibreOffice 官方说明](https://help.libreoffice.org/latest/en-US/text/shared/00/00000208.html)区分公式求值、文本列和带引号字段按文本导入；CSV 引号本身不能保证所有软件都禁用公式。本项尚无公式执行/外联证据，不能表述为自动泄露。

## 2. 目标与产品取舍

推荐明确分为“原值交换 CSV”和“表格文本导出”。原值模式逐字符保留密码，明确提示公式风险及文本导入方式；表格模式使用能显式表达文本单元格的格式，建议 XLSX，并使所有库字段成为文本单元格、禁止生成公式/外部链接。该建议需在现有产品裁决中确认后实施，不能把格式扩展当作本次已批准的产品行为。

若暂不引入文本单元格格式，可先交付 CSV 风险提示和指定软件的安全导入说明；此阶段不宣称已有通用安全 CSV，也不将原条目按“已防公式执行”关闭。只加引号、黑名单或给所有密码静默加单引号不作为最终方案。

## 3. 实施步骤与失败处理

1. 在 `SettingsExportController` 及现有导出选项 UI 中显式传递导出用途类型；扩展前先登记格式、默认选项和原值保真决策。保持现有明文导出二次确认/令牌消费边界，两种用途都不得绕过认证。
2. 原值 CSV 保持当前列契约和 RFC 4180 转义，增加用途说明：可能被表格软件解释为公式；打开时使用文本列并关闭公式求值。不要在日志或提示里回显危险字段或密码样本。
3. 表格文本导出单独实现序列化适配器，先评估 Android 可用的官方库文档、依赖体积、流式写出与可擦缓冲边界，再选库；禁止把现有 CSV 改扩展名充当 XLSX。全部字段使用文本单元格，验证无公式节点、超链接关系、外部工作簿或宏。
4. String 和秘密 CharArray 通道使用同一用途策略；秘密只在第三方 API 必需边界转换，局部可擦副本用毕清理。若库强制把整库秘密长期聚合到普通字符串，应重新选型或继续维持明确限界，不能为功能引入隐蔽明文缓存。
5. 导出写入异常/取消时关闭资源，按现有存储能力删除不完整产物并反馈失败；无法删除的外部目的地残余应提示。禁止失败后自动回退为另一用途的原始 CSV。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| `=1+1`、`+1+1`、`-1+1`、`@`、制表符/回车前缀 | 表格模式在已声明软件/版本中显示文本，不计算；使用无外联样本 |
| 逗号、双引号、换行、Unicode、空值、前导零 | 值完整，无列偏移、日期/数字自动改写 |
| 密码以公式前缀开头或本身含单引号 | 原值 CSV 导出再导入后逐字符一致，无隐式增删前缀 |
| 文本单元格文件结构检查 | 所有库值为文本类型，无公式、外链或宏；实际打开结果与结构检查一致 |
| 未认证、确认取消、写盘失败、取消导出 | 不生成成功产物、不改库；失败和残余处理可见 |

扩展 `KdbxCsvExporterTest`、`BrowserCsvImporterTest` 和导出控制器测试；Kotlin 导出器生成的合成工作簿由 `openpyxl` 3.1.5 完成读取、重写、重载，所有公式前缀值保持字符串单元格；回读值与写出值逐项相同。按用户提出的 Python 库方案，以 Python OOXML 解析/往返作为本项实际导入验收边界；这不等价于 Excel/Sheets/LibreOffice UI 实测，也不声称验证其公式计算引擎。原值模式有意保留公式样本，不能把该用例误判为清洗失败。

## 5. 顺序、交付与回退

先确认用途和格式，再交付现有 CSV 风险说明及保真回归，最后实现文本模式并实测。两阶段结果分别登记：提示完成不代表安全表格格式完成。遵守产品裁决 PD-36 的明文导出二次确认。

若文本格式兼容性或敏感数据边界不达标，回退该模式，保留明确说明的原值交换能力；不能将表格模式按钮静默接回 CSV。支持范围以实际验收软件为准，不承诺任何未来软件/导入配置都安全。
