# ISSUE-P3-657 S3签名密钥级联派生在中途异常时遗漏清理

> 状态：**已关闭（2026-10-17）**——受控故障（第 2/3/4 步）与成功路径均验证，归档 [`RESOLVED_LOG.md` §536](../../../../RESOLVED_LOG.md)。核实：2026-10-16（Asia/Shanghai）；基线：`94172d1efca004692b68ea480a1516753087fd70`。静态确认异常出口缺口，置信度：高（控制流）；异常触发概率低。

## 1. 问题与依据

kDate/kRegion/kService在第一个try内依次生成，该finally只清kSecret；清前三级的第二个try只有全部派生完成后才进入。中间HMAC抛异常时，已分配派生数组跳过清理。

影响：异常路径的可擦派生秘密等待GC；正常路径已有清理，真实HMAC异常/资源错误才触发。无外部未授权读取内存证据，不是签名密钥直接外传。

- [sync/src/main/java/com/keepasskey/sync/s3/S3RequestSigner.kt](../../../../../sync/src/main/java/com/keepasskey/sync/s3/S3RequestSigner.kt)：原始行174–194。



1. 用测试注入的HMAC工厂依次在第2/3/4步抛出受控异常。
2. 保留测试侧观测引用并检查此前派生数组。
3. 当前不会进入第二个finally；成功路径作清理正对照。

反证与限制：正常签名结果无此遗漏；不假设远端数据能直接令HMAC内部异常。 本轮没有运行产品、服务或新增运行测试。

## 2. 修复目标与边界

级联派生的所有已分配独占数组在正常和任何中途失败下均清理。

模块：sync S3RequestSigner。预期结果：派生清理不依赖完整成功的控制流。

## 3. 实施步骤与失败处理

1. 将中间派生数组纳入同一最外层finally的可空持有，逐个按分配状态擦除。
2. 只有最终signingKey成功返回才转移所有权；失败不转移，保持kSecret清理。
3. 用受控故障验证，不在真实密钥或内存耗尽环境做破坏性复现。

失败必须如实返回，不伪装成功/空列表；不打印请求认证材料，工作副本按所有权在finally清理。接口调整同时检查所有调用方，不修改生产凭据或真实远端数据。

## 4. 验收矩阵

- 每一步受控失败与正常签名向量；已分配缓冲全清理，未分配不访问。
- 最终签名一致，调用方仍负责清最终返回key。

验收用例是后续计划，不是已通过结果。实现、编译/JVM/设备、真实S3端到端尚未执行。设备用例若新增/修改必须在隔离AVD或可丢弃设备实际运行并确认非空XML。
