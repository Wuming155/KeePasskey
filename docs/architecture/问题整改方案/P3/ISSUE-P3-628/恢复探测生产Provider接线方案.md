# ISSUE-P3-628：恢复探测生产 Provider 接线方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：部分实施，仍开放。生产 Provider 生命周期与探测接线已改用统一作用域；持久化生产配置下的 HTTPS/ETag 前台恢复流程未端到端验收。

## 1. 问题与依据

当前登记为 P3、置信度高。[ResumeSyncProbeCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/ResumeSyncProbeCoordinator.kt) 的 `probeRemote()` 在生产配置检查通过后，只取默认空的 `testSyncProvider`，所以不请求生产远端。[SyncCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncCoordinator.kt) 的手动/解锁同步有生产配置解析回退，不能据此认定这些入口同样失效。

当前探测 ETag 位于 `SyncSessionState.lastRemoteEtag`，锁库/重建会清，首次探测只建立基线。接通 Provider 后不能声称可识别所有离线期间变化；该能力需要 P2-627 的持久化确认基线。

补充静态核实：`isSyncConfigured()` 本身会构造后丢弃生产 Provider，S3 clone 没有确定性清理；完整周期也有 Provider 已构造、但装配早退导致清理对象尚未登记的路径。它们归入同一 Provider 生命周期边界；未验证堆残留或外部可利用性。

## 2. 目标与边界

已解锁且持久化生产云配置有效时，回前台/网络恢复真实调用元数据接口，并按已知基线提示远端变化。统一拥有 Provider 与凭据生命周期，测试注入仅作为可替换依赖，生产行为不能依赖钩子非空。

本条负责恢复探测接线，不自动扩展为锁定态 KDBX 合并或自动下载覆盖。ETag 是不透明比较标识，不是防回滚信任根。

## 3. 实施步骤与失败处理

1. 将生产 Provider 解析收敛为受控 `useProvider` 作用域，由 Hilt 注入解析器/工厂。覆盖配置读取、Provider 构造、使用与释放；配置存在性检查改为非秘密描述读取，不构造后丢弃 Provider。测试工厂替换同一接口，不让业务层读取 `testSyncProvider` 决定是否已配置。
2. WebDAV 解封原始 CharArray 用毕清理；S3 Provider 克隆凭据从构造成功起立即纳入 finally，包含后续装配失败、取消与早退，不能仅靠成功生成 cycle context 后的清理点。借用的测试 Provider 与生产拥有的实例明确不同所有权。
3. `probeRemote()` 在作用域内调用元数据请求，沿用前台/网络恢复策略、节流与单飞；连续事件合并，并让取消传到请求。无需解密/序列化整库，不增加网络 holdoff。
4. 基线优先采用本库/目标代次的已确认 ETag；暂无持久化基线时明确“首次探测建立基线”，不能提示“已确认无变化”。P2-627 落地后复用其状态；配置切换时旧探测结果作废。
5. 远端改变仅发布当前库的待同步提示；鉴权失败、临时网络失败、远端不存在、未配置与取消分别处理。请求完成后复核库/配置代次，迟到结果不得提示另一库。
6. 手动/解锁周期也迁移到相同 Provider 生命周期边界，防止后续两套清理规则漂移；以小步接线和同批回归交付，不顺带修改合并策略。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 仅持久化真实 WebDAV/S3 配置，无测试钩子 | 回前台与网络恢复各有真实元数据请求回执 |
| 已知 ETag 不变/变化、远端 404 | 不变不重复提示；变化提示正确库；404 分类明确 |
| 首次探测、锁库重开、普通冷启 | 无基线时只建立基线；有持久化确认基线后才比较历史变化 |
| 401/403、超时、取消、Provider 构造后早退 | 错误分类正确，独占凭据在所有退出路径清理 |
| 连续前后台/网络事件，探测中换库或换目标 | 同库单飞，迟到结果丢弃，无旧目标状态污染 |
| 手动/解锁同步回归 | 生产 Provider 与凭据清理接线保持正确 |

保留现有 probe policy 纯函数测试，新增不设置 `testSyncProvider` 的生产 resolver/HTTP 接线测试。隔离 AVD 使用受控 HTTPS 和虚构凭据，触发真实前后台及网络恢复，保留服务端请求、ETag 提示和非空 XML；mock Provider 单测不能作为生产接线验收。

## 5. 顺序、交付与回退

先建立拥有式 Provider API，再替换恢复探测及周期消费者，最后与 P2-627 持久化基线联测。最小接线可独立先交付，冷启历史变化识别作为明确后续能力，不混成一个成功结论。

回退时暂停失败的自动探测并准确提示原因，保留正常手动同步；不回到“配置有效却读取测试钩子”的实现，也不留下不受作用域管理的云凭据。
