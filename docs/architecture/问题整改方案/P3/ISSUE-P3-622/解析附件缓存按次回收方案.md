# ISSUE-P3-622：解析附件缓存按次回收方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：本项已实施并于[批次 §525](../../../../resolved/batches/525-解析附件缓存按次回收实体机验收批次.md)验收闭环。以下矩阵保留原实施验收要求，实际结果和设备证据见归档批次。

## 1. 问题与依据

当前登记为 P3、置信度高。[SessionOpener.kt](../../../../../database/src/main/java/com/keepasskey/database/session/SessionOpener.kt) 的加载边界与 [ChildReadOnlySession.kt](../../../../../app/src/main/java/com/keepasskey/app/data/childdb/ChildReadOnlySession.kt) 的 `loadProjection()` 直接向 `KdbxFile.load` 传入共享 store；大附件落盘后若 XML 或终止块认证失败，没有撤销本次创建的键。`InnerHeader.clearSensitive()` 不负责 spill 文件删除。

残余位于应用私有目录，锁定/关闭/冷启动已有清理；普通根库重试也有旧缓存清理。不能据此声称其他普通应用可读，或根库每次重试无限累积。需要补的是失败解析尚未交付所有权时的按次清理。

## 2. 目标与边界

每次解析独占其新增附件键：失败、取消及成功后交付失败均撤销；会话接管成功后才转移清理责任。不得对共享 store 调全局清理而删除活动根库附件，也不改变内联阈值、附件格式或介质安全擦除限界。

## 3. 实施步骤与失败处理

1. 在 database 内部复用 [SessionExternalParser.kt](../../../../../database/src/main/java/com/keepasskey/database/session/SessionExternalParser.kt) 的 `SpillRecordingBinaryStore` 机制，核对它在流式写入异常时对未完成文件的清理契约。该类型目前为 internal，app 不得直接引用；由 database 的最小公开加载事务 API/所有权句柄承接子库调用。根库、子库与外部解析保持相同的事务边界，避免复制三套清理实现。
2. 在根库加载开始至完成会话接管之间记录本次新增键；普通错误和 `CancellationException` 都进入清理，取消仍按原语义向上传递。解析成功不等于接管成功，后续初始化失败也必须回收。
3. 子库投影加载使用独立记录器。明确投影是否仍借用大附件引用；若借用则所有权随投影移交，并在投影关闭时释放；若不借用，在投影构造完成后清理本次附件。不要未经消费方核对就把成功附件全部删除。
4. 将 `purge()`/交付设计为幂等、互斥的终态；仅删除本次实际新建键，确保共享/去重键不会被错误记为独占。清理失败保留可追踪的待清理键与非敏感错误状态，后续安全清扫重试；不得吞异常假报已清完。
5. 既有会话级锁库/启动清扫继续保留，作为进程突然终止时的兜底。崩溃清扫与按次撤销分别验收，不能靠下一次开库清理掩盖失败当时的残余。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 根库大附件落盘后 XML 晚失败/终止块认证失败 | 在返回错误时本次新增文件已删除，活动附件不受影响 |
| 子库相同晚失败，连续重试 | 每次均无新增残余，活动根库文件集合及内容保持一致 |
| 流式写入中取消、落盘后取消、接管前失败 | 已完成键及写入中临时文件均清理，取消继续传播 |
| 成功根库/子库加载及关闭 | 使用期间附件可读，关闭后由正确所有者释放 |
| 重复 purge、删除故障、共享键对照 | 不重复释放他人资产；故障可见且后续重试可回收 |

扩展现有 `SpillRecordingBinaryStoreTest`、`ChildReadOnlySessionTest`，增加根库接管失败覆盖。设备使用虚构、超过 spill 阈值的附件，直接对比私有目录文件清单、大小与受保护对照内容；仅断言内存池为空不足以验收。保留非空设备 XML 和脱敏磁盘清单。

## 5. 顺序、交付与回退

先核对记录器的所有权和写入失败契约，再接根库，最后接子库及生命周期清理；可独立于其他方案实施。正常解析、失败回收、取消和既有活动库保全必须同批通过。

回退不得改为共享目录全清；发生所有权问题时暂停失败的子库加载/交付，保留根库及会话级清扫。若只能在下一次启动清理，仍保留本条开放。
