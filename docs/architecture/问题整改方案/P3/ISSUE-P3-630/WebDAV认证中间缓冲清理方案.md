# ISSUE-P3-630：WebDAV 认证中间缓冲清理方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：本项已实施并于[批次 §523](../../../../resolved/batches/523-WebDAV认证中间缓冲清理批次.md)验收闭环。以下矩阵保留原实施验收要求，实际结果与已知 API 边界见归档批次。

## 1. 问题与依据

当前登记为 P3、置信度高。[WebDavAuthHeader.kt](../../../../../sync/src/main/java/com/keepasskey/sync/webdav/WebDavAuthHeader.kt) 的 `build()` 从 UTF-8 `passwordBuffer` 复制出独立 `passwordBytes`，随后构造 `combined`。现有 finally 清了 combined 与编码 buffer 的底层数组，没有清独立密码副本，后续分配/拼接失败也需要覆盖。

利用需要进程内存读取，超出当前云端无密钥威胁模型。最终 Basic header 的普通 String 是既有 HTTP API 边界，不承诺全堆擦除或将本条描述为已证明的云端泄露。

## 2. 目标与边界

每个局部独占的可擦秘密缓冲自创建起都有确定的清理所有者，正常、异常及提前返回均清理；不清理调用方借用的密码 CharArray。认证头字节、UTF-8 编码、Base64 和服务端互操作行为保持正确。

## 3. 实施步骤与失败处理

1. 核对编码 buffer、独立 `passwordBytes` 和 combined 的创建点与所有权。优先消除不必要的独立副本；若保留，从创建完成后立即进入覆盖所有后续操作的 try/finally。
2. 将 combined 的分配、拼接和 Base64 编码纳入外层密码副本清理范围；combined 一旦分配成功即由自身 finally 擦除。确保某次分配失败时，已经存在的秘密缓冲仍会被清理。
3. 明确只擦本函数独占副本，保留调用方密码的借用契约；用户名若与密码混在同一缓冲，也按秘密缓冲处理。保留最终 String API 限界注释，禁止新增秘密日志。
4. 将敏感缓冲契约中 WebDAV 一项与最终实现对齐，不引入通用大改或无关网络架构变动。若需要测试观察点，使用内部可测试的编码/拼接边界，不对生产公开秘密数组。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| ASCII、中文、多字节/代理对、空密码 | Basic 头解码后与虚构输入一致，不截断、不改变原调用方数组 |
| 正常构造完成 | 测试捕获的独占副本在返回后为零，头值保持正确 |
| 副本创建后、拼接后、编码失败 | 已创建的每个可擦缓冲都被清理，异常不携带秘密 |
| 多次/并发构造 | 缓冲互不共享，前一次清理不破坏后一次结果 |

扩展 `WebDavSyncProviderTest` 的 UTF-8 认证回归，并在 WebDAV 包内建立可观测的缓冲生命周期用例。可补 `CredentialIntermediateWipeTest` 接线守卫，但源码包含 finally 的断言不能替代运行时异常分支证据。无需通过真实密码堆转储验证。

## 5. 顺序、交付与回退

此项范围局部，可独立先行。先保留认证头正确性对照，再补所有权 finally 和失败路径覆盖。若去副本优化影响认证，退回保留副本但完整清理的实现，不退回遗漏清理状态。

本项预计以 sync JVM 用例和必要的生产 WebDAV 假凭据请求回归验收；若实现引入或修改设备用例，必须在隔离 AVD 实跑并保留非空 XML。未触及 Rust/JNI，不因本方案无端扩大原生验证范围。
