# ISSUE-P3-608：自动填充设备测试本地化定位方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：本项已实施并于[批次504](../../../../resolved/batches/504-首轮在途整改收口批次.md)验收闭环。 以下矩阵保留原实施验收要求，实际结果以批次为准。

## 1. 问题与依据

来源为 DYN-02。2026-10-13 直读 `app/src/androidTest/java/com/keepasskey/app/autofill/AutofillAuthChainDeviceTest.kt` 与 `DeviceAutofillProbe.kt`：认证入口、搜索入口、解锁和确认按钮使用中文常量，探针按文本包含定位。动态审计证明英语数据集已出现但测试报失败，不能因此认定生产填充失败。

## 2. 目标与边界

中文、英文环境均执行完整认证→解锁→选择→确认→填充链路。保留每阶段真实断言，不能退化为「Activity 出现即通过」或在找不到节点时静默跳过。

## 3. 实施步骤

1. 将 app 提供的文字从 targetContext 对应资源获取，包括 cred_autofill_unlock_prompt、autofill_picker_entry_title、unlock_btn_unlock、autofill_confirm_ok；使用实际运行配置，不能从测试 APK 的不同 Locale 取字串。
2. 优先用稳定资源/语义身份定位 app 窗口；系统渲染的数据集无法暴露 app 资源 ID 时，用运行时本地化文本+窗口/角色约束，而非全窗模糊 contains。
3. 保留必要空格归一化，避免固定汉字关键词；测试客户端固定合成标题可保留，但不把它当系统本地化文本。
4. 前置记录系统及应用语言，明确 app 单独设置语言的情况。若测试主动设语言，finally 恢复原配置，测试失败也不留下全局变更。
5. 超时保存窗口树、截图、服务与框架日志，按阶段指出未满足的前提；不把定位失败自动归因于生产未发请求。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 简体中文与英语 | 两套完整链路均通过，填充账号/口令正确 |
| 系统英文、app 简中及反向配置 | 使用实际窗口所属资源语言 |
| 文本包含相似项、多个窗口 | 不误点非活动窗口或无关节点 |
| 真正不发数据集/故意错身份 | 测试必须失败并留完整证据 |
| 主动切 Locale 后失败 | 原 Locale 恢复 |

设备端必须验证最终独立客户端字段值，不能以认证数据集再次出现作为全链路证据。

## 5. 顺序与实施验收

先修 ISSUE-P3-607，再与 ISSUE-P3-609、610 同轮建立完整前提。截图与日志保留合成凭据，避免真实数据。新增/修改 androidTest 后在独立 AVD 实跑中英矩阵，按设备结果非空规则验证；宿主全量、门禁和 androidTest 编译同样完成。
