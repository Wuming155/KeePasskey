# ISSUE-P3-610：自动填充设备测试活动库前提方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 DYN-04。2026-10-13 对照 `AutofillTestVaultSeeder.kt` 与 `app/src/main/java/com/keepasskey/app/data/repository/VaultDatabaseCatalog.kt`：播种合成库不等于选为活动库，目录解析优先保留会话/已保存活动选择。登记中的有旧库/无旧库对照支持前提缺口；原失败没有真实开库路径日志，具体因果仍待运行追踪。

## 2. 目标与边界

播种后显式选择并确认测试库，实际解锁路径必须属于它；已有不同密码的活动库也不影响用例。不得删除用户旧库或用全量清数据来获得测试绿。

## 3. 实施步骤

1. 默认在专用 AVD/隔离安装身份运行，仅合成数据；前置明确拒绝指向用户生产包的数据清理。
2. 播种使用独立路径，校验文件签名、内容及库身份；不能无条件删除任意同名既有库。仅允许覆盖已确认归本测试拥有的合成文件。
3. 通过既有库选择接口登记并选择播种库，处理残存打开会话优先于活动 ID 的情况；只改偏好不足以证明实际 session 已切换。
4. 在启动认证前断言 catalog 活动 ID/路径；解锁完成后断言 DatabaseSession 当前路径及 root UUID，核对合成标题/条目数量。
5. 操作前快照原活动选择，收尾恢复；没有原选择时恢复无选择状态。仅删除本轮拥有的合成库及测试元数据，清理与旧用户数据分离。
6. 增加「不同密码旧活动库」的合成干扰项，日志只记非敏感库身份和运行编号，不打印主密码或凭据。

## 4. 验收矩阵

| 起始状态 | 必须观察的结果 |
|---|---|
| 首次安装，无旧库 | 显式选择播种库，完整填充链路通过 |
| 已有不同密码旧活动库 | 实际打开播种路径，旧库哈希不变 |
| 上一轮残存打开会话 | 会话切换与活动选择一致 |
| 故意未选择/路径错配 | 在前置或路径断言处明确失败 |
| 成功/中途失败收尾 | 原选择恢复，只清本轮合成资产 |

必须保存路径级运行证据，以验证先前失败的具体因果；不把「清空后通过」升级成路径已确证。

## 5. 顺序与实施验收

先修 ISSUE-P3-607，再将 608/609/610 作为同一设备测试矩阵验收：中英两语言×有无旧库×连续两轮，至少八次完整执行，串行运行并留每次证据。androidTest 修改必须实跑，五模块设备层全跑时由非空脚本确认；随后宿主全量与门禁。
