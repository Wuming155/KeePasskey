# ISSUE-P3-607：装机时间跨时区比较方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 DYN-01。2026-10-13 直读 `tools/device/check_installed_build.py`：设备 dumpsys 的 lastUpdateTime 和宿主 APK mtime 都转成 naive datetime。动态审计已经用 GMT/Asia-Shanghai 对照证明误拒；相反方向错误放行仍需新增验证。

## 2. 目标与边界

用绝对时间比较新旧包，设备/宿主时区变化不能改变判定；保留包名、符号及 0/1/2 退出码契约。不改设备时钟或 APK mtime 绕过判据。时间、符号各有证明边界，不夸大为相同 APK 的哈希证明。

## 3. 实施步骤

1. APK mtime 保留 epoch 或转为带 UTC 的 datetime，不使用宿主墙钟。
2. 优先取得设备安装时间的绝对毫秒值；若只能读取 dumpsys 墙钟，同批读取设备时区并使用安装日期对应的历史偏移转换为 UTC，不直接套用当前 offset。
3. 时区查询失败、解析失败、缺少时区库或 DST 重复时刻无法消歧时返回 2；禁止假定 UTC 或宿主区。Windows 缺 tzdata 的依赖/降级行为写入 docstring。
4. 查询前后设备时区发生变化时重取一次或判无法确定，避免混合两次读数。
5. 处理 dumpsys 秒精度与 mtime 小数精度：时间区间重叠时不得直接放行旧包，采用额外身份核对或返回无法判定；禁止任意增加宽松容差。
6. 保留 expect-symbol 检查；若加入安装 APK 哈希核对，明确拉取当前包路径、split APK 范围和失败退出码，不能以符号相同替代哈希相同。

## 4. 验收矩阵

| 输入/环境 | 必须观察的结果 |
|---|---|
| 同一安装绝对时刻，不同时区 | 判定一致 |
| 设备早区/晚区、宿主不同区 | 真正新包通过、真正旧包失败 |
| DST 切换历史日期/重复时刻 | 正确消歧或返回 2 |
| 缺包/缺 adb/无时区/格式损坏 | 返回 2，不默认绿 |
| 符号缺失、多 dex 命中 | 保留既有正反例判据 |

扩展现有 --selftest，以合成 adb 输出和固定 mtime 覆盖边界；独立 AVD 再跑跨区实测，恢复原时区并保留首轮失败证据。

## 5. 顺序与实施验收

先做本项，为其余设备问题提供可靠前置读数。官方依据：[Python aware/naive 时间与 UTC 转换](https://docs.python.org/3/library/datetime.html)。迭代运行 --selftest，实施结案仍执行项目规定的全量 test 与门禁；不能把脚本自测绿当成实际装机验证完成。
