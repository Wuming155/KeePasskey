# ISSUE-P2-632 历史版本以条目 UUID 定位，多个修订总命中首项

> 状态：**已实施（2026-10-17）**。核实：2026-10-16（Asia/Shanghai）；实施：2026-10-17；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2。JVM 用例已实跑通过；**设备端产品复现与独立实现对拍尚未执行**，故仍留在 `ACTIVE_ISSUES`。

## 1. 问题与依据

历史快照保留条目 UUID，投影又把该 UUID 当修订 id；读取历史密码/快照时使用 firstOrNull(id==revisionUuid)，故多条历史记录具有同一定位值，选择较早记录仍读取列表首个版本。

- 审查维度：功能完整性、数据流转与一致性。
- 影响范围：历史对比、历史密码和回滚可能选择错误版本；本仓自产历史和按同 UUID 保存的外部历史都受影响。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [database/src/main/java/com/keepasskey/database/history/HistoryManager.kt](../../../../../database/src/main/java/com/keepasskey/database/history/HistoryManager.kt)：原始行 46–50。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt)：原始行 56–65。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntrySecretReader.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntrySecretReader.kt)：原始行 142–165。

复现/验证路径：

1. 同一条目连续保存三个不同密码/备注，使 history至少两项。
2. 在详情页分别选择不同历史行对比或回滚。
3. 比较每行投影id及仓库firstOrNull结果；预期不同版本，当前均指向首项。

反证和限制：database 的按 index 回滚原语不依赖该 UI id；不能修改 KDBX 条目 UUID 来规避 UI 定位问题。未实跑设备。

## 2. 修复目标与边界

建立与条目 UUID 分离、绑定快照修订的历史选择标识。

涉及模块：app 历史投影/秘密读取/详情；database HistoryManager。

预期结果：每个历史行对应所选版本，陈旧句柄不误回滚。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 用会话修订+历史索引/稳定摘要定义历史选择句柄，接口显式携带条目和历史定位。
2. 统一比较、密码读取和回滚使用同一句柄；历史发生变化时拒绝陈旧选择并刷新列表。
3. 保留KDBX历史UUID语义，避免改变磁盘互操作格式。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
