# ISSUE-P2-632 历史版本以条目 UUID 定位，多个修订总命中首项

> 状态：**已实施（2026-10-17）**。核实：2026-10-16（Asia/Shanghai）；实施：2026-10-17；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2。已于 2026-10-18 闭环（§539）：修订句柄改为进程内不透明对象身份 token，避免 KDBX 秒级时间戳碰撞导致旧句柄误命中；JVM、API 36 AVD 历史修剪 / 头插 / 真实 UI 和 KeePassXC 独立读取均通过。

## 1. 问题与依据

历史快照保留条目 UUID，投影又把该 UUID 当修订 id；读取历史密码/快照时使用 firstOrNull(id==revisionUuid)，故多条历史记录具有同一定位值，选择较早记录仍读取列表首个版本。

- 审查维度：功能完整性、数据流转与一致性。
- 影响范围：历史对比、历史密码和回滚可能选择错误版本；本仓自产历史和按同 UUID 保存的外部历史都受影响。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [database/src/main/java/com/keepasskey/database/history/HistoryManager.kt](../../../../../database/src/main/java/com/keepasskey/database/history/HistoryManager.kt)：原始行 46–50。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt)：原始行 56–65。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntrySecretReader.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntrySecretReader.kt)：原始行 142–165。

复现/验证路径：

1. 同一条目连续保存三个不同密码/备注，使 history至少两项。
2. 在详情页分别选择不同历史行对比或回滚。
3. 比较每行投影id及仓库firstOrNull结果；预期不同版本，当前均指向首项。

反证和限制：database 的按 index 回滚原语不依赖该 UI id；不能修改 KDBX 条目 UUID 来规避 UI 定位问题。未实跑设备。

## 2. 修复目标与边界

建立与条目 UUID 分离、绑定快照修订的历史选择标识。

涉及模块：app 历史投影/秘密读取/详情；database HistoryManager。

预期结果：每个历史行对应所选版本，陈旧句柄不误回滚。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 用会话修订+历史索引/稳定摘要定义历史选择句柄，接口显式携带条目和历史定位。
2. 统一比较、密码读取和回滚使用同一句柄；历史发生变化时拒绝陈旧选择并刷新列表。
3. 保留KDBX历史UUID语义，避免改变磁盘互操作格式。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。

### 4.1 设备端补验（2026-10-18）

- 新增 `app/src/androidTest/.../HistoryFieldGroupDeviceTest.kt`，经生产 `VaultRepository` 历史投影、
  历史密码 / 快照读取与 `rollbackEntryToRevision` 执行；每次核对均从正式 `.kdbx` 文件独立重解析，
  不把会话内存作为唯一证据。
- 隔离 AVD `KeePasskeyRemediation_API36` / API 36 实跑（Gradle `connectedDebugAndroidTest`）：
  `tests=5 failures=0 errors=0 skipped=0`。
- 历史句柄读数：连续保存后投影产生 3 个互异句柄，分别读到 P2/P1/P0；回滚到第 2 行并重开正式文件
  后当前值为 P1；回滚前版本归档为最新历史，再回滚归档版本恢复 P3。
- 修剪读数：把 `historyMaxItems` 调为 1 并产生下一次修订后，正式文件只剩 1 份历史；使用已修剪旧句柄
  回滚返回 `HISTORY_REVISION_UNAVAILABLE`，正式文件逐字节不变。
- 已覆盖：新增 `HistoryRevisionUiDeviceTest`，通过 debug-only 宿主挂载生产 `EntryDetailScreen`，无障碍真实点击历史对比与回滚；详情页保持打开时插入 P4，历史行数从 3 更新为 4，点击第 3 行对比读到 P1 / P4，再点击回滚，正式 KDBX 重解析和活动会话均为 P1。结果 `tests=1 failures=0 errors=0 skipped=0`。
- 另由 `HistoryFieldGroupDeviceTest` 验证投影旧句柄在生产库头插后仍按同一快照对象引用定位原修订。
- 独立互操作（2026-10-18）：隔离 API 36 AVD 应用生成综合合成库并按授权导出；KeePassXC CLI `db-info` / `ls` / `show --all --show-attachments` 解锁成功，XML 导出可读取历史与附件。当前条目显示 `Y` / `SECRET`，旧 `X` 仅在历史快照中保留，符合历史语义。
- 根因与修正（2026-10-18）：官方 KDBX 日期序列化按秒取整；`index:epochMillis` 在同一秒产生的不同修订间不具唯一性，头插也可能让旧位置的同秒快照误满足原句柄。现改为随机不透明 token → `WeakReference` 指向实际历史对象；解析时只接受该对象仍以同一引用存在于当前 history，不再使用时间猜测。弱引用不延长含秘密快照生命周期，清理由 `ReferenceQueue` 完成。
- 新增回归：相同时间戳快照有独立句柄；同秒头插后仍定位原对象；已修剪同秒旧快照不能落到剩余版本；非法 / 未登记 token 一律拒绝。AVD 设备类最新 XML `tests=7 failures=0 errors=0 skipped=0`，详情 UI 最新 XML `tests=1 failures=0 errors=0 skipped=0`。
