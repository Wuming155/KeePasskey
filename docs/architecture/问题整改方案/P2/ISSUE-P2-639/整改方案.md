# ISSUE-P2-639 恢复预览迟到结果未绑定所选副本

> 状态：**已闭环**（2026-10-18，§543）。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2；原始结论：静态确认，交错场景待实跑；置信度：高。后续实施与验收进度见 §5。

## 1. 问题与依据

预览A期间列表项仍可点击切换B；select清空preview，但A异步完成时无请求代次/selectedKey比较，直接把A预览写入当前B状态。restore只检查当前选中B及preview非空，可能用A的成功预览放行恢复B。

- 审查维度：数据流转与一致性、用户体验与易用性。
- 影响范围：显示和恢复前置校验目标错配，用户可能未解锁/比较B就覆盖其正式库；不表示能解密B或绕过KDBX密码学。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/recovery/RecoveryViewModel.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/recovery/RecoveryViewModel.kt)：原始行 67–99。
- [app/src/main/java/com/keepasskey/app/ui/screens/recovery/VaultRecoveryDialog.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/recovery/VaultRecoveryDialog.kt)：原始行 112–136。

复现/验证路径：

1. 准备两个恢复副本A、B，在A预览解密返回前用barrier暂停。
2. 列表选择B，再释放A预览任务。
3. 核对selectedKey=B而preview属于A；点击恢复B观察是否被放行。

反证和限制：只有一个副本或完成前不切换不会触发；restore仍需用户操作并对已有文件进行覆盖确认。

## 2. 修复目标与边界

预览、选择、覆盖确认和最终恢复绑定同一副本版本。

涉及模块：app RecoveryViewModel/VaultRecoveryDialog。

预期结果：展示的差异和被恢复字节始终对应用户当前选择的同一版本。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 预览结果携带vault/path/payload摘要及请求代次，迟到或选择改变即丢弃。
2. busy时禁用选择，仍保留最终绑定复核防止程序化调用和文件替换。
3. restore要求与当前payload匹配的成功预览凭证，确认后再次校验。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
