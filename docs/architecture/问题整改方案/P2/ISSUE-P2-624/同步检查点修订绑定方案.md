# ISSUE-P2-624：同步检查点修订绑定方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：本项已实施并于[批次 §527](../../../../resolved/batches/527-同步检查点修订绑定实体机验收批次.md)验收闭环。以下矩阵保留原实施验收要求，实际竞态和实体机文件证据见归档批次。

## 1. 问题与依据

当前登记为 P2、置信度中。[SyncCycleRunner.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncCycleRunner.kt) 在周期返回成功、退出同步 mutex 后才调用 [SyncLocalFileCheckpoint.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncLocalFileCheckpoint.kt) 的 `record()`，它摘要当时的 `databaseSession.currentFile`。条目保存使用另一数据库会话锁，故本轮结算 A 后、摘要前完整提交 B，就可能把未上传的 B 记作已同步检查点。

同进程锁库清缓存后重开 B，远端合法 C 可能被错判为纯远端更新并覆盖 B。该序列不依赖混合文件读；新周期的编辑快照也是 B，现有同期编辑守卫不足以识别上轮误记。

## 2. 目标与边界

检查点只能证明“本地这个正式文件版本已经与指定目标确认收敛”，不能证明“同步结束后碰巧读到的版本已同步”。需要绑定库身份、文件提交代次、内容修订、远端目标配置代次及确认结果；只扩大同步 mutex 不能约束独立用户保存。

优先从可信写入回执复用密文摘要；无可信摘要时在数据库提交边界稳定取样并复核版本，不一致就不登记。保守缺少检查点可以触发冲突/待同步，不能制造错误的已同步状态。

## 3. 实施步骤与失败处理

1. 定义贯穿周期的确认修订对象，区分“远端接受 A”和“当前本地 B”。`SyncUploadSettlement`、下载采纳、合并及无变化路径均返回明确修订，不能仅凭成功枚举触发通用 `record()`。
2. 在 `SessionPersistence.save()`/正式文件原子提交处生成库、写入代次和文件摘要回执，覆盖普通用户保存及同步采纳。现有 `SessionWriteReceipt` 只有提交状态，tracked writer 也未覆盖普通保存；需扩充或新设专用回执，而非把旧状态对象直接视为版本证明。
3. `SyncLocalFileCheckpoint` 只接收已确认修订和与之匹配的正式写入回执。共享会话提交锁内核对当前库/目标/代次，再发布检查点；UI 若已保存 B，保留 B 待同步并拒绝把 A 的结果登记为 B。
4. 若摘要只能读盘，明确持锁/稳定句柄、原子替换和前后修订校验方式，IO 在自身调度边界执行。mtime/长度及一次前后相等都不足以独自证明目标版本，不能作为唯一安全依据。
5. 锁库、换库、凭据轮换、目标 URL/账号变化后，旧回执不能污染新上下文；锁库重开若保留检查点，必须验证同一正式文件代次，而非只比较路径字符串。
6. 检查点发布失败或版本不符按未建立证明处理，不前移“已同步”状态；远端已接受 A 的事实另行保留供下轮对账。与 P2-621 共享恢复状态，不能靠清空所有缓存掩盖部分提交。

## 4. 验收矩阵

| 受控时序 | 必须观察的结果 |
|---|---|
| barrier 固定 A 结算后、checkpoint 摘要前 → 保存 B | 不生成声明 B 已同步的检查点；云端仍 A，B 保持待同步 |
| 上述时序 → 同进程锁库/重开 → 云端 C | B 不被直接覆盖，进入合并/冲突并保留 B 的更新 |
| A 结算后无新保存 | 可信检查点生成，常规纯远端更新路径不退化 |
| 首传、快速上传、常规上传、合并、远端采纳 | 所有成功分支均绑定实际确认版本，不漏旁路 |
| 保存与检查点交错、换库/换目标/换凭据 | 无跨库、跨目标或跨代次误登记 |
| 摘要失败、回执缺失、取消 | 保守不登记，正式库保全，后续可恢复同步 |

扩展 `SyncUploadSnapshotConsistencyTest`，新增结算后的 barrier；上传期间 barrier 不能替代它。联测 `SyncColdStartRemoteOnlyDifferenceTest`、`SyncMidCycleEditGuardTest`，分别核对磁盘、内存、缓存及真实远端 A/C 产物。设备验收保留非空 XML 和重解析结果。

## 5. 顺序、交付与回退

先与 ISSUE-P2-621 确定统一回执，再改检查点消费者；ISSUE-P2-626 同批保证 IO 与取消语义。暂时无法证明版本时，可先禁用不可信检查点登记并保守走冲突，但这只是遏制步骤，需评估常规同步体验。

回退不恢复“周期成功后摘要当前文件即登记”的做法。若回执接入不完整，保持该分支不登记，不能用 UI 显示成功作为正确性证据。
