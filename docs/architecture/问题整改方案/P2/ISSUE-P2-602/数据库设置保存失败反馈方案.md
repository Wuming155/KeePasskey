# ISSUE-P2-602：数据库设置保存失败反馈方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 AUD-14。2026-10-13 直读 `app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsPreferencesController.kt`：算法、KDF、Argon2、回收站更改后忽略 save 的 KdbxResult；`SettingsDatabaseMetaController.kt` 的 runCatching 只捕获抛出异常，正常返回 Failure 不会进入 onFailure。

## 2. 目标与边界

安全设置与库级 Meta 只有确认落盘后才展示为已应用；失败明确反馈并恢复一致状态。应用级主题等独立偏好不强行并入 KDBX 事务。

## 3. 实施步骤

1. 将库设置入口改为向统一仓库提交变更意图，返回 KdbxResult；显式处理 Failure，取消仍传播，不再用 runCatching 成功包装掩盖嵌套失败。
2. 推荐候选提交：从受保护快照构造新头/Meta，通过校验、漂移检查及写盘后发布已提交状态；UI 提供正在保存、失败、成功三种反馈。
3. 已有流程必须先发布候选时，失败仅回滚当前事务拥有且版本未变的字段；不得把整棵旧树覆盖到已出现新编辑的会话。
4. 保留用户待应用输入以供重试，但将「输入值」与「已应用文件配置」分开；错误反馈使用资源文案/错误码，不拼接异常 message。
5. 页面退出不取消已经进入关键提交的事务；成功后刷新列表、同步失效及必要封印收尾，取消等待不触发迟到 UI 更新。
6. 设置失败不能一律触发外部漂移三选；写权限、磁盘满、参数无效和漂移分别映射到可理解的处理动作。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| save 正常返回 Failure | 明确失败，已应用回显与磁盘一致 |
| writer 抛异常 | 同样失败，不只覆盖这一种错误 |
| KDF 参数校验失败 | 会话与磁盘未变化，无高负载派生 |
| 保存时并发编辑/换库 | 回滚不覆盖新编辑，不写错库 |
| 重试成功→锁定重开 | 算法、KDF、名称等目标值真实生效 |

对每类库设置至少覆盖一条 Failure 注入；增加控制器/仓库行为测试，不满足于静态证明出现了 `is Failure` 分支。

## 5. 顺序与实施验收

先落 ISSUE-P1-601 的统一入口和 ISSUE-P1-595 参数校验，再接本项 UI。事务取消策略与 ISSUE-P1-593 同源。迭代 app/database 定向测试和 XML，新增 UI 可见状态要补 Preview、截图包装编译；结案执行全量与门禁，并在 AVD 验证真实写错提示。
