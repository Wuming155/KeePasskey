# ISSUE-P2-635 编辑页选择根分组被当成保留原分组

> 状态：**已闭环（2026-10-18）**。核实：2026-10-16（Asia/Shanghai）；实施：2026-10-17；AVD 验收：2026-10-18；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2。JVM、设备仓库路径、编辑页根 chip 与批量移动 UI 路径均已验收；闭环记录见 [`RESOLVED_LOG.md` §537](../../../../RESOLVED_LOG.md)。

## 1. 问题与依据

根分组chip传onGroupChange(null)，保存时却用 entry.groupId?.parse ?: existing.parentGroupId；null被解释成“不变”，因此已有条目无法通过编辑页移回根。

- 审查维度：功能完整性、用户体验与易用性。
- 影响范围：界面显示已选根且保存成功，但条目仍在旧分组；批量移动有独立实现，不直接受此问题影响。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/edit/EntryEditGroupAndAppSections.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/edit/EntryEditGroupAndAppSections.kt)：原始行 74–80。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntryWriteCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntryWriteCoordinator.kt)：原始行 106–109。

复现/验证路径：

1. 打开位于子分组G的既有条目，点“根分组”。
2. 保存并重开列表/条目。
3. 检查实际parentGroupId仍为G。

反证和限制：新条目null按根落点和批量移动路径可能正常；需避免修改null含义影响其它调用者。

## 2. 修复目标与边界

明确保留/移动到根/移动到具体分组三种写入意图。

涉及模块：app 编辑分组选择/条目写入。

预期结果：选择根分组会真实移动到根，失败显式反馈。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 为编辑保存传明确目标根UUID或sealed移动意图。
2. 验证目标分组仍存在且不在回收站；采用会话单次移动原语，避免delete+save中间态。
3. 统一新建、模板、编辑、批量移动的根分组契约。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
