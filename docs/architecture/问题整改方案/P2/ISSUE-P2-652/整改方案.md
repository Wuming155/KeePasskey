# ISSUE-P2-652 测试连接忽略配置保存失败，仍验证并同步旧目标

> 状态：**尚未实施**。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。

## 1. 问题与依据

SyncStatusCard.onTestConnection先persistConfig()但不检查返回值，无条件onSyncAfterSave。与同页保存并同步按钮的if守卫不同，保存失败时后续流程使用仍在存储中的旧配置。

- 审查维度：功能完整性、用户体验与易用性、数据流转与一致性。
- 影响范围：测试的并非用户当前输入目标，且回调还会同步旧目标；用户可能把旧连接成功当作新表单验证，产生不期望的同步副作用。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/settings/subscreens/CloudSyncScreen.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/subscreens/CloudSyncScreen.kt)：原始行 402–405。
- [app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsSyncController.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsSyncController.kt)：原始行 244–253。

复现/验证路径：

1. 先保存一个有效测试端点A。
2. 把表单改为被HTTPS规则拒绝的http://B，点状态卡测试连接。
3. 跟踪persist=false后仍调用verifyConnectionThenSync，观察网络目标仍为A。

反证和限制：无旧配置时通常进一步失败；主保存并同步按钮已有成功守卫。

## 2. 修复目标与边界

测试/同步严格依赖本次配置成功提交，并绑定本次已提交目标。

涉及模块：app CloudSyncScreen/SettingsSyncController/SyncCoordinator。

预期结果：失败的表单不会触发旧目标网络操作，新目标验证结论可追溯。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 保存失败立即终止回调并保留失败反馈。
2. 为成功配置返回不可变目标/修订回执，由验证与同步消费，避免接着读取漂移的全局配置。
3. 明确测试连接是否应同时同步并让文案兑现当前产品行为。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
