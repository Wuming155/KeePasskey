## 1. 问题与依据

构造入口时已登记databaseId/sessionTicket，但只有PasswordFill消费并最终复核。Passkey断言/创建及密码保存/草稿读取当前活动库；BaseCredentialActivity仅做窗口保护，没有补偿票据检查。

- 审查维度：安全性与权限控制、数据流转与一致性。
- 影响范围：旧A入口在活动库变B后可能对B同UUID条目计数/签名或把创建数据写入B，造成账户/库上下文混淆。需用户选择与验证；未证明任意应用、静默或跨RP泄漏。

复现/验证路径：

1. A/B使用保留UUID的隔离KDBX副本，准备同RP且可区分的凭据。
2. 系统保留A候选/创建入口后切B或杀provider重建，并消费旧入口。
3. 断言应取消；核对签名来源、计数、A/B文件及保存落点。已有密码跨进程测试不能替代这些分支。

反证和限制：B缺同UUID断言会失败，包名/签名/RP检查和用户验证仍在；调用方可另发B新请求，故当前不宣称新增任意调用权限。

## 3. 实施步骤与失败处理

1. 统一按入口类型查注册上下文，缺失/过期/进程重建旧token拒绝并要求系统重新查询。
2. 首次处理、解锁/验证后、最终写盘/签名前都核对目标与票据；最终校验与敏感操作原子化。
3. 创建/锁定入口明确如何绑定解锁后的同一目标，避免把null票据当任意库授权。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。

### 2026-10-20 实施与证据

新增每窗口独立的 `CredentialSessionGate`，四类入口按类型、随机注册身份、库路径与票据受理；用户验证后的实际库操作传播原票据，最终结果在 `useCredentialTicket` 的窄临界区交付。锁定时创建的入口只以登记路径为稳定目标，解锁后绑定一次，此后同路径重开也拒绝；不把空票据当通配。系统进程重建后注册表缺失仍拒绝。传统 Autofill 继续使用原令牌通道。

2026-10-21 续办核对：JVM `CredentialSessionGateTest` 2 例覆盖四类型旧票据、锁定入口拒绝 B、只允许原路径一次重绑定、同路径重开拒绝和当前请求正对照；底层 `SessionBoundMutationTest` 另验证实际改树/保存临界区。隔离 `KeePasskey_Remediation_20261020`（Android 16 / API 36）实跑 `CredentialSessionGateDeviceTest` 1/1：使用真实 Android Intent 随机身份、实际会话与 A/B 正式文件，四类型原会话提交通过、换库后变更及成功回传全部拒绝。Service 锁定创建入口改为登记活动库的 `path`，而非私有目录使用的文件名 `id`，保证解锁后可以按相同路径绑定。

复现命令：`./gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.keepasskey.app.passkey.CredentialSessionGateDeviceTest'`。非空结果副本：`build/remediation-evidence/CredentialSessionGateDeviceTest.xml`，tests=1、failures=0、errors=0、skipped=0。该用例验证门控与文件，不驱动系统选择器、四 Activity 的用户验证回调或相同 UUID 私钥签名；跨进程和真实 Credential Manager 全链路矩阵继续开放。

竞态采用 barrier、受控调度或定点故障，不用概率性 sleep。涉及设备用例须在隔离 AVD/可丢弃设备实际执行并确认非空 XML；若改 Rust/JNI/Native 加密分派或探活，按 AGENTS 执行 crypto、database、sync、app 四层 connected 测试。
