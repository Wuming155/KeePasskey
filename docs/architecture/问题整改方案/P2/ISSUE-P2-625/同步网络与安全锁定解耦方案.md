# ISSUE-P2-625：同步网络与安全锁定解耦方案

> 编制日期：2026-10-15（Asia/Shanghai）；源码基线：`4cfedc840d8cec67d7ba9db594de3b14c9355d0d`。
> 状态：部分实施，仍开放。挂锁现限于同步锁后的本地快照与本地采纳；barrier/JVM 用例通过。慢 HTTPS、熄屏锁定时间上限、底层取消与 412 重入仍未在实体机验收。

## 1. 问题与依据

当前登记为 P2、置信度高。[SyncCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncCoordinator.kt) 在取得同步 mutex 前就增加 long-task holdoff，直到整个周期结束才释放；[AutoLockSessionGuard.kt](../../../../../app/src/main/java/com/keepasskey/app/security/AutoLockSessionGuard.kt) 发现挂锁后返回 Deferred。[SyncNetworkOptions.kt](../../../../../sync/src/main/java/com/keepasskey/sync/network/SyncNetworkOptions.kt) 的单 call 上限及 `TransientHttpRetry` 的重试不能约束整个排队/网络周期。

慢响应及排队可将锁定推迟数分钟。finally 和单请求超时是实际边界，不是永久不锁；明文暴露还需设备/应用可被访问，不等于云端能直接读库。

## 2. 目标与预算

网络等待、重试与排队不持有主凭据或解密树租约；安全锁定具有明确、可测的最长附加延期。建议将“锁定请求至会话/主凭据清理完成”的正常验收上限设为 5 秒，并以低端 AVD/设备测量复核；该值需产品/工程确认，不能当作既有承诺或无条件 OS 实时保证。

数据库原子提交只能短暂延迟锁定，不能中断后损坏文件。不能通过禁用自动锁定、延长用户设定、强杀写盘任务或忽略未保存修改达标。

## 3. 实施步骤与失败处理

1. 拆分周期为短暂会话快照/序列化、只持密文网络段、短暂版本校验/提交段。需要的加密材料仅在受控会话段借用，用完释放；仅把代码移到 IO 并不能减少秘密驻留。
2. holdoff 在真正取得数据库提交/快照租约后才增加，并有拥有者和 deadline；等待同步 mutex 不持 holdoff。同库重复触发合并为单飞/待重试标记，避免排队递增延期。
3. 锁定请求撤销继续明文工作的权限，取消可取消的序列化/下载解析，释放缓冲并阻止新租约。已开始的原子替换在受控临界段完成或明确失败，再执行锁定；超出预算必须反馈恢复状态及保全文件，不能仅把计数归零后留着秘密任务运行。
4. 给网络周期建立总预算与取消传播，覆盖所有请求和重试。现有阻塞 `Call.execute()` 不能仅凭协程取消就假定已停止，必须核对并接通活动 `Call.cancel()` 或等效可取消适配，测试服务端停顿时的实际退出时间。锁定后可继续的任务只能使用密文和允许后台使用的云凭据。云凭据所有权走统一 `useProvider`，Provider 生命周期结束立即清理。
5. 迟到上传成功后，只登记该密文修订被远端接受；若会话已锁定、重开或更换代次，不再解密/采用/发布旧树。结果通过版本化待对账状态交给下轮解锁处理。
6. 锁定完成清理主密码、派生材料和本轮借用副本；保留现有 dirty-save/recovery 机制。锁定失败、取消和迟到网络结果分别建模，不能将安全锁定 Deferred 当作完成。

## 4. 验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| HTTPS 慢响应/停顿、重试中熄屏 | 从锁定请求单调计时，会话及主凭据在约定预算内清理 |
| 后台超时、多个同步排队、重复网络恢复 | 队列不延长 holdoff；同库单飞，锁定不被连续推迟 |
| 本地保存/原子替换时请求锁定 | 文件完整可重开；完成或恢复结果明确，不取消半次提交 |
| 锁定后上传成功/失败、锁定后换库再重开 | 仅结算正确密文修订，不发布旧会话内容或污染新库 |
| 取消、超时、序列化异常、Provider 装配失败 | 租约/计数归零且秘密副本已清理，无后台残留明文任务 |

扩展 `AutoLockHoldoffTest`、`AutoLockSessionGuardTest` 和同步取消/排队测试；用屏障与虚拟时钟检查状态，不靠真实 sleep 测逻辑。设备用受控 HTTPS 慢响应、真实熄屏/后台事件测时间，结合会话/凭据清理探针及正式文件重解析，不只观察锁屏 UI。保留非空 XML 和时间回执。

## 5. 顺序、交付与回退

先交付排队不挂锁和可观测 deadline，再拆网络/明文租约，最后连通锁定与恢复。与 P2-621/624 共用代际结算，与 P2-627/P3-628 共用密文任务和 Provider 生命周期。

若某条路径尚不能在预算内安全中止，暂时停止其后台自动执行并明确限制，保留手动恢复入口；不回退到全网络持锁，也不丢弃待保存内容。未取得实际锁定耗时与文件保全证据时，本条不关闭。
