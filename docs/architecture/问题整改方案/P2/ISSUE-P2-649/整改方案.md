# ISSUE-P2-649 合并库密钥文件同步读取且失败静默降级

> 状态：**已实现 / 尚未完成运行验收**。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2；结论：静态确认；置信度：高。2026-10-20 已按本方案实施，运行证据与剩余边界见下文；不提前关闭问题。

## 1. 问题与依据

密钥文件URI重载由按钮回调同步进入presenter，直接openInputStream().readBytes()，没有IO调度或累计上限；catch Throwable后用null继续提交，读取失败被解释成未提供密钥因子。

- 审查维度：用户体验与易用性、功能完整性、安全性与权限控制。
- 影响范围：慢SAF提供者或巨大/未知长度文件可阻塞主线程、引发内存压力；错误被延后呈现为解锁失败且用户选定因子未兑现。该入口不同于已加上限的附件/漂移读取。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsImportPresenter.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsImportPresenter.kt)：原始行 71–80。
- [app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsViewModel.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsViewModel.kt)：原始行 127–130。
- [app/src/main/java/com/keepasskey/app/ui/screens/importer/ImportMergeCredentialSheet.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/importer/ImportMergeCredentialSheet.kt)：原始行 93–101。

复现/验证路径：

1. 在KDBX并入凭据表单选择密钥文件，提供慢流/超大未知长度流或抛IOException的隔离provider。
2. 点提交，追踪主线程栈和读取累计量。
3. 检查失败是否继续以keyFileData=null调用submitCredentials；不在真实用户库上构造OOM。

反证和限制：常规小密钥文件读取很快；KDBX头验证仍会挡住错误凭据，不因此推导任意文件读取或解密绕过。

## 2. 修复目标与边界

按已选因子语义异步读取；读取失败明确停止本次提交。密钥文件无大小上限是用户既有裁决，不列为本项待修缺陷；合法大文件完整读取，残余 OOM 边界仍见[已知工程限界 §37](../../../已知工程限界.md)。

涉及模块：app SettingsImportPresenter/SettingsViewModel/导入凭据UI。

预期结果：UI保持响应，选定密钥因子不会被静默忽略。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 在受控 IO 作业读取，支持取消并给忙态；保留项目密钥文件完整读取、无大小上限契约。
2. 复用生产 KeyFileAccess 通道，不依赖提供方 SIZE；空文件、异常和授权拒绝均给出静态可理解错误并停止提交。
3. 所有原件/部分缓冲由finally清理，只有成功读取才提交完整keyBytes。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。

### 2026-10-20 实施与证据

URI 入口同步复制密码后交给 `KdbxMergeController` 的受控作业，经 `KeyFileAccess.read` / `SafKeyFileAccess` 在 IO 调度器读取。读取失败不调用第二库解密；忙态和取消复用并入状态。`readKeyFileBytes` 分块检查取消并清理工作缓冲，`SafKeyFileAccess` 在 `withContext` 结果被取消丢弃时擦除未交付字节。

2026-10-21 续办核对：JVM `KeyFileByteReaderTest` 6 例覆盖原有完整读取/清理及新增读取取消后工作缓冲清零；`KdbxMergeCredentialOwnershipTest` 5 例继续通过。隔离 `KeePasskey_Remediation_20261020`（Android 16 / API 36）实跑 `MergeKeyFileDeviceTest` 2/2：选定不可读密钥文件时，即使第二库仅凭密码可打开，也返回 `KEY_FILE` 且目标文件逐字节未变；合法 2,280,000 字节密钥文件经生产 IO 通道完整读取，能够打开以该因子保护的第二库并完成并入。读取期间 UI 主线程调用只启动作业，不在主线程建流或读流；不将 File URI 样本声称为完整 SAF 提供方或实际表单 UI 验收。

复现命令：`./gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.keepasskey.app.data.importer.MergeKeyFileDeviceTest'`。非空结果副本：`build/remediation-evidence/MergeKeyFileDeviceTest.xml`，tests=2、failures=0、errors=0、skipped=0。取消交接的依据见 [Kotlin 官方 withContext 契约](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/with-context.html)；未交付结果由原拥有方清理。慢流、虚报 SIZE、权限拒绝/异常/取消完整 SAF 矩阵及表单点击验收仍待补齐。

竞态采用 barrier、受控调度或定点故障，不用概率性 sleep。涉及设备用例须在隔离 AVD/可丢弃设备实际执行并确认非空 XML；若改 Rust/JNI/Native 加密分派或探活，按 AGENTS 执行 crypto、database、sync、app 四层 connected 测试。

本批共同 JVM 选择性回归：app 285 例 + database 154 例，共 439 例，failures/errors/skipped 均为 0；选择器覆盖导入族、Credential 族、PasskeyEntryCoordinator 族、密钥读取与 database 会话族，不是全仓测试数。日志：`build/remediation-jvm-final.log`。本机失效 Cargo 镜像通过任务级 `CARGO_HOME` 与官方注册表缓存解决，未改全局配置或仓库构建阈值。设备类须分别运行并检查 XML；批量 class 参数曾只执行首个类，已逐类补跑，不把那次构建成功当作全部设备通过。
