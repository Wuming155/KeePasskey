# ISSUE-P2-659 漂移合并遗漏库级 Meta，外部设置改动被静默覆盖

> 状态：**已闭环（2026-10-18，§538）**。核实：2026-10-16；实现：2026-10-17；设备端漂移 / 同步与 KeePassXC 互操作均已验。
> 等级：P2。JVM、隔离 AVD 文件漂移与同步冲突页、MinIO 双 provider actor、独立 KeePassXC 读取均通过；不外推为 AWS / 双实体设备验收。

## 1. 问题与依据

漂移合并产物原先只合并条目树、墓碑和图标池，库级 Meta（名称、描述、默认用户名、颜色、自定义数据及历史维护参数等）一律取本地。外部桌面端修改 Meta 后，本机选择“合并后保存”会静默覆盖外部改动。

- 影响范围：多端共同编辑同一 KDBX 时，外部端库级设置可能丢失；本地 Meta 不会因该问题被覆盖。
- 触发路径：外部端修改 Meta → 本地库产生写入漂移 → 选择“合并后保存”。
- 发现来源：`ISSUE-P1-631` 第三轮审计；其因果链与 P1-631 不同，单列为本项。
- 当前实现位置：`sync/src/main/java/com/keepasskey/sync/merge/KdbxMetaMerge.kt`、`KdbxMerger.kt`；落库映射位于 app 漂移与同步冲突处理链。
- 边界：加密身份、回收站/模板组身份、主密钥时间策略、选择位置等字段恒取本地；图标池与二进制池由各自合并面处理。导入 KDBX 不提供 Meta 镜像，导入不改变当前库身份。

## 2. 修复目标与边界

让文件漂移、同步自动合并和同步用户裁决共用同一字段级 Meta 三方合并结果；有共同底版时按 base/local/remote 判定，双侧异值按字段时间戳选择，时间戳不可判定时进入显式冲突裁决。身份字段保持本地。

- 不把“双方保留”解释为 Meta 并集；同步 Meta 冲突由用户逐字段选择本地或云端。
- 不把导入行为改成覆盖当前库身份。
- 不宣称所有 KDBX 字段都可以跨端合并。

## 3. 实施步骤与失败处理

1. 已完成：新增 `KdbxMetaMerge` / `KdbxMetaLite` / `MetaFieldConflict`，并在合并结果中携带合并 Meta 与 Meta 冲突。
2. 已完成：文件漂移、同步自动合并、同步裁决三条写入路径使用同一 Meta 映射；同步冲突页提供“库设置”逐字段裁决。
3. 已完成设备路径：隔离 AVD 经生产 `SyncCoordinator` 验证共同基线、云端单侧 Meta 自动合入、双侧异值待裁决、裁决前远端字节不变；HTTPS Moto / RustFS 补验后，又以官方 MinIO 社区 tag `RELEASE.2025-10-15T17-29-55Z` 构建 TLS 回环服务。生产 `S3SyncProvider` 的两个独立实例模拟协调端与外部端，冲突页真实点击库名 / 颜色字段和确认推送，服务下载重解析确认 Meta 结果；MinIO 对正确 / 错误 SigV4 secret 分别返回 200 / 403。API 36 AVD `SyncMetaConflictDeviceTest` 2 例 0 失败。该证据是单 AVD 双 provider actor + 实际 MinIO，不声称双实体设备或 AWS 部署。
4. 待完成：用 KeePassXC 等独立实现读取同一份导出 KDBX，核验可合并 Meta 与自定义数据的格式互操作。

发生未决冲突、写盘或上传失败时，不得静默选择一侧或报告成功；裁决前文件 / 远端字节应保持不变，明确保留待处理状态并允许重试。身份字段必须维持本地值。

## 4. 验收矩阵

| 场景/检查 | 必须观察的结果 |
|---|---|
| 文件漂移：外部单侧修改名称、描述、默认用户名、颜色、自定义数据；本地保留未改字段 | 合并后保存并重新解析正式文件；外部字段合入，本地未改字段保留，customData 按键正确合并。 |
| 文件漂移：本地与磁盘同字段异值且时间戳不足以判定 | 自动合并失败并进入待裁决；裁决前字节不变；选择磁盘后正式文件读到磁盘值。 |
| 云同步：Meta 单侧变更、同字段异值、多个 Meta 字段并存 | AVD `SyncMetaConflictDeviceTest` 2 例：内存 Provider 路径验证待决数据流；HTTPS Moto / RustFS 后，官方 MinIO 社区 tag `RELEASE.2025-10-15T17-29-55Z` TLS 服务路径使用两个生产 `S3SyncProvider` 实例、`SyncCoordinator` 与真实冲突页点击，库名 / 颜色分别选云端 / 本地，单侧描述 / 默认用户名 / customData 合入、身份字段本地保留，并从服务下载重解析。MinIO 正确 / 错误 secret 分别为 200 / 403。该验收为单 AVD 两个 provider actor，不是两台实体设备。 |
| 身份字段与导入边界 | 身份字段恒取本地；导入不替换当前库 Meta。 |
| 互操作与失败对照 | KeePassXC 独立读取同一 KDBX；失败不丢待裁决状态、不改正式数据或误报成功。 |
| 当前状态 | `KdbxMetaMergeTest` 14 例 JVM 通过；隔离 AVD `DriftMetaMergeDeviceTest` 2 例、`SyncMetaConflictDeviceTest` 2 例通过；MinIO 服务双 provider actor 实际读写 / 冲突 UI / 回读已通过；本轮内存 Provider 冲突 UI 定向设备用例 1 例通过，并将真实合并落盘后的同一 KDBX 导出，由 KeePassXC CLI 2.7.12 解锁及解析 Meta / customData。见 §538。 |

涉及同步竞态时使用 barrier / 受控时序，不用概率性等待；设备测试必须使用隔离 AVD 且保留非空 XML 收据。

## 5. 顺序、交付与回退

- 顺序：生产 S3 Provider、同步冲突消费与冲突页逐字段点击已在官方 MinIO 社区版本本机 TLS 服务上补验；另对内存 Provider 生产冲突裁决后的正式 KDBX 独立读取。MinIO 接受正确签名并拒绝错误密钥，身份字段恒取本地，详见 §538。
- 交付：实现、测试、`ACTIVE_ISSUES.md`、本方案及 `已知工程限界.md` §47 同批更新；只有矩阵全部满足后才移出开放台账，并按现有流程追加闭环记录。
- 回退：按独立提交回退 Meta 合并映射；回退前保留当前正式库与远端副本，核对 Meta 与条目树，不得覆盖用户数据。
- 关闭记录：§538。KeePassXC 2.7.12 `db-info` 读取合并结果 `Remote Name` / `Remote description`，XML 导出验证 `remote-user`、`base-key` 与 `remote-key` 两项 customData，`RecycleBinEnabled=True`；具体文件哈希及测试限制见归档。MinIO 测试不在本轮重跑。
