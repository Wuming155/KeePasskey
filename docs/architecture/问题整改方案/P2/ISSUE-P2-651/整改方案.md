# ISSUE-P2-651 同步配置保存失败后输入显示与已擦除凭据副本不一致

> 状态：**尚未实施**。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2；结论：静态确认；置信度：高。本轮只记录审查和方案，不修改业务代码。

## 1. 问题与依据

表单把本地password/accessKey/secretKey数组直接传给controller；后者在HTTPS拒绝及保存收尾均清零。UI只在成功时替换/清空本地状态，失败时输入框仍显示已输入而提交数组已全零。修正端点再次提交会被isAllZero持续拒绝。

- 审查维度：用户体验与易用性、数据流转与一致性。
- 影响范围：WebDAV/S3配置错误后难以重试，输入状态误导用户，须重新键入秘密才能恢复；不应通过停止所有清理来修复。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/settings/subscreens/CloudSyncScreen.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/subscreens/CloudSyncScreen.kt)：原始行 160–179。
- [app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsSyncController.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/settings/SettingsSyncController.kt)：原始行 244–253。
- [app/src/main/java/com/keepasskey/app/sync/SyncCredentialsStore.kt](../../../../../app/src/main/java/com/keepasskey/app/sync/SyncCredentialsStore.kt)：原始行 217–222。

复现/验证路径：

1. 输入虚构凭据，端点填http://后保存使校验返回false。
2. 只修正为https://，不重新输入凭据再次保存。
3. 核对输入显示仍在但提交数组全零，第二次被存储层拒绝；重输后可成功。

反证和限制：失败后重新键入会恢复；已保存凭据的空输入复用语义另有设计，不能把全零数组混成空输入。

## 2. 修复目标与边界

保存调用只消费提交副本，或失败后明确清空输入并提示重填；显示与实际可提交值一致。

涉及模块：app CloudSyncScreen/SecurePasswordField/SettingsSyncController/SyncCredentialsStore。

预期结果：配置修正后可以按真实字段状态重试，秘密所有权清楚。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 明确字段持有/提交数组所有权，优先传copyOf并由提交方finally擦除，草稿按安全策略保留或明确清除。
2. 失败时同步驱动SecurePasswordField和本地状态，避免可见值与传输副本脱节。
3. 覆盖WebDAV和S3三类凭据及预填/保留旧秘密语义。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
