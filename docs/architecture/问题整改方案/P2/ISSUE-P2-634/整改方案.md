# ISSUE-P2-634 自定义字段删除和改名在保存时被补回旧键

> 状态：**已实施（2026-10-17）**。核实：2026-10-16（Asia/Shanghai）；实施：2026-10-17；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2。JVM 用例已实跑通过；**设备端编辑页复核与独立读取确认尚未执行**，故仍留在 `ACTIVE_ISSUES`。

## 1. 问题与依据

UI删除字段会从customFields中移除，但mergeCustomFields无条件保留所有未出现在UI键集合中的旧字段。删除的旧键被补回；改名则保留旧键并新增新键。

- 审查维度：功能完整性、数据流转与一致性。
- 影响范围：用户不能真正删除普通/受保护自定义字段，可能误以为旧敏感信息已移除；不等于明文对外泄露。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/edit/EntryEditCustomFields.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/edit/EntryEditCustomFields.kt)：原始行 74–78。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntryWriteCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntryWriteCoordinator.kt)：原始行 175–185。

复现/验证路径：

1. 创建字段X后保存，重进编辑页删除X或将X改名Y。
2. 保存并重开条目。
3. 检查KDBX当前字段集合：X仍在；改名时X和Y并存。

反证和限制：锁定的Passkey仪式字段应继续受到明确保留集保护；不能直接删掉所有未列字段破坏隐含扩展。

## 2. 修复目标与边界

区分保留、删除和改名意图，让用户管理的普通字段可真实删除。

涉及模块：app 编辑自定义字段/条目写入。

预期结果：当前版本字段集合兑现用户删除/改名意图，历史保留依既有历史策略。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 记录原字段身份和显式删除集合，改名提交旧键删除+新键写入。
2. 明确受保护Passkey/扩展保留集，与普通UI完整投影分开处理。
3. 统一校验重复键和标准字段键冲突，失败保留草稿。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
