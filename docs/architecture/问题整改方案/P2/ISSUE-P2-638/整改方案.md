# ISSUE-P2-638 恢复副本差异比较忽略密码和实际附件内容

> 状态：**尚未实施**。核实：2026-10-16（Asia/Shanghai）；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2；结论：静态确认；置信度：高。本轮只记录审查和方案，不修改业务代码。

## 1. 问题与依据

恢复预览的fingerprint只比title/userName/url/notes/tags及附件/历史数量，未比较密码、OTP、受保护自定义字段、Passkey材料或附件字节。内容改变但数量相同可显示“修改0”。

- 审查维度：用户体验与易用性、数据流转与一致性。
- 影响范围：恢复/覆盖/丢弃前的决策依据失真，尤其密码单独变化、历史已达容量上限或禁用历史的库；不意味着系统自动删除副本。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/security/VaultRecoveryCoordinator.kt](../../../../../app/src/main/java/com/keepasskey/app/security/VaultRecoveryCoordinator.kt)：原始行 211–235。

复现/验证路径：

1. 构造相同条目UUID与公开字段的正式库和恢复副本；历史数量相等（例如设0或已达上限）。
2. 只改变密码，或等数量附件的内容。
3. 输入密码执行恢复预览，观察modifiedEntries仍为0。

反证和限制：新增/删除数量可正确统计；默认未达上限时密码编辑增加历史数量可能偶然被计为修改，不能掩盖比较遗漏。

## 2. 修复目标与边界

差异计数覆盖完整用户数据，同时不输出或长期驻留秘密明文摘要。

涉及模块：app VaultRecoveryCoordinator/恢复预览。

预期结果：只要用户数据有实质差异就正确统计，未知不冒充相同。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 复用完整内容比较契约，明确哪些使用性字段不参与比较。
2. 用短期受控秘密读取比较密码/OTP/自定义字段及附件内容；用毕清理中间缓冲。
3. UI在无法完整比较时显示“未完成比较”而不是0。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
