# ISSUE-P2-596：同步内容变化语义补齐方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 AUD-08。2026-10-13 直读 `app/src/main/java/com/keepasskey/app/sync/KdbxContentComparator.kt`：changed 仅看墓碑和树；entryChanged 未看到期语义且历史只比条数。现行生产已有有效期编辑，因此 PD-20 的重开条件成立。当前 comparator 已比较 AutoType 和颜色，不重复登记这两个字段漏判。

## 2. 目标与边界

用户实际可编辑且会被写出的语义变化，必须触发重新序列化和上传；访问时间、使用计数和纯修改时间变化仍不触发无意义上传。库级配置进入上传检测不意味着推翻 PD-35 的合并本地优先。

## 3. 实施步骤

1. 对照生产编辑入口、模型和序列化器建立语义字段表，标注「会写出/只读运行态/随机生成」，作为代码及测试共同审查依据。
2. 比较 expires / expiryTime；按序列化实际语义处理禁用到期时的日期，避免将不生效的旧日期误判为变更。
3. 库级加入名称、描述、默认用户名、回收站/历史预算、自定义图标、MemoryProtection，以及可编辑的算法/KDF参数等；逐项核对现有模型字段。
4. 对头部比较语义参数，排除每次保存随机生成的 MasterSeed、salt、IV、内流密钥等。凭据代次使用独立标记，不能从密文字节是否相同推断凭据未变。
5. 将历史改为内容级判定，覆盖历史满额换入换出时条数不变的可达路径；复用受保护字段等值标签，禁止为比较物化口令/附件明文。历史遍历避免重复递归及无界开销。
6. 更新 comparator KDoc 和 PD-20 的已失效前提与例外保留范围；不把本端上传判据直接复制成合并的 isModified。

## 4. 验收矩阵

| 只改变的内容 | 必须观察的结果 |
|---|---|
| expires / expiryTime，历史禁用/满额 | changed=true，实际远端产物包含新有效期 |
| 名称、默认用户名、算法、KDF | changed=true，不复用旧缓存字节 |
| 相同条数历史中替换内容 | changed=true |
| 访问时间/usageCount/纯修改时间 | 内容相同则 changed=false |
| 随机头材料、标准字段保护往返差异 | 不误报；保留既有字段等值契约 |

扩展 `KdbxContentComparatorTest`，用逐字段正反例证明覆盖；补真实同步测试回读远端，而非只测试纯比较器返回值。

## 5. 顺序与实施验收

与 ISSUE-P1-591 的版本基线配套，随后验证 ISSUE-P2-597 合并。先定向单测和 XML，再真实保存/上传产物对拍、全量与门禁。只有明确变更产品语义才修改对应裁决，不能把所有时间字段一律纳入。
