# ISSUE-P2-633 历史回滚通过当前附件索引合并，不能恢复历史附件

> 状态：**已实施（2026-10-17）**。核实：2026-10-16（Asia/Shanghai）；实施：2026-10-17；源码基线：`94172d1efca004692b68ea480a1516753087fd70`。
> 等级：P2。JVM 用例已实跑通过；**设备端附件导出比对与独立 KDBX 工具核对尚未执行**，故仍留在 `ACTIVE_ISSUES`。

## 1. 问题与依据

回滚将历史投影传入通用saveEntry；历史附件投影只有refIndex/名称，没有历史字节来源。AttachmentMergePolicy按当前条目附件列表的同索引或同名项取数据，未命中时构造空附件。历史附件内容被当前内容替代或变空。

- 审查维度：功能完整性、数据流转与一致性。
- 影响范围：历史回滚显示成功却未恢复附件；同名附件、替换/删除/重新排序后尤其明显。
- 核实方式：当前源码调用链、状态转换及相关测试源码核对；下列产品复现序列未实跑。

- [app/src/main/java/com/keepasskey/app/ui/screens/detail/EntryDetailRevisionController.kt](../../../../../app/src/main/java/com/keepasskey/app/ui/screens/detail/EntryDetailRevisionController.kt)：原始行 55–69。
- [app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/VaultEntryMapper.kt)：原始行 70–79。
- [app/src/main/java/com/keepasskey/app/data/repository/AttachmentMergePolicy.kt](../../../../../app/src/main/java/com/keepasskey/app/data/repository/AttachmentMergePolicy.kt)：原始行 33–61。

复现/验证路径：

1. 保存含附件A（字节old）的版本，再把相同附件位置替换为字节new或删除。
2. 选择历史版本回滚；为隔离632，可从唯一历史项开始。
3. 导出回滚后的附件并比摘要：当前路径取当前索引内容或空占位，而非历史old。

反证和限制：通用编辑保存的refIndex匹配对当前附件是合理设计；问题在历史恢复复用它。尚未实跑端到端。

## 2. 修复目标与边界

回滚直接恢复选中历史KdbxEntry的完整内容和附件所有权，不从UI投影重建历史。

涉及模块：app 历史快照/EntryDetailRevisionController/AttachmentMergePolicy；database 写入意图。

预期结果：回滚后的条目内容和附件属于选中的真实历史版本。

保持现有产品裁决和已接受边界；方案中的新接口、屏障与测试是拟议实现，不能记作已落地。未经独立实现端到端读取/对拍，不声称 KDBX 互操作已经通过。

## 3. 实施步骤与失败处理

1. 增加绑定历史句柄的会话级回滚提交意图，保留当前条目身份和目标分组。
2. 恢复历史fields/customFields/附件source与元数据，归档回滚前当前版本；共享缓冲按存活集合清理。
3. 禁止用空附件占位替代不存在的历史source；读取失败显式拒绝且保留现状。

失败处理：出现目标库/修订不匹配、IO失败或取消时，不谎报成功；保全已确认的正式文件和用户仍持有的草稿/恢复材料，明确展示部分完成边界。秘密仅在确定所有权后擦除，禁止误擦活动库共享引用。对“需要进一步验证”的后果先完成正负对照；反证成立则调整或撤销该结论，不硬凑修复。
