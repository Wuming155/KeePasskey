# ISSUE-P2-597：三方合并条目语义补齐方案

> 编制日期：2026-10-13（Asia/Shanghai）；源码核对基线：`65cc39f8`。
> 状态：方案已编制，尚未实施；登记条目继续开放。以下测试均为实施时的验收要求，不是本次实测结果。

## 1. 问题与依据

来源为 AUD-09。2026-10-13 直读 `sync/src/main/java/com/keepasskey/sync/merge/KdbxEntryMerger.kt`：标量词汇表仅覆盖图标、覆写 URL、质量检查，冲突结果从 local.times 保留到期值，只更新修改时间，AutoType/颜色同样取本地底版。此项关注完整条目，不变更 PD-35 库级 Meta 裁决。

## 2. 目标与边界

本地与远端改不同语义字段应合并保留；同字段异值遵循现有冲突/LWW规则并进入差异清单。判修改、实际合并、冲突上报三者必须使用同一词汇表。

## 3. 实施步骤

1. 对 KdbxEntry 可序列化字段逐项审查，保留标准字段、自定义字段、附件和历史的专门策略，补齐未覆盖标量。
2. 将 expires 与 expiryTime 作为联合到期语义处理，避免逐字段获胜产生两端都未选择的混合状态；times 的修改时间仍按既有取最新规则装配。
3. 将 AutoType 视作完整配置对象参与三方合并，双侧同值无需冲突，双侧异值采用已有裁决并完整上报；本项不新增自动输入执行功能。
4. 前景/背景颜色及其他核实遗漏字段纳入统一词汇表，补稳定冲突键及 UI 本地化映射，防止协议已上报而界面丢失差异。
5. 保留单侧变更取该侧、双侧同值不冲突、双侧异值明确裁决、无 base 的既有规则；合并后所有字段值来自可解释的来源。
6. 更新生产 KDoc，按共享所有权保留未修改字段引用，擦除只针对已下线且不被新树使用的秘密。

## 4. 验收矩阵

| 三方输入 | 必须观察的结果 |
|---|---|
| 本地标题/口令，远端到期/AutoType/颜色 | 独立修改全部保留 |
| 两端同一到期配置 | 不产生虚假冲突 |
| 两端不同到期/AutoType配置 | 字段键完整、获胜值符合既有规则 |
| base 缺失、时间戳相等、禁用到期 | 结果确定，不生成拼接配置 |
| 远端仅改库名或历史预算 | 保持 PD-35 本地优先 |

扩展 `KdbxEntryMergerFieldsModifiedTest` 并经公开 merger 入口测试；回写 KDBX 后用官方实现核对到期和 AutoType，不能只比较内存 copy。
