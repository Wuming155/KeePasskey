# KeePasskey 架构

本文只记录稳定的模块边界与设计理由。实际依赖以各模块 Gradle 配置为准，具体实现以源码为准。

## 模块职责与依赖

| 模块 | 职责 | 依赖 |
|---|---|---|
| `app` | Android 界面、平台服务、应用编排与活动数据库会话 | `core`、`database`、`crypto`、`sync` |
| `core` | 跨模块共用的基础类型与领域概念 | 无 |
| `crypto` | 密码学算法、密钥派生及加密原语 | `core` |
| `database` | KDBX 格式读写、数据库树、条目操作与合并 | `core`、`crypto` |
| `sync` | 远端文件存储协议、缓存及版本/冲突协调 | `core` |

依赖保持单向：

```text
app ──> database ──> crypto ──> core
 ├───> crypto ─────────────────> core
 └───> sync ───────────────────> core
```

`database` 通过 `api` 暴露其接口使用的 `crypto` 类型；`app` 也因自身直接使用加密能力而依赖 `crypto`。`sync` 不依赖 `database`，以避免远端传输层与 KDBX 格式实现耦合。

## 边界理由

- `crypto` 不感知 KDBX 格式；格式解析、序列化及数据库语义由 `database` 承担。这样密码学原语和文件格式可以分别验证与演进。
- `sync` 面向整个数据库文件及远端版本，不自行解释条目内容。数据合并属于数据库语义，不属于 WebDAV 或 S3 传输实现。
- `app` 负责平台入口和应用会话编排；平台服务不能假设界面进程或 UI 状态始终存活。
- WebDAV 与 S3 暂留在 `sync` 模块。只有出现明确的依赖冲突或独立演进需求时，才重新评估拆分。

## 日志级别与详细度

诊断事件分两条通道、五个级别，选择依据是**这条事件回答什么问题**，不是「重不重要」。

| 级别 | 回答的问题 | 典型内容 | 闸门 |
|---|---|---|---|
| `DEBUG` | 过程怎么走的 | 同步分段推进、路径选择、命中哪个分支 | 诊断开关 + 详细模式 |
| `INFO` | 状态变成了什么 | 解锁成功、库挂载 / 卸载、同步完成与结果 | 诊断开关 |
| `WARN` | 哪里降级了但仍继续 | 回落非原生实现、跳过候选、读失败改用兜底 | 诊断开关 |
| `ERROR` | 哪里失败了 | 保存失败、解锁失败、导出失败（附异常类型与栈帧） | 诊断开关 |
| `AUDIT` | 谁在何时做了数据出域动作 | 日志导出 / 复制 / 清除 | **不受**诊断开关约束 |
判定规则：

- **只写发生的事实，不写预期**。`INFO` 写「同步完成，结果=已是最新」，不写「即将开始同步」这类不含结果的过程叙述；后者属 `DEBUG`。
- **级别由「调用方能否继续」决定**，不由异常类型决定。捕获后降级继续 ⇒ `WARN`；捕获后本次操作失败 ⇒ `ERROR`。同一异常在不同调用点可以是不同级别。
- **异常对象只经带 `Throwable` 的 `AppLog.e/w` 传入**，不要自行拼接 `e.message`；脱敏与栈帧预算由 `diagnosticText` 统一处理。异常 message 属不可信外部输入，永不上浮文案槽。
- **`AUDIT` 仅限数据出域与用户可见的治理动作**（导出、复制、清除、进程退出记录）。它不是「更重要的 INFO」，不得用于业务状态。入口是 `AppLog.audit(tag, message)`：它走独立出口、不受诊断开关约束；业务代码**不得**改为经 `AppLog.i` 记录审计事项——那会让该行随用户关闭诊断日志一起消失。
- **`DEBUG` 是详细模式通道**：已判过详细模式开关的调用方用 `AppLog.verbose(tag, message)`——它 logcat 侧按 `i` 级输出（`AppLog.d` 在 release 被 R8 剥离，详细模式必须在稳定版生效），缓冲侧仍受诊断总开关约束。`SyncPreferences.verbose()` 即此入口。不得用 `INFO` 冒充过程细节，也不得用 `verbose` 记普通事件（那会绕过详细模式开关）。
- **`v` 只用于开发期临时排查**，不得进入需要用户导出的路径：`AppLog.v/d` 在 release 被 R8 剥离，写进去等于该事件在稳定版不存在。

静态约束：`DebugLogBuffer` 的级别常量与类型只允许出现在 `data/logger`、`core/log` 与诊断日志功能自身（`DiagnosticLogReport` / `SettingsDebugLogActions` / `SettingsExportController` 及其装配点）内；业务代码不得直接传级别字符串，也不得直接注入 `DebugLogBuffer`（应经 `AppLog`）。两者由 `tools/doc/check_log_levels.py` 检查。
