# 已知工程边界

本文记录仍需维护者了解的限制，不代替 [当前缺陷清单](../ACTIVE_ISSUES.md)，也不作为测试已通过的证明。产品取舍见 [产品与设计约定](产品裁决登记.md)。历史测量与验收细节查 Git 历史；新结论须重新验证其适用环境。

## 内存与缓存

- KDBX 对象树整体驻留内存。大附件按策略暂存应用私有目录，锁定、关闭和冷启动清理；进程直接死亡后，附件可能留到下次启动。删除文件只解除目录引用，不保证闪存物理擦除。
- `ProtectedString` 的内存加密使用进程级密钥，单个会话不能将其清除；拥有进程内存或执行能力的攻击者仍可取得秘密。Android 接口、UI 及模型中部分明文使用不可确定擦除的字符串。
- 实时验证码状态可能保留上周期字符串直至 ViewModel 销毁或刷新，不能宣称锁库后堆上已无验证码。输入法学习、剪贴板历史与其它应用保存的副本不受本应用清理控制。
- `ProtectedString` 展示读取仍承担完整性复核成本；不能以缩短耗时为由让写入或交付静默采用不可读值。
- 附件引用预算约束单个池项的引用数与物化字节，无法用同一上限覆盖所有分散引用的累计内存。大库、历史与大量小附件仍可造成内存压力。
- 持久化基线是会话内保留的一份整库密文快照，打开路径在捕获缓冲、取出与登记之间另有瞬时整库副本，保存路径以所有权移交避免基线克隆，峰值随库体积增长，锁定、关闭与换库时释放。实测合成 5.26 MiB 大库（emulator-5554 API 36，2 ms 采样下界）打开、保存与快照读取的堆峰值增量分别为 31.7~36.5 MB、13.8~15.0 MB 与 5.6 MB，代码推断整库密文副本数分别为 3、2、2 份（推断不作实测宣称）。留存失败时旧基线作废（快照为空、修订前移），下游按「无可信基线」保守合并；各处峰值以设备读数为准，不由上限推导。
- 流式解密按有界预读消费底层密文：小请求（单字节、内层头逐字段短读）按最小预读块 4 KiB 摊销原生调用，批量读取仍以 64 KiB 封顶，故未交付明文只驻留当前一次预读量（小读 4 KiB，批量至多 64 KiB），交付即归零、close 整段兜底归零。预读不得扩大到吞掉整段载荷。

## 密码学与性能

- KDF 以参数预算限制工作量，原生阻塞派生不能在任意中途取消；协程超时不等于停止运算。过去机型上的耗时不能当作所有设备的墙钟上界。
- KDBX 保存需要整库 XML 序列化、压缩与加密，没有增量更新保证；大库在低端设备上仍有 CPU、电量与等待成本。
- JNI 整块数组路径有拷贝；流式直接缓冲减少部分开销但不证明所有调用零拷贝。ChaCha20 原生解密流在实测设备（emulator-5554 API 36）上单字节读取耗时 41.642 ns/byte、64 KiB 批量读取 19.666 ns/byte（旧逐字节 JNI 参照为 1035.651 ns/byte），仅代表本设备测量结论。AES、ChaCha20 和 RSA 的性能结论需分别按实际设备测量。
- 空凭据库沿用格式复合密钥语义，不能当作有效的秘密保护。弱 KDF 评估器的存在也不意味着所有打开与导入入口都会展示弱参数告警。
- 健康检查与 HIBP 只检查条目，不检查主口令；强度高于门槛不代表该主口令从未泄露。

## 文件、漂移与恢复

- `.kdbx.bak` 为同目录上一稳定版本的滚动备份，可能仍可用旧凭据打开；不能代替用户的多代独立备份。
- `AtomicFileWriter` 先写临时件、原子替换主文件，最后提交暂存备份（`.bak.tmp` → 正式 `.bak`）。主文件替换成功而备份提交之前进程死亡时，正式 `.bak` 仍是更早一代稳定版本并可能残留 `.bak.tmp`，由下次写盘覆盖或清理。原子 move 与标准 rename 均不可用时拒绝非原子覆盖并如实失败，原主文件与既有 `.bak` 保持原样；备份偏好（生成与清理）保留。
- SAF 提供方通常以截断式写回，缺少跨提供方原子替换与内容级 compare-and-swap 保证，外部 SAF 库不参与当前云同步。
- SAF 元数据缺失会使漂移检测放行；元数据异步刷新也可能产生一次误报。内容钉扎有摘要时重读校验，无摘要时退回 size/mtime，无法识别同尺寸同时间的改动。
- 内容复核与提交之间仍有竞态窗口；本地原子替换保证文件完整性，不等于与外部写入者进行 compare-and-swap。阻塞的提供方写回可能延迟取消。
- 新建库排他创建保证不覆盖已有文件；发布过程中进程被杀可能留下零长或部分新文件，不会将其登记为成功新库。
- 漂移合并依赖会话内密文基线（见[内存与缓存](#内存与缓存)）；基线缺失时保守合并。漂移裁决为整批策略，粒度与同步冲突页面不同。
- Meta 合并保留本地身份与加密配置；“双方保留”不产生第二套库级配置。分组副本会复制子树，可能增加库体积。
- 崩溃草稿只保护已经捕获并成功保存的版本，不能保证任意强杀前的最后一次按键都可恢复。待决裁决本身不跨进程恢复；已保全候选与正式写入之间的每个死亡窗口并未穷尽验证。
- 密钥文件目前整体读入且不设大小上限，用户选中的异常提供方可造成 OOM；不能通过截断或采样解决，需改成流式派生后重新评估。

## 同步与网络

- 服务端必须正确实现条件写才有相应并发保护；预检 HEAD 无法替代服务端原子条件。WebDAV 的 MOVE/If、弱 ETag 和覆盖行为随服务实现变化，本地 WsgiDAV 样本的正常 MOVE 与 HTTPS 往返只证明该样本，不能外推为全部服务兼容。
- WebDAV 覆盖上传默认依赖服务器支持 MOVE 覆盖（`Overwrite: T` / 条件 `If`）：服务器拒绝覆盖已有目标（409/423）时返回可处理的协议错误并保留远端旧文件。用户可在「设置 → 云端同步 → 网络安全」显式开启「兼容拒绝覆盖的 WebDAV 服务器」（默认关闭）以支持坚果云等拒绝覆盖的服务：仅在 409/423 且 PROPFIND 重探确认 ETag 与预期基线一致后，DELETE 正式目标并以 `Overwrite: F` 重试 MOVE；恢复 MOVE 失败时保留临时文件作为下轮恢复锚点。开启即接受云端文件在 DELETE 与 MOVE 之间短暂消失、进程死亡或取消可能让正式路径缺失，以及多端并发写入时的覆盖风险；`Overwrite: F` 只能阻止服务端可见的目标重建被静默覆盖，不能替代跨请求事务。ETag 漂移、重探失败、无 ETag 可核验时仍走冲突或 fail-closed，不删除目标。PROPFIND 响应不可解析（损坏、截断或非 multistatus，如网关错误页）时元数据读取如实失败，不退化为「成功 + 空元数据」，该服务端将无法同步而非静默降级。
- WebDAV Basic 认证头在每次构造请求时现算，Provider 只持有口令的独占可擦副本；会话终止、换引擎、配置撤销与丢弃待决引擎时经 `SyncEngine.releaseProviderCredentials` 确定性失效，失效后取头抛认证错误而非降级为空口令。OkHttp header API 仍要求 String，该不可擦副本只存在于单次请求作用域。
- 同步缓存按规范目录、库命名空间和远端路径共享进程内协调锁；固定数量的锁可能让无关路径串行。缓存字节与版本标记仍为多个文件，进程死亡或跨进程写入不具备整体原子提交保证，恢复判定须核对实际字节摘要。
- 本地已同步版本证明只持久化密文摘要，并绑定库路径、本地写入目标及云端目标；不随锁库清缓存销毁，撤销对应同步配置时清除。普通文件在会话提交锁内读取正式文件摘要，流式通道使用已读取或写盘确认的密文基线摘要。记录缺失（含升级后尚未成功同步）、目标不符、文件已重写或基线不可用时仍保守合并，可能重新上传；不根据空证据覆盖本地内容。它不是可信远端版本证明，也不提供与外部文件写入者的 compare-and-swap 保证。
- 防回滚依赖本地最近摘要记录，不是可信远端版本证明。状态缺失或不可解析时放行，只覆盖有限历史窗口；具备应用私有文件写能力者可重置状态。
- IP 字面量会绕过 OkHttp DNS 接口，所以连接期地址复核仍有独立职责；仅配置的目标主机获内网豁免，不能把 DNS 检查成功等同于连接安全。IPv4-mapped / IPv4-compatible 形态按内嵌 IPv4 判定，云元数据红线先于白名单豁免；平台把映射地址归一为 4 字节还是保留 16 字节由系统决定，两种形态都须命中同一判据。
- 同步失败通知每个失败周期只提示一次；用户划掉后同周期不重发，错误详情仍需在应用内查看。
- S3 虚拟主机模式连接期豁免授给实际请求主机（`bucket.endpointHost`），路径模式授给端点主机（自建内网在缺少通配符 DNS 时适用路径模式）；实测通过真实 MinIO 样本（RELEASE.2025-09-07，本机回环 `minio.127.0.0.1.nip.io`）验证，未跑 Ceph RGW，不能外推为全部 S3 兼容实现或商业云对等兼容。Android XML 解析器能力不同，须保留外部实体隔离与合法响应对照。

## 平台与凭据

- Credential Manager 的口令候选在包名从未登记签名绑定时仍按 `android://` 包名维度匹配，这不等于已验证签名。通行密钥候选同样可能按包名维度列出，但原生签发（含显式 RP）要求签名绑定成立：未绑定拒签、签名不符拒签且不提供就地重绑，未绑定只能在受保护窗口内显式授权后重试。候选检索、最终 origin/RP 校验与系统用户验证各有职责，系统用户验证不替代签名绑定。
- 内置公共后缀表是随 APK 版本冻结的快照，运行期不更新：未收录的新公共后缀按默认规则归组，可能使同一新后缀下的不同租户被当作同一可注册域（授权偏宽），已删除后缀只会偏严。IP 字面量与 `localhost` 不参与后缀匹配，其匹配口径见[设计约定](产品裁决登记.md#自动填充与通行密钥)。刷新与校验方式见 [刷新工具说明](../../tools/publicsuffix/README.md)。
- 后台读不到主剪贴板时无法证明内容仍属本应用（Android 10+ 后台读取与变更广播均受限），此时不物理清空，待清标记与截止期保留至回到前台核验；设备证据覆盖外部 UID 真实粘贴、外部覆盖、真实熄屏与前台锁定，冷启动只验证对账内核而非强杀后的完整恢复。
- 前台闲置计时由窗口受理的触摸 / 按键与 Compose 输入法会话的编辑操作刷新，只读查询与锁定态交互不刷新；设备证据覆盖实测输入法与对话框形态，不外推到所有输入法实现。
- 解锁节流的进程内等待由单调时钟推进，持久截止以墙钟记录并在恢复时截断到策略上限；设备证据使用真实 `elapsedRealtime` 与注入的墙钟偏移，不具备 `SET_TIME` 权限未做真实系统调时，也未做真实进程重启，新实例读真实 prefs 只覆盖恢复路径。
- 生物识别凭据的遗留迁移在确认硬件删除成功并提交 prefs 清理后写完成标记，失败保留 prefs 键以供重试，重复扫描已消除；首次构造在主线程同步执行（实测 emulator-5554 API 36 样本：无遗留时中位 1.918 ms，含别名首次迁移中位 23.695 ms，标记后快速路径中位 0.009 ms，不外推全部真机），该一次性同步设计用于确保在首次使用封印/解封前完成迁移收敛；先装旧版再覆盖升级会跳过重扫并留下惰性残留。
- 关闭服务开关不使组件从系统服务列表消失。系统设置深链、通知动作、CM Action 和浏览器接入都受 ROM 与调用方影响，不能从 JVM 策略测试推出系统 UI 已验收。
- 导入通行密钥的随机高位计数与原认证器历史无映射，不能承诺克隆检测；非 32 字节 PRF 可保真保存，但当前消费方可能拒绝计算。
- 高密度二维码的生成图片可解不代表相机实拍必可解；既有实拍失败没有足够证据归因于硬件或软件。
- 按防截屏设置放开的扫码窗口与通行密钥导入确认可能暴露秘密；截图、录屏或输入法已保存内容不能追溯撤销。遮挡触摸过滤与悬浮窗绘制抑制在实测设备（emulator-5554 API 36）通过系统 InputDispatcher 路由与 UiAutomation 像素采样验证，各 OEM 定制 ROM 对窗口分发与悬浮窗穿透的实现可能存在差异，不作为全平台所有实现的无条件证明。系统认证弹窗的可观测性也受系统窗口策略限制。

## 构建与验证

- Windows 宿主测试不能证明 Android 文件权限位、Keystore、生物识别、系统填充与真实设备时序；这些结论需隔离设备实跑。
- app 的 JVM 测试通过 `MainDispatcherGuard` 跟踪并取消 ViewModel，在收尾安装新调度器；遗漏登记仍可能形成跨用例干扰。
- CI 当前为定时及手动触发，没有合并前必需检查。构建脚本和签名读取脚本同处可修改仓库，仓内哈希不能阻止同时修改脚本与基线的恶意变更。
- 独立实现的 KDBX 互操作、真实服务器和设备报告各自有适用边界；用例被跳过、零用例执行、编译成功均不能算运行验证通过。
- 静态扫描（`gate_readings.py` 的敏感数据与作用域扫描）保留作为全局语法边界约束；测试断言退役纯源码文本匹配，改由真实平台与组件行为测试（如 Autofill 平台契约、Attachment 导出与 Compose 交互）覆盖输入输出与状态迁移，不以源码静态存在代替运行时有效性证明。
- release 构建已通过真实 release 构建设备运行验收（DI / 解锁 / 保存 / 原生 Argon2 / BC 探活 / retrace）；诊断栈可定位性依赖 `SourceFile`/`LineNumberTable` 与 retrace，R8 对被改写或内联的方法可能不再输出行号，此时只能还原到「类.方法」，不得为补行号关闭优化或整类保留。
- 进程级未捕获异常处理器只覆盖 Java/Kotlin 异常（主线程、Binder 线程、协程根）；native 崩溃（SIGSEGV、Rust abort）不经该路径，归档里只会留下崩溃前的普通行与新进程头，仍需 `adb logcat` 或 tombstone 定性。用户关闭诊断日志时崩溃行同样不写入。
