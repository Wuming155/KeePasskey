# 产品与设计约定

只记录仍有效、不能仅从代码推知的取舍。具体参数和行为以代码及测试为准；未解决缺陷见 [当前问题](../ACTIVE_ISSUES.md)。历史论证可查 Git 历史。调整下列边界时，同步修改实现、相关测试和本文。

## 格式与密码学

- 仅支持 KDBX 4.x；旧库先用其他客户端升级。复合凭据支持主密码与密钥文件，暂不支持硬件 challenge-response。
- 新库沿用固定 KDF 默认配置，不自动采用设备性能测量结果。读取既有库保留其工作因子；修改默认强度须评估兼容性及低端设备成本。
- 原生密码学实现集中在 Rust 内核，保留 JVM 回退路径及等价性测试，不另引入 Botan、OpenSSL 等密码学栈。RS256 继续使用 BouncyCastle。
- 原生 CBC 流与 JCA 回退流并存，错误、边界及擦除语义须对拍。采用 Rust 的理由包含维护一致性，不能笼统宣称它在所有算法与设备上更快。
- 主口令长度不足 8 时拒绝，估算强度不足 40 bits 时要求确认；估算不可用时不冒充弱口令结论。主口令不纳入条目健康检查和在线泄露查询。
- 保留自研强度估算器，JVM 回退对应 Rust 模型；更换估算器须重新标定门槛。OTP 每次初始化 MAC，避免缓存长期持有种子。
- HMAC 块流层只拒绝负块长；通用分配、格式长度与附件预算仍生效。不能据此放宽其它解析上限。

## 保存、同步与恢复

- 应用管理的本地文件使用原子替换；事务写入是完整性要求，没有关闭开关。新建库使用排他创建，不覆盖同名文件；SAF 差异见 [工程边界](已知工程限界.md)。
- 保存时重建树和复制内存附件用于隔离别名，不能为减少分配破坏“清除附件不影响池”的所有权保证。
- 同步基线与工作缓存承担不同职责，允许各保留一份；不缓存跨周期的整棵解密树。离线缓存是引擎内置行为。
- 同步端点仅 HTTPS、仅信任系统 CA；用户明确配置的自建内网端点可用。重定向与 DNS 重绑定到非预期内网地址仍受连接期守卫约束，云元数据地址不豁免。
- 内容变化比较忽略纯访问计数与访问时间，覆盖有效期、历史内容、Meta 和语义头参数；三方合并的修改判定可包含修改时间。两者不要求机械一致。
- 标准凭据字段按内容比较，忽略保护存储标志差异；自定义字段保留保护语义。条目与分组 customData 保留第三方键并参与合并；有效签名计数合并取较大值。
- 漂移合并以最后确认持久化的版本为共同基线。缺失可信基线时采用保守并集，不推断删除；同字段双侧异值需用户裁决。
- 用户裁决绑定所提示的库与版本；只覆盖差异字段，保留其它已合并改动。“双方保留”的分组副本复制整棵子树并重生成身份、重映射内部引用。采纳与持久化必须形成同一提交边界。
- Meta 参与三方合并，身份与加密配置仍取本地；具体字段分类由 `KdbxMetaMerge` 维护。Meta 的“双方保留”不表示生成第二份配置，冲突按字段选择。
- 加密崩溃草稿沿用库复合凭据，恢复前重新验证凭据并预览差异，由用户选择恢复或另存，不自动覆盖正式库。
- 密钥文件 URI、记忆和副本按库隔离，缺失时不跨库兜底。密钥文件完整读取，不截断或采样派生。
- 应用私有库移除会删除文件；外部库移除只删除登记。保留副本使用同目录的加密 KDBX 副本，名称冲突递增编号；副本落地成功后才执行相应覆盖或删除。

## 自动填充与通行密钥

- 产品不依赖 Chrome 或 GMS。浏览器密码填充按实际 Autofill 调用路径验收；Credential Manager 和浏览器专有行为单独核实，不把单个浏览器结果外推到所有浏览器。
- 通道开关控制候选、交付和保存，不保证应用从系统服务列表消失；通行密钥开关仅约束公钥请求。
- 内置信任仅覆盖已核实浏览器，其它浏览器由用户逐项授权。拒绝页可就地加入浏览器信任，授权后由调用方重新请求，不能中途放宽本次请求。
- 自动填充同一结构出现不同非空 webDomain 时整结构拒绝。过期与回收站条目不进入填充候选。
- 明确 RP ID 必须与通行密钥 RP ID 归一化后精确相等；父子域规则仅用于 origin 对 RP 的授权。候选检索与最终签发分别校验，列出候选不等于已授权签发。
- 无匹配时的新建动作仅用于密码请求，并要求可写会话与入口开启；通行密钥必须由站点注册或导入产生。新建动作不静默更新旧条目。
- “记住应用关联”须询问用户，仅对空 URL 的纯 App 条目写入 `android://<包名>`；包名或系统签名不可读、只读会话、浏览器表单均不写回。本地关联记忆仍按包名、签名和域隔离。
- 注册侧“跳过站点归属校验”默认关闭，仅作用于该注册校验，不关闭 Autofill 域归属检查。
- 通行密钥采用 KeePass 生态 KPEX 字段与 PKCS#8 PEM 私钥；旧 `Passkey.*` 只读兼容，需写计数时迁移该条目。新增字段方案须独立实现互操作验证。
- 二维码与相册导入支持 CXF 和 KeePassXC 单凭据载荷；导入第一把有效凭据并提示其余未导入数量。仪式字段严格验证，缺少展示字段可补齐并告知来源未提供。
- PRF 保真保存 withUV 与可选 withoutUV，不伪造缺失值、不截断异常长度。导入计数以随机高位起始，其克隆检测限制见工程边界。
- 私钥与凭据标识不可在普通自定义字段编辑器中修改；用户名与显示名可编辑。解除通行密钥须确认；导入即时保存，提示必须明确。
- 结构化卡片取值兼容 Android hint、既有中文模板键与英文回退名，hint 优先，避免破坏存量条目。
- 真实 RP 验证不绑定单一站点；PRF 可优先使用 [Corbado 演示站](https://webauthn-passkeys-prf-demo.explore.corbado.com/)，站点不可用时使用适合的替代并注明范围。

## 安全与界面

- 不运行 root、调试器或注入痕迹门控，不承诺防御已控制应用进程的攻击者；不增加本地节流、防回滚或字段屏蔽文件的 MAC 层。
- 大附件允许明文暂存应用私有目录；显式明文导出需确认。普通窗口遵循防截屏设置，建库、改主密钥、子库凭据、附件预览和修订差异对话框始终保护；扫码窗口与导入确认跟随设置。
- 展示与检索读取已擦除字段时允许降级；写盘和凭据交付不能用空值掩盖读取失败。不采用“先查 cleared、再读取”的两步竞态判断。
- 冷启动发现剪贴板待清标记时保守清空，可能误清其它应用的新内容；不持久化口令摘要。运行期间仍按摘要与覆盖状态判断。
- 常驻通知只提供锁定、复制用户名和 TOTP，不承载密码、受保护字段、种子或库名；复制对象仅为进程内最近查看条目，锁库或关库时撤销。
- 解锁失败节流默认关闭，可由用户开启。生成器不读取库内容，锁库时仍可用；已有敏感状态按生命周期清理。
- 动态取色与调色盘互斥；界面适配系统字号，不另设缩放偏好。动效与降级行为由统一主题和导航配置维护。
- 手机优先，暂不做宽屏双栏、列表滑动快捷操作、外部图标包、PIN 包装解锁、自定义输入法或第三方插件宿主；不增加多态条目 schema。AutoType 仅兼容保存，不执行。
- 设置主页保持分组与二级页结构，不加搜索框；云同步设置维持单页。库内检索通过搜索和高级搜索，不恢复常驻标签或收藏筛选行。

## 工程维护

- 测试和文档的准入、更新与退役统一遵守 [工程规则](../../.codebuddy/rules/engineering-rules.md)，本文不重复维护流程。
- 依赖使用明确版本及受控来源；当前未引入 Gradle 依赖完整性元数据与全量锁文件。供应链扫描覆盖生产配置，AGP 内部工具配置单独处理，不据此豁免生产依赖。
- CI 保持定时与手动触发；目前没有必需状态检查或分支保护。结果提供检测信号，不构成合并前阻断；若调整触发频率或保护策略，应直接修改配置并说明理由。
