## 1. 结论与授权边界

没有合适的真实服务后，采用**专用模拟器 + 本机 HTTPS WebDAV + 临时测试 CA + 合成密码库**，完成实际应用上传、下载和重新解锁验证。没有关闭应用 TLS/主机名校验，没有向真实账户写入资源。

第一阶段 18 项产品问题仍全部开放；本阶段新增 4 项 Low 验证工具/测试前提缺陷。两阶段合计 **22 项：Critical 0、High 8、Medium 9、Low 5**。普通同步成功不能反证第一阶段的并发、失败持久化和取消问题。

- 用户授权安装、HTTPS WebDAV、子代理；手机断连后指定改模拟器。
- Redmi 4X / API 37 在隔离安装期间 ADB 断连，未取得成功安装回执。本轮不能宣称 ARM 真机、StrongBox 或手机 LAN 到达验证通过。
- 用户提供的真实服务通过系统 CA/主机名校验，凭据及匿名探测返回 401，OPTIONS 的 DAV 能力响应不代表认证成功。未修改远端资源，不登记为应用缺陷；本地暂存真实凭据文件已删除，Git/报告没有凭据。
- 旧 `Pixel_10` 处于用户加密锁屏，runner 报非 encryption-aware，未形成有效用例后中止；恢复 GMT 并停止，不重置旧 AVD 或清除既有用户包数据。

## 2. 架构与安全模型的动态补证

完整架构、安全模型和十八面覆盖见 [第一阶段 §2–§5](全面软件审计_2026-10-13.md)。依赖为 app→database→crypto→core，app→sync→core，app 直接使用 crypto；库会话、UI 仓库与同步基线属于不同的状态/锁域。本阶段补充 Android 系统回调、实际网络配置和已提交磁盘证据。

生产网络只信任系统 CA。宿主 LIVE 用例使用固定测试证书与 localhost 专用验证器，其通过不能证明生产 TLS 通过，因此另外运行真实应用 HTTPS 路径。新 AVD 的 root 仅用于加入测试信任根及读取合成库，不证明抵抗 root 或硬件 Keystore 等级。

CA 只加入新 AVD 的 Conscrypt 临时挂载命名空间，保留原信任根；app 冷启动继承。没有改 Manifest、网络配置、应用 TLS 或旧设备信任库。CA SHA-256：`f2c9907702ec19670f0bab895aba953d35d996a320ccd96d18bc819e158f0c14`；叶证书有 10.0.2.2 / 127.0.0.1 / localhost SAN。结束重启撤销挂载，并核对系统信任目录没有测试 CA。

## 3. 实测结果

### 3.1 实际应用 HTTPS 与独立 KDBX 互操作

AVD 使用 `https://10.0.2.2:19446/`，随机本地测试账户。此前 LAN `192.168.1.14:19443` 完成宿主协议探测，但没有手机到达证据；实际 app 走模拟器宿主映射，不外推 Wi-Fi 网络测试。

| 步骤 | 实际结果 | 边界 |
|---|---|---|
| 不信任测试 CA，保存并同步 | “连接测试未通过，已跳过同步”，远端为空 | 符合拒绝行为；未取到 SSL 栈，证书原因由仅改变 CA 后成功的对照支持 |
| 临时信任 CA，冷启动同一配置 | 解锁上传空库；新增合成条目后上传成功、状态已同步 | 生产网络栈，未放宽校验 |
| pykeepass 打开 app 创建库与云端库 | KDBX4，标题、用户名、密码逐项匹配 | 重序列化使密文 SHA 不同，以内容核对 |
| 服务端 pykeepass 新增条目 | 源 SHA 校验后原子替换；HTTPS GET/独立回读为两条，原条目保留 | 仅合成库，加密备份留存 |
| 实际 app 解锁后下载 | 同时展示 HTTPS-Audit-Entry / HTTPS-Remote-Entry | 不只是协议 PUT/GET 探测 |
| 导出下载后的本地库并独立打开 | KDBX4、1379 字节，两条 UUID 与凭据匹配 | URL/备注/时间/分组/AutoType 等本例字段也匹配；历史/附件为空，不能证明非空资产合并 |
| 强停 app 再启动 | 自动锁定、保留 passwords.kdbx 选择，重输主密码后两条仍在 | 仅证明已提交数据恢复，不代替断电或挂起事务测试 |

### DYN-01：装机读数未归一时区

- **位置**：tools/device/check_installed_build.py:49,119,133–142。
- **描述/触发**：设备 GMT、宿主 Asia/Shanghai；本地 APK 10:59:35、实际更晚安装的设备 UTC 03:10:45，naive datetime 直接比较。
- **后果**：新包被误判旧包；相反方向可能错误放行（该方向未运行复现），影响验证可信度。
- **建议**：绝对时间/时区归一、跨区正反例，独立哈希身份核对。
- **证据/可信度**：仅改设备区后变为 11:10:45，时间与符号通过，未改系统时间/APK mtime；高。

### DYN-02：AutoFill 中文硬编码定位

- **位置**：AutofillAuthChainDeviceTest.kt:175,181,690–699；DeviceAutofillProbe.kt:139；生产资源使用处 AutofillDatasetBuilders.kt:98–100。
- **描述/触发**：英文设备展示正确英文引导，测试按中文 contains，未建立语言前提。
- **后果**：误报未下发，首轮后半认证链未执行。
- **建议**：资源身份/本地化定位，或建立并恢复语言前置；中英实跑。
- **证据/可信度**：同轮英文窗口、服务日志与中文对照；高。未确认生产本地化缺陷。

### DYN-03：客户端未结束，重跑不请求

- **位置**：AutofillClientActivity.java:76,145–153；AutofillAuthChainDeviceTest.kt:101–118,476–478。
- **描述/触发**：收尾不结束独立客户端；NEW_TASK 复用原 Activity，requestedOnce 已 true。
- **后果**：重跑超时假红，依赖执行历史。

- **证据/可信度**：11:34 LAUNCH_SINGLE_TOP、原进程无新 request；冷停后请求/引导恢复；高。
