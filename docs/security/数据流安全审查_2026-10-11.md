# KeePasskey 数据流安全审查报告

审查基准：git 提交 cd22370104bc3716e76174e3c5b4165e3f18caa1（main 分支）。

威胁模型：攻击者可读全部源码；可在设备上安装普通恶意应用（无 root、无签名密钥）；完全控制网络与云同步服务端；可提交恶意 PR。root 场景明确不在防护范围。密码学原语本身视为不可破，本次审查只追「绕过密码学保护」的数据流。

方法：9 个攻击面并行审查（每面一名审计员，逐跳追踪数据流）→ 每条发现由独立复核员换人读码核实 → 独立汇总评审员去重定稿。

## 执行摘要

最危险的两条均在供应链/CI 检测面且共享『恶意 PR 被人工合并』这一唯一前置（main 无分支保护，PD-04 登记）：发布签名口令与 keystore 文件可经被篡改的 tools/signing/read-cred.ps1 在维护者本机构建时静默外传（medium，伪造官方更新通道的前提被打开），CI 全部门禁判定本体无完整性护栏、单行削弱判据后持续假绿（medium）。其余 12 条均为 low——威胁模型内没有任何可直达成『凭据明文到达攻击者』的路径，最值得先修的是任意无权限应用可经 OpenVaultEntryActivity 以 file:// URI 登记任意路径并覆写活动库指针（F14，唯一普通恶意 App 零前置可达的发现）。总体态势：密码学完整性链（头部/块 HMAC、防回滚）、调用方归属判定、TLS/SSRF 防线、导入解析加固等主干经逐跳复核稳固；输入 8 个攻击面共 14 条发现全部经独立复核成立（11 confirmed + 3 adjusted，无 rejected），其中 2 处复核结论推翻了 safeNote 的表述（OpenVaultEntryActivity『仅接受 content/file scheme』与 runImport 清零『全量』），已在相应 notes 指出；剩余缺口集中在敏感数据清零合规、纵深防御一致性（落盘权限/通道闸门不对齐）与登记漂移。
