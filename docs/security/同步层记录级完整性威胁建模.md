# 同步层记录级完整性威胁建模

本文界定云端攻击者能否通过密文置换破坏 KDBX 数据完整性，以及当前防回滚机制未覆盖的剩余风险。它记录威胁边界和设计取舍；实现细节以代码与测试为准。

## 范围与信任边界

- 用户库包含凭据、附件、历史记录和通行密钥材料，是保护对象。
- 云端 WebDAV / S3 服务视为不可信：攻击者可以读取、替换、重放或删除远端密文，但不掌握用户主密钥或其派生密钥。
- 本地已控制进程、读取进程内存或绕过 Android 系统隔离的攻击者不在本模型内。

## 完整性边界

KDBX 是单体加密文件，条目不是独立加密记录。头部认证和带位置绑定的块完整性保护可以发现对文件内容、块顺序或块位置的未授权修改。云端攻击者没有密钥，不能把任意条目或块改造成仍可通过验证的内容。

同步防回滚依赖设备本地状态；状态缺失时的放行与有限历史窗口见[工程边界](../architecture/已知工程限界.md#同步与网络)。该状态不是远端提供的可信时间或版本证明。

## 攻击分析

### 文件内部置换

攻击者不能单独重排条目、交换加密块或修改块内容并让认证继续通过。KDBX 的单体结构和位置绑定完整性校验使 mdbx 一类“独立 AEAD 记录之间搬移密文”的前提不成立。

### 跨路径的合法文件替换

云端仍可把同一用户已有的合法密文从路径 A 返回给路径 B；攻击成立还要求 B 当前使用的凭据能够验证该文件，例如两个路径指向同一数据库副本或使用兼容凭据。此时文件可通过密码学验证；若 B 的本地防回滚状态从未见过该摘要，系统无法仅凭文件内容证明它原属另一条远端路径。

这可能造成用户看到或继续编辑另一份自己的数据库，属于路径混淆和误覆盖风险；它不能伪造数据库内容或取得明文。风险成立需要云端控制路径映射，且用户在打开后未察觉内容异常仍继续写入。

## 当前取舍与重评条件

不增加 KDBX 记录级承诺，也不把远端路径绑定进防回滚摘要：前者会改变 KDBX 字节格式并破坏互操作；后者会拒绝用户有意在多个路径保存同一数据库的合法场景。现有本地摘要链用于阻止同一路径已知历史版本的重放，不声称能识别所有跨路径替换。

若数据模型改为独立记录 / 独立 AEAD，或产品不再允许同一数据库出现在多个远端路径，应重新评估记录上下文承诺和路径绑定。重评时须同时考虑格式互操作、迁移和误报影响。
