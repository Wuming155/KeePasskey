## 2. 取证方法与已踩过的坑（务必沿用）

1. **UI 取证**：`adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml build\ui.xml`，
   再 `python build/uidump.py build/ui.xml`。**不要用 `screencap`**——本机 gfxstream 下截图全黑。
2. **文本输入**：每个字段输入后必须 `adb shell input keyevent 4` 收起键盘，否则下一次点击落在 IME 上；
   清空已有内容用 `input keycombination 113 29`（Ctrl+A）后直接覆写。
   **库列表顶部搜索框无法 adb 注入**（P3-60 待复核），人工测试时请手动敲键盘验证。
3. **开关切换**：Compose Switch 点击后**必须重新 dump 校验 `checked` 状态**（曾出现点击未生效的假象）。
4. **取库地面真值**：`adb shell run-as com.keepasskey toybox base64 files/passwords.kdbx` →
   本地 base64 解码 → `python build/vd.py <file>` 看外层头（或 `python tools/kdbx-corpus/generate_corpus.py --verify`，
   注意：本 App 产物会因 ISSUE-P1-13 的 `P` 类型错误而**解析失败**，这本身就是复现手段）。
5. **崩溃监控**：每个操作后 `adb shell logcat -d -v brief | Select-String "FATAL"`。

## 3. 未实测功能清单（按优先级）

### 3.1 附件导出 0 字节复核（对应 ISSUE-P2-20，最优先）
1. 先把「设置 → 设备解锁与安全策略」的**后台/熄屏自动锁定全关**（排除 P1-14 干扰变量）；
2. 重做附件导出全流程（方法见 P2-20 条目）；
3. `adb shell ls -l /sdcard/Download/` 看产物大小；非 0 则 `adb pull` 后与源文件比对 md5；
4. 若仍 0 字节 → 升级为确认缺陷，排查 `EntryDetailAttachmentExporter` 的 SAF 写回流（是否漏 flush/close）。

### 3.2 后台自动锁定重测（对应 ISSUE-P1-14）
- 已知矛盾证据：HOME 回前台不锁，但 SAF（DocumentsUI）占前台后返回**会锁**。
- 重测：开启立即档 → `adb shell input keyevent 3` → 立即
  `adb shell dumpsys activity processes | Select-String "keepasskey"` 看进程 lifecycle/`ProcState`，
  确认 HOME 是否真使进程进入后台态；再对照 `am start` 回前台后的锁定情况。
- 顺带测：熄屏锁定（`adb shell input keyevent 26` 熄屏 → 亮屏看是否已锁）、返回键锁定开关。

### 3.3 导入密码库（4 个导入器 UI 入口）
- 入口：设置 → 密码库与加密 → 导入与导出 → **导入密码库**。
- 逐个测：KeePass XML / Bitwarden JSON / 浏览器 CSV / 1Password PUX。
- 素材可用仓内既有测试资源；CSV 需自备样例。关注：解析失败提示、导入报告对话框、
  条目实际落库（列表可见、密码明文正确）。

### 3.4 导出密码库 / 导出密钥文件
- 入口同上「导出密码库」（KDBX / XML 两种格式）与「导出密钥文件」。
- 导出后拉回产物验证：KDBX 产物用 `generate_corpus.py --verify`（预期因 P1-13 失败，记录即可）；
  XML 产物检查 XML 结构与条目数。
- 注意 `VaultExportCoordinator` 会跳过「模板」分组，产物条目数应 = 全部条目 − 模板分组内条目。

### 3.5 子密码库挂载
- 入口：设置 → 密码库与加密 → **子密码库挂载**（当前显示「未挂载子密码库」）。
- 准备第二个 .kdbx（可用官方语料 `database/src/androidTest/assets/argon2-interop/argon2d-v19-t89-m64-p4-keepassxc.kdbx`，
  push 到 /sdcard/Download 后经 SAF 挂载；其口令/密钥见该目录伴生 JSON）。
- 关注：挂载后列表子库分区、子库条目只读、搜索态「子库条目不参与搜索」提示、卸载。

### 3.6 设置页其余小项
- **TAN 序列号** / **数据库 UUID** 开关（完整性校验区）——打开后的列表行为；
- **条目模板**：安装后从「新建 → 从模板新建」走一遍模板创建（P3-63 只测了安装）；
- Argon2 参数/加密算法/KDF 三个「修改」对话框：只打开校验回显（**不要保存**，避免污染 P1-13 证据）；
  回显值本身即 P2-19 的证据之一。

### 3.7 自动填充 / Passkey / 通知（依赖系统交互，难度最高）
- 自动填充：需把本 App 设为系统自动填充服务 + Credential Manager 提供者，再装一个含登录表单的
  App（或 Chrome 打开测试页）触发填充；关注下发前二次确认、30 秒免重复确认。
- Passkey：需要支持 WebAuthn 的依赖方；最低限度先测「编辑页 → 为此网站创建 Passkey」入口的报错路径。
- 通知：解锁后的常驻通知、TOTP 通知（对应 `notification/` 包）——验证渠道创建与点击行为。
