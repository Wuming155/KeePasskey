## 2. 取证方法与已踩过的坑（务必沿用，第二批新增 ①②③④）

1. **UI 取证**：`adb shell uiautomator dump //sdcard/ui.xml && adb pull //sdcard/ui.xml build/ui.xml`，
   再 `python build/uidump.py build/ui.xml`（Git Bash 下路径须写 `//sdcard/...` 防 MSYS 转义）。
   **不要用 `screencap`**——本机 gfxstream 下截图全黑。
2. **开关状态判定（第二批新教训，最关键）**：`uiautomator` 的 `checked` 属性**可能陈旧/失真**——
   实测 Compose Switch 真实渲染为 on 时 dump 报 false。地面真值一律读存储字节：
   `adb shell "run-as com.keepasskey cat files/datastore/keepasskey_settings.preferences_pb"`（protobuf，
   键名后跟 `12 02 08 00/01`）与 `shared_prefs/keepasskey_extended_settings.xml`（文本）。
   P1-14 的整场误报即由此而来（详见 RESOLVED_LOG §27.2）。
3. **开关注入点击**：部分 Compose Switch 对 `input tap` 不响应，用
   `adb shell input motionevent DOWN <x> <y>` + `input motionevent UP <x> <y>` 必中。
   P3-60 的「搜索框注入不落字」与此同族（见 RESOLVED_LOG §27.8）。
4. **对话框吞点击**：「自动锁定倒计时」等对话框打开期间会吃掉后续所有注入点击（且 uiautomator
   dump 偶发只回上一层 UI），长流程**每一步先 dump 定位再点击**，点完立即 dump 校验。
5. **二进制传输**：`adb shell cat` 直出会因 CRLF 转换损坏 KDBX（本批次实测 +1 字节即不可解锁），
   必须走 `toybox base64` 编解码。
6. **文本输入**：每个字段输入后 `adb shell input keyevent 4` 收起键盘；含 `*` 等特殊字符的口令在
   设备侧要单引号包裹：`adb shell "input text 'xxx/*xxx'"`，否则被设备 shell 通配符展开。
7. **取库地面真值**：`adb shell run-as com.keepasskey toybox base64 files/passwords.kdbx` →
   本地解码 → `python build/vd.py <file>`；P1-13 修复后本 App 产物已可通过
   `python tools/kdbx-corpus/generate_corpus.py --verify`。
8. **崩溃监控**：每个操作后 `adb shell logcat -d -v brief | grep FATAL`。

## 3. §3 未实测清单——第二批实测结果（全部跑完，详情见 RESOLVED_LOG §27）

### 3.1 附件导出 0 字节复核（P2-20）✅ 已闭环
关闭自动锁定后完整走通：SAF 另存 → 「确认导出明文附件」→ 产物 **md5 与源文件一致**。
0 字节系「SAF 保存即建空文件 + 确认前被自动锁定熔断」的遗留；已系统化整改
（`SafDocumentCleanup`，覆盖导出失败/取消 4 路径），实测取消后无残留。

### 3.2 后台自动锁定重测（P1-14）✅ 行为符合设计，结案
立即档：HOME 返回已锁 ✅、SAF 返回已锁 ✅；30 秒档：5s 不锁 ✅、35s 锁 ✅；熄屏锁 ✅。
上会话误报根因 = 偏好写入被对话框吞掉 + `checked` 假象（见 §2.②）。
**新发现并整改**：返回键锁定是死设置 → ISSUE-P2-21（已接线修复并实测）。

### 3.3 导入密码库 ✅ 四导入器全过（修复 P1-15 后）
Bitwarden JSON（新增 2 条）、浏览器 CSV（1 条）、1Password 1PUX（1 条）原生通过；
**KeePass XML 设备侧 100% 失败 → 新发现 ISSUE-P1-15**（Harmony SAX 延迟拒绝加固特性），
整改后 1 条/2 条样本（含中文、分组、TOTP）均成功。注意：语料类 .kdbx 需要 `111.keyx` 配套密钥文件。

### 3.4 导出密码库 / 导出密钥文件 ✅
KDBX 完整副本导出后 `generate_corpus.py --verify` **通过**（P1-13 修复证据）；
明文 XML 导出结构合法（6 条目、3 分组，含「模板」分组——`VaultExportCoordinator`
**两种导出均不跳过模板分组**，原交接文档该表述更正）；密钥文件导出在未绑定密钥时如实报错
（修复前曾静默留 0 字节文件，已随 P2-20 清理）。

### 3.5 子密码库挂载 ✅
KeePassXC 语料库（argon2d-v19-t89-m64-p4）+ `111.keyx` 挂载成功、独立凭据解锁 **14 条条目**；
库列表出现只读子库分区，条目标注「只读子库条目，无编辑或复制入口」；卸载入口正常（仅解除关联）。

### 3.6 设置页其余小项 ✅（一项转 ISSUE-P3-65）
Argon2 / KDF 对话框回显**真实文件头值**（2 轮 / 64 MB / P=2）；TAN 序列号、数据库 UUID 开关
**可拨动但无持久化、无消费方** → 新登记 **ISSUE-P3-65**；模板安装后列表不即时刷新升级为
**ISSUE-P3-63**（导入亦触发，见下）。

### 3.7 自动填充 / Passkey / 通知 ⚠️ 部分实测（转 ISSUE-P3-66）
设置页如实反映「系统未选择本应用为自动填充服务」；常驻通知（`keepasskey_unlocked_status`，ONGOING）
确认存在。**端到端填充 / Passkey 创建断言未实测**（需系统服务接管 + 登录表单测试页），登记为
ISSUE-P3-66，待专项批次。
