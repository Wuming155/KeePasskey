## 2. Kp2a：关联记忆＝「Remember search text?」写回条目 URL

### 2.1 关联的载体

条目 URL 上的**伪 schema** `androidapp://<包名>`：

- `KeePass.cs:89` — `public const string AndroidAppScheme = "androidapp://";`
- `Utils/Util.cs:336-338` — 识别该前缀后剥离出包名（用于「打开应用」等消费点）。

### 2.2 询问点就在自动填充流里（关键）

- 自动填充的选择器走的任务类**就是** `SearchUrlTask`：
  `services/Kp2aAutofill/ChooseForAutofillActivity.cs:83` — `var task = new SearchUrlTask() { ... }`。
- `SearchUrlTask` 重写了 `CompleteOnCreateEntryActivity`：
  `app/AppTask.cs:494-538` — 用户打开所选条目后弹出询问，确认即 `activity.AddUrlToEntry(url, ...)`
  把**搜索词**写进该条目 URL。
- 文案（`Resources/values/strings.xml:368-369`）：
  - 标题 `Remember search text?`
  - 正文 `Would you like to store the search text "%1$s" in the selected entry in order to find it automatically next time?`
  ⇒ 语义与用户诉求逐字对应：「弹出提示是否记住这个，下次直接出现」。
- 纯 App 场景被搜索的词即伪 schema（`services/AutofillBase/AutofillServiceBase.cs:235`
  `AddQueryDataset(query.PackageNameWithPseudoSchema, ...)`）⇒ 写回的正是 `androidapp://<包名>`。

### 2.3 三个前置否决（同处 `AppTask.cs:499-503`）

`库只读（CanWrite == false）` / `搜索词为空` / `该条目已能被搜索词命中` ⇒ **不询问**。

## 3. Monica：三条并行机制 + 数字类字段的专门兜底

### 3.1 关联侧（问题 A）

**(1) 互动记忆**（按 identifier 记下"上次填的是哪条"）

**(3) URI / 应用绑定写回条目**：`AutofillPickerActivityV2.kt:1528+` `saveUriBinding(password)` →

**(4) 纯 App 的准入档**：`BitwardenLikeAutofillMatcherNg.kt:203-262` ——
`EXACT_PACKAGE 120` / **`EXACT_APP_TITLE 95`** / **`PACKAGE_TOKEN_TITLE 70`**，

⇒ Monica 让「调用方应用名 == 条目标题 / 应用名」或「包名 token 出现在条目标题里」**直接入选**（不是仅排序）。

### 3.2 字段识别侧（问题 B，含点名 QQ 的注释）

- 数字类 ⇒ 账号候选：`EnhancedAutofillStructureParserV2.kt:1702-1745` ——
  `TYPE_CLASS_NUMBER` + `TYPE_NUMBER_VARIATION_NORMAL` 产出 `InternalHint.USERNAME`，
  精度取 `AutofillDetectionPolicy.genericNumberFallbackAccuracy()`＝`Accuracy.LOW`（`AutofillDetectionPolicy.kt:74`）。
- 保留门槛：`AutofillDetectionPolicy.kt:96-102` `shouldKeepTarget` ——
  账号类「精度 ≥ MEDIUM **或** 表单存在密码目标 ⇒ 保留」⇒ 低精度数字账号框**在有密码框时保留**（正是 QQ 形态）。
- 可见性口径：`:104-115` `shouldIncludeHiddenCredential` —— 密码类 ≥ `LOWEST` 也纳入（不可见也收），
  账号类仍须 ≥ `MEDIUM` ⇒ 数字兜底**不会**让隐藏账号框被误收。
- 词表另有「<名称>号」枚举：`:10-17` `explicitAccountTerms` 含「工号 / 学号 / 职工号 / 员工编号 /
  student id / employee id」。
- **注释点名 QQ**（兜底带登录上下文门，不是无条件放宽）：
  `EnhancedAutofillStructureParserV2.kt:1648`（防止「搜索框/备注等纯文本框误判为登录账号（QQ 搜索框误弹修复）」）、
  `:1857`（「无 password 术语的（如 QQ 搜索框）不受影响」）。
- 上游出处：Monica 自述对齐 **Bitwarden**（`updateForMissingPasswordFields`、「有 Login 字段就 Fillable」门槛）。
