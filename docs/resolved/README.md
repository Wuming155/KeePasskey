## 为什么这样拆

- 原先的整册文件达数百 KB / 上千行，难以逐条引用与审阅；拆为**一批次一文件**后每份自成一体。
- **索引只做引用、不复制正文**，避免同一结论在两处漂移。
- 例外：单批次本身即长篇（如 §42 234 行、§43 195 行、§49 190 行、§27 181 行），
  **保持整节完整**而不按小节切碎——批次叙事被切断会降低可读性。

## 维护规则

1. **新增批次**：在 [`../RESOLVED_LOG.md`](../RESOLVED_LOG.md) 索引末尾加一行，并在 `batches/` 新增
   `<NN>-<中文短名>.md`（编号零填充两位，便于排序）。
2. **编号不复用**：§ 编号全局递增；当前最大为 **§67**，下一批次从 **§68** 起。
   > **注**：`AGENTS.md` §1 / §6 与 `ACTIVE_ISSUES.md` 已引用 §68（ISSUE-P3-116 闭环），
   > 但该批次正文**尚未落入本目录** —— 已登记为 **`ISSUE-P3-129`**。
3. **只搬迁、不改写**：确需更正时**新增更正节**并保留原文（如实留痕）。
4. **回溯**：拆分前的完整单文件版本见 git **`a144d21`**：
   `git show a144d21:docs/RESOLVED_LOG.md`（含当时的三册全文）。

## 引用约定

仓内其它文档写「`RESOLVED_LOG.md` §NN」时，按总索引的「正文」列跳到 `batches/` 下的对应文件；
跨文件定位用批次文件内的 `<a id="sNN"></a>` 锚点。
