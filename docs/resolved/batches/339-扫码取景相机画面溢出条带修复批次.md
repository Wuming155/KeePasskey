## 339.0 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪切）

> ### ISSUE-P3-333 TOTP 扫码对话框卡片上缘漏出相机画面条带（用户直报）
>
> - **优先级**：P3（视觉缺陷；取景与解码功能正常，无功能与安全影响）
> - **背景**：扫码取景对话框（`TotpScanDialog`）打开后，卡片上边缘之外（对话框窗口上边距内）露出一条
>   与取景框同宽、约 12px 高的**相机画面条带**——用户场景暗时呈「小黑线」、场景亮时呈灰白条，
>   观感为「取景框之外还有一条能看到镜头对象的横线」。条带位于预览区之外，不影响解码。
> - **核实时间点**：2026-09-26
> - **核实方式**：用户真机直报并附照片与截图；同日 `dumpsys SurfaceFlinger` 实测——相机 SurfaceView 图层
>   显示区 `x[104..1176] y[681..2111]`（1072×1430），`PreviewView` 视图区 `y[857..1933]`（1072×1076），
>   上下各溢出约 177px；对上 camera-view 1.6.2 官方源码 `SurfaceViewImplementation.initializePreview`
>   （内部 `SurfaceView` 按 `LayoutParams(相机分辨率)` 布局 1200×1600）与 `PreviewTransformation.transformView`
>   （FILL_CENTER 视图矩阵 `scale = max(1072/1200, 1076/1600) = 0.893`、放大后居中 ⇒ 上溢 `(1600×0.893−1076)/2 ≈ 177px`）
>   ——源码推导与 SF 读数逐位吻合。**根因**：SurfaceView 的独立 Surface 图层不受视图层级 `clipChildren` 裁剪，
>   不透明窗口下溢出被窗口内容遮住不可见；Compose 对话框窗口在卡片之外是**透明**的，上溢便从卡片上缘漏出。
> - **涉及文件**：`app/src/main/java/com/keepasskey/app/ui/screens/edit/TotpScanDialog.kt`
> - **验收标准（AC）**：
>   1. `PreviewView` 强制 `implementationMode = COMPATIBLE`（TextureView）：渲染落回视图层级、受父级裁剪，
>      卡片外不再漏出相机画面；取景与解码链路（`ImageAnalysis` + zxing）不随实现模式变化；
>   2. 真机复验：`dumpsys SurfaceFlinger` 中不再存在该 `SurfaceView` 图层（TextureView 不产生独立 Surface 层），
>      对话框取景正常、扫码功能不变；
>   3. 全量 `test` 全绿 + `gate_readings.py` 7/7 PASS；批次归档（`RESOLVED_LOG` 索引 + 批次正文）。

## 1. 取证与根因（判定链）

1. **现象对拍**：用户 10:57 物理照片与 11:38 系统截图（原图自设备 `DCIM` 拉回）显示：卡片上缘外侧
   （对话框窗口上边距内）有一条与取景框**同宽**、约 12px 高的条带——条带内容即相机画面
   （用户场景暗 ⇒ 近黑「小黑线」；代理复现时桌面场景亮 ⇒ 灰白条，与白卡相融一度被误判为「无异常」，
   经与用户截图逐行对拍后确认**两张截图同位同宽**，条带为常驻而非瞬态）。
2. **SurfaceFlinger 实测**（修复前，真机 `dumpsys SurfaceFlinger`）：
   - 相机 SurfaceView 图层 `x[104..1176] y[681..2111]`（1072×**1430**）；
   - PreviewView 视图区 `y[857..1933]`（1072×**1076**，宽度相同）；
   - ⇒ Surface 上溢 857−681 ≈ **176px**、下溢 2111−1933 = 178px；上溢被卡片（自 693 起）盖住 164px、
     在窗口上边距（641~693）内露出 **12px** ⇒ 恰为截图量得的 `y681..692` 条带；下溢落在卡片下部被完全遮住
     ⇒ 只见上边一条、与用户观感一致。
3. **官方源码对拍**（`androidx.camera:camera-view:1.6.2` sources，Google Maven 官方构件）：
   - `SurfaceViewImplementation.initializePreview()`：内部 SurfaceView 按
     `LayoutParams(mResolution)` 布局 ⇒ 1200×1600（与 SF `geomBufferSize=[0 0 1200 1600]` 逐位吻合）；
   - `PreviewTransformation.transformView()` 对其施加 FILL_CENTER 视图矩阵：
     `scale = max(1072/1200, 1076/1600) = 0.8933`（与 SF `scale x=0.8933 y=0.8938` 吻合），
     放大后高 1430、居中 ⇒ 上溢 `(1430−1076)/2 = 177px`（与实测 176/177px 吻合）。
4. **为何只有对话框受害**：Surface 图层不受视图层级 `clipChildren` 裁剪；不透明窗口里溢出被窗口内容
   遮住不可见，Compose `Dialog` 窗口（`fmt=TRANSPARENT` + `DIM_BEHIND`）在卡片之外透明，溢出即漏出。

## 2. 整改内容

1. **`TotpScanDialog.kt`**：`PreviewView(context)` 改为
   `PreviewView(context).apply { implementationMode = PreviewView.ImplementationMode.COMPATIBLE }`——
   TextureView 渲染落在视图层级内、受父级裁剪，物理上不可能再溢出；取景与解码链路
   （`ImageAnalysis` + zxing `MultiFormatReader`）不经实现模式，行为不变。
   创建处内联注释与 `TotpCameraPreview` KDoc「取景」条同批写明根因与读数出处（`ISSUE-P3-333`）。
2. **守卫**：`SensitiveWindowHardeningTest` 第一例追加断言锁定
   `implementationMode = PreviewView.ImplementationMode.COMPATIBLE`（同文件静态守卫先例，**不新增
   `@Test` 方法**、用例计数不变）——回退默认 PERFORMANCE 即报红，失败消息指向本批次。

**未采用的替代方案（留痕）**：①不透明化对话框窗口/取消外边距——改变既有浮层观感，属产品面变更；
②给卡片外区域铺遮挡层——治标且新增冗余绘制。COMPATIBLE 是官方为「SurfaceView 不可用场景」提供的
标准降级面（`PreviewView.ImplementationMode` 文档语义），代价仅为一次额外纹理拷贝，对扫码取景无感知。
