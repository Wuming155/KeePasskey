### 1.2 真机取证（2026-10-08 09:55，设备 `M332BF` / `com.keepasskey` / Android 17）

**结论**：UI 投影链在 `Dispatchers.Default` 上投影一棵「字段实例已被**就地清零**」的条目树 ——
`entry.userName` → `ProtectedString.readString()` → `checkNotCleared()` 抛 `IllegalStateException`；
该异常逃逸到**协程根**（全仓无 `CoroutineExceptionHandler`、无 `setDefaultUncaughtExceptionHandler`）⇒
直达线程默认处理器 ⇒ 进程被杀 = 闪退。

### 1.3 根因链（三段，缺一不崩）

1. **擦除侧不变量写反**：会话层三处收口都是「**先就地擦当前树中被替换下线的实例 → 再发布新树**」——
   - `database/.../session/SessionPersistence.kt` 的 `save()` 历史修剪（`db.rootGroup.clearSupersededSensitiveData(prunedRoot)`
     之后才 `core.database.value = it`）；
   - `database/.../session/SessionContentMutations.kt` 的 `updateDatabaseMeta`（旧第 120/125/129 行擦除 → 第 130 行发布）；
   - 同文件 `adoptDatabaseIfUnchanged`（旧第 157-160 行擦除 → 第 161 行发布）。

   擦除启动时 `currentDb` **仍是发布中的活动树**。
2. **读侧与之无共享锁**：UI 投影链 `VaultEntryQueryCoordinator.entriesFlow()` 为
   `databaseSession.databaseFlow.map { ... entryMapper.mapKdbxEntryToUi(...) }.flowOn(Dispatchers.Default)`
   —— 投影被搬到 Default 线程且有调度延迟，与同在 Default 的擦除**互不排斥**；`VaultEntryMapper` 读
   `entry.userName`（第 88 行）与**历史条目** `h.userName`（第 59 行；历史条目正是 `save()` 修剪的首当其冲擦除候选）
   时命中已清零实例。
   本仓既有定则明示过该形态：`ProtectedString.cleared` 的 KDoc（`ISSUE-P2-287`）「调用方据此对已擦实例**降级**，
   而非依赖 fail-fast 异常做流程控制」；`PasskeyEntryCoordinator` 的 signCount 竞态 KDoc「读回点必须与落树同处一个临界区」。
3. **异常无安放点**：全仓无全局 `CoroutineExceptionHandler` / `setDefaultUncaughtExceptionHandler`；UI 侧
   `VaultListSyncController` / `SettingsSyncController` / `ConflictResolutionViewModel` / `ResumeSyncProbeCoordinator`
   的 `scope.launch` 均无 `try/catch` ⇒ 逃逸异常直接杀进程。

**为何表现为「同步一小会后闪退」**：同步周期必然调用 `databaseSession.save()`（R3 落盘，含历史修剪）与远端接管 /
合并采纳（`adoptDatabaseIfUnchanged`），正是上述擦除点；下载 + 合并跑一小会后进入收口，此刻擦除与 UI 投影撞车。
`ISSUE-P2-528`（§467，换密后强制 `LocalContentChangeState.CHANGED` 重传）会让同步**必然**走到「采纳 / 合并」收口，
把原本偶发的竞态变为必现 —— 属机制推断，**未做提交级版本二分**（见 §4 如实声明）。

## 2. 整改（四层，缺一层即复发）

### 2.1 读写责任分层：`core` 新增「展示面安全读取」原语

`core/src/main/java/com/keepasskey/core/security/ProtectedString.kt` 新增两个成员（**既有 `readString()` /
`readUtf8()` / `readChars()` 语义逐字不变**，仍 fail-fast）：

- `readStringForDisplay(fallback: String = "")`：已清零返回 `fallback`，不抛；
- `readUtf8ForDisplay(): ByteArray?`：已清零返回 `null`（刻意**不**返回空数组 —— 空数组会被下游误读为
  「字段存在但内容为空」）。

两者 KDoc 写死使用边界：**仅限非持久化展示 / 即时计算面**；写路径（序列化 / 保存 / 合并 / 导出 / 加解密 /
凭据下发）必须继续走 fail-fast —— 就地降级会把空值写进用户的库，属数据损坏。

### 2.2 投影面降级（关闭残余窗口）

- `app/.../data/repository/VaultEntryMapper.kt`：新增私有 `KdbxEntry.displayField(key)`（已清零 → 空串），
  替换全部投影读点 —— 当前条目 `title` / `username` / `url` / `notes`、**历史条目** `username` / `notes`、
  非保护自定义字段值、卡面字段（`projectCardFields`）；通行密钥**展示性标记**
  （`PasskeyData.fromCustomFields`）以 `catch (IllegalStateException)` 有界降级为「非通行密钥条目」
  （签发 / 断言路径不经此处，凭据面 fail-fast 不变）。
- `app/.../data/repository/VaultEntryTotpMapping.kt`：`parseTotpConfig` 的种子读取改走
  `readUtf8ForDisplay() ?: return null`（本文件整体是投影 / 即时出码面，已清零 → 无码显示）。

### 2.3 纠正不变量：三处收口改为「先发布、后擦除」

- `SessionContentMutations.updateDatabaseMeta`：`databaseFlow.value = updated` + `stateFlow = DIRTY`
  **前移**到擦除之前；
- `SessionContentMutations.adoptDatabaseIfUnchanged`：同上口径；
- `SessionPersistence.save` 的修剪分支：`core.database.value = pruned` 前移到擦除之前。

擦除**仍按身份集合判定**（`clearSupersededSensitiveData` / `clearBinaryPool` / `clearCustomIconPool` 逐字未动），
`ISSUE-P3-235` / `ISSUE-P3-258` / `ISSUE-P3-471` 的红线不变。发布在前把「下游读旧树」的窗口压到最小，
**但不为零** ⇒ 与 2.2 的降级**两层缺一不可**（改一侧必须复核另一侧，注释已就地写死）。

### 2.4 UI 入口异常兜底（消除「逃逸即闪退」）

- 新增 `app/.../sync/SyncGuardedLaunch.kt`：`CoroutineScope.launchGuarded(onFailure, block)`
  —— `CancellationException` 原样重抛，其余 `Throwable` 交 `onFailure`（**不静默吞**，Kdoc 写明调用方须给用户可读提示）。
- 接线 7 处：`VaultListSyncController`（下拉同步 / 绑改绑 / 另存副本并覆盖）、`SettingsSyncController`
  （`triggerSync` / `testSyncConnection`）、`ConflictResolutionViewModel.applyMerge`、
  `ResumeSyncProbeCoordinator.maybeProbe`；每处 `isSyncing` / `isResolving` 状态复位收进 `try/finally`
  （整改前一次异常会让指示器永久停在「同步中」）。异常详情只用**类名**（脱敏，沿用 `SyncCycleRunner` 既有口径）。

### 2.5 用例与防复发机检

- 新增 **10 例**：`core/.../ProtectedStringDisplayReadTest.kt` 4 例（降级确定值 / fail-fast 未削弱 /
  正常路径与 fail-fast 逐字一致 / `EMPTY` 的 `clear()` no-op）；`app/.../VaultEntryMapperDisplayFallbackTest.kt`
  5 例（含**正向对照**防「一律返回空」的退化实现）；`database/.../SessionAdoptIfUnchangedTest.kt` 追加 1 例
  （采用后共享实例**不得**被擦、被下线实例**必须**清零）。
- 新增 `tools/doc/check_projection_read_safety.py`：投影面文件清单内禁止裸 `readString()` / `readUtf8()` /
  `readChars()`（写路径刻意不在判据内），含 `--selftest` 双向反校；接入 `hygiene-gate` 作为**第十条**
  （`.github/workflows/build.yml`，fail-closed，禁 `|| true`）。
