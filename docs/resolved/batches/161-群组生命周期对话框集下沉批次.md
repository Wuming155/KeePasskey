## 1. 为什么切这五个

母文件的九个对话框按「读什么状态」自然分成两族：**分组树的结构变更入口**（新建 / 重命名 / 换图标 /
删除群组、清空回收站）与**列表页自身的视图动作**（排序、新建类型、模板选择、批量移动）。
前者参数一律是「目标分组 + `onDismiss` + 确认回调」，**不读列表页状态**，故可独立成文件而不引入
`ViewModel` 依赖或跨文件私有成员；后者留在母文件（其 §131 的惰性 + 高度上限修复判据仍锚在母文件，
本批实测无需扩扫描清单，见 §3）。

| 对象 | 行数 |
|---|---:|
| `.../vault/VaultListDialogs.kt` | **491 → 281** |
| `.../vault/VaultListGroupDialogs.kt`（**新增**，五个对话框） | **243** |

两文件均在 400 行阈值之下。

## 2. 做法与清理

- 整块搬移（含各对话框的 KDoc），**不改一行实现**；
- 两个文件各自补全 import 后编译，再按「符号是否还出现在代码正文」**剪除失效 import**：
  母文件剪 10 条、新文件剪 21 条；
- **运算符 / 委托类 import 不剪**（`getValue` / `setValue` 等）——§160 刚踩过这个坑，
  本批在脚本里显式加白名单，一次编译通过。
