# §332 无障碍假提示摘除与旧版无障碍填充通道落地批次（`ISSUE-P3-324` 闭环）

> **批次性质**：用户直报展示缺陷整改 + 功能补齐（同批闭环）。
> 用户命题（2026-09-25）：「安全防护里的『已启用无障碍服务』根本就是假显示——我根本没开无障碍权限它却显示；
> 之前有个旧版自动填充开关才是真正需要无障碍的，应该去掉的是这个假提示，而不是那个开关。」
> 并在开工后追加裁决：「展示链路要去掉，但旧版自动填充服务开关你要加上，并落实相关功能。」

---

## 1. 整改对象

| 条目 | 判据来源 | 本批处置 |
|---|---|---|
| `ISSUE-P3-324`（假提示摘除 + 旧版无障碍自动填充通道落地） | 用户直报 + git 历史取证（`4f8d030c` ISSUE-P2-228）+ 全仓 grep | **闭环** |

### 1.1 误报根因（取证结论）

「已启用无障碍服务」状态卡（`ISSUE-P2-44` 引入信号、`ISSUE-P3-215` 迁至安全分区）的唯一判据是
`RuntimeIntegrityDetector.detectThirdPartyAccessibility`：`getEnabledAccessibilityServiceList()` 中任一
**非本应用**服务即为真（**含系统预装**）。ROM 预装 / 默认启用的系统无障碍服务会被算入，
对未开无障碍的用户构成「假提示」。`RESOLVED_LOG` §224 已预留「用户未主动开启却提示已启用」的取证方向，
本批按用户裁决直接摘除整条链路（不放宽口径、不留半截信号）。

### 1.2 旧开关史（git 取证）

原「旧版自动填充服务（兼容低版本 Android 的无障碍填充方式）」开关：`4f8d030c`（ISSUE-P2-228）查明
其「无障碍填充」描述属**虚假**（当时全仓没有任何 `AccessibilityService`），遂改名「系统自动填充服务」并做实。
本批按用户新裁决把该通道**真实落地**：新增真正的 `AccessibilityService`，开关加回并做实（默认关闭）。

## 2. 整改内容

### 2.1 摘除「已启用无障碍服务」展示链路（AC①）

- UI：`SecuritySettingsScreen` 渲染分支与 `SecuritySettingsComponents.AccessibilityStatusCard` 整体删除（含失效 import）；
- 策略：`RuntimeIntegrityPolicy` 的 `requiresAccessibilityNotice` / `IntegrityEnforcement.requireAccessibilityNotice` /
  `IntegritySignals.thirdPartyAccessibilityEnabled` 三处删除，`evaluate` / `enforcingEnforcement` 签名同步收敛；
- 探测：`RuntimeIntegrityDetector.detectThirdPartyAccessibility` 及 `AccessibilityManager` 系 import 删除；
- 资源：`sec_accessibility_notice_title/body`（zh / en 各 2 条）删除；解锁页仅留防回潮注释；
- `SystemSettingsNavigation.accessibilityIntent` **保留**（旧版通道引导等仍走官方 action，`OneTapInteractionWiringTest` 判据同步改指）。

### 2.2 旧版无障碍自动填充通道落地（AC②③）

新增 `app/src/main/java/com/keepasskey/app/autofill/legacy/`：

| 组件 | 职责 |
|---|---|
| `LegacyAutofillAccessibilityService` | Manifest 注册（`BIND_ACCESSIBILITY_SERVICE` 权限保护，exported=true 同既有两服务口径）；窗口口令框检测 → 发通知；消费待决载荷 → 重扫 → 包名复核 → `ACTION_SET_TEXT` 回填 |
| `LegacyFieldScanner` / `LegacyFieldPolicy` | 判定与探测分离：扫描层只读元数据（不物化任何窗口文本、有界 400 节点）；纯函数选框（口令框为唯一锚点，已有内容即放弃；用户名取口令框前最近可编辑框） |
| `LegacyAutofillCoordinator` | 选择器 → 服务回填的单例桥（单载荷、消费即清、`toString` 脱敏、销毁/锁定兜底 clear） |
| `LegacyFillPickerActivity` | 受保护窗口选择器（FLAG_SECURE + hideOverlayWindows + 遮挡触摸过滤），复用 `AutofillPickerViewModel` 按需解密与 `AutofillPickerScreen`；生物识别确认退化语义同框架选择器 |

通道放行链（缺一不发 / 不填）：应用内开关（`autofillLegacyAccessibilityEnabled`，出厂**关闭**）→ 库已解锁
（通知与回填两处复核）→ 完整性闸门 `awaitEnforcement()` → 自我排除（ISSUE-P2-226 同口径）→ 黑名单（TASK-44）
→ 窗口存在可填充口令框。服务说明文案（`legacy_autofill_service_desc`）如实描述读取范围。

开关接线（AC②）：`ExtendedSettings` 字段 + `ExtendedSettingsStore` 读写键成对（单键缺省显式 `false`）+
`SettingsUiState` / 投影取自持久化 `extState` + 控制器与 VM 门面 setter + `AutofillProviderCard` 开关行 +
导航路由接线。新通知通道 `LEGACY_AUTOFILL`（id `keepasskey_legacy_autofill`，IMPORTANCE_DEFAULT）。

**v1 有意裁剪（如实登记）**：无字段级屏蔽写入与会话授权宽限（旧版通道每次选择都需显式确认，无重复确认可免）；
锁定时不提供解锁引导（与框架通道的解锁数据集不同，本通道锁定即静默）。

### 2.3 测试资产处置

- **删除** `AccessibilityNoticeWiringTest`（4 例）：①②③项被测生产代码整体移除、无法再测；第 4 项
  （`SecurePasswordField` 口令语义显式声明，ISSUE-P2-44 AC②）与被删链路无关，**迁出保留**为
  `SecurePasswordFieldSemanticsWiringTest`（1 例）。符合「测试资产纪律」① 的登记式删除。
- **新增** `LegacyFieldPolicyTest`（8 例，纯 JVM 穷举选框形态）+ `LegacyAutofillWiringTest`（7 例静态接线守卫，
  体例沿用 `AutofillChannelSwitchWiringTest`；含「单键缺省不得沿用 CHANNEL_SWITCH_DEFAULT」「锁定复核两处」
  「PendingFill toString 必须脱敏」「配置 XML 可读窗口内容」等形态锁定）。
- **修改**：`NotificationChannelSpecTest` 通道白名单 +1；`AutofillChannelSwitchWiringTest` 键成对 / 投影断言扩至
  新键、「虚假措辞」守卫改为白名单口径（`autofill_legacy_accessibility_*` 措辞如实描述真实存在的服务，例外放行；
  框架通道仍禁）；`RuntimeIntegrityPolicyTest` / `RuntimeIntegrityCheckSwitchTest` / `IntegrityBlockReasonTest` /
  `OneTapInteractionWiringTest` 删除或改指无障碍信号相关判据（被测对象已移除，逐处留 ISSUE-P3-324 注记）。
