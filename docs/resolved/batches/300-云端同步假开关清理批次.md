- **背景与根因**：三项「偏好只落盘不消费」+ 一项「偏好不落盘不消费」。前三项的界面文案已向用户承诺具体行为（`strings.xml`：`sync_auto_sync_sub`「数据变更后自动推送到云端」、`sync_file_tx_sub`「先写入临时文件再原子替换，意外中断不损坏数据库」、`sync_preload_sub`「Wi-Fi 下后台预取云端副本，加快解锁速度」）与「仅在指定 SSID Wi-Fi 下允许同步」（`SettingsUiState.kt:118`），实际行为与承诺无关；自动同步连回显都在重启后归位，属 `ISSUE-P2-228` 同型假开关。

## 2. 整改

### 2.1 四项逐项结论（AC①）

| 开关 | 结论 | 落点 |
|---|---|---|
| `autoSyncEnabled`（自动同步） | **真实接线** | 改走 `ExtendedSettingsStore` 持久化；消费点＝`VaultListViewModel` init「解锁后自动同步一次」，与「是否已配置云同步」合取 |
| `useFileTransactions`（事务化写入） | **如实移除**（原子写**不可关闭**，登记 `PD-39`） | UI 开关 / 状态字段 / setter / 投影 / 偏好键 / 字符串键全链删除 |
| `preloadDatabaseEnabled`（预加载远程数据库） | **如实移除**（零生产实现） | 同上全链删除 |
| `allowedWifiSsids`（允许的 Wi-Fi SSID） | **如实移除**（无过滤实现，网络约束收敛于 `wifiOnlySync`） | 同上全链删除 |

> AC② 关于「Wi-Fi SSID 若接线须与 `wifiOnlySync` 合流」的分支**未触发**（选移除）：现有网络约束**只有一个**入口，语义重叠问题随之消失。

### 2.2 自动同步：不落盘不消费 → 持久化 + 真实消费点（AC②）

1. **偏好载体**：`ExtendedSettings` 以 `autoSyncEnabled`（缺省 `true`）承接；`ExtendedSettingsStore` 新增偏好键 `K_AUTO_SYNC_ENABLED = "auto_sync_enabled"`，`load()` 读侧 / `save()` 写侧同时落位（原 `allowedWifiSsids` 键位就地让出，键名与字段一一对应）。
2. **写入通道**：`SettingsSyncController.setAutoSyncEnabled` 由「只写本控制器内存 `StateFlow`」改为「`extendedSettingsStore.publish(next)` + `save(next)`」——内存权威快照与持久化**原子完成**，重启不再回弹。
3. **投影**：`SettingsUiStateProjection` 的 `autoSyncEnabled` 由 `syncState.autoSyncEnabled`（内存态）改读 `extState.autoSyncEnabled`（持久化快照）。
4. **消费点（真实接线）**：`VaultListViewModel.init` 的「解锁后自动同步一次」触发点改为
   `val autoSyncOnUnlock = extendedSettingsSource?.load()?.autoSyncEnabled ?: true` ⇒ `if (autoSyncOnUnlock && syncController.isSyncConfigured()) triggerPullRefresh()`。
   显式取值而非内联：`?:` 优先级高于 `&&`，内联虽等价但读起来像「关掉开关即恒不触发」被短路，而本开关与「是否已配置云同步」本是**两个独立合取项**。

### 2.3 三项移除（AC②③）

逐项删除，链上无残留：**UI 开关渲染点 → 屏幕形参（`CloudSyncScreen` / `WebDavSyncScreen`）→ 导航图实参 → `SettingsViewModel` 委托 → 偏好控制器 setter → `SettingsUiState` 状态字段 → 投影 → `ExtendedSettings` 字段 → `ExtendedSettingsStore` 键位（读 / 写两侧）→ 中英字符串键**。

- `CloudSyncSections.kt`：`FileSafetySection` 移除「事务化写入」开关项、`NetworkOptionsSection` 移除「预加载远程数据库」开关项（两处原位改为 KDoc 说明移除缘由与 `PD-39` 指针，避免后来者「看起来是漏了」）。
- 字符串键删除 **4 个 × 2 侧**：`sync_file_tx_title` / `sync_file_tx_sub` / `sync_preload_title` / `sync_preload_sub`。
- **键成对与总数核对（AC③）**：合并 `Values/` 三份字符串文件（`strings.xml` + `strings_sync_passkey.xml` + `strings_ui_messages.xml`）后与 `values-en/strings.xml` 逐键比对：**两侧各 1219 键，双向差集皆空**（改动前后同口径复核；单文件口径会漏读另两份，**勿以单文件为准**）。

### 2.4 文案修订（AC④）

| 键 | 改前（谎报） | 改后（真实行为） |
|---|---|---|
| `sync_auto_sync_sub`（zh） | 数据变更后自动推送到云端 | 解锁后自动与云端同步一次；关闭后仅手动同步 |
| `sync_auto_sync_sub`（en） | Push changes to the cloud automatically | Sync with the cloud once after unlock; when off, manual sync only |
| `sync_file_tx_*` / `sync_preload_*` | 承诺「先写临时文件再原子替换」「Wi-Fi 下后台预取」 | **键随开关一并删除**（无开关即无承诺） |

> 首次构建即红：英文字符串文件的整段注释误用了 XML 非法的 ASCII `--`（`values-en/strings.xml:733`）——注释已改写为合法形态。**这是本批 WIP 里唯一一处会直接阻断构建的缺陷，已修**。

## 4. 如实声明

1. **`hygiene-gate` 在 `HEAD`（`dbdf1a34`）上已是红态**：`tier1=4`、`functions_ge_100=2`。§285 曾记 `tier1=0 / functions_ge_100=0`（§280 收工线），其后 §286~§299 的增长把它推回去了。本批**未修复**（拆 4 大文件 + 2 长函数属独立批次，混入本案会放大回归面），已按规则 6.1① **即时补登 `ISSUE-P3-305`**（附核实时间点与复核方式），并在此登记红态，**不以「test 全绿」冒充「门禁全绿」**。
2. **未主动清理既有安装的残留偏好键**：`save()` 为「整体写」而非「清空重写」，升级用户的 `SharedPreferences` 中会遗留 `allowed_wifi_ssids` / `use_file_transactions` / `preload_database_enabled` 三个**惰性死键**（读写两侧均已无引用，无功能影响）。未加显式 `remove` 清理——避免为无行为影响的键引入一次性迁移逻辑。
3. **结构注记（不构成缺陷）**：`SettingsSyncController` 仍持有并调用 `ExtendedSettingsStore`（本批前该注入是**死依赖**，现成为 `setAutoSyncEnabled` 的唯一用途）。`ExtendedSettings` 的其余 setter 统一在 `SettingsExtendedPreferencesController.updateExtended`，本条为该域的**第二个写入路径**；因该 setter 语义属「同步开关」且控制器已持有该依赖，未强行搬迁（搬迁需改 `SettingsThinOrchestrationTest` 的构造签名，收益不抵回归面）。
4. **无设备侧必跑项**：本批未触 `*/src/androidTest/**`、未改原生（`crypto/src/main/rust/`）面、未改 KDBX 序列化 / 合并 / 附件 / `PasskeyData`，故无 AVD 实跑义务；`tools/passkey-interop/verify_interop.py` 与 `generate_corpus.py` 不在本批判据面。
5. **未跑**：`lint` / `assembleRelease` / 截图包装编译门禁（未改 `@Preview` 与预览生成器）/ `:crypto:connectedDebugAndroidTest` 等 instrumented 面。
