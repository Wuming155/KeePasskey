# §326 CI 触发频率治理批次（`ISSUE-P3-316` 闭环）

> **批次性质**：CI 基础设施批次——无生产代码改动面（三个 workflow 的 `on:` 触发块 + 文档）。
> 整改对象是**触发频率**而非门禁语义：三个 workflow 原「每 push 全量触发」下，09-20 起 5 天产生
> 382 次 run（build 126 / dependency-scan 127 / CodeQL 129），纯文档提交也跑满 5 job build、
> 约 55 分钟 OWASP 全量扫描与三路 CodeQL。按用户裁决（2026-09-25）改为**纯定时巡检 + 手动触发**。

---

## 1. 整改对象

| 条目 | 判据来源 | 本批处置 |
|---|---|---|
| `ISSUE-P3-316` CI 触发频率治理：三 workflow 每 push 全量触发，配额消耗与计数膨胀 | `GET /actions/runs` 分页聚合 + 三 workflow `on:` 块现行内容比对 | **闭环**（AC①~④ 落地并经 dispatch 实跑验证，AC⑤ 定时首轮由下一周期自然验证） |

## 2. 整改内容（只动触发面，门禁语义一字未动）

| workflow | 原触发 | 新触发 | 说明 |
|---|---|---|---|
| `build.yml` | `push: main` + 全部 `pull_request` + dispatch | `schedule: "0 21 * * *"`（每日 UTC 21:00 = 北京 05:00 全量巡检，含 Device gate）+ dispatch | 定时首轮跑在 NVD 等缓存之上，无额外冷启成本 |
| `dependency-scan.yml` | `push: main` + 全部 `pull_request` + dispatch | `schedule: "0 3 * * 1"`（每周一 UTC 03:00 = 北京 11:00）+ dispatch | **与 §325 建立的 NVD 周粒度缓存 key（ISO 周）天然对齐**：每周首跑恢复上周库增量更新；依赖未变时新 CVE 仍由周巡检承接；头注释「触发策略」同步更正（防声明漂移） |
| `codeql.yml` | `push: main` + `pull_request: main` + 周巡检 + dispatch | 移除 push / PR，保留既有周巡检 `23 4 * * 1` + dispatch | 头注释同步更正 |

**未弱化的保证（如实声明）**：①本地门禁（`gradlew test` 全绿 + `gate_readings.py` 7/7）仍是每批
入库的前置条件（规则 6.2），CI 由「每 push 第二道层」改为「每日/每周独立复核层」——代价是
坏提交落 main 后最迟约 24 小时（build）被 CI 揭出，此前为分钟级；需要即时验证时用
`workflow_dispatch`（本批三条 dispatch 即为演示）。②各 job 语义、fail-closed 断言、timeout、
concurrency 一律未动。

## 3. 验证读数

**触发面移除实证**：推送 commit `b46ad520`（含触发面整改）后等待 60 秒，`GET /actions/runs?head_sha=…`
返回 `total_count = 0`——push 触发已确实移除（此前每次推送必产生 3 条 run）。

**手动触发实证（AC⑤ 的可立即验证部分）**：对三个 workflow 各 `workflow_dispatch` 一次，全部 success：

```
CodeQL            run 36090539694  success
dependency-scan   run 36090534765  success（CVSS 闸门通过，SARIF 上传）
build             run 36090529506  success（五 job 全绿，含 Device gate）
```

**cron 现查反校**：以 PyYAML 现读三个 `on.schedule[0].cron` 与注释声明逐字符比对，三处一致
（`0 21 * * *` / `0 3 * * 1` / `23 4 * * 1`，均为 UTC，GitHub Actions cron 原生 UTC）。

**预期配额收益**：由「每 push × 3 workflow」降为「每日 1 次 build + 每周 2 次扫描」，
约 **15 次/周**（原约 270 次/周量级）。
