# §429 常驻通知「展开可供性」修复批次（`ISSUE-P3-440` 三轮回执：补 `BigTextStyle` 展开态）

> 批次日期：2026-10-03。
> 触发＝第三轮装机走查回执（用户原话：「还是不一样，KeepassDX 右上角有个箭头，点击就能展开」）。
> 性质＝**缺陷修复**（承接 §428）：§428 修的是「通知被归入静默分类」，本批修的是
> **「通知根本没有展开态 ⇒ 系统只给长按这一条路径」**——两者是两处独立成因，缺一不可。
> 装机形态＝debug 版（`com.keepasskey.debug`）；设备＝Xiaomi M332BF / HyperOS OS4.0 / Android 17。

## §1 取证：展开箭头从哪来

用户观察到的目标行为＝**折叠态标题右侧有「展开箭头」，点一下即展开**（一次点按，不是长按）。
据此按 `AGENTS.md` §3.3 定向检索参考实现（`参考项目/` 只读）：

| 实现 | 展开态来源 | 关键片段 |
|---|---|---|
| **KeePassDX** | `NotificationCompat.MediaStyle()` | `services/DatabaseTaskNotificationService.kt:598-604`：`if (SDK_INT > R) setStyle(MediaStyle().setShowActionsInCompactView(0))`，源码自注 `// Won't work with Xiaomi and Kitkat` |
| **Monica** | `NotificationCompat.BigTextStyle()` | `autofill_ng/utils/SmartCopyNotificationHelper.kt:118`：`.setStyle(BigTextStyle().bigText(notificationText))`（同时挂两个动作） |
| **本仓（修订前）** | **无任何 style** | `UnlockedNotificationController.post()` 只设 title / text / chronometer / 动作，**没有展开态** ⇒ 系统无「展开箭头」可给，折叠态又不渲染动作 ⇒ 只剩长按 |

结论：**「有动作」并不会自动带来展开箭头；展开态必须由 `setStyle(...)` 提供。**
KeePassDX 的箭头来自 `MediaStyle`（其 `setShowActionsInCompactView` 在小米上不生效，作者已自注——
即小米上仍要展开，这正是用户看到的「箭头 + 点击展开」）；Monica 走 `BigTextStyle`，同为一次点按。

## §2 整改

`notification/UnlockedNotificationController.kt`：

- 把倒计时 / 空闲两态文案先算成 `contentText`，再统一 `setContentText(contentText)`；
- 新增 **`.setStyle(NotificationCompat.BigTextStyle().bigText(contentText))`** ⇒ 通知获得展开态，
  折叠态出现**展开箭头**，点一下展开即见动作按钮；
- 收起态与展开态**共用同一份文案**（不为展开态另立第二份用户数据面），
  `setOngoing` / `VISIBILITY_SECRET` / `setOnlyAlertOnce` / Chronometer / 动作集**零变化**。

选 `BigTextStyle` 而非 KeePassDX 的 `MediaStyle`：① `MediaStyle` 是媒体通知版式，语义不合；
② 其独有能力 `setShowActionsInCompactView` 被 KeePassDX 自注「Won't work with Xiaomi」——
本机正是 Xiaomi，采用它等于赌一个已知不生效的 API；③ `BigTextStyle` 已被 Monica（同为面向
HyperOS 的中文密码管理器）在同代系统上验证。

- `UnlockedNotificationWiringTest` 增 `常驻通知必须给出展开态以便一键展开动作`：
  断言 `NotificationCompat.BigTextStyle()` 存在、且展开态复用 `contentText`。
