## 1. 原条目（自 `ACTIVE_ISSUES.md` 原样收录）

- **背景**：`app/.../ui/screens/vault/VaultListViewModel.kt:248` 的 `uiState` 由
  `combine(…) { buildVaultListUiState(…) }.stateIn(scope = viewModelScope, …)` 构成——
  `stateIn` 的收集上下文即 `viewModelScope`（Main），而变换体内是全库过滤 / 排序 / 面包屑上溯 /
  回收站后代递归 / 分组路径装配。`ISSUE-P3-154` 只给**数据层**两条投影流补了 `flowOn`，
  **UI 侧这段变换的执行线程未变**；同仓 `AuthenticatorViewModel.kt:118` 已显式 `flowOn(Dispatchers.Default)`，
  且本 VM 已有可注入的 `displayDispatcher`（现只用于 decorations / TOTP）。
- **整改方向**：`… }.flowOn(displayDispatcher).stateIn(…)`，与自动填充页 / 验证器页同一写法。
- **验收标准**：新增用例（记录型调度器或结构断言）锁定「整库投影不在收集上下文执行」；
  既有列表页状态用例全绿；`ISSUE-P2-89` 的节拍契约（窄通道 / `WhileSubscribed`）不得回退。
- **核实时间点与方式**：2026-09-17 主控直读 `VaultListViewModel.kt:238-267` 核实。
- **风险提示**：`§114` / `§117` 的记录显示该 VM 的调度器改动曾两次影响既有用例，
  实施时须与 `TestScope` 的虚拟时间轴对齐，避免改成偶发红。

## 2. 本批实现

- `uiState` 在 `stateIn` 之前补 **`.flowOn(displayDispatcher)`**（复用本 VM 已有的展示调度器
  `@EntryDisplayDispatcher`，生产为 `Dispatchers.Default`），并补导入 `kotlinx.coroutines.flow.flowOn`
  （该文件此前未用过该算子）。就地 KDoc 写明「与数据层两条投影流（§117）同口径」。
- **未改任何算子语义**：`combine` 的输入流、变换体、`SharingStarted.WhileSubscribed(5000)`、
  `initialValue` 全部逐字保留 ⇒ `ISSUE-P2-89` 的节拍契约（窄通道 + 订阅驱动）**未受影响**。

### 关于「风险提示」的实测处置（本条的关键）

条目风险提示记「该 VM 的调度器改动曾两次影响既有用例」。本批开工即核对**测试侧是否已注入可控调度器**：
`VaultListViewModelTest.newViewModel(...)` 已经以
`displayDispatcher = UnconfinedTestDispatcher(testScheduler)` 构造 VM
（decorations 早已使用该调度器）⇒ 补 `flowOn(displayDispatcher)` 后，整库投影仍落在**测试调度器**
与同一虚拟时间轴上，**不引入真实线程池**，故不会造成 §114 那类「测试里跑真线程」的偶发红。
本批全量单测一次通过（2071 例，含 `VaultListViewModelTest` 20 例）即为该判断的证据。

### 为何验收判据取「结构断言」而非「记录型调度器」

AC 明列二者择一。本批取**源码文本守卫**，理由是 §117 的记录型调度器（`DispatchRecordingDispatcher`）
需要「订阅 `uiState` + 断言派发计数」的额外编排，而本 VM 的测试已把该调度器注入为
`UnconfinedTestDispatcher`——**在该调度器上计数不等于证明「离开了 Main」**（要证明需要再引入一个
计数包装层并保证订阅时序），收益与复杂度不成比例。**代价如实声明**：该守卫只锁「接线未被删」，
**不构成**运行期派发证据（见 §4）。

## 4. 边界如实声明（不得外推）

1. **无任何性能实测**：本批是「把变换的执行线程从 Main 挪到注入的展示调度器」的**结构性**改动，
   **不得**宣称「列表页不再卡顿」或任何百分比收益；真机帧率 / jank 未测。
2. **守卫是源码文本断言**：只锁「`flowOn(displayDispatcher)` + `stateIn(` 的相邻形态」，
   对「把变换体搬进别的函数」或「在中间插入算子」的部分退化**无鉴别力**；
   **不构成**「投影确实派发到了该调度器」的运行期证据（理由见 §2 末）。
3. **`displayDispatcher` 的默认值仍是 `Dispatchers.Default`**：Hilt 生产绑定未变；
   若未来有实现方把它绑定到 `Dispatchers.Main`，本改动即失效——该契约由
   `@EntryDisplayDispatcher` 的模块提供（本批未加断言）。
4. **本批只处理 `uiState` 这一条**：条目内的其它流（如 decorations / 窄通道刻度）沿用既有线程口径；
   `ISSUE-P3-176`（冷流重复订阅与导航图重建）**仍未做**。
5. **未跑设备侧与 `assembleRelease`**（本批不涉 UI 呈现，`lint` / release 未复跑）。
