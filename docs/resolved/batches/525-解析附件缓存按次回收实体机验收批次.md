# §525 解析附件缓存按次回收实体机验收批次

<a id="s525"></a>

## 1. 闭环范围

本批关闭 ISSUE-P3-622。原问题是在解析已创建明文附件 spill 后，库开关失败或会话未接管候选时，候选 spill 可能残留在应用私有缓存目录。

## 2. 实施与验收

- 新增 AttachmentSpillTransaction：每次 KDBX 解析通过记录型 BinaryStore 登记本次成功创建的 key；解析异常、取消或候选未能交给会话时只删除本次 key。成功打开后显式移交附件所有权；子库投影结束按次清理。
- FileBinaryStore 对流式写入失败在 key 未交付前自行清理，并保留未清理 key 供后续安全重试。清理范围不调用共享存储的全局 clear。
- database JVM 全量通过：656 项，0 失败、0 错误；包括解析失败、取消、写入失败及活动根库附件不得误删的对照。
- API 37 Redmi 4X 实体机执行 AttachmentSpillEvictionSaveGuardDeviceTest：2 项通过，0 失败、0 错误。新增场景先把活动根库 5 MiB 附件真实写入 cacheDir/attachments，再解析另一含附件候选库，并让输入流在成功解析后 close 时失败；候选开库失败后磁盘文件集合回到原活动 spill 集合，活动附件仍可逐字节读取。
- 实体机测试前确认 com.keepasskey 主应用包未安装；测试只创建和清理虚构库、虚构附件。非空 XML：app/build/outputs/androidTest-results/connected/api37-evidence/TEST-AttachmentSpillEvictionSaveGuardDeviceTest-API37.xml。

## 3. 过程与限制

- 设备通过的是“解析成功、会话接管前的流关闭失败”路径；数据库 JVM 另覆盖解析晚失败和取消。没有用真实用户库或用户附件。
- API 34 模拟器未用于本批验收；设备证据来自用户指定的 API 37 实体机 Redmi 4X。
