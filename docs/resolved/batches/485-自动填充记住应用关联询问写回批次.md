## §3 如实声明

1. **锁定丢弃分支无 VM 层单测**：`offerAppBindingWriteBack` 内「询问期间 `isLocked()` 翻转 → 返回 false」
   一态未测——`FakeVaultRepository.isLocked` 恒 false 且类为 final 不可覆写；该复核与交付链既有
   「回传前再次校验」（TOTP 段）同型同谓词，判定内核（policy）侧无此分支。
2. **VM 层不设「URL 非空不询问」用例**：mock 条目 id（`"1"`~`"6"`）非合法 32-hex，`KdbxUuid.fromHexString`
   抛异常回退 `KdbxUuid.random()` ⇒ Fake 每次转换 id 都变，`getKdbxEntry` 往返查找**不可依赖**——
   「条目当前 URL 非空」在本 VM 层不可构造；该否决态由 policy 12 例中的三条（Web 绑定 / 已绑定其它应用 /
   已绑定同包名）锁定。生产链路 entryId 来自真实库条目，无此坑。
3. **确认页（`AutofillConfirmActivity`）交付点不询问**（PD-83 边界③）：询问只落手动选择器流（Kp2a 同型）；
   确认页既有静默关联记忆写入不变。
4. **浏览器表单不询问**（PD-83 边界）：`webDomain` 非空的表单一律不置询问；域维度由归属校验通道与 CM 保存链承载。
5. **写回失败不阻断交付**：`updateEntryUrl` 失败（含锁定竞态）只记日志，凭据交付照常完成——填充是用户主诉求，
   写回是附加持久化，失败语义与「拒绝」一致（不写、不重试、无提示，本页即将 finish 无提示面）。
6. **过程坑留痕（三次红，逐次收口）**：
   ① VM 测试首版 `launch(Dispatchers.Unconfined)` 在 runBlocking event loop 里**入队而非同步启动**，
   叠加主线程 `Thread.sleep` 等待 ⇒ offer 协程永不启动、`completeBindingWriteBack` 打在 null 上 no-op、
   `job.join()` 永悬（测试 worker 挂死，jstack 定位 `joinBlocking`）——修复：`CoroutineStart.UNDISPATCHED`
   （同步执行到 `decision.await()` 挂起点）＋ 等待 sleep 移入 `withContext(Dispatchers.IO)`；
   ② 同因下另一坑：mock 短 hex id 的 `KdbxUuid` 往返不稳定（见第 2 条）→ 改观测点断言；
   ③ `deliver` 被询问块推到 103 行越 `long_functions` 阈值（fail-closed 红一次）→ 抽 `resolveOtpIfDeclared`
   收口，复跑时暴露漏 `suspend` 编译红一次 → 补修饰符收口。
7. **环境坑留痕**：被本代理杀掉的测试 worker 残留句柄锁 `bundleDebugClassesToRuntimeJar` 的 `classes.jar`
   （`FileSystemException: 另一个程序正在使用此文件`）两次 → `./gradlew.bat --stop` 释放后重跑转绿；
   教训：杀超时任务后须确认 test worker 进程已退，勿留持锁僵尸。
8. **未跑**：`connectedDebugAndroidTest`（本批无 `*/src/androidTest/**` 与原生面改动）、`lint`、
   `assembleRelease`、KPEX 对拍（未触碰 `PasskeyData` / `PasskeyPkcs8Codec` / KPEX 字段）。
   设备侧源集编译门禁不在 `test` 依赖图内且本批未改 `*/src/androidTest/**`——仍跑（见 §2.4）。
