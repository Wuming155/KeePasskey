# §395 新建向导云端恒可选与二次收敛批次（§394 后续走查反馈，会话内整改随批归档）

> **触发**：2026-10-01 用户在 §394 实现态装机走查后反馈：「第一，这个弹窗太大。第二，
> 云端根本没法选择呀。」
> **结案条目**：会话内整改（未占 ISSUE 编号），随本批次文档归档。

## 0. 根因与核实

- **「云端没法选择」核实（2026-10-01）**：§391 的裁决是「云端直建要求已配置云账号——
  未就绪时 Chip 置灰禁选」（`enabled = cloudSnapshot.ready`）。用户当前 debug 包
  （`com.keepasskey.debug`，数据与生产包隔离，§390）**尚未配置云账号**——此前冒烟 dump
  即命中「尚未配置云账号：请先在『设置 → 云同步』中配置 WebDAV 或 S3」——故 Chip 恒灰，
  用户观感为「根本没法选择」。
- **裁决（§395）**：云端**恒可选**——未配置不禁选，选中后副文案如实告知去哪里配置；
  建库闸收窄到「创建」按钮层（云端未就绪时禁用），与 `DatabasePickerViewModel.createDatabase`
  既有的 fail-closed 守卫（`storageLocation == CLOUD && !cloudAccount.cloudReady` 显式失败）
  构成双闸，**不互替、不静默降级**。置灰禁选的旧口径（§391 AC 的呈现面）由本批废止。
- **「弹窗太大」**：§394 收敛后仍偏大——本批把表单纵向间距 10→6dp、密钥文件卡内边距
  10→8dp / 内距 8→6dp、「存储位置」小节标题由 labelLarge 加粗降为 labelMedium 副色
  （与「加密算法与 KDF」标签同族），整体高度再降约一档。

## 1. 整改

| 层 | 变更 |
|---|---|
| `CreateVaultWizardDialogSections.kt` | ①「云端」Chip 移除 `enabled = cloudSnapshot.ready`，恒可选；②未就绪时选中态副文案仍走 `cloudLocationSubtitle` 三态（读取中 / 尚未配置→去设置），就绪显示同步目标；③「存储位置」小节标题降为 `labelMedium` + `onSurfaceVariant`（去加粗）；④KDoc 同步新裁决 |
| `CreateVaultWizardDialog.kt` | ①「创建」按钮 enabled 追加 `(storageLocation != CLOUD \|\| cloudSnapshot.ready)` 闸——云端未就绪时按钮禁用（fail-closed 双闸之 UI 层）；②表单纵向间距 10→6dp；③密钥文件卡 padding 10→8dp、内距 8→6dp |

**行为不变式**：`createDatabase` VM 守卫一字未动；「自选位置」SAF 链路、busy 禁用、
弱口令确认、`SecureDialogWindowEffect`、CharArray 离场擦除原样。

## 3. 如实声明

   按钮禁用」——建库安全闸未变（VM fail-closed 守卫原样），变的只是**选择自由度与告知位置**；
   §391 批次文档按「只搬迁、不改写」纪律保持原样。

   的「设置 → 云同步」配置账号（这是 §390 包名隔离的预期行为，非缺陷）。
