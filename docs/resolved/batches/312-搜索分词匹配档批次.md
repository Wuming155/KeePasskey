# §312 搜索分词匹配档批次（ISSUE-P3-309 闭环）

## 1. 整改对象

`ISSUE-P3-309`（自 `ISSUE-P3-297` AC⑤ 拆出）：全文匹配为纯子串 `contains`，短查询误报多；补齐一个匹配档。

## 2. 整改内容

- **档位裁决（AC①）**：新增**分词档（`ALL_TERMS`）**——查询串按空白切词，每个词都须在候选文本中命中（子串口径、大小写不敏感）。选分词而非整词 / 正则的理由：整词 `\b` 边界对 CJK 无效（中文用户无收益）、正则档有用户输入 ReDoS / 注入面与成本评估负担；分词 AND 对中英文一致可用、语义可一句话说清。默认档保持 `CONTAINS`（既有子串口径，行为零变更）。
- **可达性（AC①）**：外观设置页「搜索、分组与常驻通知」分节新增「搜索匹配方式」二态 FilterChip 选择器（结构对齐既有密度选择器），经 `ThemeSettingsScreen` → 导航路由 → `SettingsViewModel.setSearchMatchMode` → `SettingsExtendedPreferencesController`（内存 + 持久化原子完成）接线；持久化键 `search_match_mode`（`ExtendedSettingsStore` 整体读写）。列表页经既有 `extendedSettingsFlow` 通道消费，返回列表页即生效（与 `ISSUE-P3-17` 显示偏好同一刷新机制，无轮询）。
- **实现**：`matchesSearchQuery` 增 `mode` 参数（默认 `CONTAINS`，既有调用零改动）；候选文本收敛为惰性 `searchableTexts()` 序列（受保护自定义字段只出**键**不出值，契约原样）。`ALL_TERMS` 最坏 O(词数 × 文本量)，与 CONTAINS 同阶（AC③ 成本口径：状态层匹配 + 既有 300ms 防抖不变，未引入预计算或正则编译热路径）。
- **受保护字段契约（AC②）**：受保护值明文不物化、不参与命中的既有语义原样保留，既有锁定用例（`受保护字段值不参与命中但键可命中`）未改动；另加分词档同型用例双锁。
- **既有语义不回退（AC④）**：`VaultListProjectionSearchTest` 原 7 例逐字保留，仅追加 5 例（分词 AND、词内子串、多空白、受保护双锁、空查询）。
- **文案（中英成对）**：`theme_search_mode_title / _desc / _contains / _contains_desc / _all_terms / _all_terms_desc` 共 6 键，`values/` 与 `values-en/` 同步。
