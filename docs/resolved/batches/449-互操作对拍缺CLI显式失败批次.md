# §449 互操作对拍「缺 CLI 静默丢弃判据」显式失败批次（2026-10-06）

**条目**：`ISSUE-P1-495` **单条整条闭环**（P1 1 → **0**，现存最高优先级清空，P0/P1 双双归零）
**来源**：[`records/三类隐蔽性故障排查报告_2026-10-06.md`](../../records/三类隐蔽性故障排查报告_2026-10-06.md)（报告标 high → **P1**）。
本批属该报告「读取源错误与静默降级」类，形态与「闸门存在 ≠ 闸门被执行」（§308 / `ISSUE-P3-305`）同型：
**官方实现侧判据可被「环境缺失」整体丢弃，而退出码仍为 0**——即「判据存在 ≠ 判据被执行」。

  （无自动调用点 ⇒ 缺陷暴露面是「人工引用退出码入库」），与条目「触发状态 dormant」判断一致。

## 449.2 整改（AC① / AC②）

- **环境前置（第一层）**：`main()` 在**产物检查之前**做 `shutil.which("keepassxc-cli")`，未命中即向 `stderr`
  显式说明缺什么并 `return EXIT_ENV_MISSING(2)`——与同仓正确先例
  `tools/template-group-interop/verify_template_group.py:15`（「2 = 环境缺失（不得当绿）」）口径对齐。
  置于产物检查之前的两条理由写进注释：① 缺 CLI 需**独立退码**（否则会被「产物缺失」的退码掩盖语义）；
  ② 使 `--selftest` 无需 gradle 产物即可反校。
- **第二层（防止中途消失）**：`read_with_keepassxc_cli` 的 `which` 未命中分支改为**记入 `_failures` 并置
  `_environment_missing`**；`verify_entry` 的 `None` 分支文案由「不视为通过」改为「已记入失败清单」——
  **文案与 verdict 同向**，该分支现在必然使退出码非 0。
- **摘要行只列实际运行过的实现**：新增 `note_implementation` / `format_summary` / `implementations_text`；
  `_implementations` 仅在实现**真正产出读数**时登记（`pykeepass` 解锁成功 / `cryptography` 解析成功 /
  `keepassxc-cli` 读取成功），通过摘要与失败清单均只列此清单，**不再写死**。
- **退出码语义**：模块文档串补「`0` = 全部判据通过 / `1` = 对拍不成立（判据失败 / 产物缺失）/
  `2` = 环境缺失（不得当绿）」；`README.md` 依赖节兑现原有承诺（「显式失败并说明缺什么，不做静默降级」）
  并补退 2 与摘要口径，常用命令补 `--selftest`。
- **索引同步**：`AGENTS.md` §5 该命令条目由「退出码 1 即失败」改为三分语义 + `--selftest` 说明。

## 449.5 如实声明

- 本批只改 `tools/passkey-interop/**`（Python 工具）与文档 / 索引，**未触** `crypto/src/main/rust/**`、JNI、
  原生分派与探活，按 AGENTS.md 测试资产纪律**无四层真机义务**；亦未新增 `*Manager/*Util/*Helper/*Common` 类型。
- 未新增或删除任何测试用例（含设备侧）；本批的「自检」以工具自带 `--selftest` 形态落地（与
  `preserve_test_failures.py` / `check_installed_build.py` 既有先例同型），未引入新的测试资产。
- **未把对拍接入 CI**：本机 `keepassxc-cli` 在场，但 CI runner 无该依赖；接入需同步解决 runner 侧安装与
  探针产物生成（`PasskeyInteropProbeTest`），超出本条 AC 范围，**故如实声明本脚本仍无自动调用点**——
  「人工引用退出码」这一暴露面未消除，但已由「缺环境必须显式失败退 2」堵住其最坏后果（假权威证据入库）。
