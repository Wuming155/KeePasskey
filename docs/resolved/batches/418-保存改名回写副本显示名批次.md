# §418 SAF 保存密钥文件改名回写副本显示名批次（ISSUE-P3-462 整条闭环）

## 1. 原文收录（原样迁移自 `ACTIVE_ISSUES.md`，未删改）

### ISSUE-P3-462：SAF 保存密钥文件改名后，应用内记忆的显示名仍是建库默认建议名

- **核实时间点**：2026-10-03；**核实方式**：用户 §416/§417 装机走查回执「保存到本地的时候，如果改了密钥文件的名字，保存后默认使用的还是原来默认的名字」+ 代码直读：
  建库收编（`DatabasePickerKeyFileDeliveryController.adoptOnCreate`）时副本显示名取**建议名**
  （`resolution.sourceDisplayName ?: suggestedFileName(vaultName)`，生成型因子此刻尚无真实文档名，
  这是当时的最优猜测）；`saveTo` 写盘成功后**未**按用户实际命名的 SAF 文档回写副本显示名 ⇒
  解锁页「已自动载入记住的密钥文件: xxx」恒显示建库默认建议名。
- **验收标准**：  
  ① `saveTo` 写盘成功后、密钥字节擦除前，按目标 SAF 文档的实际显示名（`querySafDisplayName`）回写本库副本
  （`vaultCopyStore.save(dbId, bytes, actualName)`，同字节重封存，显示名以用户保存的为准）；  
  ② 实际名查询失败（提供方不支持）时保持现名不阻断保存回执；  
  ③ 全量 test 绿 + 门禁全 PASS；真机走查「改名保存 → 冷启动解锁页提示显示用户实际命名」留痕。
- **关联**：`ISSUE-P2-460` §416 批次交付链的走查回执产物；与 `ISSUE-P2-461`（§417）同走查轮发现。

## 2. 整改

`DatabasePickerKeyFileDeliveryController.saveTo` 写盘成功路径（`Dispatchers.IO` 内、密钥字节
`fill(0)` 擦除**之前**）新增回写：`querySafDisplayName(appContext, targetUri)` 取用户在 SAF
选择器里最终确定的文档名，非空即 `vaultCopyStore.save(pendingDbId, bytes, actualName)`
同字节重封存本库副本——此后解锁页「已自动载入记住的密钥文件: xxx」与副本元数据均以
**用户保存的命名**为准。查询失败（提供方不支持 DISPLAY_NAME）保持现名，不影响保存成功回执。

擦除契约保持全覆盖：`bytes.fill(0)` 移回成败两路径共同收口（回写在擦除前完成）。
取证日志新增 `副本显示名已按用户保存命名回写` 一条。

## 3. 过程留痕

1. 首版实现把 `bytes.fill(0)` 只放在成功分支——失败路径不再清零，违反密钥材料擦除铁律；
   复查即改回「成败两路径共同收口」，回写插入点在擦除之前。
2. 该路径核心动作（SAF 写盘 + 文档名查询）无 JVM 实现（无 Robolectric），单测无鉴别力，
   不变量由走查留痕锁定（AC③）。
