## 2. 整改

### 2.1 AC①：单一词汇表（条目 `MERGED_SCALAR_FIELDS` / 分组 `MERGED_GROUP_FIELDS`）

每侧定义一份「字段描述符」表（`displayName` / `read` / `write` 三元组，`write` 闭包内的泛型擦除转型由词汇表自身绑定同一字段保证不错位）：

- 条目 `KdbxEntryMerger.MERGED_SCALAR_FIELDS`：`iconId` / `customIconId` / `overrideUrl` / `qualityCheck`；
- 分组 `KdbxGroupMerger.MERGED_GROUP_FIELDS`：`name` / `notes` / `iconId` / `customIconId` / `parentGroupId`。

`isModified` / `isGroupModified` 的标量判定段与合并函数的取胜段**同表驱动**（`any { read(base) != read(current) }`），结构上杜绝两份清单再漂移。分组侧原四个手写 `when` 块逐字段核验与新实现**逐项等价**（`lv == rv` 与原 `local == remote` 分支、LWW 兜底次序一致），新增 `customIconId` 一项。

### 2.2 AC②：LWW 明确裁决 + `modifiedFields` 留痕

- **干净合并**（单侧变更 / 双侧同值）：取变更侧 / 本地侧，不进冲突清单——与标准字段既有口径一致；
- **双侧异值**：按 `times.lastModificationTime` 的 LWW 取胜（与标准字段冲突的取胜口径一致），并把字段显示名记入 `diffFields` ⇒ 产出冲突对，`PROMPT_USER` 与 `AUTO_MERGE`（其 KDoc 自明「同字段分歧转用户决策」）下均交用户——**不再静默**。分组无冲突清单通道（分组本就无冲突对模型），按 LWW 明确裁决，与 `name` / `notes` 既有口径一致。

### 2.3 AC③：`qualityCheck` 适用范围声明

已写入 `KdbxEntryMerger` 词汇表 KDoc：本仓**无写入者**（仅序列化写出 / 健康检查读取），保留在词汇表内是为合并 KeePassXC / 官方桌面端产生的改动（对端关闭某条目质量检查后同步回本端），**非空转判定**；本条正文（本节）同步留痕。

### 2.4 既有行为兼容性

- `mergeScalarFields` 以 `local` 为底版仅覆写四标量取胜值，其余字段仍走原 `copy` 装配——未变动字段的产物与整改前逐字段一致；
- 图标等标量分歧**新增**冲突对：此前静默丢值的场景现在 `AUTO_MERGE` 默认策略下也会转用户决策——这是 AC② 要求的语义变化，非回归；既有合并用例（`KdbxMergerTest` / `KdbxMergerV2Test` / 等价性测试）全绿证实既有面未动。
