# §527 同步检查点修订绑定实体机验收批次

<a id="s527"></a>

## 1. 闭环范围

本批关闭 ISSUE-P2-624。问题是本轮同步已经上传并确认 A 后，用户可能在检查点登记前保存 B；若检查点摘要了“当时当前文件”并把 B 当成 A 已同步，锁库重开后远端 C 可能直接覆盖 B。

## 2. 实施与验收

- 同步周期保留本轮实际确认收敛的数据库对象身份。检查点通过 DatabaseSessionWriteIntents.digestStableFileFor(expectedDatabase) 在会话提交锁内确认仍是同一数据库、已提交状态和同一正式文件，并在 IO 调度器读取摘要；修订已变化或仍未提交时不产生摘要，因此不登记检查点。
- Provider 目标描述由同一配置快照产生，路径或端点变化不会复用另一目标的检查点。
- app barrier/cold-start 用例 SyncColdStartRemoteOnlyDifferenceTest：9 项通过，0 失败、0 错误。用确定性 barrier 在 A 结算后、检查点摘要前提交 B，确认 B 不会被记成已同步；锁库重开并给出只含 A 和远端修改的 C 后，进入合并/冲突且 B 保留。
- API 37 Redmi 4X 实体机运行 SyncCheckpointRevisionDeviceTest：1 项通过，0 失败、0 错误。实际文件对照确认：A 有稳定摘要；未提交 B 无正式摘要；B 提交后摘要不同；关闭并重开后 B 内容仍在，摘要与提交后相同。
- 非空设备 XML：app/build/outputs/androidTest-results/connected/api37-evidence/TEST-SyncCheckpointRevisionDeviceTest-API37.xml，设备序列号 1c859bcc7d24。
- app JVM 全量套件 2522 项通过，0 失败、0 错误。

## 3. 限制

- 本批用确定性 Provider 控制 A/C 远端内容；不需要真实 HTTPS 服务来验证本地数据库修订与检查点的绑定。
- 数据库摘要仍需读取正式文件；读盘位置与大库主线程响应另见 §526。该检查点不作为 P2-621 持久化恢复状态的替代。
