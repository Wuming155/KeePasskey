## 1. 核实、裁决与整改

### 1.1 核实（用户问题的如实回答，先于改动）

用户问「密码库搜索框下面有三个常驻的选项，分别是 passkey、应用、通行密钥，这是什么？」——
代理读码核实后如实回答三件事：

1. **它们不是内置分类**：该行是 `VaultFilterChipRow`（`VaultListFilterChips.kt`，`ISSUE-P3-297` 处置③），
   芯片标签＝`buildAvailableTags` 对**当前库全部条目的 `tags`** 精确去重 + 大小写不敏感排序；
   用户所见三枚即其库内标签，顺序 `passkey`（`p`=0x70）→ `应用`（0x5E94）→ `通行密钥`（0x901A）
   与 `String.CASE_INSENSITIVE_ORDER` 的升序完全一致（这一处顺序自洽正是「它们是库内数据而非预置项」的判别依据）。
2. **行为**：点一枚 = 只显示带该标签的条目（`selectedTag in entry.tags`），再点取消；会话态不持久化；
   回收站内不渲染；库里既无标签也无收藏时整行隐藏。
3. **标签来源**：编辑页「标签」字段手填或导入 / 合并 `.kdbx` 带入——全仓**无**任何自动打标签的代码路径
   （`grep` 全仓 `tags = ` 仅见投影 / 合并 / 写协调器的**透传**，无字面量写入）。

### 1.2 用户裁决与三选项问答

代理在动代码前把「同一条行里还含**唯一**的『只看收藏』入口」这一后果单独提出（高级搜索的字段范围**不含收藏**），
给出三选项并请用户定夺；用户选定 **整行移除**（另两选项：只删标签芯片保留收藏 / 收藏挪进三点菜单）。
**据此本批不新增任何替代入口**——用户明示「有高级搜索就够了」。
