## 1. 条目正文（原样收录）

### `ISSUE-P2-278`：同步周期起点之后的本地编辑被「远端整库接管」静默覆盖（写路径不参与本周期互斥）

- **核实时间点**：2026-09-23 经接管前置判据与写路径互斥两侧核对。
- **核实方式**：`isDirty`（`SyncCycleRunner.kt:163`）与 `hasLocalContentChanged`（`:139`）**均只在 setup 取一次**；接管前置为「setup 时无本地变更 且 `remoteBytes != localBytes`」（`SyncCycleRemoteOutcomes.kt:38/42/44/69-73`）；`SyncCycleRunner.kt:204-205` 注释自陈「UI 写路径不取本周期 `SyncSessionState.mutex`」；`save()` 不推进基线（`DatabaseSession.kt:261-322` 不动 `session.lastSyncedDb`）；`isSyncing` 是纯 UI 态（`VaultListComponents.kt:63-96`），全仓无写路径 gate。
- **后果与边界**：网络往返期间用户编辑并保存（DIRTY 被自身 `save()` 复位）⇒ 走远端接管并落盘，该编辑从内存与文件**同时消失**；合并支同理（`SyncCycleRunner.kt:380` 的 `updateDatabaseMeta` 整树替换）。窗口须有真实远端变更，故窄于 `ISSUE-P1-275`（已闭环，见 `RESOLVED_LOG.md` §272），但同属「同步与用户写入无互斥」一族。`applyForcedConflictStrategy:184-191` 属用户显式策略（`:171` KDoc 已声明覆盖语义），**不计入本条**。
- **涉及文件**：`app/src/main/java/com/keepasskey/app/sync/SyncCycleRunner.kt`、`app/src/main/java/com/keepasskey/app/sync/SyncCycleRemoteOutcomes.kt`、`database/src/main/java/com/keepasskey/database/session/DatabaseSession.kt`。
- **验收标准**：AC① 接管 / 合并**落库前**重取一次会话脏态与内容摘要（或令写路径参与同一互斥），二选一但须单点化；AC② 确有未同步编辑时如实转为冲突流程或中止本周期，禁静默接管；AC③ 竞态用例：setup 后注入一次保存，断言「不丢编辑」（含 `updateDatabaseMeta` 侧）；AC④ 若裁定「同步窗口内禁编辑」为交互取舍，须登记 `PD-*` 并在界面呈现，禁保留现状不声明。

**开工前前提复核（2026-09-23）**：成立。`isDirty` / `hasLocalContentChanged` 仍仅在 `setupCycleContext` 取样一次；`handleRemoteSynced` 接管支仍直达 `loadAndApplyRemoteBytes`；合并侧三处采纳点（`autoMergeAndUpload` 两处 `updateDatabaseMeta { mergedDb }`、`adoptMergedDatabase` 一处）均无窗口内编辑校验；写路径（`SessionContentMutations` 全部入口）确为 copy-on-write 实例替换——这是守卫判据得以成立的前提。

## 2. 整改

### 2.1 方案裁决（AC① 二选一 → 取「落库前重取」，且比条目预想更强：无 TOCTOU）

条目给的两条路：① 落库前重取会话脏态与内容摘要；② 写路径参与同一互斥。**② 被否证**：`DatabaseSession.save()` 持的是会话自有 `Mutex`，而同步周期在持 `SyncSessionState.mutex` 期间会多次调 `save()`（R3 预存、H3 落盘），若写路径改持同一把锁即自死锁；且 UI 保存阻塞于网络级同步周期属可用性倒退。故取 ①。

单点化落点 = **会话层原子「校验-采用」**：`SessionContentMutations.adoptDatabaseIfUnchanged`（`DatabaseSession` 同名委托）。判据不用「重取脏态 + 内容比较」（O(全库) 且有 `times` 豁免面的口径争议），而用**实例身份**——`SessionContentMutations` 全部写入入口均为 copy-on-write（`databaseFlow.value` 必被替换），故「会话树仍 === 周期起点实例」⇔「窗口内无本地编辑」；校验与采用在**会话 Mutex** 内一次完成，与全部写路径互斥，**无 TOCTOU**（这是比重取-再判更强的不变量）。已知保守面：`save()` 触发按龄修剪历史时也换实例（误判 ⇒ 本轮如实中止、下轮收敛），已在 KDoc 声明——宁可误中止，不可静默丢编辑。

### 2.2 改动清单（五个落库点全部收口）

| 落库点 | 文件 | 整改 |
|---|---|---|
| 远端整库接管 | `SyncDatabaseCodec.loadAndApplyRemoteBytes` | 返回值 `Boolean` → `ApplyRemoteResult` 四态（`APPLIED/PARSE_FAILED/SAVE_FAILED/SESSION_DIVERGED`）；新增 `expectedSessionSnapshot` 形参，非 null 走 `adoptDatabaseIfUnchanged`，未采用的远端解析树就地 `clearSensitiveData()` |
| 接管分支编排 | `SyncCycleRemoteOutcomes.handleRemoteSynced` | 传 `ctx.localDbSnapshot`（周期起点实例）；`SESSION_DIVERGED` ⇒ `SyncOutcome.Error(sync_error_local_changed_during_sync)`（新字符串，中英成对） |
| 自动合并采纳 ×2 | `SyncConflictAutoMerge.autoMergeAndUpload` | 新增 `expectedSessionSnapshot` 形参；函数顶部单点 `adoptMergedIfSessionUnchanged()` + 上传前预拦 + 两处采纳点（直传成功 / 412 重试成功）各校验一次；中止统一出口 `abortDiverged()`（四棵树按身份集合判定擦除） |
| 用户裁决采纳 | `SyncConflictController.adoptMergedDatabase` + `resolveConflicts` 入口 | 待决起点快照 `pendingSessionSnapshot`（`beginPendingConflict` 捕获，**绝不擦除**——它是活动会话树的身份别名）；入口校验不通过即废弃冲突会话如实报错；采纳前再经 `adoptDatabaseIfUnchanged`（覆盖入口校验之后的上传窗口） |
| 快照透传 | `SyncCycleRunner` × 1 + `SyncCycleRemoteOutcomes` × 2 + `handleConflictMerge` 重入 + `handleResolveUploadSuperseded` | 周期起点实例 `ctx.currentDb` 一路透传至合并采纳点；412 重入轮原样透传（窗口覆盖整个重入过程） |

**显式排除**（条目边界）：`applyForcedConflictStrategy` 的「以云端为准」仍直采（用户显式策略，KDoc 已声明覆盖语义），调用点仅适配新返回类型。

### 2.3 AC②：中止语义

守卫不通过 = `SyncOutcome.Error(sync_error_local_changed_during_sync)`（「同步期间检测到新的本地修改，为避免覆盖已中止本次同步，请重新同步」）。本地编辑保留在会话树中；下一轮同步按既有 `isDirty` / 内容比较判据走冲突流程收敛——禁静默接管的口径达成。

### 2.4 AC④：不适用

未裁「同步窗口内禁编辑」（写路径保持不取锁），故无 `PD-*` 登记面。
