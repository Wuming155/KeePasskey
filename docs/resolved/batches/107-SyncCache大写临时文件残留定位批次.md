### 107.3 结论与两项残余（**均登记为已接受残余**）

**结论（置信度如实标注）**：
- 残留**不是任何写入者产出的磁盘文件**，而是 NTFS 目录枚举鬼影——**高**（四路交叉取证）。
- **本仓源码非写入者**：**高**；**外部进程非写入者**：**高**（外部写入者必留实体，四路独立手段一致否认其存在）。
- **具体由 Windows/NTFS/过滤驱动哪条内部路径产生：未证实**。旁证：纯文件系统 churn **20 000 轮 0 命中**（与「写」无关，与「删后的目录索引」有关）；`isFile` 假阳性率两轮测量**互相矛盾**（100% vs 0%）⇒ 鬼影**非单一稳定形态**。本机 `WinDefend` 已停止、由 Kaspersky `avp.exe` 接管，`fltmc filters` 权限被拒 ⇒ **不能排除**过滤驱动参与（不影响上述结论）。

**残余 1：口径更正后仍有约 3% 假阳性**（`isFile` 不是百分百可靠的判别式）。
实测：修复前定向复跑 **107 次 / 7 次失败（≈6.5%）**；口径更正后 **30 次 / 1 次失败（≈3.3%**，经取证仍为鬼影）。已实测的更强判别式：**同路径短时有界重枚举（15 ms × 4 次）在 380 例假阳性上 0 命中**——本批**未采纳**（避免引入时序依赖断言），留档备后人按需采纳。

**残余 2：`SyncCache.deleteOrphanTmpFiles` 的匹配为大小写敏感**（`file.name.startsWith(key) && file.name.endsWith(SUFFIX_TMP)`，`SyncCache.kt:381`），对**大写拼写**的孤立 tmp 不匹配。当前所有写入者均为小写，**不构成本缺陷根因**；仅在引入大写命名写入者或外部工具落临时文件时才会漏清。**本批刻意未改产品代码**（无根因依据不动产品代码——正确克制）。

### 107.5 验证证据

- **同族风险面扫描（实际执行）**：`grep -rn "listFiles()\|\.list()" --include=*.kt */src/test`
  - **受影响（已改）**：`SyncCacheTest` 2 处；`SyncCacheEvictorTest:89/:142`（后者为**急求值断言消息**，每次用例多枚举一次）。

  - **范围声明（不得读作全仓结论）**：仅扫 `*/src/test` 下 `*.kt`；**未**扫 `androidTest`、`*.java`、`*.kts`、`tools/`、`docs/`。
- **主控复核（不照抄子代理结论）**：① 逐行读过断言改动，判定**不构成放宽**（真残留仍必红），并要求删除其中一段**恒真死断言**（`filterNot { !isFile }` 后再断言 `isFile == false`，永远成立）——已删；② 复核确认**全部探针已撤净**（5 个探针文件、`SyncCacheResidueProbe`/`RuleChain`、硬编码路径 `D:/tmp/probe/**` 均已移除，`sync/src/test/.../engine/` 下只剩 3 个正式用例文件）；③ 行长尾以**字节级 `od -c`** 复核为 **LF**（此前用 `grep -c $'\r'` 判定行尾曾得出错误结论，该仪器教训已在 §105.4 留痕）。
- **主控在提交前复核中发现并纠正的一处「无谓且收窄」改动（如实留痕）**：同族第二处 `SyncCacheEvictorTest` 的原判据本就是
  `syncDir.walkTopDown().filter { it.isFile }.toList()`——**已经是以「实体存在」为判据**，故子代理首版把它改为
  `listFiles().orEmpty().filter { it.isFile }` **既未改善鬼影问题**（`isFile` 两侧同源），又**丢掉了递归**（缓存目录一旦出现
  嵌套子目录，其中残留将不再被发现）⇒ 属**收窄覆盖**。主控已把该助手恢复为 `walkTopDown()` 递归实体判据
  （断言强度与改前**完全一致**），**该文件的改动因此收敛为「仅丰富失败信息」**（额外列出目录索引条目名以便区分鬼影与真残留），
  并在 KDoc 中写明「刻意保留递归」的理由与该形态的 3% 残余。⇒ 结论更正：本批**真正修正断言判据的只有 `SyncCacheTest` 两处**；
  `SyncCacheEvictorTest` 两处仅为**失败信息增强**。
- **最终验收**：本批两个用例类定向复跑 **BUILD SUCCESSFUL**，本批改动文件**告警 0 / 编译错误 0**。

### 107.6 边界与残余（如实声明）

1. **机制层面未钉死**（可接受粒度）——只到「NTFS 枚举鬼影」分类，未定位到 Windows/NTFS/过滤驱动的具体内部路径。
2. **约 3% 假阳性残余仍在**（见 107.3 残余 1）：本批两处断言仍有小概率因鬼影而假红；更强判别式（有界重枚举）**已实测但未采纳**。
3. **同族扫描范围有限**（见 107.5），**不得**据此声称「全仓已无同类模式」。
4. 全量 `:app:testDebugUnitTest` 在本批施工期间存在一项**与本条无关**的红项（`ClipboardSecurityManagerScheduledClearTest`，属 `ISSUE-P3-144` 面、另一工作线在改）与一条既有告警（`ExportedComponentHygieneTest.kt:91:37`）——**均不在本批改动文件内**，故本批验收以两个用例类的定向复跑为依据。
