# §281 工程卫生硬门禁：行数分档与超长函数 fail-closed 进 CI 批次

> 本批次由 2026-09-23 全仓工程卫生梳理触发（**非** `ACTIVE_ISSUES.md` 既有条目整改），
> 收口「无 detekt / ktlint 硬门禁——行数 / 函数长度只靠人工与自研脚本」缺口。
> 取向＝**不引入 detekt**（全量阈值与现存 tier2 债务冲突，首跑即红且无法收敛），
> 改把既有自研度量挂进 CI **fail-closed**。本批**零测试增减**、**零生产代码改动**。

## §1 背景

工程规则的行数 / 函数长度软阈值此前只有本地脚本可量，CI 无任何兜底：
`count_line_tiers.py` / `long_functions.py` **恒退出 0**（只打印），漏跑或越过阈值都不会红。
§280 已把 `tier1(>500)` 与 `functions_ge_100` 收到 **0 / 0**，若无硬门禁即可能静默回潮。

## §2 整改内容

### 2.1 两个度量脚本改 fail-closed

| 脚本 | 原 | 现 |
|---|---|---|
| `tools/doc/count_line_tiers.py` | 模块顶层打印，恒 0 | `main()`：`tier1(>500)` **恒 0** + `tier2(400~500)` **棘轮预算** `TIER2_BUDGET=37`（§280 收工读数，只紧不松）；越过任一即退出码 1 |
| `tools/doc/long_functions.py` | `return 0` 恒 0 | 存在任何 ≥ 阈值 的函数即 **1**；CI 用默认阈值 **100**（§280 收工线）；传 40 等仅作本地普查 |

**棘轮口径**：`TIER2_BUDGET` 只允许随拆分**下调**，禁止「先超标再补登记」。改常量须在批次文档留痕。

### 2.2 CI 新增 `hygiene-gate` job（`.github/workflows/build.yml` 门禁 0）

秒级、无 JDK / NDK 依赖，五条机检串行 fail-closed（**严禁** `|| true` / `continue-on-error`）：

1. `count_line_tiers.py` — 规模闸门
2. `long_functions.py` — 超长函数闸门（阈值 100）
3. `check_md_links.py` — 文档相对链接
4. `check_resolved_index_sync.py` — 归档索引双向一致
5. `check_tautological_assertions.py` — 重言断言

与 `fast-gate` / `native-gate` / `rust-supply-chain` / `device-gate` 并行；任何一条非 0 即整 job 红。

### 2.3 `AGENTS.md` §5 同步

两脚本描述补 fail-closed 语义；新增 `hygiene-gate` 入口行（含「严禁吞退出码」纪律，对齐
「构建失败则 fail-closed 直接失败——严禁再引入吞退出码的开关」既有口径）。

## §4 如实声明

- **未引入 detekt / ktlint**：现行全量阈值（函数 ≤40 / 文件 ≤300 等）与 tier2 37 个文件的既有债务冲突，首跑即红且无豁免表；本批取向是「把已达成的硬线（tier1=0、functions_ge_100=0）与 tier2 棘轮钉进 CI」，软阈值仍靠人工 + 本地脚本。
- **CI 未在真实 runner 复跑**（本机无法端到端验证 `hygiene-gate` job）；改动为纯 YAML 步骤串接既有脚本，脚本本体已在本机逐条现跑 EXIT 0。
- 未触 `*/src/**` / `crypto/src/main/rust/**` / `*/src/androidTest/**` / `参考项目/` ⇒ **无设备侧必跑项**。
- 未跑 `lint` / `assembleRelease` / 截图门禁 / KPEX 对拍。
- `TIER2_BUDGET=37` 是**棘轮起点**而非「允许 37 个大文件」的产品口径；拆分降档后应下调。
