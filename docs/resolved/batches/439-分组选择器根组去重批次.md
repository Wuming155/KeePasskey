## 439.0 任务口径（硬约束）

1. 仅 UI 呈现去重，**零落库语义变化**：新建 / 移动对 `groupId == null` 与 `groupId == 根组id` 本就等价（均归根组），过滤根组与哨兵并存只是消除 UI 重复项。
2. 根组是投影列表里**唯一** `parentId == null` 的节点（顶层子组 `parentId` 为根组 id，非空）；过滤判据仅排除该唯一节点，不影响顶层子组与回收站子树排除逻辑。
3. 编辑页哨兵高亮须覆盖「条目位于根组」的情形：根级条目 `groupId` 为根组 id（非空），原哨兵仅按 `groupId == null` 判选中会丢失高亮。

## 439.1 整改内容

1. `EntryEditGroupAndAppSections.kt`（新建 / 编辑页「所属群组」横排）：`selectableGroups` 过滤加 `&& it.parentId != null`，使根组不再作为普通 chip 出现；另取 `rootGroupId = availableGroups.firstOrNull { it.parentId == null }?.id`，哨兵「根目录 (未分类)」选中判定由 `groupId == null` 改为 `groupId == null || groupId == rootGroupId`。
2. `VaultListDialogs.kt` 的 `VaultBatchMoveDialog`（移动对话框，单条 + 批量复用）：目标列表 `selectableGroups` 过滤加 `&& it.parentId != null`（哨兵「移动至根目录」`onMove(null)` 不变）。

根因（`VaultGroupCoordinator.groupsFlow()` → `db.rootGroup.allGroups()`）：`KdbxGroup.allGroups()` 把**根组自身**也拍平进列表，根组名即库名、其 `parentGroupId == null` ⇒ 投影为 `VaultGroup(parentId == null)`；两处选择器各自另有「根目录 / 移动至根目录」哨兵，于是根组以「普通 chip / 行」与「哨兵项」两形态重复出现，落到同一位置（均归根组）。本批只在选择器层排除根组，**投影 `groupsFlow()` 不动**（列表树仍依赖根组渲染）。
