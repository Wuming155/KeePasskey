# §539 P2-632 历史修订句柄同秒碰撞修正与 AVD 闭环

<a id="s539"></a>

**闭环日期：2026-10-18（Asia/Shanghai）**
**条目：** `ISSUE-P2-632`。
**关联：** P2-633 / P2-634 的回滚与字段语义已在 §538 归档；本批修复 P2-632 的旧句柄误命中边界。

## 1. 根因与修正

- 原句柄由 `history index + lastModificationTime.toEpochMilli()` 组成。官方 KDBX 时间写出按**秒**取整；一秒内多个修订可共享同一时间值。头插后，旧下标位置的新快照若具有相同秒时间，旧句柄会被误认为仍命中；历史尾部修剪后，时间戳回退匹配也可能将已删除快照映射到剩余版本。
- `EntryRevisionHandle` 改为随机 UUID 不透明 token，并以 `WeakReference` 注册到实际的历史 `KdbxEntry` 对象；读取 / 回滚只在该对象仍以同一引用存在于当前 history 时成功。修剪、替换、会话重开后对象不再匹配，旧 token fail-closed。映射用 `ReferenceQueue` 清理，不对含密码的快照建立强引用；KDBX 文件时间与 UUID 格式不变。
- 新 JVM 用例覆盖：同秒快照各自有不同 token；头插同秒快照仍定位原对象；已修剪同秒旧对象不得命中剩余快照；未登记与非法 token 均拒绝。
