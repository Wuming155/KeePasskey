### §354.2 AC① 触发面与挂点（平台依据 + 为何不越权）

**触发面裁定＝legacy 无障碍通道的「口令框检测 → 通知」链路**（`LegacyAutofillAccessibilityService`），
本批对其做节流升级与安全面锁定；**不**新增第二条触发链。依据：

1. **系统 Autofill 正常工作时不存在「主动提示」缺口**：框架在口令框聚焦时**自己**弹出填充面板——
   若再发应用通知即双重打扰。Monica 的主动提示同样挂在无障碍检测上，与其 Autofill 服务互补而非并行。
2. **`onFillRequest` 无法观测「系统没展示 UI」**：该回调只在系统**决定**询问填充服务时到来；
   「有候选但面板未出现」在提供方侧不可判定（平台不回传呈现结果），据此发通知＝对每次系统询问
   都打扰，属越权面。⇒ 该挂点判**死**，如实记录不实施。
3. **无障碍检测是唯一非重复的主动面**：本仓 `autofill/legacy/`（§332 落地）在目标应用窗口出现
   可填充口令框时发通知、点按进受保护窗口选择器——**与 Monica `MonicaAccessibilityService:334-363`
   同型**。权限依据：无障碍服务由**用户在系统设置显式启用** + 应用内通道开关（出厂关闭）双闸门，
   无任何越权采集（`LegacyFieldScanner` 只读字段元数据，不物化窗口文本）。
4. **域名字面量裁决（条目预留项）**：通知文案**不入域名 / 不入包名 / 不入条目字段**——固定两句
   静态文案（「检测到密码输入框 / 点按选择要填充的条目」）。理由：目标包名对用户是无意义的
   技术标识，入文案只增加暴露面不增信息量；跨窗口误触风险由点击后的「目标包名复核 + 重扫」
   既有链路承担，与文案无关。

### §354.3 整改内容

1. **AC② 按包冷却节流**（新增 `autofill/legacy/AutofillActivePromptThrottle.kt`）：
   取代原服务内「全局 2 秒去抖」（`NOTIFY_DEBOUNCE_MS`，只挡瞬时毛刺、挡不住停留页反复提示）——
   现为**同包 60 秒冷却**（`COOLDOWN_MS` 命名常量）、跨包独立、时钟回拨 fail-closed 拒绝、
   记忆容量闸门 64 按插入序淘汰；判定纯函数 `shouldPromptAt` + 实例记忆层（与 service 同生命周期，
   不落盘；不经 Hilt——无跨注入点共享需求，同 `serviceScope` 先例）。服务侧
   `postOfferNotification` 先过 `promptThrottle.shouldPrompt(targetPkg)` 再构建通知。
2. **AC③ 通道低调 + 零敏感**：`LEGACY_AUTOFILL` 通道 `IMPORTANCE_DEFAULT → IMPORTANCE_LOW`
   （不发声、不横幅，静默入通知栏）；通知构建仅引用两条零插值静态文案（域名字面量见 §354.2 裁决）。
   **限定如实声明**：Android 不允许代码修改**已创建**通道的重要度——存量安装仍为建立时的
   `DEFAULT`，改动对新装 / 新通道生效（KDoc 同步写明，不虚称全量即时生效）。
3. **AC④⑤ 安全面锁死**（新增 `LegacyActivePromptWiringTest`，7 例源码守卫）：节流接线且旧去抖
   零残留；三态闸门（通道开关 / 库锁定 / 自我排除）齐备且先于通知、自我排除 ≥2 处（事件入口 +
   求值链）+ 黑名单闸门在场；通知点击只指向 `LegacyFillPickerActivity`（受保护窗口选择器）且
   通知构建区无 `ACTION_SET_TEXT` 关联；通道 `IMPORTANCE_LOW` 且不回潮；中英文案零插值 +
   通知构建区无带参 `getString`（防运行时标识混入）。
4. **AC② 用例**：`AutofillActivePromptThrottleTest`（6 例：首次放行 / 冷却边界 0 与 cooldown-1
   拒绝、到期与超期放行 / 时钟回拨拒绝 / 同包冷却跨包独立 / 空白包名 fail-closed / 容量淘汰 /
   reset）。
5. **盘点表修正注（P3-376 遗留项收口）**：Monica `active_fill_notification_enabled` 在 §353 表中
   记「随第 3 批接线」——本批实施时按「做不出**独立**消费点即裁决不做」纪律改判：
   该开关与 `autofillLegacyAccessibilityEnabled` **语义重合**（通知即该无障碍通道的唯一触发面，
   关通知 ⇒ 通道整体静默 ≡ 关通道），双开关只增布尔组合态。⇒ **改判裁决不做**，以本注为准
   （§353 盘点表相应行的「随第 3 批」读作已由本注取代）。
