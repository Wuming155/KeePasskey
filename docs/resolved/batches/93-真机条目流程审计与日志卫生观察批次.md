### 93.2 一处**我自己的误判**及其根因（如实记录，避免后人重复怀疑）

审计中途我一度怀疑「**用户名框被掩码**」（观察到 `●●●●●●●`），并准备登记为缺陷。逐项核对后确认
**是我的误判**：

- 应用侧字段语义**正确**——用户名框无 `PASSWORD` 标志（明文）、密码框有 `PASSWORD`（掩码）、
  TOTP 密钥框有 `PASSWORD`（掩码，正确）；密码强度按实际内容计算。
- **误判根因是我自己的 UI 定位模型错了**：Material 3 的 `OutlinedTextField` 标签是**浮动在输入框内部**
  的（标签 y 落在框的 y 区间**内**），而我按「标签在框**上方**」推算点击坐标，于是**每次错位一格**——
  把密码填进了用户名框、把 URL 填进了标题位。同一错误在本轮内重复出现了三次（每次都靠 dump 才发现）。

**留给后人的可用配方**（已写入本文档，勿再踩）：用 `android layout --flat` 解析后，**取「y 区间包含
标签中心」的那个 `EditText`** 作为目标（`y1 <= labelCenterY <= y2`），**不要**用「标签下方最近的框」，
更不要硬编码 y 坐标——键盘弹出/收起会使布局上下漂移约 100–150 px。

### 93.3 两条日志卫生观察（**未登记为缺陷**，理由随附）

审计收尾时以应用 pid 过滤 `logcat`，除 §92 已记录的两类设计内输出外，另见两项：

1. **`W/com.keepasskey: Cleared Reference was only reachable from finalizer (only reported once)`**
   ——ART 的 GC 警告，提示存在「仅被 finalizer 可达」的对象。**未登记为缺陷**的理由：该警告在 Android
   框架内部（`Parcel` / 文件描述符包装等）亦常见，仅凭一行警告**无法归因到本仓代码**；要转为可整改项
   必须先做一次归因（堆快照 / 分配栈），而当前没有证据表明它对应真实泄漏。**登记为观察项**，
   归因工具已具备（本会话已装 CLI 官方 `android-profiler` 技能：堆快照 / 方法录制 / perfetto trace）。
2. **`W/KdbxXmlParser: SAX 解析器 XXE 加固特性设置失败，已跳过该项: …disallow-doctype-decl=true`
   （带完整栈）**——这是 `buildHardenedParser` 的**逐特性探测**在按设计工作（平台不支持该特性 ⇒
   跳过并告警），**不是缺陷**。唯一可议之处是**日志卫生**：对**预期内**的探测失败打出完整栈，
   每次解析都会重复（合法库也如此），会淹没有效信息。**未改**：该告警文本与栈是 ISSUE-P1-12
   设备侧排查的依据（当时正是靠它确认特性不被支持），删栈会削弱可诊断性；若日后要治理，
   应在**保留「跳过哪一项」结论**的前提下把栈降为 `DEBUG` 或只在首次打印——属独立小项，本批不动。
