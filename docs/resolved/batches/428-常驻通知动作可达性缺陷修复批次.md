# §428 常驻通知动作可达性缺陷修复批次（`ISSUE-P3-440` 二轮回执：通道重要度 `LOW` → `DEFAULT`）

> 批次日期：2026-10-03。
> 触发＝第二轮装机走查回执（用户原话：「如果只能做到只有长按才能出现复制选项，我认为它也没有必要存在，
> 因为太麻烦了。或许你可以参考一下别的项目，比如说 keepassdx、moica，看他们是怎么做的，
> 他们好像可以手动按，不用长按。」）。
> 性质＝**缺陷修复**（不是产品口径调整）：§426 / §427 曾按 `PD-71` 把「动作要长按才出」判为
> **平台既定行为、非缺陷**；本批按用户指路做参考实现对照后，定位到**自家可控的成因**，故修正实现并更正 `PD-71`。
> 装机形态＝debug 版（`com.keepasskey.debug`）；设备＝Xiaomi M332BF / HyperOS OS4.0 / Android 17。

## §1 取证与根因

| 项 | 本仓（修订前） | KeePassDX | Monica |
|---|---|---|---|
| 通道重要度 | **`IMPORTANCE_LOW`** | **`IMPORTANCE_DEFAULT`**（`services/NotificationService.kt:67-72`） | **`IMPORTANCE_HIGH`**（`utils/SmartCopyNotificationHelper.kt:154-165`） |
| 通道静音 | 无（靠发送侧 `setSilent(true)`） | `setSound(null, null)` + `enableVibration(false)` | 通道不显式静音（`PRIORITY_HIGH`） |
| 通知侧额外标志 | **`setSilent(true)`** | 无 | 无（有 `BigTextStyle`） |
| 动作构造 | `Action.Builder(null, …)` | `addAction(icon, title, pi)` | `Action.Builder(0, …)` + `setAuthenticationRequired(true)` |
| 同机表现（用户走查） | 折叠态**不渲染按钮**，须**长按** | 动作**可直接点按** | 动作**可直接点按** |

根因：**MIUI / HyperOS 把 `IMPORTANCE_LOW` 的通知归入「静默通知」**，该分类下通知在折叠态
**不渲染动作按钮**（须展开 / 长按才出现）。本仓 `UNLOCKED_STATUS` 通道恰为 `IMPORTANCE_LOW`
且发送侧再叠了 `setSilent(true)`，双重坐实「静默」分类 ⇒ 用户看到的「只有长按才出」。

参考实现一律以 `DEFAULT` 及以上承载带动作的通知——**「动作按钮要长按」不是平台必然，而是通道重要度选择的结果**。

## §2 整改

- `notification/NotificationChannels.kt`：
  - `UNLOCKED_STATUS` 通道 → 新 id **`keepasskey_unlocked_status_v2`** + **`IMPORTANCE_DEFAULT`**
    （重要度不可程序化修改，故必须换 id）；
  - `ensureCreated` 内**静音下沉到通道层**：`setSound(null, null)` + `enableVibration(false)`
    （原先只靠发送侧 `setSilent(true)`）——「不发声/不震动」由**通道**表达，与决定动作渲染的**重要度**解耦；
  - 新增私有常量 `LEGACY_ID_UNLOCKED_STATUS` 并在 `ensureCreated` 末尾
    `deleteNotificationChannel(...)`：删除旧 `IMPORTANCE_LOW` 通道，避免系统通知设置里残留同名空通道。
- `notification/UnlockedNotificationController.kt`：**去掉 `.setSilent(true)`**
  （该标志会把通知推向 OEM 的「静默」分类），保留 `setOnlyAlertOnce(true)`；
  `setOngoing(true)` / `VISIBILITY_SECRET` / 动作集（`立即锁定` + `PD-69` 字段子集的复制动作）零变化。
- `NotificationChannelSpecTest`：`解锁状态通道为低重要度静默通道` →
  `解锁状态通道为默认重要度（动作按钮可直接点按，§428）`；新增 `解锁状态通道使用迁移后的新 id`。
- **安全面零变化**：`PD-69` 的字段子集（只许用户名 + TOTP）、`VISIBILITY_SECRET`、固定通用文案、
  跨 `PendingIntent` 只带字段名、后台复制不展开明文 UI、既有剪贴板擦除链——**逐条未动**。
  本批只改「通知在系统里的分类」，不扩大任何暴露面。

## §6 如实声明（残余）

- **修复本身未取得装机回执**：本次改动需重装 debug 包，而重装会结束应用进程 ⇒ 库回到锁定态，
  「已解锁常驻通知」在本机**无法自行复现**（需用户解锁后才出现）。故「动作现在可直接点按」
  仍是**按根因与参考实现推出的预期**，须由用户装机回执确认。
- **回执为否时的处置（用户已预先裁决）**：若仍须长按，则按用户原话「也没有必要存在」**移除通知上的
  复制动作**（`UnlockedNotificationCopyAction` / `Receiver` / `EntryTracker` 及其动作集退场，
  `立即锁定` 去留另裁）——不得再以「平台行为」为由挂着不可达入口。
- `PD-71` 已按本批结论**更正**（保留原文 + 新增更正节，不美化历史判断）。
