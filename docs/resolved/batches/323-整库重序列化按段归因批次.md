# §323 整库重序列化按段归因批次（`ISSUE-P3-313` 闭环）

> **批次性质**：量级归因与取舍登记（AC① 按段读数 + AC② 取向登记），无生产代码整改面。

---

## 1. 整改对象

| 条目 | 判据来源 | 本批处置 |
|---|---|---|
| `ISSUE-P3-313` 同步周期「内容一变即整库重序列化」在低端真机上是 4.8 秒 CPU 成本 | §316 实测随批补登 | **闭环**：AC① 按段归因读数（§2.2）+ AC② 取向登记（§2.3 / 限界表 §32）；**红线未触碰** |

## 2. 整改内容

### 2.1 方法（AC①）

新增设备用例 `database/src/androidTest/.../SerializationSegmentAttributionDeviceTest.kt`（`:database:`
androidTest，同模块可及 `internal` 的 `KdbxFile.deriveKeys`）：复刻 §316 同夹具口径
（10,000 条目 ×（4 标准字段 + 1 自定义字段）+ 每 50 条 1 份历史快照共 200 份 + 1 个 2 MiB 附件），
按生产管线（`savePayload`：`[内层头 + XML] → GZip → 外层块加密 → HMAC 块流`）**分段隔离计时**：
XML 写出分别以 ChaCha20 / None 内层流驱动（差值 = 内层流加密受保护字段份额）；GZip 对同一份
XML 字节；HMAC 单独与「外层加密链在 HMAC 之上」链式驱动（差值 = 外层块加密份额）；缓存落盘按
`writeCache` 同口径（tmp + `fd.sync()` + 原子 rename）；端到端 `KdbxFile.save` 与 KDF 单列对照。

### 2.2 AC① 原始读数（Redmi 4X / Android SDK 37，§316 同设备；logcat `P3313Attribution` 原样粘贴）

```
段读数(ms) = 端到端save=7198; KDF(AES-KDF)=767; XML写出(ChaCha20)=4485; XML写出(None)=4250; 内层流加密差值=235; GZip=549; HMAC块流=10; 外层块加密(含HMAC)=30; 内层头(2MiB池)=0; 缓存落盘=23; XML字节=10066277; 压缩后字节=570474
```

对照点（同测试在 AVD Pixel_10 上的第二轮读数，设备基线差异留证）：

```
段读数(ms) = 端到端save=569; KDF(AES-KDF)=135; XML写出(ChaCha20)=288; XML写出(None)=305; 内层流加密差值=-17; GZip=41; HMAC块流=1; 外层块加密(含HMAC)=3; 内层头(2MiB池)=0; 缓存落盘=5; XML字节=10066277; 压缩后字节=570275
```

**归因结论（AC①）**：§316 的 4.8 s 重序列化中，**XML 写出占 ~93%**（本批 4,485 ms + GZip 549 ms
≈ 5,034 ms，与 §316 读数 4,812–4,844 ms 同量级互证）；内层流加密 235 ms（3%）、外层块加密 + MAC
≈ 30 ms（0.4%）、缓存落盘 23 ms（0.5%）均可忽略。成本几乎全部在**纯 CPU 的 XML 生成**
（树遍历 + 字符串编码），不在任何加密层。如实声明：本批端到端读数 7,198 ms 高于 §316 的
4,844 ms，因本测试的端到端含 KDF（767 ms）与夹具构建差异、且受同机热状态影响；分项读数与
§316 主体互证一致，归因结论不依赖绝对值。

### 2.3 AC② 取向评估与取舍登记（本条不预设结论 ⇒ 依归因登记）

| 取向 | 评估 | 处置 |
|---|---|---|
| 复用上次字节 / 跳过重序列化 | 被 `ISSUE-P2-309` 红线禁止（KDBX4 每次保存重生成 masterSeed/IV/KDF salt，字节必漂移；须重证防回滚判据） | **排除** |
| 自研增量写 | 破坏 `.kdbx` 互操作证据纪律（规则 8），工程量与风险不成比例 | **排除** |
| 收紧「需要重序列化」触发判据 | 现状已是最小触发（仅内容变化时重序列化） | **无可收紧** |
| 序列化与缓存覆盖解耦 | 仅省 23 ms（0.5%），不解决主体 | **无意义** |
| XML 生成微优化（编码 / 树遍历） | 收益为个位数量级百分比，属常规性能工程 | **登记为常规工程面，不立条** |

**登记结论**：接受现状——低端机上「改一条即同步」的整库重序列化是 KDBX4 无增量写的格式使然，
残余面（同步完成时延与 CPU/电量成本）登记为已知工程限界 **§32**（`docs/architecture/已知工程限界.md`），
含解除条件。P3-313 就此闭环。
