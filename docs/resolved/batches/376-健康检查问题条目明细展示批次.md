## 0. 原文登记（用户命题 + 核实）

> **ISSUE-P3-405**（核实时间点 2026-09-30；核实方式 = 用户命题 + 代码审计）：密码健康检测只报计数不报条目——用户不知道「哪些是弱密码」。
>
> - **核实方式**：`HealthCheckEngine.analyzeEntries` 已产出 `EntryHealthIssue`（含 `entryId` / `title` / `username` / `riskLevel` / `description`），但 `SettingsHealthController.rescanHealth` 只对弱/复用/过期做 `count` 后丢弃明细；`HealthCheckScreen` 的弱密码审计行仅有计数徽标，无受影响条目列表。
> - **背景**：用户报告「健康检测能找出弱密码，但不知道哪些是弱密码」。引擎明细数据已存在，属 UI 接线缺口，非检测算法缺陷。
> - **整改**：
>   1. `SettingsHealthController` / `SettingsUiState` / 投影层透出 `healthIssues`（含弱/复用/过期）与 `expiredPasswordCount`；
>   2. 健康检查页在弱密码 / 重复密码 / 凭据过期审计行下展示受影响条目（标题 + 用户名 + 风险标签 + 原因）；
>   3. 点击条目经 `Screen.EntryDetail` 跳转详情，便于就地修改；
>   4. 中英文案成对（过期审计行与风险标签）。
> - **验收**：扫描后弱密码计数 > 0 时页面可见对应条目标题列表；点击可进入条目详情；相关单测与 `python tools/doc/gate_readings.py` 全 PASS。

## 1. 根因与整改

### 1.1 根因

引擎层明细完整，控制器只保留计数；健康检查页无「受影响条目」呈现。用户主诉「不知道哪些是弱密码」属 UI 接线缺口。

### 1.2 整改落地

| 层 | 变更 |
|---|---|
| UI 模型 | 新增 `HealthIssueUi` / `HealthIssueRiskUi` + `PasswordRiskLevel.toHealthIssueRiskUi()` |
| 控制器 | `HealthCheckUiState` 增 `healthIssues` / `expiredPasswordCount`；扫描产出明细不再丢弃；`rescanHealth` 拆出 `buildHealthScanSummary` / `applyHealthScanSummary`（压回 `long_functions`） |
| 投影 | `SettingsUiState` + `SettingsUiStateProjection` 透出明细与过期计数 |
| UI | `HealthCountAuditRow` 支持挂明细；新增 `HealthIssueListCard` / `HealthIssueRow`（独立 `HealthCheckIssueList.kt`）；新增「凭据过期」审计行；问题条目可点击 |
| 导航 | `settingsHealthRoute` 接 `onEntryClick` → `Screen.EntryDetail.createRoute`（同 NavHost，返回栈自然回到健康检查页） |
| 文案 | 中英：`health_expired_*` / `health_issue_*` 成对 |

### 1.3 行数拆分留痕

补明细后 `HealthCheckComponents.kt` 一度 506 行（tier1 红）、`rescanHealth` 106 行（`long_functions` 红）；拆出 `HealthCheckIssueList.kt`、把 `HealthTipsCard` 移入 `HealthCheckScreenSections.kt`、控制器汇总逻辑下沉后回绿。**过程缺陷如实**：首轮拆分后 `HealthCheckComponents` 落在 400 行、tier2 变 38 > 预算 37（棘轮只紧不松）⇒ 继续下沉 `HealthTipsCard` 后压回 37/37。
