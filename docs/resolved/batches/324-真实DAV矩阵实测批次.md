**读数 1 —— 签发 ETag 的强/弱形态（原样响应头）**：

```
【Apache/mod_dav】GET /etag-probe
HTTP/1.1 200 OK
Server: Apache/2.4.68 (Win64)
Last-Modified: Thu, 24 Sep 2026 18:52:58 GMT
ETag: W/"12-65c3f1bc65073"                       ← ★ 弱 ETag（W/ 前缀）——mod_dav 本身即弱签发服务器
（PUT 响应无 ETag 头，仅 201 + Location）

【nginx-dav】GET /etag-probe
HTTP/1.1 200 OK
Server: nginx/1.30.5
Last-Modified: Thu, 24 Sep 2026 18:56:22 GMT
ETag: "6ab57256-12"                              ← 强 ETag（mtime-size 形态，无 W/）
（PUT 响应无 ETag 头）
```

**读数 2 —— MOVE `If` 头对弱/强形态预条件的接受性**（`If: <url> ([W/"…"])` 弱 / `(["…"])` 强，
方括号语法为 RFC 4918 §10.4.3 的 If 实体标签记法；圆括号内直接引号属解析错误形态，实测 400，不作为读数）：

```
【Apache/mod_dav】（服务器签发 W/"7-65c3f258d4f41"）
2A 原形态回传  If: <url> ([W/"7-65c3f258d4f41"])              → HTTP/1.1 201 Created   ← 弱比较接受原形态
2B 反模式强化  If: <url> (["7-65c3f258d4f41"])                → HTTP/1.1 400 Bad Request ← 响亮失败（非静默）
2C 对照错值    If: <url> ([W/"deadbeef"])                     → HTTP/1.1 412 Precondition Failed ← If 在 MOVE 上真实生效
2D 对照无 If   MOVE                                            → HTTP/1.1 201 Created
2E If-Match: W/"…"（HTTP 核心强比较 × 弱存储标签）             → HTTP/1.1 412 Precondition Failed ← 恒 412，印证 §272「禁止 If-Match 弱期望」裁决

【nginx-dav】（服务器签发强 "6ab57256-7"）
2A 原形态回传  If: <url> ([W/"6ab57255-7"])                   → HTTP/1.1 204 No Content
2B 反模式强化  If: <url> (["6ab57255-7"])                      → HTTP/1.1 204 No Content
2C 对照错值    If: <url> ([W/"deadbeef"])                      → HTTP/1.1 204 No Content
2D 对照无 If   MOVE                                            → HTTP/1.1 204 No Content
（四形态与无 If 基线完全一致 ⇒ nginx 对 MOVE 的 If 头【整体忽略】——无 412 误报风险，亦无预条件保护）
```

**读数 3 —— PUT+MOVE 事务写兼容性**：

```
【Apache/mod_dav】PUT /tx-tmp → 201；MOVE → /tx-final（目标不存在）→ 201；GET 内容一致 ✓；
覆盖写 MOVE（默认 Overwrite:T）→ 204。
【nginx-dav】PUT /tx-tmp → 201；MOVE → /tx-final → 204；GET 内容一致 ✓；默认 Overwrite:T → 204。
两类服务器 PUT+MOVE 事务写均兼容（201/204 状态序与内容一致）。
```

**AC⑤(a) —— `Overwrite:F` 预条件实验（404 恢复分支 TOCTOU）**：

```
【Apache/mod_dav】MOVE Overwrite:F 且目标已存在  → HTTP/1.1 412 Precondition Failed  ← Overwrite:F 被真实尊重
【Apache/mod_dav】MOVE Overwrite:F 且目标不存在  → HTTP/1.1 201 Created
【nginx-dav】     MOVE Overwrite:F 且目标已存在  → HTTP/1.1 412 Precondition Failed  ← 同样尊重（目标内容未被覆盖，实测保持 tx-payload-002）
【nginx-dav】     MOVE Overwrite:F 且目标不存在  → HTTP/1.1 204 No Content
```

## 3. 判定（AC②）与裁决

1. **「回传原形态」取向：实测证实。** 决定性证据是 **mod_dav（参考实现）自身签发弱 ETag**
   （`W/"size-mtime"`）——§272 所担心的「弱 ETag 服务器」不是理论类，就是本矩阵的参考实现；
   在其上「弱签发 → 原样弱回传 → If 弱比较」实测通过（201），而强化形态 400 响亮失败、
   错值 412 如实暴露冲突。nginx（强签发）对 MOVE 的 `If` 整体忽略：回传原形态无任何 412 副作用。
   两条路径均不产生「静默覆盖 / 数据丢失」，§272 取向按 AC② 证实分支闭环。
2. **AC⑤(a) 404 恢复分支 TOCTOU：非真实残余（对实测矩阵）。** `Overwrite:F` 在 Apache 与
   nginx 上均被真实尊重（目标已存在 → 412，内容未被覆盖）；本仓 404 恢复分支经
   `WebDavSyncProvider` 下传的 `Overwrite: F`（`remoteExists` 未知时现探 PROPFIND 后置 F）
   在「探测—写入」窗的并发创建竞争会被服务器以 412 如实暴露 ⇒ 不需要换用 `If` 预条件。
3. **AC⑤(b) S3 兼容端：未执行**（本机无 S3 端点 / Docker 不可用）。S3 类路径按既有产品口径
   走原子条件 PUT（`If-None-Match:*` / `If-Match`），残余维持原登记。
4. **AC③ 标注**：Nextcloud（Sabre/DAV 类）、IIS 未执行——本机无对应运行时 / 需管理员启用，
   环境不可得；这两类样本的补充实测义务随限界表 §28 的收窄残余继续开放。
5. **裁决透明声明**：条目 AC④ 原文「环境不可得期间维持开放」针对 §272 当时「完全无证据」状态；
   本批已在**可取得环境**（含参考实现 mod_dav，且其为弱签发服务器本身）完成 AC① 三项读数并
   触发 AC② 证实分支，按 AC② 闭环，未取得的环境按 AC③ 标注并把残余收窄登记入限界表 §28
   （残余面由「四类全部未证」收窄为「Nextcloud / IIS / S3 类样本未证」）。
