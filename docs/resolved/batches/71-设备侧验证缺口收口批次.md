### 71.1 三项逐项判定

| # | 待验证行为 | 判定 | 实测证据（可复现） |
|:--:|---|:--:|---|
| 1 | 敏感对话框窗口的 `FLAG_SECURE` 是否**真实生效** | **PASS** | 打开「新建密码库向导」（`CreateVaultWizardDialog`，7 处接线点之一）后 `dumpsys window windows`：**对话框窗口** `Window #6 … fl= DIM_BEHIND SECURE SPLIT_TOUCH HARDWARE_ACCELERATED`，**Activity 窗口** `Window #7 … fl= LAYOUT_IN_SCREEN SECURE …`；点「取消」关闭后**仅剩 1 个应用窗口**且 `SECURE=True` ⇒ **未误清** Activity 的 flag（`SecureDialogFlagPolicy.onDispose` 只撤销自己施加的） |
| 2 | 附件缓存**冷启动清理**端到端 | **PASS** | `run-as … touch cache/attachments/probe.bin`（T0 探针落盘）→ `am force-stop`（T1 **探针仍在**，证明进程被强杀时无回调可执行、即 F-13 缺口）→ `am start` 冷启动（T2）→ `run-as … ls -la cache/attachments` **目录为空** |
| 3 | `SecureDialog` 是否**静默 fail-safe 空操作** | **PASS** | 第 1 项已证对话框窗口带 `SECURE`；该 flag **只可能**由 `SecureDialogWindowEffect` 施加（`FlagSecureGuard` 仅作用于 Activity 的 `decorView`，对话框是独立窗口，不继承 Activity flags），而该 effect **仅在** `dialogWindowOrNull()` 解析到 `DialogWindowProvider` 时才 `addFlags` ⇒ 真机上**确实取到了 provider**，非空操作 |

**截图面佐证（第 1 项的「应为黑屏」口径）**：对话框开启时 `adb shell screencap` 全屏
**meanLuma = 0.43 / 255**（720×1280 采样 14400 点，其中非黑样本仅 **38** 点，来自状态栏等**独立**窗口）；
**对话框位于最上层却完全不出现在截图里**——若其窗口无 `FLAG_SECURE`，其内容会正常叠在（被遮蔽的）
Activity 之上。故该证据对「对话框窗口」是**有区分力的**，不只是「整个应用都黑」。

### 71.4 过程缺陷（如实留痕）

1. **adb shell 复合命令被双层引号吞掉**：首次探针写入用 `run-as … sh -c "mkdir -p … && echo … > …"`，
   设备侧实际收到 `mkdir: Needs 1 argument` ⇒ **静默未写入**，随后的「目录为空」险些被当成 PASS。
   ⇒ 纪律：adb shell 内**不要**依赖外层引号传递复合命令，优先用**单个 toybox 命令**
   （本次改为 `run-as … touch <path>`）；**每次实测都必须先证明前置条件成立**
   （本次已加 T0「探针必须真的落盘」断言）。
2. **UI dump 拿到的是系统窗口**：设备当时处于 `mWakefulness=Dozing` + 通知栏展开，
   `uiautomator dump` 与 `mCurrentFocus` 全部指向 `NotificationShade`，一度误判「应用无界面」。
   ⇒ 纪律：设备侧 UI 断言前先确认 `mCurrentFocus` **属于被测包**；
   必要时先 `svc power stayon true` + `settings put system screen_off_timeout` +
   `input keyevent KEYCODE_WAKEUP` + `cmd statusbar collapse`。
3. **AGP 在 device 测试后会卸载被测应用**：`connectedDebugAndroidTest` 结束后 `am start` 报
   `Activity class does not exist`（应用已被 uninstall）。⇒ 顺序建议：**先做 UI / ADB 实测，
   再跑 `connectedAndroidTest`**，或跑完重新 `adb install`。
4. **实测后已恢复设备原状**：卸载调试包（`adb uninstall com.keepasskey` 返回 Success）、
   屏幕超时与 stay-on 设置复位——避免调试包以**同包名不同签名**留在用户机上，
   影响后续正式包覆盖安装。
