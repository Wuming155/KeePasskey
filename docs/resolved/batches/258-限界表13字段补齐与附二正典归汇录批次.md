**「边界（不得据本条外推）」（条目 AC「经裁决后另写入并留痕」路径；本段即留痕）**：
批次 139 / 114 / 120 与汇录 §13 均无可搬句（§1.1 ④ 实测），按条目给出的两个候选裁决合写为：

> `- **边界（不得据本条外推）**：① **不得**读作「锁库后内存中已无任何验证码」——即使码已过期，`Map` 中的字符串仍驻留至 ViewModel 被销毁或下次刷新（见「事实」），解除条件中的 `clearLiveCodes()` 是**待建**机制而非现状；② **不得**据此要求在本通道之外另建擦除路径——本条只登记 `ui/model/TotpCountdownTracker.liveCodes` 一处，其它驻留点各自见其登记与解除条件。`

裁决理由（对应候选原文）：
- **候选 ①「不得读作『锁库后内存中已无任何验证码』」**——本条的解除条件以将来时描述 `clearLiveCodes()` 机制，
  粗读易误作现状；且汇录 §13「为什么维持现状」② 的「按周期失效」说的是**码值失效**，不是**字符串从内存消失**。
  故边界同时钉住两点：过期码字符串仍驻留；解除条件是待建机制。
- **候选 ②「不得据此要求在本通道之外另建擦除路径」**——本条只登记 `TotpCountdownTracker.liveCodes` 一处；
  其它明文驻留点（§1.1 附件快照、§1.6 池内擦除、`ISSUE-P2-65` 口径下的其它点）各有自己的登记与解除条件，
  不得援引本条外推要求。

**§13 最终字段序**（登记纪律「事实 → 边界 → 依据 → 解除条件」；解除条件与依据的先后沿用本表 §2.1 / §6 既有惯例
「事实 → 边界 → 解除条件 → 依据」）：`**事实**：` → `**边界（不得据本条外推）**：` → `**解除条件**：` → `**依据**：`——
机检断言四字段齐备且顺序正确：**True**。
