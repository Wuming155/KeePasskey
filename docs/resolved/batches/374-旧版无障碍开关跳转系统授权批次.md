# §374 旧版无障碍开关跳转系统授权批次（`ISSUE-P2-405` 闭环）

> **批次性质**：用户直报体验缺陷整改（同轮登记并闭环）。
> 用户命题（2026-09-30）：「点击旧版自动填充服务（无障碍）。打开这个开关没有反应，正常应该直接跳转无障碍权限界面，然后自己授权。另外你再查一下这个开关是不是真实开关？链路有没有打通？」

---

## 1. 排查结论（先答用户两问）

### 1.1 开关是不是真实开关？

**是。** §332 起链路齐备：

| 环节 | 证据 |
|---|---|
| 读写键 | `K_AUTOFILL_LEGACY_ACCESSIBILITY_ENABLED` 成对（`ExtendedSettingsStore`） |
| UI 投影 | `SettingsUiStateProjection` 取 `extState.autofillLegacyAccessibilityEnabled` |
| 服务消费 | `LegacyAutofillAccessibilityService.evaluateAndOffer` 真求值 `isAutofillLegacyAccessibilityEnabled()` |
| 组件声明 | Manifest 注册 `LegacyAutofillAccessibilityService` + 配置 XML |
| 默认值 | 出厂 `false`（数据类默认 ⇄ 单键缺省同值） |

### 1.2 链路有没有打通？

**应用内闸门已通，系统授权闸门半通。**

| 链路 | 状态 |
|---|---|
| 应用开关 → 偏好 → 服务求值 | **通** |
| Manifest 无障碍服务注册 | **通** |
| 打开开关 → 跳转系统无障碍设置 | **断**（本批修复） |
| 系统侧启用态展示 / 一键入口 | **断**（本批修复） |

根因：通道是**双闸门**（应用内开关 + 系统侧启用本应用无障碍服务），UI 只接了应用内闸门。`SystemSettingsNavigation.accessibilityIntent` 在 §332 摘除假提示状态卡后成为**零生产消费点**的死代码（批次 332 正文称「旧版通道引导仍走官方 action」与代码不符）；打开开关只写偏好，服务因系统未授权从未启动 ⇒ 通道静默，用户体感「没反应」。

---

## 2. 整改内容

### 2.1 真机反馈后的二次收口（2026-09-30，覆盖 §2.2 初版）

用户真机实测：点开关后**只出现健康卡提醒 +「打开系统设置」按钮，按钮点击也无效**，未跳转。初版缺陷形态：

1. 优先 `ACCESSIBILITY_DETAILS_SETTINGS` + `resolveActivity` 前置门，MIUI 上详情页可能解析异常/启动失败后**无回落**；
2. 清单 `<queries>` **未声明**系统 Settings action ⇒ Android 11+ 包可见性下 `resolveActivity`/`startActivity` 可能静默失败（按钮在、点了没反应）；
3. 健康卡按钮预构造详情页 Intent，同样踩在同一条坏路径上。

**二次整改口径（用户目标：点开关立刻跳）**：

- [SystemSettingsNavigation.kt]：
  - `openLegacyAccessibilitySettings`：详情页可解析则先试，失败**无条件**回落 `ACTION_ACCESSIBILITY_SETTINGS`（不依赖 resolve 门）；
  - `accessibilityIntent` 不再被 `resolveActivity` 前置否决（返回可启动的通用 Intent）；
  - 全部启动路径加 `FLAG_ACTIVITY_NEW_TASK`；失败 `AppLog` 留痕；
  - 健康卡「打开系统设置」点击直接调 `openLegacyAccessibilitySettings`（与开关同路径）。
- [AndroidManifest.xml] `<queries>` 增补：`ACCESSIBILITY_SETTINGS` / `ACCESSIBILITY_DETAILS_SETTINGS` / `REQUEST_SET_AUTOFILL_SERVICE` / `CREDENTIAL_PROVIDER`。

### 2.2 开启时跳转系统无障碍设置（AC①）

- `SystemSettingsNavigation.openLegacyAccessibilitySettings`：见 §2.1。
- `AutofillProviderCard`：`onCheckedChange` 在 `enabled=true` 时调用该入口；**关闭只落偏好**（应用无法动态摘除已绑定无障碍服务，与限界「关开关≠从系统列表摘除」同口径）。
- 组合期捕获 `LocalContext`（回调不在 `@Composable` 上下文）。

### 2.3 健康卡揭示「半接通」（AC③）

- `AutofillHealthIssue.LEGACY_ACCESSIBILITY_SYSTEM_NOT_ENABLED`：应用开关开 + 系统侧本应用无障碍服务未启用。
- `AutofillHealthProbe.isLegacyAccessibilitySystemEnabled`：`AccessibilityManager.getEnabledAccessibilityServiceList` 按 `ComponentName` 精确比对；异常收敛为**未启用**（不谎报正常）。
- `AutofillHealthReport.legacyAccessibilityAppEnabled` / `legacyAccessibilitySystemEnabled` **无默认值**（漏传即编译失败）。
- 健康卡映射该项到 `openLegacyAccessibilitySettings`，一键跳系统设置；中英文案成对。
- **不污染框架通道**：`isLegacyAutofillOperational` / 传统链路可用性**不**要求系统侧无障碍启用（legacy 是可选兜底）。
- 应用开关关闭时**不**因系统侧未启用而列该项。

### 2.4 既有链路零改动（AC②）

偏好读写键、投影、服务求值、Manifest 服务声明一行未改；`LegacyAutofillWiringTest` / `AutofillChannelSwitchWiringTest` 既有语义保持。
