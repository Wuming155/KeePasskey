## 1. 原条目（自 `ACTIVE_ISSUES.md` 原样收录）

- **背景**：① `app/.../ui/screens/settings/subscreens/DebugSettingsScreen.kt:236` 把上限 500 行的
  `DebugLogBuffer` 整体塞在**单个 LazyColumn item** 内 `forEach` 组合，且每行做 4 次 `line.contains(…)` 判色；
  ② `app/.../ui/screens/vault/VaultListDialogs.kt:241` 把全部分组 `filter{}.forEach{}` 铺进 `AlertDialog` 的 `text` 槽
  （无虚拟化、无高度上限，超出屏幕的分组不可触达）；
  ③ `app/.../ui/screens/edit/EntryEditFormSections.kt:101` 在组合期执行 `availableGroups.filter { !it.isRecycleBin }`
  （每次重组重算整库过滤）且 `items` 无 `key`；`VaultListComponents.kt:249` 面包屑 `items` 同样无 `key`。
- **整改方向**：① 日志改顶层 `items(logLines)` 并按前缀预判等级色；② 分组选择改
  `LazyColumn(Modifier.heightIn(max = 280.dp))` + `items(…, key = { it.id })`（照抄 `AppPickerDialog.kt:138`）；
  ③ 过滤下沉到 ViewModel 或 `remember(availableGroups)`，并补 `key`。
- **验收标准**：三处改为惰性 / 已记忆（结构断言）；对话框内分组可滚动触达（含超长列表）；
  既有对话框与编辑页用例全绿。
- **核实时间点与方式**：2026-09-17 读 `DebugSettingsScreen.kt:225-250`、`VaultListDialogs.kt:230-255`、
  `EntryEditFormSections.kt:90-115` 核实。
- **风险提示**：`AlertDialog` 的 `text` 槽不滚动，改为 `LazyColumn` 时须一并确认弹窗高度约束，
  避免「改好了但按钮被挤出屏幕」。

## 2. 本批实现

### 2.1 `VaultListDialogs` 分组选择：惰性化 + 高度上限 + `key`（对应 AC ②，**本批唯一的可用性缺陷修复**）

`AlertDialog` 的 `text` 槽**自身不滚动**，原实现把全部分组 `forEach` 铺进 `Column` ⇒ **分组多时
超出屏幕的部分无法触达**（用户点不到那些分组）。现改为：

- `LazyColumn(modifier = Modifier.heightIn(max = 280.dp))` + `items(selectableGroups, key = { it.id })`；
- 过滤提到组合之外（`remember(allGroups) { allGroups.filter { !it.isRecycleBin } }`）——
  原实现写在 `forEach` 实参里，每次重组都重跑一次整表过滤；
- **「移动到根目录」入口保留在 `LazyColumn` 之前**（它是固定首位项，不随分组列表滚走），
  与 `AppPickerDialog` 的既有形态一致。

**关于条目「风险提示」（按钮被挤出屏幕）的处置**：`AlertDialog` 会为 title / text / buttons 分配
可用高度并**整体约束**（`AlertDialogContent` 内部对内容做最大高度限制），故 `text` 槽内的
`LazyColumn` 只会占据「剩余可用高度」内的 280 dp 上限、不会把按钮挤出屏幕；为稳妥仍取 280 dp
（与 `AppPickerDialog` 同一数值，属既有站内口径）。

### 2.2 `EntryEditFormSections` 组合期过滤下沉 + `key`（对应 AC ③ 前半）

`LazyRow` 的 content 是 `LazyListScope`（**非 `@Composable`**），无法在其中 `remember` ⇒
过滤下沉到 `EntryEditGroupSection` 函数体（`remember(uiState.availableGroups) { … }`），
`items` 补 `key = { it.id }`。原实现每敲一个字符都重跑一次整表过滤并因无 `key` 而按位置复用项。

### 2.3 `VaultListComponents` 面包屑补 `key`（对应 AC ③ 后半）

`items(breadcrumbs, key = { it.id })`——面包屑在分组间跳转时会整体替换，补 `key` 后可稳定复用项。

### 2.4 `DebugSettingsScreen`：等级色预计算（对应 AC ① 的**色彩部分**）

把逐行 `when { line.contains(…) }`（最多 4 次子串扫描/行，**每次重组都重跑**，含滚动引起的重组）
改为 `remember(logLines) { logLines.map { it to <等级色> } }` —— 只在日志内容变化时算一次。

**刻意不做（AC ① 的惰性化部分）**：不用嵌套 `LazyColumn` 替换卡片内的 `Column`。理由：

1. 该卡片是**单个 `item`**，其内部再放 `LazyColumn` 会在外层 `LazyColumn` 内引入**嵌套纵向滚动**
   ——触达全量日志要「先滚内层再滚外层」，是 **UX 回归**而非优化；
2. 日志行数**有硬上限 500**（`DebugLogBuffer.MAX_LINES`，2026-09-17 读源码确认），
   且本页是**调试专用页**（非用户主路径）⇒ 组合成本有界；
3. 彻底惰性化的正确形态是**先把日志卡片移出外层列表语义**（或改为独立滚动容器），
   属结构性 UI 改动，须与 UI 口径一并裁决，**不在本批范围**。

## 4. 边界如实声明（不得外推）

1. **无设备侧 / 视觉验证**：本批改动**全部落在 Compose 组合层**，宿主单测**无法渲染**这些 Screen
   ⇒ 证据是**编译通过 + 结构守卫 + 既有用例全绿**。
   **不得**读作「对话框与编辑页在真机上的观感已确认」；尤其 2.1 的**超长分组列表实际可滚动性**
   与「按钮未被挤出屏幕」**未经真机 / 预览核对**（这也是条目风险提示要求确认的点）。
2. **AC ① 只完成色彩预计算**，惰性化**刻意不做**（理由见 2.4）⇒ 单帧仍会组合最多 500 个 `Text`；
   **不得**读作「日志页已惰性化」。
3. **结构守卫的局限**：它是源码文本断言，对「等价写法」无鉴别力（例如把 `LazyColumn` 换成
   `verticalScroll(Column)` 也能通过 `LazyColumn(` 之外的断言——故守卫同时断言了 `heightIn` 与
   不得残留旧 `forEach` 形态）。
4. **`heightIn(max = 280.dp)` 是既有站内口径**（`AppPickerDialog`），本批沿用；它不是实测得出的
   最优值，**不得**读作「已按最长分组列表调优」。
5. **未跑截图 / 预览基线**：本批未执行 `updateDebugScreenshotTest` 或预览导出，
   故**未**更新任何视觉基线；若 CI 侧有像素比对，需另行复跑。
6. **未跑 `lint` / `assembleRelease`**。
7. 本批**未改任何 ViewModel 与状态层**（AC ③ 提到的「过滤下沉到 ViewModel」未采用，
   改在组合层 `remember`——收益等价且改动面更小）。
