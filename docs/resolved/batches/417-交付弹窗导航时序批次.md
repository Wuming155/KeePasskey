# §417 生成型密钥文件一次性交付弹窗被导航拆掉：离页事件推迟到交付了结（ISSUE-P2-461 整条闭环）

## 1. 原文收录（原样迁移自 `ACTIVE_ISSUES.md`，未删改）

### ISSUE-P2-461：生成型密钥文件「一次性交付」弹窗挂出即被导航拆掉——用户根本无法点「立即保存」

- **核实时间点**：2026-10-03；**核实方式**：用户 §416 批次装机走查回执「创建密钥文件出现立即保存和另一个按钮后又会迅速消失，根本无法选择」+ 本轮**取证日志实锤**（`adb logcat -s KpLog` 毫秒级时序）：
  `10:55:29.049 交付状态机 None→PendingSave` 与 `10:55:29.049 发 DatabaseSelected 事件（离页信号）` **同一毫秒**，
  `10:55:29.050 库管理页收到事件 → 即将离页`、`10:55:29.070 交付弹窗挂载`、`10:55:29.831 交付弹窗卸载`——
  弹窗挂上 **0.78 秒**即随页面被拆。与「会话锁定」无关（全程无 lockDatabase 日志）；
  `ISSUE-P2-460` 条目当初「弹窗宿主随会话锁定被拆」的归因**就此更正**：真凶是**导航时序**。
- **根因**：`DatabasePickerViewModel.createDatabase` 成功路径在同一协程内先 `requestSave`（挂交付提示）
  再 `_events.emit(DatabaseSelected)`；导航图对该事件的处置是 `navController.popBackStack()`
  （`KeePasskeyNavGraphRoutes.kt` 的 `onDatabaseSelected`）——承载
  `KeyFileOneTimeSaveDialog` 的 `DatabasePickerScreen` 整页离场，弹窗随之湮灭。
  §416 的 AC② 副本收编已先行完成（`files/keyfiles/` 有副本、密钥文件不再丢失），故该缺陷**不再构成数据丢失**，
  但「一次性交付」功能形态完全不可用（用户拿不到便携副本，只能事后经设置页导出）。
- **验收标准**：  
  ① `DatabaseSelected` 离页事件在生成型因子路径**推迟到交付提示了结**（写盘成功 → None，或用户点「暂不保存」→ None）
  之后才发出；交付提示驻留期间弹窗宿主稳定存活、可正常点按；  
  ② 交付失败路径（写盘失败 / 判定丢失）提示**保持驻留**，用户可重试或搁置，不得自动离页；  
  ③ 既有因子（无交付提示）路径行为不变（立即离页）；  
  ④ 全量 test 绿 + 门禁九条全 PASS；真机走查「建库→弹窗可点→保存成功→离页」全链路留痕。
- **关联**：`ISSUE-P2-460` §416 批次的真机走查回执直接产物（该批次 AC④ 走查由此缺陷受阻，
  修复后同一次装机继续走 §416 批次 §5 判据）。

## 2. 取证过程（本轮方法论：先布日志、不猜不改）

用户走查回执只给出现象（弹窗一闪即逝）。本轮**先沿弹窗完整生命周期布取证日志、行为零改动**，

全程无 `lockDatabase` 日志 ⇒ §416 之前「宿主随会话锁定被拆」的推测归因**就此更正**。

## 3. 整改

- **离页事件推迟**（`DatabasePickerViewModel.createDatabase`）：生成型因子路径挂出交付提示后，
  `viewModelScope.launch { delivery.first { it is KeyFileDeliveryState.None } }` 等待交付了结
  （写盘成功或用户「暂不保存」→ None）才发 `DatabaseSelected`；
  - 交付失败路径（写盘失败 / 判定丢失）状态机**不落 None** ⇒ 提示驻留，用户可重试或搁置，绝不自动离页（AC②）；
  - 既有因子路径无交付提示，立即离页，行为不变（AC③）；
  - 用户在弹窗驻留期间直接退栈（VM 销毁）则事件不再发——库已建成且登记、副本已收编，
    落点页自然呈现该库，无死路。
- **取证日志保留**：本轮布下的探针全部留在位（受「诊断日志」闸门约束，release 恒关），
  供 §416 §5 真机走查时序复核与后续同类「一闪即逝」问题的定位范式复用。
