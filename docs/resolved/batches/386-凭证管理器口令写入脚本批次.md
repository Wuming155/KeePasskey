>
> - **状态（2026-10-01 用户指示，同时认领整改）**：进行中。
> - **核实时间点**：2026-10-01。
> - **核实方式**：§385 交付后用户指示「能给个脚本，运行后用户输入密钥，然后就可以自动写到 Windows 凭证管理器」；现状核对——§385 只交付了读取通道（`tools/signing/read-cred.ps1`）与写入指引（`keystore.properties.example` 中的 UI / `cmdkey` 说明），`cmdkey /pass:` 传参存在 shell 转义坑且口令会进进程命令行。
> - **整改方案**：新建 `tools/signing/write-cred.ps1`：`Read-Host -AsSecureString` 掩码输入（不回显、不经命令行参数，口令不进 shell 历史/进程列表）；P/Invoke `CredWriteW` 写入「普通凭据」（UTF-16LE blob，全程 SecureString/非托管内存，写入并回读校验后立即清零）；keyPassword 直接回车＝与 storePassword 相同；目标已存在时先确认覆盖；<16 字符给 P2-55 预警；写入后回读逐字节比对；成功后提示从 `keystore.properties` 删除明文两行。`read-cred.ps1` 与本脚本统一补 UTF-8 BOM（PS 5.1 无 BOM 会按 ANSI 误读中文注释，存在 unlucky 序列吞换行的解析风险）。
> - **涉及文件**：`tools/signing/write-cred.ps1`（新建）、`tools/signing/read-cred.ps1`（仅加 BOM）、`keystore.properties.example`（写入指引改为优先推荐本脚本）。
> - **验收标准**：AC① 管道喂入测试口令跑通交互流，两目标写入成功且回读校验一致；AC② keyPassword 留空＝与 storePassword 同值；AC③ 清理后 read-cred.ps1 对两目标 exit 1；AC④ 全量 test 绿 + 门禁 8/8。

## 1. 整改

| 层 | 变更 |
|---|---|
| `tools/signing/write-cred.ps1` | **新建**。交互主流程 `Invoke-WriteSigningCredentials`：掩码输入 storePassword / keyPassword（留空取同值）→ <16 字符 P2-55 预警（可确认放弃）→ 目标已存在先确认覆盖（`CredWriteW` 是无条件覆盖）→ `CredWriteW` 写入（Persist=LOCAL_MACHINE）→ 回读逐字节比对（`BlobEquals` 在 C# 层完成，明文不回 PS 字符串层）→ 成功提示三步后续（删 properties 明文两行 / `:app:tasks` 确认 / CI 不受影响）。**结构**：点源（`. .\write-cred.ps1`）只加载类型与函数不进交互（供自动化测试）；退出码 0=成功 / 1=取消 / 2=失败。**敏感数据纪律**：口令全程 SecureString / 非托管内存 / UTF-16LE 字节缓冲，不经命令行参数、不写文件，所有经手字节缓冲在 `finally { Clear-HeldBytes }` 中清零 |
| `tools/signing/read-cred.ps1` | 仅补 UTF-8 BOM（PS 5.1 无 BOM 按 ANSI/GBK 误读 UTF-8 中文注释，存在 unlucky 字节序列吞换行/引号的解析风险；§385 版本实测可用属侥幸）。逻辑零改动 |
| `keystore.properties.example` | 写入指引改为**优先推荐本脚本**（掩码输入、不经命令行、回读校验）；UI 方式保留为手工等价路径；删除 `cmdkey /pass:` 直接传参示例（口令进 shell 历史与进程命令行，与本仓敏感数据铁律相悖） |

## 2. 验证

- **过程缺陷如实**：AC① 原计划的「管道喂入口令跑通交互流」**前提不成立**——`Read-Host -AsSecureString` 只从控制台读输入，不吃重定向 stdin（实测挂起，已终止）。整改＝把主流程收进 `Invoke-WriteSigningCredentials` 并加「点源只加载不执行」守卫，核心路径改由点源测试桩驱动。
- **AC①（写入 + 回读校验）**：点源测试桩以一次性测试口令调用 `ConvertFrom-SecureStringToBytes` + `Write-AndVerifyCredential`：两目标均「✓ 已写入并回读校验一致」。
- **AC②（keyPassword 留空取同值）**：`Resolve-KeyPasswordBytes -KeyBytes <空>` 后与 storeBytes `BlobEquals` = **True**。
- **交叉对拍**：`read-cred.ps1`（§385 已归档的读取路径）对两目标读出逐字原值（exit 0）——写/读两脚本对同一凭据达成一致。
- **AC③（清理）**：`cmdkey /delete:` 两目标后，`read-cred.ps1` 重读 exit 1（静默未配置）。
- **AC④（全量回归）**：`.\gradlew.bat test --rerun-tasks --max-workers=1` **BUILD SUCCESSFUL**（114 tasks executed）；聚合 `xml=498 tests=3222 failures=0 errors=0 skipped=13`（与 §385 基线一致，零用例增减——本批不触任何 Gradle 编译路径，属防御性全跑）。
- **交互主流程（Read-Host 提示语 / 覆盖确认 / 弱口令确认分支）**：无法在无头环境驱动，未实跑；其分支逻辑均为薄封装，核心读写路径已由测试桩覆盖。**待用户首次交互使用时自然核验**。
