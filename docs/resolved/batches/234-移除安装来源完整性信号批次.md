# §234 移除安装来源完整性信号批次

> 对应条目：`ISSUE-P3-231`（整条结案）
> 闭环日期：2026-09-20
> 涉及模块：`app`（`security` 完整性闸门 + 解锁 / 设置页呈现 + 单测）

## 1. 背景与原貌（原样收录自待办条目）

### ISSUE-P3-231：安装来源完整性信号过度严苛，误禁用正常侧载/第三方商店用户的生物解锁

- **核实时间点**：2026-09-20 经代码走查 + 用户真机反馈核实。
- **核实方式**：`RuntimeIntegrityDetector.detectUntrustedInstallSource`（`RuntimeIntegrityDetector.kt:293`）读
  `getInstallSourceInfo().installingPackageName`，不在 `TRUSTED_INSTALLERS`（`:470`，仅 4 项：Play /
  两个系统 packageinstaller / F-Droid）即置 `untrustedInstallSource=true` → `RuntimeIntegrityPolicy.evaluate`
  （`:187`）`elevated = … || untrustedInstallSource` → ELEVATED → 禁用生物快速解锁；用户解锁页见
  `sec_biometric_block_installer`（「安装渠道不在受信任清单内」）。
- **背景与影响**：该信号安全收益极低——`installingPackageName` 可被任意应用伪造，重打包攻击者填
  `com.android.vending` 即可「骗过」；真正防伪靠签名指纹（README 已公布 release 证书 SHA-256）与未接入的
  Play Integrity。判据还自相矛盾：`installer == null`（可能正是重打包版）不升级，但诚实的 `com.android.shell`
  （adb 装 release 包）或任一合法第三方商店却升级。结果把开发者与侧载/第三方商店用户一律关掉生物解锁，却没挡住篡改威胁。
  用户 2026-09-20 在 ISSUE-P2-227 归属批次「不放宽」的口径之上，**明确反向选择「直接去掉该信号」**。
- **裁决**：移除 `untrustedInstallSource` 信号（检测、字段、枚举、`TRUSTED_INSTALLERS`、专属文案一并清理），
  仅保留 `appDebuggable`（debug 构建）为 ELEVATED。篡改防护仍靠签名指纹核对 + 后续 Play Integrity（未排期）。
- **验收标准**：AC① release 包无论 installer 如何均不因此被禁（字段删除后相关构造不再可编译）；
  AC② `appDebuggable` 仍判 ELEVATED 禁用生物解锁（debug 严苛不变）；AC③ 删除 `detectUntrustedInstallSource` /
  `TRUSTED_INSTALLERS` / `UNTRUSTED_INSTALLER` 枚举 / `sec_biometric_block_installer` 文案及全部相关用例；
  AC④ 宿主单测全绿。

## 2. 整改方案与代码落点

判据（风险分级、`disableBiometricQuickUnlock` 的后果）**收窄一处**，其余动态攻击特征与 fail-closed 分级完全不动。

### 2.1 移除信号与判定（纯函数层）

- `security/IntegritySignals.kt` 删除 `untrustedInstallSource: Boolean` 字段（含类级 KDoc 中「安装来源与调试签名同属可选信号」的说明，改为「安装来源信号已移除」的口径注）；
- `RuntimeIntegrityPolicy.evaluate` 中 `val elevated = signals.appDebuggable || signals.untrustedInstallSource`
  → `val elevated = signals.appDebuggable`（ELEVATED 仅余 debug 构建一类静态可疑特征）。

### 2.2 移除归因枚举与呈现载体

- `security/IntegrityBlockReason.kt` 删除枚举项 `UNTRUSTED_INSTALLER`（原携 `R.string.sec_biometric_block_installer`）
  及其在 `from` / `hit` 中的分支；声明顺序仍为「危害度降序」（动态攻击特征 → 静态可疑 `DEBUGGABLE_BUILD` → 未判定）；
- `app/src/main/res/values/strings.xml` 与 `values-en/strings.xml` 删除 `sec_biometric_block_installer`
  （zh/en 各 1 条）；该文案原仅由枚举引用，删除后无悬空引用。

### 2.3 移除探测与白名单（Android 探测层）

- `RuntimeIntegrityDetector.detectSignals` 不再调用 `detectUntrustedInstallSource(ctx)`；
- 删除 `detectUntrustedInstallSource` 整函数（含其 KDoc：ISSUE-P2-227 的「adb 直装 installer 为假前提、实为
  `com.android.shell`」更正注，与 ISSUE-P1-23「installer == null 不升级」决策留痕——该决策随信号移除一并失效）；
- 删除伴生对象内的 `TRUSTED_INSTALLERS` 白名单（4 项），无其它引用。

### 2.4 同步清理单测

- `IntegrityBlockReasonTest`：移除「`untrustedInstallSource → UNTRUSTED_INSTALLER`」映射用例、「清单顺序」用例中的
  该信号与期望项、「凡禁用」枚举集中的该信号构造；不变式「无障碍信号不得被当作降级原因」「凡禁用必有原因」逐字保留；
- `RuntimeIntegrityPolicyTest`：删除 `非受信任安装来源仅升级为可疑` 整条用例，并在 `动态特征优先于静态可疑特征` /
  `提示判定与 UI 取文案的等级范围严格一致` 的信号矩阵中移除该信号构造；等级映射矩阵其余断言未改仍绿；
- `BiometricFailureMessagePolicyTest`：多信号点名用例移除 `UNTRUSTED_INSTALLER`（取首项错误文案断言不变）。

## 4. 残余与未执行声明

- **真机核对未执行**：本环境无可用设备 / AVD，故「release 包经 adb 或第三方商店安装后解锁页不再显示安装渠道文案」这一效果
  **未实测**（限界 §4.1 手工冒烟边界）；但拆除面仅为纯函数字段 / 枚举 / KDoc 与字符串资源，无设备侧必跑项；
- **安全口径收窄的取舍**：安装来源信号移除后，对「侧载 / 第三方商店 release 包被重打包」的**应用内**探察归零；
  该威胁的真实缓解仍在应用外——README「官方签名指纹」公布 release 证书 SHA-256 供安装前核对，未来上架后接入
  Play Integrity（或同等平台完整性证明）方为有效闭环；本批**未**排期该接入；
- **未一并放宽 debug 构建**：用户 2026-09-20 仅选「去掉安装来源信号」，debug 构建仍判 ELEVATED——若日后也要放宽，
  落点仅 `RuntimeIntegrityPolicy.evaluate` 的 `elevated` 判定（与 §231 结案时声明的一致）。
