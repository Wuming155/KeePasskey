# §369 同步首传探测失败如实归类批次（`ISSUE-P2-402` 整条闭环）

- **触发**：2026-09-30 用户真机日志——解锁后自动同步 `同步周期开始: cached=false…` 后 **0.4s**
  即报 `同步结束: Offline(离线/网络不可达)`，而设备网络正常、且 1 分钟内同配置 WebDAV
  浏览 + 下载刚成功；用户并指出该症状在旧入口时代即存在（当时经「本地打开 + 同步配置」绕过），
  §366 新链路后再次出现。
- **开放项变动**：P2 区 0 → **1** → **0**（本批闭环）。

## 1. 根因

`establishRemoteBaselineIfMissing`（cached=false 首传路径）的 `getMetadata` 失败分支：
**只有 404** 走「远端不存在 → 上传基线」，**其余一切异常**（401/403 鉴权失败、429/503 限流、
超时、DNS、TLS）一律 `return SyncOutcome.Offline`，且无任何异常类型日志。即「离线/网络不可达」
是一个**兜底误报**，真实原因被整体吞掉，用户无从定位。

## 2. 回归排查结论（回应用户「随打开界面修改而复现」）

逐行比对新链路（§366 导入）与手工链路（本地打开 → 同步配置）在同步周期里的全部输入：
URL 归一化（`HttpsEndpointPolicy` 同一单点）、remotePath 补根斜杠（同一口径）、凭据封印与
Provider 构造（`SyncProviderResolver` 同一出口）——**未发现配置分歧点**。0.4s 即失败指向
快速 HTTP 拒绝（401 / 503）而非超时；浏览 + 下载 + 元数据连续请求恰好构成坚果云免费额度
**限流**（503/429）的典型压力形态——高概率诱因，但在误报修复前无法从日志证实。
本批修复后，下一次同步失败将直接显示真实原因，自证。

## 3. 整改

- `establishRemoteBaselineIfMissing` 非 404 分支按异常类型归类：`NetworkError` → 真离线
  （Offline 语义收窄为名副其实）；`AuthenticationError` → `sync_error_auth_failed`
  （引导核对同步配置的用户名 / WebDAV 专用密码 / S3 密钥）；其余（`ProtocolError` 等）→
  `sync_error_remote_rejected`（携带 HTTP 状态码 / 异常类型名，点明 429/503 限流可能）；
- `AppLog.w` 留痕异常类型 + remotePath（非敏感元数据，与 RemoteBrowse 日志同口径）；
- 中英文案成对（`sync_error_auth_failed` / `sync_error_remote_rejected`）。
