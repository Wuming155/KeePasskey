## §1 回执结论（两条，均为「已确认」）

### §1.1 「立即锁定」已在**收起行**直接可见 ⇒ `setShowActionsInCompactView` 在本机 Xiaomi **生效**

§430 曾依据 KeePassDX 源码自注 `// Won't work with Xiaomi and Kitkat`
（`services/DatabaseTaskNotificationService.kt:598-604`）**回避**该方法；§431 改以实测为准补上它，
并在 §5 声明「是否生效以装机回执为准」。本轮回执确认「锁已经看见了」——即：

- `MediaStyle().setShowActionsInCompactView(...)` 在 **Xiaomi HyperOS OS4.0 / Android 17** 上**生效**，
  动作按钮确实落进**收起行**（无需展开、无需长按）；
- 因此 **KeePassDX 的那条注释在本机不成立**，此后**不再**作为回避该方法的理由；
- 也让 §426→§431 的六轮定位闭环：**通道重要度（§428，静默分类）+ 展开态样式（§430，`MediaStyle`）
  + 动作落点（§431，收起行按钮位）三者缺一不可**——前两轮各自单独修都无效，正是因为三处成因叠加。

### §1.2 「复制用户名 / 复制验证码」未出现**不是缺陷**，是 `PD-69` 的触发条件

两动作由 `NotificationGate.shouldShowUnlockedCopyActions(recentEntryId)` 门控——**仅在存在「最近查看条目」时挂出**；
该登记（`UnlockedNotificationEntryTracker`，**仅进程内存**）唯一写入点是**用户打开某条目详情页**
（`EntryDetailViewModel`）。故：

| 场景 | 通知上应出现的动作 |
|---|---|
| 只解锁、本次进程内未点开过任何条目 | 仅「立即锁定」 |
| 本次解锁后点开过任一条目详情页 | 「立即锁定」+「复制用户名」+「复制验证码」（收起行三个按钮位，`actionCount = 3`） |
| 锁库 / 关闭库 / 关偏好 | 通知整体撤销并清空登记，下次解锁重新开始 |

本轮「只有锁」的现象**可由重装 debug 包解释**：重装结束应用进程 ⇒ 内存登记为空 ⇒ 只余锁定动作。
用户按 §1 指引（解锁 → 点开任一条目 → 回通知栏）即可看到三按钮。

> 另：用户已确认的两项边界保持不变——用户名未配置 / 条目未配 TOTP 时，点按如实提示「未配置 / 无验证码」，
> 不造假。

## §2 口径维持（用户裁决，2026-10-03）

**不放宽**「作用对象」的定义。曾提出的两条扩大通知动作作用面的候选——
① 上次会话最后查看的条目；② 库列表选中项 / 上次解锁停留条目——**均不实施**（用户「行，那就先就这吧」）。
即 `PD-69` 的存活口径原样维持：**动作必须有本次会话内的真实「最近查看条目」**。

若日后要放宽，属安全复核范围（会扩大通知动作的作用面），须按 `PD-69` 重开条件重新复核后另行登记。
