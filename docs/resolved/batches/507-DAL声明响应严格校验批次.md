### ISSUE-P2-604：DAL 接受重定向来源及非 200 成功响应

- **整改方案**：[ISSUE-P2-604 独立方案](../../architecture/问题整改方案/P2/ISSUE-P2-604/DAL声明响应严格校验方案.md)；方案已编制，尚未实施。

- **来源 / 严重度**：全面软件审计 `AUD-16`，Medium，可信度高（实际设备后果未实测）。
- **核实时间点 + 核实方式**：2026-10-13；现行调用链与相关测试直读，对照 Google DAL 官方规则。仅审计，未整改。
- **背景 / 位置**：`DalVerifierModule.kt:75-82` 使用默认跟随重定向的同步客户端；`DigitalAssetLinksVerifier.kt:143-164` 仅检查最终 isSuccessful，未核验原地址直返 200 或 Content-Type。
- **触发 / 后果**：assetlinks 端点返回重定向，最终 JSON 被当作原 RP 声明；若该端点有可控跳转则削弱域名授权边界。协议偏差确认，真实域名可利用条件未验证。
- **建议 / 验收**：DAL 专用客户端禁止重定向，严格 200 与声明媒体类型；测试跨主机、同主机重定向和 201/206。依据 Google 官方声明位置规则。
- **详细证据**：[全面软件审计](../../security/全面软件审计_2026-10-13.md)。

## 2. 实施与验收

- **前提复核（认领时）**：直读 `DalVerifierModule.provideDalHttpClient()` 与 `DigitalAssetLinksVerifier.fetchAndMatch()`
  确认前提成立——出口沿用 `SyncHttpClientFactory.createSyncClient`（OkHttp 默认跟随重定向），
  响应判据仅 `!response.isSuccessful`（放行 201/204/206 等其它 2xx，且不核对媒体类型）。

- **改动一（出口禁跳转，`DalVerifierModule.kt`）**：在加固工厂产出的客户端上以 `newBuilder()`
  **派生** DAL 专用配置并 `followRedirects(false)` + `followSslRedirects(false)`。派生而非另建裸客户端，
  是为**保住**工厂已装配的 `SsrfGuardDns`（解析期）/ `SsrfGuardSocketFactory`（连接期）双层 SSRF 守卫与
  TLS-only 连接规格（`newBuilder` 逐项复制既有配置，`DigitalAssetLinksEgressHardeningTest` 逐项断言仍在）。

- **改动二（严格响应判据，`DigitalAssetLinksVerifier.kt`）**：新增纯函数 `DalResponseGuard.accepts(...)`，
  取代原 `!isSuccessful` 判据。仅当 **HTTP 状态恰为 200** 且 **未发生跳转**（`priorResponse == null`，
  覆盖「跟随跳转的调用方」的纵深防御）且 **媒体类型为 `application/json`**（`type`/`subtype` 大小写不敏感、
  `charset` 等参数由 OkHttp 解析后剥离、缺失或格式非法解析为 null 即拒绝）时才接受后续读取与匹配。
  有界流式读取、JSON 结构 / relation / 包名 / 证书指纹匹配、`use{}` 关闭响应体均逐字保留。

- **测试**：
  - `DigitalAssetLinksVerifierTest` 由 20 例扩至 **29 例**：新增 201 / 204 / 206 拒绝、Content-Type 缺失 / text-plain /
    text-html 拒绝、`application/json; charset=utf-8` 接受、**重定向不被跟随**（断言目标地址零访问、`requestCount == 1`）
    与 `DalResponseGuard` 纯函数边界 9 例。夹具改注入**不跟随重定向**的客户端以对齐生产语义；
    因 MockWebServer 的 `setBody(String)` **不**自动补 Content-Type，新增 `json(...)` 辅助函数为既有用例显式设类型。
  - `DigitalAssetLinksEgressHardeningTest` 由 5 例扩至 **6 例**：新增断言生产出口 `followRedirects == false`
    且 `followSslRedirects == false`。
