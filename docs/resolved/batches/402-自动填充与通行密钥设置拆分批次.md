## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-432：设置主页「自动填充与 Passkey」单一入口混装两条独立通道，应拆分为「自动填充」与「通行密钥」两个设置项

- **核实时间点**：2026-10-02；**核实方式**：用户走查设置主页提出；对 HEAD `5c3005ea` 逐行复核 `SettingsScreen.kt` / `AutofillSettingsScreen.kt` / `AutofillSettingsComponents.kt` / `KeePasskeySettingsNavGraphRoutes.kt`：主设置页「偏好」组仅一枚 `settings_autofill`（「自动填充与 Passkey」）入口，二级页同时承载 **CM 凭据管理器通道**（凭据管理器开关 / Passkey 支持开关 / 特权浏览器白名单 / DAL 归属校验降级）与**传统 AutofillService 通道**（系统自动填充服务 / 旧版无障碍 / 会话宽限 / 手动选择器 / 体验 / TOTP / 捕获与三级黑名单）的全部开关。
- **背景**：两条通道的系统服务、开关语义、健康判项（`AutofillHealthPolicy`）相互独立；单一入口使「只想配通行密钥」与「只想配表单填充」的用户都要在混排页里找开关，入口文案也无法如实概括任一通道。
- **整改方向**：主设置页拆为「自动填充」「通行密钥 (Passkey)」两枚入口；新增 `PasskeySettingsScreen` 二级页承载 CM 通道四项（凭据管理器开关、Passkey 支持开关、特权浏览器白名单入口、DAL 归属校验降级开关，后两者自 `AutofillCaptureCard` 迁出）；`AutofillSettingsScreen` 保留 AutofillService 通道全部开关。
- **验收标准**：
  ① 主页两入口独立导航（`launchSingleTop` 口径与既有二级页一致）；
  ② 两二级页开关语义与接线零变化（偏好键、UiState 字段、生产消费方均不动；纯 UI 重组）；
  ③ `DalSkipSwitchCopyWiringTest` / `SettingsSubscreenScaffoldWiringTest` 的源码锚点随搬迁同步改指新文件，锁定强度不降；
  ④ 全量 test 绿 + 门禁读数 8/8。
