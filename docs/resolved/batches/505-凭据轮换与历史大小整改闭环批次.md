- **当前收口 / 暂停前交接（2026-10-13）**：Mutex覆盖事务内部，提交回执及无分配缓存采用、应用所有权已实现并有专项证据。应用受理到数据库取锁之间尚未贯穿稳定会话身份/凭据代次票据；换库/目录选择变化、完整同步标记/封印与真实SAF不确定写入矩阵仍需补齐。因此保持开放，不把核心取消用例通过写成整条闭环。

- **整改方案**：[ISSUE-P1-593 独立方案](../../architecture/问题整改方案/P1/ISSUE-P1-593/凭据轮换取消事务方案.md)；核心实现已接入，尚未完整验收；当前范围与剩余工作见[批次504](504-首轮在途整改收口批次.md)。

- **来源 / 严重度**：全面软件审计 `AUD-05`，High，可信度高；真实 ViewModel 销毁及写后窗口验证待补。
- **核实时间点 + 核实方式**：2026-10-13；直读 `SessionPersistence.changeCredentials` 与 `SettingsViewModel` 的 `viewModelScope` 注入，核对 Kotlin 官方 `withContext` 取消语义；临时合成库的写通道注入取消，复现缓存新密码、磁盘仍只接受旧密码。
- **背景 / 位置**：`database/.../session/SessionPersistence.kt:187-213` 先换缓存再挂起序列化 / 写盘；捕获取消时在回滚之前重抛。旧快照只在成功路径擦除或普通错误路径移交恢复。
- **触发 / 后果**：离开设置页导致协程取消，可能留下「旧磁盘 + 新缓存」或「磁盘已换密但上层未执行同步标记 / 重封印」，后续保存和重新解锁不一致。
- **建议 / 验收**：按提交点区分未写入回滚与已写入收尾，用确定性 finally 管理快照；覆盖取消发生于派生前后、写盘前后及回到调用上下文时，验证缓存、磁盘、封印与同步标记一致。
- **详细证据**：[全面软件审计](../../security/全面软件审计_2026-10-13.md)。

### ISSUE-P2-599：历史大小计数物化大附件并遗留未擦除的明文副本

- **整改方案**：[ISSUE-P2-599 独立方案](../../architecture/问题整改方案/P2/ISSUE-P2-599/历史尺寸免读取附件方案.md)；方案已编制，尚未实施。

- **来源 / 严重度**：全面软件审计 `AUD-11`，Medium，可信度高（实际设备后果未实测）。
- **核实时间点 + 核实方式**：2026-10-13；现行调用链与相关测试直读。仅审计，未整改。
- **背景 / 位置**：`HistoryManager.kt:249-250` 使用 attachment.data.size；`KdbxAttachment.kt:47-52` 的落盘来源每次 load 新副本，已有 size 可免读取。
- **触发 / 后果**：普通编辑触发历史裁剪，多份大附件历史被逐个读回，仅求尺寸却留下 GC 前明文副本；在 Main 调用链可造成卡顿、内存压力。
- **建议 / 验收**：使用 Long size 计数并避免物化；用禁止 load 的 BinarySource 验证计数，补大附件历史性能和调度验证。实际 ANR/OOM 阈值需要设备验证。
- **详细证据**：[全面软件审计](../../security/全面软件审计_2026-10-13.md)。
