## 446.1 ISSUE-P2-466：`jni_bridge_ext.rs` AES / Twofish 两个 JNI 入口约 45 行逐字重复

- **整改**：合并为单一私有入口
  ```rust
  type CbcKernelFn = fn(&[u8], &mut [u8], &[u8]) -> Option<Vec<u8>>;
  fn block_cbc_jni(env, key, iv, data, block_len: usize, kernel: CbcKernelFn) -> jbyteArray
  ```

  四个 `#[no_mangle]` 导出（Twofish/AES × 加/解密）各缩为**一行转发**，按方向直接传 `twofish_cbc::cbc_encrypt` / `cbc_decrypt` / `aes_cbc::cbc_encrypt` / `cbc_decrypt`。**取消 `bool encrypt` 二次分派**（函数指针已在编译期选定方向，保留 `bool` 反而多一处可漂移的分派）。

## 446.2 ISSUE-P2-467：`aes_cbc.rs` CBC 加/解密「拷出形态」与「原地形态」双份手写实现

- **前提复核**：`cbc_encrypt`/`cbc_decrypt`(64-89 / 95-120) 与 `cbc_encrypt_in_place`/`cbc_decrypt_in_place`(128-149 / 155-177) 的参数闸门、链值单缓冲、逐块循环三处逐项同构；四个函数的失败路径**全部先于** `iv.copy_from_slice` 返回，空数据边界亦等价 ⇒ 薄委托不改可观测语义。
- **整改**：两个拷出形态改为薄委托——
  ```rust
  pub fn cbc_encrypt(key: &[u8], iv: &mut [u8], data: &[u8]) -> Option<Vec<u8>> {
      let mut out = data.to_vec();
      cbc_encrypt_in_place(key, iv, &mut out)?;
      Some(out)
  }
  ```
  闸门与循环**只留 in_place 一份**，两条生产管线（整块 JNI 路径 / direct `ByteBuffer` 零拷贝路径）自此共用同一实现 ⇒ 「静默漂移」这一失效模式被结构性消除，而不再依赖人工对照 + 测试维持。
- **等价性证据**：既有 NIST SP 800-38A 官方向量（加密 F.2.5 / 解密 F.2.6）、分段等价性、`iv` 出口契约、往返、闸门负例，以及 `in_place_matches_allocating_variant`（两形态逐字节对拍）**全绿**，产物逐字节不变。

## 446.3 ISSUE-P2-468：`strength.rs` 热路径每次调用全量分配 `Vec<char>` / `String`

- **前提复核**：`estimate`(158-279) 在模块头(23-29) 自陈的「全库审计对每条口令调用」热路径上，原每次调用分配：`chars: Zeroizing<Vec<char>>`（UTF-32 物化，长度×4 字节）、`lowered: Zeroizing<String>`、`date_like_weight` 两处 `Zeroizing<String>`、`unique_char_count` 的 `Vec<char> others`、`minimal_period` 的 `Vec<usize>`。`MAX_ANALYZED_CHARS=256` **不约束**这些全量分配 ⇒ 条目前提成立。
- **整改（热路径零堆分配）**：`estimate` 拆为薄入口 + `&str` 内核 `estimate_str`；有效 UTF-8（生产全量）**直接借用入参字节**：
  | 原分配点 | 现形态 |
  |---|---|
  | `chars: Vec<char>` | 按字符边界切 `&str` 字节视图（`char_indices().nth(MAX_ANALYZED_CHARS)`），零物化 |
  | `lowered: String` | 流式小写比较 `chars().flat_map(to_lowercase).eq(table.chars())` |
  | `date_like_weight` 两处 `String` | 直接消费 `&str` / `as_bytes()` |
  | `unique_char_count` 的 `Vec<char>` | `Zeroizing<[char; MAX_ANALYZED_CHARS]>` **栈缓冲**（顺带把原先未受管的 `Vec` 纳入擦除纪律） |
  | `minimal_period(&[char])` | 字节级 KMP `minimal_period_bytes(&[u8])`（`pi` 表分配归 `ISSUE-P3-480` 收口，本条不触动） |
- **等价性论证**：① 小写比较由「先收集再 `contains`」改为流式 `eq`，等价性为序列等价的直接推论；② 小写对尾部 ASCII 判据（`is_ascii_digit`/`is_ascii_punctuation`）为恒等映射，故「先截尾再小写」与原「先小写再截尾」等价；③ **字节级整周期蕴含字符边界对齐**——UTF-8 前导字节（`0xC2..=0xF4`）与后续字节（`0x80..=0xBF`）区间不交叠，错位周期需前导字节等于后续字节，不可能成立；另在调用点以 `text.is_char_boundary(unit_bytes)` 复核后才对周期单元做字符集统计；④ 流式递推版的 `longest_repeat_run_str` / `longest_sequence_run_str` 保留原「`cur == 1 || step == prev_step`」续段条件与 `prev_step` 的 `is_some()` 语义。
- **边界如实声明**：仅**非法 UTF-8** 的容错分支仍分配一次受管 `String`（`String::from_utf8_lossy(...).into_owned()` 装入 `Zeroizing`）。生产口令恒为合法 UTF-8，该分支仅测试的任意字节探针可达；`chars()` 解码路径下 UTF-16 代理对会 panic，故流式方案仅适用于 `from_utf8` 成功的路径。
