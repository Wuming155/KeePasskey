## 2. 安全语义随迁且未放宽（逐条）

1. 私钥仍只经 `passkeyData.usePrivateKeyBytes { … }` 的受控字节流取用，解码出的签名材料由
   `finally` 清零（ISSUE-P1-02）；
2. 派生中间量 `authData` / `clientDataBytes` / `dataToSign` / `signingKeyBytes` 的擦除集合与顺序未动；
3. `clientDataJSON.androidPackageName` 仍**只写系统背书的调用方包名，取不到即省略该字段**（ISSUE-P2-72），
   未回退为本应用包名；
4. PRF 分支仍「算不出即返回空对象」，不伪造输出（WebAuthn Level 3 §10.1）；
5. 日志 tag 保持 `"PasskeyAssertionActivity"` 同值，使迁移前后的 logcat 归因一致（新对象内自带同名常量）。

`CredentialManagerCallerBindingWiringTest` 对本文件的判据是「必须出现
`CredentialManagerPackageBindingGate.`」——门控调用点在本次搬动范围**之外**，仍在 Activity 内，
故**无需**改该守卫（本批没有放宽任何定位串）。

## 3. 本批顺手打开的新验证面（下一批落地）

搬动之前，`buildAssertionJson` 是 Activity 的 `private` 成员，宿主单测**无法直调**——
ISSUE-P2-72 的「归属字段只写系统背书包名」与「authData 里 signCount / rpIdHash 落位」这类判据
只能靠静态接线守卫与设备侧用例。搬动之后它是同包 `internal object` 的纯函数：
输入 `PasskeyData` + 会话参数，输出响应 JSON，**可离线断言**。

已登记为 `ISSUE-P3-188` 剩余清单第 5 项（§174 补：`PasskeyAssertionPayloadTest` 直调用例，
覆盖归属字段省略 / `clientExtensionResults` 空对象 / authData 37 字节与 rpIdHash 与 signCount 落位 /
签名对公钥可验）。
