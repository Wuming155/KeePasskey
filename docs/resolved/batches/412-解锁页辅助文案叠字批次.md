## 2. 定性与整改

### 2.1 根因：不是弹窗叠加、也不是「密度」，是 **`supportingText` 槽本身是 `Box`**

条目背景的两条假设都不成立：

1. **不是**「生物识别弹窗负向按钮与页面内容视觉叠加」——用户提供的真机照里**没有任何系统弹窗**，「取消」二字来自页面自身。
2. **不是**「supportingText 多行堆叠密度问题」——不是「太挤」，而是两行文案**画在同一个 y 上**（Box 同层兄弟叠放），且外层 `heightIn(min = MinSupportingTextLineHeight)` 只按**最高子节点**量高，所以容器高度也只算一行。

**逐字对齐证据（「取消」的出处）**：错误文案 `sec_biometric_auth_failed` =「生物识别验证未通过或**已取消**」（13 字），info 文案 `keyfile_restored_from_memory` =「已自动载入记住的密钥文件: usr.dat」（前缀 12 字 + `": usr.dat"`）。两串**左端对齐**逐字叠印，第 11/12/13 位恰好是「文|已」「件|取」「:|消」——所以乱码行会呈现「中国式叠字 + 尾部干净的 `sr.dat`」，用户读到的「取消」正是错误文案自身的尾三字。真机照与 JVM 渲染图（§3.2）逐字同形。

**框架侧证据**：Material3 `OutlinedTextField` 把 `label` / `prefix` / `suffix` / `leadingIcon` / `trailingIcon` / `supportingText` **各自包在 `Box(...)` 里**（`material3/internal/TextFieldImpl.kt` 的 `TextFieldLayout` 与 `CutoutTextFieldLayout` 两处同形；本机缓存 `1.5.0-alpha27` sources 逐行核对；运行期解析为 `1.5.0-alpha28`（`./gradlew :app:dependencies` 实测），其字节码内同类 `BoxKt.maybeCachedBoxMeasurePolicy` 构造点 17 处、`CutoutTextFieldLayout` 的源码行号映射（`TextFieldImpl.kt:506` 起）与 alpha27 一致）。⇒ `SecurePasswordField.supportingText` 槽**只接受单个节点**。

**影响面比报告更大（本批顺带纠偏）**：`MasterPasswordUnlockSession` 在「凭据错误 + 节流生效 + 未达锁定阈值」时**同时**置位 `errorMessage` 与 `throttleAttemptsRemaining`（同一个 `uiState.update`）⇒ **一旦用户在设置里开启**「解锁失败重试限制」（`sec_throttle`，**出厂默认关闭**），**每次输错主密码都会叠字**（「主密码错误或密钥不匹配，解锁失败」+「剩余 N 次尝试」）。该缺陷自 §186（2026-09-19）`supportingText = { … }` 平铺直出起潜伏，§349（`ISSUE-P2-355 AC②`）加入「剩余 N 次尝试」后由「错误 + info 偶发」变成「（开启节流后）输错即现」。

> **更正（2026-10-03，真机走查回执后）**：本节初稿把该行写成「（默认开）」——**错**。
> 节流的出厂默认是**关闭**：`RealSettingsRepository.kt:121` `prefs[KEY_UNLOCK_THROTTLE_ENABLED] ?: false`、
> `SettingsRepository` 的 `unlockThrottleEnabled = false`，且 `UnlockThrottleConfigProvider` KDoc 明载
> 「进程启动初期设置尚未抵达的短窗内回落 `UserSettings` 出厂默认（2026-09-12 用户裁决：关闭 + 30 分钟封顶）」。
> `ThrottleConfig()` 无参构造的 `enabled = true` **只用于未接配置源的 JVM 单测场景**，把它当作生产默认是本条初稿的
> 误读来源。证据＝§412 装机后用户真机照（SAF 库 `passwords.kdbx`、错误文案 `keyfile_or_password_mismatch`，
> **只有一行错误、无「剩余 N 次尝试」**）与设备侧设置文件实读（`files/datastore/keepasskey_settings.preferences_pb`
> 内无 `unlock_throttle_enabled` 键 ⇒ 走 `?: false`）。
> **结论不变**：叠字机制与整改口径不受影响；受影响的只是「该形态有多常见」——「错误 + info」形态与设置无关，
> 「错误 + 剩余次数」形态需用户显式开启节流。同批推送的提交信息里亦含同一处「默认开」，**以本更正为准**。

### 2.2 整改

1. **单节点契约**（`UnlockContentSections.kt`）：`UnlockPasswordSupportingText` 的四路文案（倒计时 / 错误 / 剩余次数 / info）整体收进**一个 `Column`**，使该槽**只发射一个节点**；单行成立时渲染结果与平铺直出等价，多行成立时逐行上下分离。
2. **契约写进组件 KDoc**（`SecurePasswordField.kt`）：显式声明该槽只接受单个节点、多行须自包 `Column`——该形态**编译期不报错、默认态预览也看不见**，不写下来后来者必再踩。
3. **补该态 `@Preview`**（`UnlockScreenPreviews.kt`，浅/深两态）：错误 + 「已自动载入记住的密钥文件」info + 已加载密钥文件——该组合此前**没有任何预览**，正是 `ISSUE-P3-340` 要堵的缺口（不可见态只能靠真机肉眼撞见）。
4. **不采「错误态收起 info 行」**（条目 AC② 的备选）：info 行承载「本次解锁自动载入了哪个密钥文件」这一**与失败原因直接相关**的事实（密钥错配时用户需要知道加载了哪个文件），条目 AC② 的硬要求是「无任何文字交叠」，由 1 达成，不牺牲信息。

### 2.3 机检扩面（防回潮，`tools/doc/check_box_slot_children.py`）

该脚本自 `ISSUE-P3-337` 起在 CI `hygiene-gate` 内（fail-closed），但原判据**只能看见本仓声明的 `BoxScope` 内容槽组件**（`BentoCard`），框架槽与「助手函数间接发射」都在盲区。本批补两条互补判据（扩扫描**不删不放宽**原判据）：

- **规则 A｜框架 Box 槽同层多子节点**：`supportingText = { … }` 直传 lambda 内 ≥2 个同层发射节点即红。
  名单**只收 `supportingText`**：`label` / `leadingIcon` 等槽在 MD3 里同样是 Box，但同名形参在本仓被 72 处非文本框组件复用（`NavigationBarItem` / `FilterChip` / 自绘底栏等，其槽不是 Box），纳入会产出误报——误报会诱使后来者放宽判据，本仓明禁（口径与边界已写进脚本 docstring）。
- **规则 B｜「多发射助手函数」作槽的唯一子节点**：先全仓解析「块体顶层发射 ≥2 节点的 `@Composable`」，再对「槽里只发一个节点、而那个节点是该类助手」报红。**这正是 P3-457 的原形**：`supportingText = { UnlockPasswordSupportingText(uiState) }`——只看调用点是绿，看穿调用点才是红。
- **判据自校（红→绿，两个方向都跑）**：`--selftest` 由 3 例扩到 **6 例**（原 3 例 + 规则 A 坏样本 + 规则 B 坏样本 + 规则 A/B 好样本）；另拿 `git show HEAD:` 的**修复前源码单文件**用 `--root` 反校 → `box_slot_stacked_sites=1`（命中规则 B）；修复后同文件转绿。
- **过程留痕（一版误报被自己抓住）**：规则 B 首版把 `SecurePasswordField`（`LaunchedEffect` + `DisposableEffect` + 只做预填赋值的 `if`）判成「多发射助手」，误命中 `EntryEditComponents.kt:86 BentoCard { SecurePasswordField(...) }`。修法是**收紧判据本身**而非放宽：① 新增「零布局节点组合体」名单（`LaunchedEffect` / `DisposableEffect` / `SideEffect` / `produceState` / `rememberUpdatedState`）；② 控制流改为**看块内**（块里没有任何会发射节点的调用即计 0）。
- **同批修正的第二处漏检**：旧「发射行」正则的 `.let/.forEach` 分支要求接收者为单层小写标识符，`uiState.errorMessage?.let { … }` 这类**带链 / 带 `?.`** 的形态整行不被识别 ⇒ 首版规则 B 对 P3-457 原形**无鉴别力**（实测：修复前源码反校得 `box_slot_stacked_sites=0` 假绿）。改为「控制流 / 具名调用 / 作用域函数」三条**线性**检查（刻意不用单条大正则：接收者链用嵌套量词会被 CodeQL 判 `py/redos`，本仓 §355/§356 已因同类写法吃过告警）。
