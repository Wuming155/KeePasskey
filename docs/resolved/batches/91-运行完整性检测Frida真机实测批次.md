### 91.3 本批最实质的产出：**两层防线互补**（由矩阵直接读出，不是推测）

- **落点层**：只在**默认路径**命中，但**不需要注入**——连「已下载未运行」都能发现（形态 1）；
  对**改名**完全无效（形态 2a）。
- **maps 层**：覆盖「改名 + 已注入」（含 memfd 内存加载）（形态 2b / 3）；
  对**未注入**的落点无效（形态 2a 中服务端在跑但未注入应用，等级仍 `ELEVATED`）。

⇒ **两层缺一不可**：只留落点层则改名即绕过；只留 maps 层则「落点已就位、尚未注入」的准备阶段不可见。

### 91.5 未经实测的规避面（**如实声明，不得读作已覆盖**）

1. **把 agent 的 memfd 名一并改掉**（`/memfd:frida-agent-64.so` → 不含 `frida`）⇒ 六条特征串均不命中。
   给 frida-server 打补丁即可做到——**这是本实现最直接的绕过面，且未测**；
2. **不产生具名映射的注入**（匿名映射），或**纯读取**类手法（`process_vm_readv` / `/proc/<pid>/mem`
   无需注入）——未测；后者已由 `ISSUE-P3-83` 的 `TracerPid` 信号部分补足；
3. **hook 本进程的 `open`/`read`** 使自检读到空 maps 或伪造内容——未测，且原理上无法在应用层完全防御；
4. **时序窗口**：周期重扫间隔 30 秒，若 `attach → 读取 → detach` 完整落在两次扫描之间可不被捕获
   ——由矩阵推断的残余（本次 attach 持续约 75 秒故被覆盖）。
   该项须与 `P2-63`（快照陈旧 fail-closed + 敏感操作前重扫）一起理解：**高价值通道**在求值时
   会 `escalateForLiveSignals` 实时并入，故该窗口影响的是风险提示的**及时性**，不是「放行与否」。
