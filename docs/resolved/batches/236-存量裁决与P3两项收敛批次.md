## 2. 两项裁决的结论与关键理由

### 2.1 `PD-13`：完整性风险升级**不**触发活动会话熔断（方向 A）

**关键补正（本轮新发现）**：原「误伤形态」登记只写出了 Frida **落点层**
（`/data/local/tmp/frida-server` 仅在案未运行即判 `COMPROMISED`）；本轮直读
`RuntimeIntegrityPolicy.evaluate` 后发现 `COMPROMISED` 的五项构成中有 **三项都是纯文件存在性检查**
——`rootArtifactsDetected`（11 条 `su` / Superuser 路径）、`magiskDetected`（6 条 Magisk 痕迹路径）、
`hookFrameworkDetected` 的落点层（5 条 Frida 落点）。

⇒ 若按候选 B / C 字面实施「`COMPROMISED` → 熔断」，**所有 root / Magisk 设备**以及
**装过 frida 但未运行**的设备会在解锁后 ≤30 s（`LIVE_RESCAN_INTERVAL_MS`）被强制锁库；
本仓**无草稿自动保存**，未保存的条目编辑即丢失，且每次解锁都复发 ⇒ 本应用对这类设备**实质不可用**。

其余理由：① 熔断增益受 30 s 探测上界限制（缩短暴露窗口，而非阻止已发生的读取）；
② 既有四条消费点已 fail-closed（后续通道不给新秘密）；
③ 「只对确证注入熔断」须先**拆分现有信号**（`hookFrameworkDetected` 把 maps 层与落点层合并为一个
`Boolean`）——属安全口径变更且验收**必须真机**，而裁决时经 `android-cli info` 核实**本环境无可用设备**。

**残余风险**已登记 [`已知工程限界.md`](../../architecture/已知工程限界.md) **§26**；
**重开条件**三条规定于 `PD-13`。

### 2.2 `PD-14`：Java 依赖面**不**引入完整性锁定（重开决策）

**覆盖既有裁决**：§87 批次已作「本批不引入」⇒ 本批按 `ISSUE-P2-231` AC① 要求落一次**重开决策**，
**维持结论**（非静默沿用），理由是逐项复核实施条件：

1. `verification-metadata.xml` 的**信任根必须来自可信环境**（官方路径 = 干净 CI runner 首次生成并提交）；
   在开发机生成等于把本机缓存固化为「信任根」，反而制造虚假安全感——本环境**无 CI 通道且推送不可用**
   （同 §225 的如实声明），无法完成 AC③ 明令的「CI 实跑通过」。
2. dependency locking 收益面窄：本仓版本声明**已全部为精确版本**（本批新增守卫机检），
   传递依赖版本由上游 POM 固定；且它对条目所述威胁链（**同版本内容被替换**）**完全无效**。
3. 引入半成品闸门的代价明确（AC② 自陈会成为长期红灯源）。

**替代缓解口径（均已落地）**：① 既有 `dependencyCheck` CVSS ≥ 7.0 fail-closed 断言不变（AC④）；
② `settings.gradle.kts` 的 `FAIL_ON_PROJECT_REPOS` + 仅 `mavenCentral()` / `google()`（已具备）；
③ **新增机检** `DependencyResolutionDeterminismTest`（版本目录不得含动态版本 / 快照 / 区间）；
④ 依赖变更可见性纪律（集中声明 + 批次留痕）。

## 4. 同轮登记并闭环：`ISSUE-P2-236`

**缺陷**：`app/src/main/res/drawable/ic_launcher_monochrome.xml` 使用 Android **VectorDrawable 不支持**的
`<circle cx cy r fill>` 元素（6 处 × 4 属性 = **24 条 `MissingPrefix` Error**）。

**来源（核实时间点 / 方式）**：2026-09-20 本批跑 `lint` 时发现；`git log -1` 核实该文件最后修改为提交
`a1c1dce`（2026-09-20「替换应用启动图标为自适应图标方案」），**非本批引入**。

**双重影响**：
1. **门禁失效**：24 条 Error 使 `lint` 持续 `BUILD FAILED`（AGENTS.md §5 的 lint 门禁长期红 ⇒ 无人再看）；
2. **真实视觉缺陷**：VectorDrawable 不支持 `<circle>` ⇒ 这些图元（4 个密码指示圆点、钥匙头部圆盘与其圆孔）
   **根本不渲染**，图标缺件。

**修复**：6 个 `<circle>` 一律改写为等效 `<path>`（「两段半圆弧」经典写法，如
`M49.7,61 a1.8,1.8 0 1,0 3.6,0 a1.8,1.8 0 1,0 -3.6,0`），属性改用 `android:fillColor`；
圆点顺序与坐标**逐项照搬**，其余 path 一字未动。
