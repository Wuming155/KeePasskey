## 1. `ISSUE-P3-189`：防护覆盖面与静态门禁闭合，**症状仍在**（本批为部分闭环，条目留开放）

### 1.1 为什么不以「多轮实跑绿」作为闭环依据

条目原文的判据是「连续三轮全绿」，但 §150 已自证该判据是**弱证据**（修复前命中率仅 1/2，
时序 / 核数相关）。更根本的问题是：**漏防护的用例污染的是别人**——表现为无关用例红，
故「本类跑绿」永远证明不了「本类有防护」。本批因此把验收改成**静态门禁**（本仓先例：
`AlgoHotPathGuardsTest`），实跑三轮只作为「改动未引入回归」的旁证。

### 1.2 共享守卫：`app/src/test/java/com/keepasskey/app/testutil/MainDispatcherGuard.kt`

- `track(viewModel)`：登记本用例创建的 ViewModel 并原样返回（故可在构造表达式 / `also` 块上包裹，
  **不改任何被测语义**）；
- `trackScope(scope)`：登记非 ViewModel 的自持作用域（同族泄漏面）；
- `tearDown()`：**先**取消全部已登记作用域、**后** `Dispatchers.resetMain()`。顺序即本条缺陷本体，不可颠倒。

### 1.4 新增静态门禁：`app/src/test/java/com/keepasskey/app/quality/MainDispatcherPollutionGuardTest.kt`（3 例）

1. 凡调用 `Dispatchers.resetMain()` 的测试文件，只能是守卫本体、带豁免注记（含依据）的文件，
   或已改走 `MainDispatcherGuard.tearDown()` 的文件；
2. 凡 `Dispatchers.setMain(` **且**构造 ViewModel 的用例，必须出现 `MainDispatcherGuard.track(`；
3. 守卫本体内部：`.cancel()` 的源码位置必须**早于** `Dispatchers.resetMain()`，且不得出现
   `try {` / `runCatching`——条目明令禁止的两种「掩盖污染而非修复」形态就此钉死。

三条判据在改造后对本仓 195 份测试源文件**全部零命中违例**（先以脚本同源复核，再交由该用例长期把关）。

- **本批不动 `androidTest` 源集**，故未跑设备侧四件套（`AGENTS.md` §5 的实跑义务只在改动原生面 / 设备用例时触发）；

### 1.7 关键反证：「先 cancel 再 `resetMain()`」不能消除本条污染（原模型需修正）

第 4 轮的栈顶（原文摘录）：

```
java.lang.IllegalStateException: Dispatchers.Main was accessed when the platform dispatcher was
absent and the test dispatcher was unset. …
  at TestMainDispatcherJvmKt.reportMissingMainCoroutineDispatcher(TestMainDispatcherJvm.kt:45)
  at TestMainDispatcher.isDispatchNeeded(TestMainDispatcher.kt:32)
  at DispatchedContinuationKt.safeIsDispatchNeeded(DispatchedContinuation.kt:262)
  at DispatchedCoroutine.afterResume(Builders.common.kt:588)      ← withContext 回送结果
  …
  at CoroutineScheduler$Worker.runWorker(CoroutineScheduler.kt:807)  ← Default 真实线程
```

- **结论**：`withContext(Dispatchers.Default)` 的块**正常跑完**后，把结果回送给父协程时要对父作用域的
  `Dispatchers.Main` 问一次 `isDispatchNeeded`。取消父作用域**只保证续体不被执行，不保证不再访问 Main**——
  取消本身反而**制造**一次回跳访问。故 §18 / §150 的「漏 cancel ⇒ 污染」模型只是**必要非充分**。
- **与历史结果不矛盾**：§150 修复后连续三轮绿、本批第 1 / 2 轮绿、第 4 轮红 ⇒ 命中率与时序 / 核数相关
  （本批实测 **1/4**），「跑几轮绿」在本条上不构成任何结论。
- **下一步的判据已写入 `ACTIVE_ISSUES.md` 的 `ISSUE-P3-189`**：三条候选路线（① Main 只装不卸 + 补装门禁 /
  ② 不依赖超时的静默判据 / ③ 生产侧暴露可 await 的 `Job` 句柄）与其代价，验收改为**连续 8 轮**全绿。
  本批**刻意未**顺手实施路线 ①——它改变全仓测试的 Main 生命周期语义，须与门禁配套单独评估（且 8 轮实跑的
  判定窗口远超单批范围）。
