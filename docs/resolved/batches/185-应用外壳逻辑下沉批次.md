## 2. 两处「不是纯搬」的地方，单列出来

1. **合并两段一模一样的回落导航**：原实现是 `if (在 Authenticator 且已关) navigate(VaultList) else if (在 Generator 且已关) navigate(VaultList)`，
   两段 `popUpTo(start) { inclusive = false } + launchSingleTop` 完全相同 ⇒ 判定收进
   `hiddenTabRedirectRoute`，导航体只留一份。**逐字核对**显示这正是 `launchSingleTop` 由 3 处变 2 处、
   `popUpTo(...) { inclusive = false }` 由 2 处变 1 处的唯一原因，**语义与键集合不变**。
2. **本地化配置两处重复并一处**：原先 `localizedConfiguration` 与 `localizedContext` 各自
   `Configuration(base)` + `setLocale` + `setLayoutDirection`（后者用 `.apply {}` 写法），
   现统一走 `localizedConfigurationOf(...)`。**行为差异：无**（副本构造与两次 setter 顺序一致）。

**刻意保留的重复**：`AppBottomBar` 与 `AppNavigationRail` 两处 `onNavigateToRoute = { route -> navController.navigateToTopLevel(route, currentRoute) }`
——两条是不同组件的形参接线，强行抽成一个 lambda 变量会让「谁在用」失去现场，且这正是 §183 里
`navigateToTopLevel` 局部量与扩展函数同名带来的可读性代价，故改为**各自显式调用**。

## 4. 逐字性核对（`tools/doc/check_verbatim_move.py`）

- 原文件内容行 **180** 种；找不到 **32** 种，逐条归类：
  `launchSingleTop` / `popUpTo` 的计数下降（§2.1 的合并）、`if (currentRoute == …)` 判定改由
  `hiddenTabRedirectRoute` 承担、`val action: () -> Unit` / `action` / `null` 局部形态改 early-return、
  `cfg` / `setLocale` / `setLayoutDirection` 两组改走共享函数、`settingsViewModel.setThemeMode(` 
  收成一行、`onNavigateToRoute = navigateToTopLevel` 改显式扩展调用；
- **无一处绘制调用被删除或新增**：`AppBottomBar` / `AppNavigationRail` / `NavHost` /
  `keepasskeyNavGraph` 的实参与顺序逐字保留（`appSettings.themeMode` → `themeMode` 为形参改名）。
