## 2. `null` 而不是 `Color.Unspecified`：一个必须写下来的语义差

原页是**根本不传** `titleContentColor` ⇒ `TopAppBar` 走自身的 `contentColorFor(containerColor)` 推导链。
若用 `Color.Unspecified` 顶替，就成了「显式写入一个未定色」——两条路径在 MD3 里的落点不同，
`Color.Unspecified` 会被当成已提供的值参与合并。故可空参数的语义固定为
**「null ⇒ 整个参数省略」**，并在实现里用分支构造而非传参兜底。

## 3. 守卫：为什么这次不是「核过一次就算完」

§189 的 `scaffold_block_fingerprint.py` 是**一次性核对**——它能查出当年的差异，
挡不住将来有人把参数默认值改掉、或把例外页的两行具名实参当冗余删掉。故新增静态接线守卫：

| 用例 | 钉住什么 |
|---|---|
| 骨架必须把顶栏配色以参数暴露，默认值复刻多数页 | 不得再写死 `containerColor`；`titleContentColor` 必须**可空**；null 分支必须整体省略该参数 |
| 例外页必须显式复原 `background` 与不传标题色 | 例外必须**显式存在**且带 `ISSUE-P3-195` 注释锚点（防被当冗余清理） |
| 多数页不得重新各写顶栏配色参数 | 九页出现这两个具名实参即报红 ⇒ 差异不许再长回十份 |
| 多数页清单不得把例外页也算进去 | 反向哨兵：例外页若混进多数页清单，上一条会**空扫自绿** |

**判据性质（不作突变测试，按机制论证）**：没有往生产文件里注入「回归态」再观察报红
（那会短暂产出带未登记呈现改动的代码，且此类改动本就容易被拦）。改法是把守卫的谓词**在 git 历史态上重算**：
`git show HEAD:…PrivilegedBrowserSettingsScreen.kt` 与骨架旧版一起代入四条判据的字符串条件 ⇒
回归态下「例外页复原」与「参数暴露」两条均为 **False**（即守卫会红），当前工作树均为 **True**。
这同时反证了当年 §188 的状态确实处在断言的对面，而不是断言写空了。
