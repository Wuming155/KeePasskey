# §311 历史方向归一与孤儿 tmp 清理批次（ISSUE-P3-306 + ISSUE-P3-308 闭环）

> 本批同批闭环两个纯代码修复条目（同批两提交先例 §290 / §297+§298），文档与代码同一批次入库。

## 1. 整改对象

- `ISSUE-P3-306`：KDBX `<History>` 列表方向未在读取侧归一——官方 KeePass 形态（最旧在前）的库在本仓内存中方向倒置，保存路径 `pruneHistory` 按位置口径（`take(maxItems)` 保留头部）会误裁最新端（数据损失方向）。
- `ISSUE-P3-308`：`SyncCache.clear(remotePath)` 的孤儿 tmp 清理按「未加库身份命名空间的裸 remotePath 键」通配——scoped 缓存目录里的崩溃残留 tmp 永不被清掉（潜在缺陷，`clear(remotePath)` 当前无生产调用点）。

## 2. 整改内容

### 2.1 ISSUE-P3-306（读侧方向归一）

- **方向裁决（AC①）**：选「内存 / 文件均为头部最新」路线——与本仓既有约定（`recordHistorySnapshot` / `rollbackToSnapshot` 头插）及 `ISSUE-P3-292` 起合并路径 `sortedByDescending` 一致，不翻转官方「最旧在前」语义涉及的 `recordHistorySnapshot` / `pruneHistory` / 修订列表 UI。写侧不改：写回文件序 = 内存序 = 头部最新；官方读取端按时间戳维护历史（`PwEntry.RemoveOldestBackup` 按时间戳扫描），功能不受影响，故**不触发** AC⑤ 的官方对拍义务（未判定「文件序须与官方一致」）。
- **读侧归一（AC②）**：`KdbxXmlGroupReader.EntryNode.end()` 装配点以 `sortedByDescending { it.times.lastModificationTime }` 归一（**稳定排序**，同刻快照保持文档序）；这是全仓唯一历史装配点（`HistoryNode` 复用 `EntryNode`，快照自身无嵌套历史，归一为 no-op）。任一来源（官方 / KeePassXC / 本仓）的库进入内存后方向恒一致，位置口径恒正确。
- **只调序不改内容（AC④）**：归一仅重排列表；`HistoryManager.pruneHistory` KDoc 中「读取侧尚未归一」的残余标注随闭环更正。`KdbxMergerTest` / `KdbxMergerV2Test` 的既有方向断言未被触碰（合并在读侧归一之后的内存树上进行，口径不冲突）。
- **用例（AC③）**：新增 `database/src/test/java/com/keepasskey/database/file/KdbxHistoryDirectionNormalizationTest.kt` 3 例：
  1. 升序（官方形态）输入经 save→load 往返后头部为最新，且快照集合（标题 + 时间戳）逐项不变（只调序）；
  2. 归一后 `pruneGroupHistoryByLimit(maxItems=2)` 裁掉的是最旧一端（V1）；
  3. 官方形态库归一后的修订列表方向与本仓自产路径（`recordHistorySnapshot`）一致（均为头部最新）。

### 2.2 ISSUE-P3-308（孤儿 tmp 清理键口径）

- **键口径裁决（AC①）**：`SyncCacheFiles.deleteOrphanTmpFiles` 参数改收**调用方已派生的规范键**（语义与 `fileFor` 对齐：本方法只做 `SHA-256` 命名派生，不自持命名空间——键派生唯一实现仍是 `SyncCache.scopedKey`，未新增第二份派生）。
- **两代键通配（AC②）**：`SyncCacheMaintenance.clear(remotePath)` 先按 `keyOf(remotePath)`（scoped 规范键）通配一遍；scoped 与裸键不同时（即非空命名空间），再按裸 `remotePath` 通配一遍——`ISSUE-P2-291` 的 `adoptLegacyKeysIfPresent` 只迁移**已交付**文件、不迁移 tmp 残留，故旧键崩溃残留同样就地清掉。
- **AC③**：本批未把 `clear(remotePath)` 接进生产路径（保持「潜在缺陷修复」定位，evictor 行为不变）。
- **AC④（`SyncRollbackGuard` 同型复核，如实登记）**：其 `scopedKey` 虽为独立副本，但**无同型缺陷**——防回滚状态没有通配清理入口（tmp 仅在写入 `finally` 中自删），且状态目录在生产布局下位于 `filesDir/rollback`（不在 `cacheDir`），`deleteOrphanTmpFiles` 不可达；已交付状态文件另受 `clear` / `clearAll` 的 F-23 保护。
- **用例**：`SyncCacheTest` 新增 1 例——scoped 实例下放置 scoped 键与旧裸键两代崩溃残留 tmp + 他人路径 tmp，调 `clear(remotePath)` 后两代均被清、他人路径不越界清除。

## 3. 过程缺陷（如实留痕）

1. **本批新测试首版两处断言口径写错**（非被测代码缺陷）：「只调序」用例误按**有序列表**比对（应为集合比对）；「与自产库方向一致」用例误把自产路径快照标题写成 `[V3,V2,V1]`（快照是被归档的**旧版本**，实为 `[V2,V1,V0]`，与当前版本差一档）。更正断言后隔离与全量复跑均绿。
