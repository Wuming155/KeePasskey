## 450.2 整改（AC① / AC②）

落点：`core/src/androidTest/java/com/keepasskey/core/log/AppLogDeviceTest.kt`——**只改用例，产品代码零改动**。

- **前提自探**：新增 `platformRetains(level)`——用 `android.util.Log`（**刻意不经** `AppLog`）逐级写真探针，
  再以既有 `waitUntilLogged` 回读，得 `LevelCapability(verbose, debug)`；`observableChannel` 取「平台确实保留」的级别
  （**`d` 优先、`v` 回退**、两级皆不保留为 `null`）。
  > **关键设计点**：探针**必须**绕过 `AppLog`——若经 `AppLog` 写，「平台丢弃」与「门控拦下」**无法区分**，
  > 而那正是本条病灶（旧版把前者读成了后者）。
- **门控「开 → 落」改走平台保留通道**：`debugEnabled 为 true 时 v 级别真实落 logcat`
  → `debugEnabled 为 true 时门控在平台保留的通道上真实落 logcat`（历史名写入 KDoc，便于检索）。
  `v` 与 `d` 在 `AppLog` 中受**同一个** `debugEnabled` 门控（`AppLog.kt:29-35`）⇒ 换通道**不削弱**判据。
- **两级皆不保留**时 `Assume` 并写明条件（AC① 允许的降级路径）：该分支不落到断言、不冒充覆盖。
- **v 级降为读数**：`printCapability` 打印「本机保留 v/d + 本次判据通道」，**不作断言**（AC① 后半句）。
- **AC② 负向判据标注 + 鉴别力补强**：v 级关闭态断言的消息内**明写**「本机若不保留 v 级则本条**恒真、无鉴别力**，
  不得当作覆盖」；并在**平台保留的通道**上补做一次关闭态断言（该断言在真实平台上确有鉴别力）。
- **测试资产口径**：改名属测试资产纪律允许的**修改**（只增不减、覆盖**不减反增**）；删除 0 例、新增 0 例，4 例仍为 4 例。

## 450.4 过程缺陷（如实留痕）

首跑 `:core:connectedDebugAndroidTest` 连续 3 次失败于**设备 / UTP 抖动**（与本批代码无关），两种症状与处置：

1. **`DeviceException: No connected devices!` / `Skipping device '1c859bcc7d24': Device is OFFLINE`**，
   而同一时刻 `adb devices` 与 `adb get-state`（连续 5 轮）均显示 `device`；
2. **运行中途掉线**：UTP 报 `Failed to get device API level for 1c859bcc7d24 via ADB … device '1c859bcc7d24' not found`
   （`AndroidTestRunner.kt:105` 附加输出收集 + `:107` 收尾清理两处），**异常被吞** ⇒ `BUILD SUCCESSFUL`
   + `test-result-exit-code.txt = 0` + **无结果 XML**。

第 2 条正是 `ISSUE-P3-493`「空转显绿」的**另一种触发路径**：`tools/device/check_connected_device_results.py`
当场判 `UNDECIDABLE(缺结果层：core)` 退 **2**——**闸门有效，未被 `BUILD SUCCESSFUL` 骗过**（这正是该闸门存在的意义）。

处置：`adb kill-server && adb start-server` 后仍报 `No connected devices!` ⇒ 根因是**Gradle 守护进程缓存的 ddmlib
桥接在 adb server 重启后失效**（守护进程跨命令复用）；`./gradlew --stop` 后重跑即通过（35 s）。两条症状与处置
已写入 [`architecture/实现约定与验证现状.md`](../../architecture/实现约定与验证现状.md)。
