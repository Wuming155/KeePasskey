### §352.2 整改内容

1. **AC① 弱目标二次解析**（`AutofillFieldFallback.runWeakReparse`，纯函数）：首轮零登录目标时，
   把 `htmlName + label + autofillHints` 拼成干草堆按既有中英/西里尔词表再扫一轮（覆盖中文命名
   `密码框`/`用户名输入` 这类结构化信号查不到的形态）；**登录上下文门**——仅产出密码目标、或全页
   任一节点干草堆含密码术语时才采纳，否则原样返回首轮零结果（防非登录页误弹）；搜索框 / 非凭据 /
   OTP 排除与 `importantForAutofill` 尊重、可见性口径与首轮**逐字一致**。`ScanResult` 增
   `usedWeakReparse` 诊断标记（默认 false，首轮语义不变）。
2. **AC② 聚焦字段补齐**（`AutofillFieldFallback.synthesizeFocusedUsername`）：有密码目标缺账号目标时，
   把聚焦、可见、未被选中的可编辑文本字段（输入类型 = 未知 0 / 纯文本非密码变体 / 邮箱电话）合成
   账号目标，置信度 MEDIUM；带密码信号 / OTP / 搜索 / 非凭据信号的字段一律不合成，找不到如实不合成。
3. **AC③ 跨请求记忆回补**：新增 `AutofillLoginFieldMemory`（@Singleton，`LinkedHashMap` 进程内存，
   容量闸门 16 上下文按插入序淘汰）+ `AutofillLoginFieldRecovery`（纯函数裁决：记忆**全部**键仍在当前
   结构才回补、只补缺失侧、密码健在不回补）。编排落 `AutofillTargetFieldResolver`：回补在字段级屏蔽
   **之前**（回补目标同过 `AutofillFieldBlockPolicy`），记忆写入在屏蔽判定**通过之后**；实现
   `SessionLockObserver` 并由 `DatabaseModule` 注册（锁定 / 关闭 / 换库即清，不落盘）。
4. **AC④ 打分维度**：`AutofillCandidateRanker` 新增 `SUBDOMAIN_OF_ORIGIN`（110，条目主机名以
   `.<目标域>` 结尾，严格点号边界）与 `APP_TITLE_MATCH`（95，条目标题 ⇄ 调用方 launcher label
   归一互含，仅对 score>0 已入选条目加成）；去 www 归一相等计 `EXACT_DOMAIN`（140）——
   `www.` 剥离属归一化（与 P3-339 剔除 DNS 根点同性质），不可能造出跨域命中。调用方应用名由新
   助手 `AutofillCallerAppLabel.callerAppLabelOrNull` 现取（异常回落 null），两处 `rank` 调用点
   （服务端装配 / 解锁路由）均下传；**打分仍只排序不改入选**（纯标题相似不构成入选，有反例锁定）。
5. **AC⑤ 域名感知三档降级**：`AutofillEntrySearch` 在子串命中之外叠加「主机等值 → 双向子域后缀 →
   去 www 归一」加性 OR（查询须形如多标签域名、`android://` 条目不进域名档、点号边界严格；
   既有子串行为一字不改）；覆盖 `accounts.example.com` ↔ `https://example.com` 正反例。
6. **P3-371 三处 `{REF:}` 展开**：选择器 `resolveCredentials` 用户名侧补 `USER_NAME` 面（与同函数
   密码侧 `PASSWORD` 面口径统一）；CM 回传 `deliverPassword` 双通道补展开（用户名 `USER_NAME` /
   密码 `PASSWORD`；展开为 suspend 调用故回传段迁入 `lifecycleScope.launch`，**先验证后取密**次序
   不变，异常 fail-closed）；自定义字段复制补 `USER_NAME` 面展开（非口令消费点，`{REF:P@…}` 经
   引擎掩码；引擎签名为 String 文本语义，String 物化属引用解析边界、随 chars 在 finally 清零）。
