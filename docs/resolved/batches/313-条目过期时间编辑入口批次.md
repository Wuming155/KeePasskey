# §313 条目过期时间编辑入口批次（ISSUE-P3-310 闭环）

## 1. 整改对象

`ISSUE-P3-310`（自 `ISSUE-P3-297` AC⑤ 拆出）：`KdbxTimes.expires/expiryTime` 有读端与序列化写端，但 app 侧零编辑入口——保存不破坏既有过期值，但用户无法设置。

## 2. 整改内容

- **编辑页两态（AC①）**：高级属性区（标签 / AutoType / Override URL 同卡）新增「过期时间」编辑行——「永不过期」开关（默认关闭，行为零变更）+ 开启后的日期入口（Material3 `DatePickerDialog`）。选定日期按**当日 23:59:59 本地时刻**落库（用户选中当天即当天全天生效）；关闭开关写 `expires=false`（不清理 `expiryTime` 残值，与官方「开关 + 时刻」两字段语义一致，读端只认 `expires`）。
- **数据链路**：`UiVaultEntry.expiresAt: Instant?`（null = 永不过期）单一投影字段贯穿三侧——
  - 读：`VaultEntryMapper` 投影 `times.takeIf { it.expires }?.expiryTime`；
  - 编辑：`applyLoadedEntry` 回填两态（Instant → 本地日期）；`buildEntrySaveSnapshot` 回投影（本地日期 → 当日 23:59:59 Instant）；
  - 写：新建路径 `mapUiEntryToKdbx` 直接构造 `KdbxTimes(expires=true, expiryTime=…)`；既有条目合并路径 `VaultEntryWriteCoordinator.saveMergedEntry` 经新增 `mergeEntryTimes` **只改 `expires` / `expiryTime` 两字段**，其余时间属性（创建 / 修改 / 访问 / locationChanged）原样保留；`recordHistorySnapshot` 仅覆盖 `lastModificationTime`，过期语义随之自然带入历史快照。
- **详情页呈现（AC③）**：新增 `ExpiryStatusCard`——仅当条目设置了过期时间时渲染；已过期以 `error` 色如实标注「已过期」，未过期显示「将于该日期过期」+ 日期。是否进列表排序 / 筛选维持原条目口径（可另拆条目，本批不做）。
- **文案（中英成对，AC①）**：`edit_expiry_title / edit_expiry_never / edit_expiry_pick_date`、`detail_expired_badge / detail_expires_on` 共 5 键，`values/` 与 `values-en/` 同步。
- **互操作留证（AC②）**：未触及 KDBX 序列化代码（`KdbxXmlEntrySerializer` 的 `<Times>` 写出与解析器原样），仍例行跑 `python tools/kdbx-corpus/generate_corpus.py --check` ⇒ 通过；未触及 Passkey schema，不强制 `verify_interop`。
- **既有语义不回退（AC④）**：合并路径（`KdbxEntryMerger`）与历史回滚（`rollbackToSnapshot`）对 `expires` 的既有读端 / 比较语义零改动；本批只新增「写侧入口」，未触碰任何既有 `expires` 消费点。
