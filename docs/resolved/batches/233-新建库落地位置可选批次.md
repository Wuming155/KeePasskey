## 1. 背景与原貌（原样收录自待办条目）

### ISSUE-P2-229：新建密码库强制落应用私有目录，未给位置选择（SAF 缺失）

- **核实时间点**：2026-09-20 经新建链路走查核实。
- **核实方式**：`DatabasePickerScreen.kt:197`「新建」→ `CreateVaultWizardDialog`（`:263`）→ `DatabasePickerViewModel.kt:131` → `RealVaultRepository.kt:151` → **`VaultLifecycleCoordinator.kt:125/130` `File(context.filesDir, "$name.kdbx")`** ⇒ 实际路径 `/data/user/0/com.keepasskey/files/x.kdbx`；对照「打开已有库」已走 SAF：`OpenExistingVaultDialog.kt:43` `OpenDocument` + `VaultLifecycleCoordinator.kt:209` `takePersistableUriPermission(READ|WRITE)`。`产品裁决登记.md` PD-01~PD-12 **无**存储位置裁决；`Privacy-Policy.md:82` 反而承诺「或用户自行选择的存储位置」。
- **背景与根因**：新建即静默落在私有目录，用户既看不到也无法选位置；而既有能力（SAF 读写通道）已具备，属**遗漏**而非取舍。**改造风险面**：① `AtomicFileWriter.kt:12-30` 的 `.tmp` + `renameTo`/`ATOMIC_MOVE` + `.bak` + 目录 fsync 在 SAF 文档上**不可用**；② `SessionOpener.create` 只收 `File`；③ `SyncCycleRunner.kt:180-181` 硬依赖 `currentFile`、`:102` 以 `activeFile.name` 推 remotePath ⇒ SAF 库失去同步能力；④ `takePersistableUriPermission` 现为静默 `catch`；⑤ `VaultDatabaseCatalog.kt:107-112/162/172` 以文件名作 id，内外同名可碰撞。
- **裁决范围（用户 2026-09-20 明示）**：新建向导提供**二选一**——①应用私有目录（默认，原子写 + 同步全功能）②自选位置（`ACTION_CREATE_DOCUMENT`）；选②时**如实提示**该库不支持 WebDAV/S3 同步、写盘为非原子降级方案，并登记进限界表。
- **验收标准**：AC① 新建向导落地位置二选一，默认内部存储；AC② SAF 分支持久化 `content://` 位置且授权失败**显式告警**（不再静默 catch）；AC③ 非原子写降级面在限界表登记，不得声称已满足规则 4；AC④ 现有内部存储路径行为与既有测试语义零回归。

## 2. 整改方案与架构落地

### 2.1 向导：位置二选一（AC①）

- `CreateVaultWizardDialog` 新增 `internal enum class VaultStorageLocation { INTERNAL, EXTERNAL }`
  与 `VaultStorageLocationSection`（下沉到既有的 `CreateVaultWizardDialogSections.kt`，
  本体函数不增行）；默认 `INTERNAL`；
- 选 `EXTERNAL` **当场**拉起 `ActivityResultContracts.CreateDocument("application/octet-stream")`
  （建议名 = 库名 + `.kdbx`，与密钥文件另存为同一 contract 口径），挑定后回显文档显示名
  （复用 `queryDocumentDisplayName`）；用户在系统面板取消 ⇒ 单选项**可见地**回落 `INTERNAL`；
- **不静默降级**：`isLocationValid = location == INTERNAL || selectedVaultUri.isNotBlank()`
  并入 `isFormValid`——未挑定文档时「创建」按钮保持禁用，绝不悄悄改投内部存储；
- `onConfirm` 形参增第 6 位 `targetUri: String?`（与 `DatabasePickerViewModel.createDatabase`
  严格同序，`viewModel::createDatabase` 方法引用接线不变），`DatabasePickerScreen` 的
  回调类型与预览 lambda 同步。

### 2.2 建库链路：SAF 分支抽为独立件（AC②③）

- `VaultRepository.createDatabaseWithKeyFile` / `RealVaultRepository` / `VaultLifecycleCoordinator`
  统一增 `targetUri: String? = null`；`null` 分支的原实现**逐字**搬入私有
  `createInFilesDir`（AC④「内部路径零回归」即指此：同一函数体、同一 `selectDatabase` + `refresh` 顺序）；
- 新增 `data/repository/SafVaultCreation.kt`（**独立成件的动因**：SAF 建库与内部建库无一行共享代码，
  留在协调器内会让该文件恰好顶到 400 行、越入 tier2——工程规则「约 400 行即拆」，
  抽出后协调器回到 **301 行**）；
- 编排顺序即安全边界（四条不可回退约束由守卫用例锁定）：
  **① 持久化授权先行**（拿不到 `takePersistableUriPermission` 即在建库**之前**返回
  `repo_saf_persist_consent_failed`，绝不留「重启后打不开」的半成品）→
  ② `cacheDir` 造临时库（复用 `DatabaseSession.create` 的原子写通道）→ ③ 字节搬到目标文档
  （`openOutputStream(uri,"w")`）→ ④ 失败出口一律 `SafDocumentCleanup.deleteCreatedDocument`
  （**复用既有已测助手**，只删本流程 `CreateDocument` 产出的文档，不碰用户既有文件）→
  ⑤ `close()` 后以 `openStream` **读回复核**并绑定到该文档（既证明写得进读得回，又让用户停留在已解锁态）→
  ⑥ 登记复用 `importExternalDatabase(name, uri, SYNC_TYPE_FILE_PICKER)`；
- `content://` 写回通道 `"rwt"` 由 `SafVaultCreation.saveWriter` **单点定义**，
  协调器 `unlockActiveDatabase` 改调它（消除原先内联的第二份拷贝）；
- 魔法字符串收口：`syncType` 的两个本机值提为 `SYNC_TYPE_LOCAL_DEVICE` / `SYNC_TYPE_FILE_PICKER` 常量
  （此前以裸字面量写在 `isRemote` 判定里）；
- ViewModel 成功事件下行改为 `DatabaseSelected(targetUri ?: fileName)`
  ——自选位置库在目录中的标识就是 uri 字符串，以文件名下行的选中事件对这类库无效。

### 2.3 文案与登记

- 新增 8 条 UI 文案 + 2 条建库失败文案（中英各 10 条）；`EXTERNAL` 选中时同屏显示两条降级：
  「该位置写盘非原子（保存途中断电或闪退存在损坏风险，建议定期导出备份），且不参与 WebDAV / S3 同步」；
- 限界登记：[`已知工程限界.md` §24](../../architecture/已知工程限界.md)（SAF 库非原子写 + 不同步的
  事实、接受理由、三条不得外推的边界、解除条件）；
- **同轮新登记**：`ISSUE-P3-230`——**打开已有** SAF 库的 `takePersistableUriPermission` 仍是静默
  `catch`，重启后该库可能打不开且无归因提示（新建路径本批已改为前置硬失败；打开侧因涉及
  「provider 不支持持久化时仍须允许本次打开」的容错取向，未一并改动，故立条待办）。

## 4. 残余与未执行声明

- **设备侧未执行**（本环境无可用设备 / AVD），以下须真机冒烟：
  ① 选「自选位置」→ 系统保存面板出现且建议名为 `<库名>.kdbx`；
  ② 创建成功后库出现在列表、**处于已解锁态**、可保存修改；
  ③ **杀进程重启后仍能打开该库**（持久化授权生效的直接验收）；
  ④ 在云盘类 provider（不支持持久化授权）上应得到「已取消创建」的显式提示且**不留空文档**；
  ⑤ 内部存储路径与整改前完全一致（AC④ 回归）。
  本批只改生产代码、未新增/修改 `androidTest` 用例，不触发 AGENTS.md §5 ②「设备用例必跑」条款，
  但按限界 §4.1 手工冒烟边界如实登记为**未核对**；
- **`rwt` 非原子写是本批**接受**的降级**（限界 §24），不是「已满足工程规则第 4 条原子写盘」——
  若不接受该降级，用户应选内部存储（默认项即此）；
- **同名碰撞面未处理**：`VaultDatabaseCatalog` 对内部库以文件名作 id、对外部库以 uri 字符串作 id，
  本批沿用（未引入新的碰撞形态：内部与外部 id 空间不同）；条目维护规则要求的
  「核实方式」层面本批未复测该面，故不据 §1 风险清单第 ⑤ 条声称已解决；
- **数据层的分层小妥协**：`SafVaultCreation` 复用 `ui.screens.settings.SafDocumentCleanup`
  （同模块 `internal`，且 `data/repository` 早已依赖 `ui.model`）。选择复用**已测**助手而非
  在数据层重写一份归属判定（`isDocumentUri`），是把「误删用户既有文档」的风险集中到一处既有守卫之下。
