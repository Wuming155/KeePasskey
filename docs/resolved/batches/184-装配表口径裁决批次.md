## 2. 判据做成可执行工具，而不是留在一次性脚本里

新增 `tools/doc/logic_lines.py <文件> <函数名…>`：逐行分类计数（`composable` 分支 / 具名实参 /
状态绑定 / 注释 / 空行 / **逻辑行**）并给出 **PD-11 重开条件是否触发**。
这样 PD-11 的重开条件「**装配表内逻辑行 ≥ 5 或出现 `when` / 循环 / 状态写入 ⇒ 重新计入本目**」
今后是一条**跑一下就有数**的判据，不依赖谁的印象。

`KeePasskeyApp` 的 10 处逻辑行实测为：语言 `when` 1、locale 应用判定 2、主题 `when` 1、
退出确认入口判定 1、Tab 可见性与路由守卫 3、底栏形态判定 2——**全是可独立命名、可单测的逻辑**，
这正是它与两个 NavGraph 的分界。

**顺带踩到的坑（已写进工具文档串）**：按 `fun 函数名(` 定位会漏掉带接收者的扩展声明
（`internal fun NavGraphBuilder.keepasskeySettingsNavGraph(`），首版因此抛 `StopIteration`；
工具改用 `fun\s+(?:[A-Za-z0-9_]+\.)?名字\s*\(` 并在找不到时**打印中文错误**而非抛栈。

## 3. 本批刻意不做的事

- **不动任何生产代码**：豁免不等于「读都不用读」，两个 NavGraph 一行未改；
- **不把 `KeePasskeyApp` 一并豁免**（用户否决了该更宽选项）：它的逻辑段仍要在后续批次按
  §178 配方下沉，届时本目 25 → 24；
- **不放宽任何断言**：本批改的是「哪些函数属于整改范围」这一**范围口径**，
  与「测试是否通过」无关；仓内接线守卫与套件保持原样。
