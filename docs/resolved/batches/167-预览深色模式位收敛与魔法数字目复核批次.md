## 2. 为什么用平台常量而不是本仓自定义常量

`@Preview` 的 `uiMode` 是注解参数，只接受**编译期常量**。`android.content.res.Configuration.UI_MODE_NIGHT_YES`
在 Java 侧即 `public static final int`，正是该位名的**权威定义**；本仓已另有 3 处直接用它
（收敛前 `src/main` 的 4 处 `Configuration.` 引用中 3 处为既有），本次把余下 71 份对齐到同一写法，
不新造第二个名字。

> **取证方式说明**：本会话**未连接** `google-developer-knowledge` / Context7 知识服务器（可用 MCP 仅
> browser-use / builtin / node-repl / qmind / sites），故未凭记忆断言，改以**编译器为权威**：
> 先做**单文件试点** `:app:compileDebugKotlin` 通过，再批量替换（`BUILD SUCCESSFUL`）。

## 3. 第 4 目复核结论（这一步是本轮真正的省功之处）

原判据 `grep -E '0x[0-9A-Fa-f]{2,}'` 把「同一行里的常量定义」也计入，导致清单**假阳性偏多**。
按「排除位掩码 → 排除 `const val` / `val NAME = byteArrayOf(…)` 定义 → 逐条看上下文」重测：

- **真实违例仅 `uiMode = 0x20` 一族**（151 处），已归零；
- `CborEncoder`(10) 全是 `and 0xFF` 字节截断掩码（与已登记的 `LittleEndianUtil` 同族）；
  `TotpKeyUriParser`(16) 全是 `val` 常量定义；`PasskeyKeyText`(31) 全是 OID/DER 字节串与 ASCII 常量定义；
  `UnlockPasskeyManager` / `SyncEndpointGuard` / `OtpEngine` 各仅余 1~2 处掩码 —— **均不改**；
- **仍待裁定**（低价值，已登记在条目内备查）：`PasskeyKeyText` 同文件内 `ASCII_NEWLINE` 与 `CHAR_LF`
  等**重复命名的同一值**、三处 `<= 0x20` 控制字符阈值、`PasskeyCryptoEngine` 的 6 处位值定性。

## 4. 过程留痕（两条都是编译期/运行期暴露，未入库即修复）

1. **生成器会把 LF 文件整文件改写成 CRLF**：其 `kt.write_text(...)` 在 Windows 上按 `os.linesep` 落盘。
   首次运行后 `git status` 出现 3 份「只有行尾不同」的 `src/main` 文件，另有 71 份的行尾被一起翻掉——
   这正是 `.gitattributes`（`* text=auto eol=lf`）**开头登记过的历史事故形态**。
   提交面因 `text=auto` 归一而未受影响（核对：`git add` 后差异仍为 +146/−75、非目标行 0 处），
   但工作区噪声会喂给后续所有工具。处置：读写统一显式 `newline=""`（读到什么写回什么，
   且因 `read_text` 已做行尾归一，等效于**强制 LF**），再跑一次生成器即自愈——复跑后
   `src/main` 仅余 71 份内容改动，`:app:compileDebugScreenshotTestSources` 由红转绿；
2. **给工具脚本打补丁后必须先跑一次**：§1 的 import 条件表达式被紧跟在 f-string 之后，
   Python 把它解析成「字符串调用」——语法合法、运行期 `TypeError: 'str' object is not callable`，
   且崩在**已写回 src/main 之后**（于是暴露了上面第 1 条）。改为先算 `cfg_import` 变量再拼接。
3. **`--tests "*X*"` 在本机不生效**：`cmd //c` 下通配符形态报 `No tests found for given includes`，
   须用**全限定类名**（§166 §4 同型教训，已在批次文档留例）。

   已补进 `AGENTS.md` §5 命令表，Preview/包装漂移从此在本地即可被抓到。
