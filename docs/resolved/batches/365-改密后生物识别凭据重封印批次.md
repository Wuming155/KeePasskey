# §365 改密后生物识别凭据重封印批次（`ISSUE-P2-398` 整条闭环）

- **触发**：2026-09-30 用户报告「修改密码之后，杀掉后台，不能使用指纹登录，需要重新输入新的密码才能进去」，并指定参考 KeePassDX。
- **开放项变动**：P2 区 1 → **0**（P3 仅剩搁置项 `ISSUE-P3-339`）。

## 1. 根因

快速解锁封印载荷（`BiometricSealedPayloadCodec` v1 帧 = 主密码 + 可选密钥文件因子）只在**主密码解锁成功后**
由 `BiometricEnrollmentCoordinator` 登记；改密链路
`SettingsMasterKeyChangeController.submit → VaultRepository.changeMasterPassword → DatabaseSession.changeCredentials`
**不触碰封印凭据**——旧封印载荷内的密码随改密确定失效。冷启动指纹解锁时 BiometricPrompt 授权通过、
封印凭据解封成功，但解出的是旧密码 → `unlockActiveDatabase` 失败 → `completeBiometricUnlock`
清除陈旧凭据回落主密码页。用户被迫**手输一次新密码**（此后自动重新封印才恢复指纹）。

## 2. 参考口径（KeePassDX）

读 `docs/references/KeePassDX-架构分析.md` §6.5 后定点查看其源码（规则 3 允许的定向取证）：
改密保存时 `MainCredentialActivity` 收集 `DeviceUnlockViewModel.uiState.credentialRequiredCipher`，
以 `encryptCredential(credential, cipher)` 把**新凭据经 BiometricPrompt 授权 Cipher 重新加密**，
经 `CipherEncryptDatabase` 覆盖写回 `cipher_database` 存储——指纹解锁随即对新凭据可用。
本批即该语义在封印体系（prefs + per-db 硬件别名 + Class 3 强生物识别 per-use 授权）下的落地。

## 3. 整改

- **新增 `BiometricResealCoordinator`**（settings 包）：前置 = 生物识别已启用 **且** 活动库已有封印凭据
  （未登记时不动，下次主密码解锁自然登记新密码）；顺序 = **先摘除陈旧封印**（此后任何失败都不残留
  「注定失败态」）→ 供给封印密钥（`prepareEncryptCipher` + 落位探测，与登记路径同一供给形态）→
  软件级降级闸门复检（`requiresDowngradeConsent` 且无确认记录时不封印，**不得绕过** ISSUE-P1-22）→
  强生物识别校验（`canSeal`，无宿主 Activity fail-closed）→ `BiometricSealedPayloadCodec.encode`
  编码新密码 + 会话密钥文件因子（`DatabaseSession.exportKeyFileBytes()` 快照克隆）→ 一次 BiometricPrompt
  授权加密 → 落库前复核开关（防「关闭 = 删除」竞态写回，与登记路径 ISSUE-P2-253 同批关闸）→ 保存。
  失败语义：任何失败路径仅留痕日志，**不影响已成功的改密**，遗留恢复通道兜底；
- **接线**：`SettingsMasterKeyChangeController` 增 `resealAfterChange` 挂点（改密 `Success` 后、`finally`
  清零入参**之前**执行——这是唯一能以新密码重封印的窗口；忙态语义不变，BiometricPrompt 收起后对话框才回落）；
  `SettingsViewModel` 把协调器装配收敛进 `SettingsBiometricGate`（复用其活动库跟踪，行数分档闸门倒逼），
  控制器经方法引用 `biometricGate::resealAfterMasterKeyChange` 挂接；`SettingsScreen` 经
  `LocalActivity` 透传宿主（与 `SecuritySettingsScreen` 同口径，规避 Lint `ContextCastToActivity`）；
- **文案**：`sec_biometric_reseal_title` / `sec_biometric_reseal_subtitle` 中英成对登记。

## 4. 验收

- AC① 改密成功 + 启用 + 已封印 → 新封印落库且载荷可解码出**新密码**与密钥文件因子
  （`BiometricResealCoordinatorTest`，替身 AES/GCM 密钥 + 生产解码器回读，行为级判据）；
- AC② 未启用 / 未封印 / 无活动库 → 不弹窗、不动存储（同上 3 例）；
- AC③ 授权取消 / 密钥供给失败 / 无强生物识别 / 软件级降级未经确认 → 陈旧封印已摘除、新封印不落库
  （同上 4 例；降级闸门用例锁定「不得绕过」）；
- AC④ 改密失败不触发重封印（`MasterKeyChangeTaskTest`）；
- AC⑤ 重封印窗口内入参未清零、任务收尾清零 + 载荷/密钥文件快照 `fill(0)` 源码守卫（各 1 例）；
- AC⑥ 全量 `test --rerun-tasks --max-workers=1` 绿 `xml=489 tests=3172 failures=0 errors=0 skipped=13`
  （较 §364 基线 3139 的 +33 中，本批新增 12 例〔协调器 10 + 换密接线 2〕，余 21 例为 §364 后
  远端浏览导航批次提交的存量增量）+ 门禁读数 8/8（§6）。
