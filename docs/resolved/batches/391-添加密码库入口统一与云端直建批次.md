# §391 添加密码库入口统一与云端直建批次（`ISSUE-P2-424` / `ISSUE-P3-425` / `ISSUE-P3-426` 三条闭环）

> **触发**：2026-10-01 用户反馈三条问题——「点击打开已有的密码库会直接访问本地的，应该预选打开云端的或者本地的」「新建密码库只能新建到本地，不能新建到云端」「新建密码库里面有一个打开已有的 KDBX，这不合适」；同日登记三条（`ISSUE-P2-424` / `ISSUE-P3-425` / `ISSUE-P3-426`），用户指示「将这 3 个问题解决掉」，同日整改闭环。
> **结案条目**：三条**整条闭环**（P2 0→1→**0**；P3 净 −3，仅剩搁置 339）。

## 0. 原文登记（三条合并收录）

> ### ISSUE-P2-424：打开已有密码库的两入口行为不一致——解锁页空状态入口只走本地 SAF（文案却承诺「云盘」），云端来源还须手输凭据、不复用已配置云账号
>
> - **背景**：用户反馈「点击打开已有的密码库会直接访问本地的，期望可预选打开云端或本地」。核实发现「打开已有库」实际有**两个入口、能力不一致**：入口 A（库管理页）三来源 Chip 齐全但云端凭据须现场手输（`DatabasePickerViewModel.kt:48-51` 未注入任何云账号仓库）；入口 B（解锁页空状态）文案 `unlock_empty_open_desc`=「从本机存储或云盘导入 .kdbx」**承诺了云盘**，实际仅本地 SAF 无任何云端路径。
> - **核实**：2026-10-01，用户反馈触发；Explore 铺开代理全库定位，主会话抽查文件行号与字符串资源原文逐条确认。
> - **整改方向**：① 入口 B 与入口 A 统一走三来源对话框；② 云端来源与设置页云账号打通（默认预填，手输仅兜底）；③ 来源 Chip 支持「预选」记忆。
> - **验收标准**：AC① 解锁页空状态入口可从 WebDAV / S3 打开库；AC② `unlock_empty_open_desc` 文案与实际行为一致；AC③ 已配置云账号时打开对话框默认展示该账号（无需重新手输）；AC④ 全量 test 绿 + 门禁读数全 PASS。

> ### ISSUE-P3-425：新建密码库只能落本地，无「直接建到云端（WebDAV/S3）」路径
>
> - **背景**：用户反馈「新建密码库只能新建到本地，不能新建到云端」。核实：存储位置仅 `INTERNAL` / `EXTERNAL` 两档均本地落盘，云端只作为建库后的同步能力存在。
> - **核实**：2026-10-01，同上方式。
> - **整改方向**：a) 新建向导存储位置增加「云端」来源（复用已配置云账号）；b) 或产品裁决「先本地后同步」并登记。**实施取 a**（用户原诉即「不能新建到云端」）。
> - **验收标准**：AC① 存在可用的云端直建路径且创建后同步闭环；AC② 全量 test 绿 + 门禁读数全 PASS。

> ### ISSUE-P3-426：「打开已有 KDBX」入口与「新建密码库」并排混排，「添加密码库」信息架构须重整
>
> - **背景**：用户反馈「在新建密码库里面有一个打开已有的 KDBX，这不合适」。核实：新建向导内部并无该入口（其 `OpenDocument` 是选密钥文件）；混排发生在库管理页同一 Row 内两按钮各占一半并排，且与解锁页空状态的两卡片上下排列组织方式不一致。
> - **核实**：2026-10-01，同上方式。
> - **整改方向**：a) 合并为单一「添加密码库」入口再分新建/导入；b) 分区呈现、次要动作视觉降级，两屏组织方式一致。
> - **验收标准**：AC① 两屏新建/导入入口组织方式一致、语义清晰；AC② 全量 test 绿 + 门禁读数全 PASS。

### 1.1 方案裁决（云端直建的形态）

「新建到云端」落地为 **filesDir 建库 + 云 syncType 幂等重登记**，而非「直接在远端写初始文件」：

- 与「云端打开」（`CloudVaultImporter`：下载 → 落凭据 → 按本地路径登记）**同形态**——本地文件是落地细节，卡片只显示云端库（§371 单条目口径）；
- 远端上传交由**既有同步周期**，`SyncVaultBindingStore` 的绑定不符保护（跨库整库覆盖须用户显式确认）照常生效——自造上传路径会绕开这套保护面；
- 本地副本享有原子写盘（`.tmp` + rename + `.bak`），云端直写的非原子降级不再引入。

## 3. 如实声明

1. **真机未走查**：本批全部为 UI 流程改动，真机上「解锁页导入入口 → 三来源对话框 → 云账号预填 → 云端打开」「新建向导云端直建 → 首次同步上传」两条链路的端到端体验未实机验证，待用户下次装机自然核验。云端直建的**真实远端上传**依赖既有同步周期，JVM 单测只覆盖到登记层（Fake 仓库），未做真实 WebDAV/S3 对拍。
2. **弱因子提示覆盖面收窄**：解锁页直连导入退役后，导入路径的弱因子提示通道归零（此前仅解锁页直连路径有提示，选择器路径本就因「立即退栈」无提示，见限界 §8）。属已知取舍，非本批引入的新缺口，解除条件不变。
3. **云端直建不触发即时上传**：创建后不强制 `syncNow()`（新建库未解锁、同步周期需要会话），上传随既有同步时机（解锁后自动/周期/手动）进行；向导内文案如实表述为「远端上传随同步周期进行」。
4. **快照读取时窗**：进入库管理页的头几百毫秒内「云端」行可能短暂显示「正在读取云同步配置…」（快照 init 期异步读取，避免 Keystore 解封落 Main），就绪后自动转为可用态。
5. 未触 `androidTest` / 原生面（`crypto/src/main/rust` 零改动）；`lint` 未单独跑（无 CI 强制点）。
6. **守卫锚点由本批自身改动**（如实声明的利益冲突）：两处静态守卫的锚点因本批生产改动而失效——
   `CreateVaultLocationWiringTest` 的位置有效性判据由等值式改为排除式（三档存储位置），
   `SecureDialogFlagPolicyTest` 的 `AlertDialog` 调用点清单因对话框搬家而跨文件计数。
   两处均**只改锚点位置、不改判据强度**（前者另加两条云端 fail-closed 判据，后者总数仍 7 且逐项列出计数依据）；
   另**退役** `VaultPermissionNoticeWiringTest` 判据 2 一例（其断言目标已无生产代码）。

   不得以「守卫变绿」反推「守卫仍等价」。
