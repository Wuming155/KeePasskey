### ISSUE-P3-440：前台通知补「复制用户名 / 密码 / TOTP」快捷动作——**须先过安全复核**

- **核实时间点**：2026-10-02；**核实方式**：竞品对照报告 §3.6 / §5-G6——本仓「密码库已解锁」常驻通知已有「立即锁定」动作（`UnlockedNotificationController.kt:137-141`），无复制类动作；keepass2android `CopyToClipboardService.cs:111-156` 前台通知带 Copy username/password/TOTP 三动作。**裁决**：G6 「可以做」，**前置安全复核为硬门**。
- **前置门槛（先于实现）**：安全复核须裁决——① 通知动作携带哪个字段（用户名 / TOTP 低敏，主密码 / 保护字段禁上通知面）；② 锁库超时窗口内通知动作的存活口径；③ 通知展开态在锁屏 / 受信设备上的暴露面。复核结论落 `docs/security/` 或裁决登记，未过复核**不得**开工。
- **验收标准**：  
  ① 经安全复核批准的字段子集上通知动作，复制行为复用 `ClipboardSecurityManager` 既有定时擦除与提示链；  
  ② 动作点击后不展开任何明文 UI（后台完成复制 + Snackbar/通知反馈）；锁库即收起对应动作；  
  ③ 全量 test 绿 + 门禁全 PASS；真机走查动作可用（设备侧验证留痕）。

### ISSUE-P3-442：应用内搜索补「记住搜索词」自愈——用户手选结果后询问是否把搜索词写进条目

- **核实时间点**：2026-10-02；**核实方式**：竞品对照报告 §3.2 / §5-G5——keepass2android `AppTask.cs:494-534` 在用户手选条目且条目 URL 不覆盖搜索词时弹「Remember search text?」（`AddUrlToEntryDialog_title`），一次操作永久修正匹配错误；本仓无对应机制（域名感知档已由 P3-352 闭环，但用户手选结果的**回灌自愈**缺位）。**裁决**：G5 「可以做」。
- **验收标准**：  
  ① 仅在「搜索态 → 用户点开条目」且该条目 URL 与搜索词域不匹配时触发，对话框询问「将搜索词写入该条目 URL？」（可勾选不再询问）；  
  ② 写入走条目更新的既有保存链（含 {REF} / Override URL 字段不被误覆盖）；敏感搜索词（含粘贴口令形态文本，P2-105 同源红线）**不预填不回显**；  
  ③ 一次会话内对同一条目只询问一次；全量 test 绿 + 门禁全 PASS。

### ISSUE-P3-444：「界面偏好」设置组——界面缩放 / 等宽字体开关 / 设置页搜索 / 动效降级开关

- **核实时间点**：2026-10-02；**核实方式**：竞品对照报告 §2.3 / §2.6 / §3.6 / §5-G14（代码直读）——Monica 具备界面缩放（`SettingsScreen.kt:747-752` InterfaceScale + BottomSheet）、设置页内置搜索（`SettingsSearchSupport.kt:23`）、动效降级开关 `LocalReduceAnimations`（`ui/LocalSharedTransition.kt:10-18`，为 HyperOS 2 / Android 15 卡顿设）；KeePassDX 等宽密码字体开关默认开（`donottranslate.xml:230-231`）；本仓均无（仅列表密度偏好）。**裁决**：G14（含并入的动效降级项）「可以做」。
- **验收标准**：  
  ① **等宽字体开关**：密码 / TOTP 字段的等宽展示改为可关偏好（默认开＝现状），收口既有等宽样式常量；

  ⑤ 四项均在设置页新增「界面偏好」分组；逐项 `@Preview` 覆盖；全量 test 绿 + 门禁全 PASS。

## §2 前置安全复核定案（`ISSUE-P3-440` 硬门，落 `PD-69`）

条目要求「复核结论落 `docs/security/` **或裁决登记**，未过复核**不得**开工」。本批按后者处置，
结论落 [`docs/architecture/产品裁决登记.md`](../../architecture/产品裁决登记.md) `PD-69`，三问逐项裁决：

| 复核问题 | 裁决 |
|---|---|
| ① 通知动作携带哪个字段 | 只允许**用户名**与 **TOTP 动态码**；**密码 / 受保护自定义字段 / TOTP 种子 / 库文件名一律不上通知面**（通知动作是「零二次确认」一键路径，最高敏项必须留在「须进应用」一侧） |
| ② 锁库超时窗口内动作存活口径 | 只在**存在「最近查看条目」**时挂出（`UnlockedNotificationEntryTracker`，仅进程内存、不落盘、不进 `SavedStateHandle`）；库锁定 / 关闭 / 偏好关闭 / 权限回收 → 通知整体撤销并**同时清除登记**；自动锁倒计时窗口内动作仍可用（此刻库确实仍解锁，与「立即锁定」同一面）；进程重启后登记为空 |
| ③ 锁屏 / 受信设备暴露面 | 通知保持 `VISIBILITY_SECRET`；动作文案为固定通用文案（不含条目名 / 用户名值 / 域名）；跨 `PendingIntent` 载荷**只有字段名**（不含条目 id 或任何用户数据），作用对象点击时现读；点击**不展开任何明文 UI**（广播接收器 + 后台复制）；明文只进剪贴板，复用既有 `ClipboardSecurityManager` 链（`EXTRA_IS_SENSITIVE` + 定时擦除 + 熄屏 / 后台 / 锁库清除）；受信设备上按钮可见判为**可接受**（按钮零用户数据、明文受既有擦除约束） |

与竞品的差异如实记录：keepass2android 前台通知带 username / password / TOTP **三个**动作，
本仓**主动放弃**密码一项——「竞品有」不构成让密码上通知面的理由。

## §3 整改

### §3.1 `ISSUE-P3-440`：解锁通知复制快捷动作（字段子集＝用户名 / TOTP）

- 新增 `notification/UnlockedNotificationEntryTracker.kt`（`@Singleton`，「最近查看条目」内存态登记）。
- 新增 `notification/UnlockedNotificationCopyField`（enum，`extraValue` 即跨 `PendingIntent` 的唯一载荷）
  与 `notification/UnlockedNotificationCopyAction.kt`（`@Singleton`，自持 `SupervisorJob + Default` 受控协程）：
  会话态**第二道闸门**（`NotificationGate.isUnlockedState`，锁库后残留点击一律作废）→ 经仓库**现读**
  用户名（`getKdbxEntry`）/ TOTP（`calculateEntryTotp`）→ 走 `ClipboardSecurityChannel`
  （用户名 `copyPlainText`、验证码 `copySensitiveText`）→ 反馈（主界面可达发全局 Snackbar，否则 Toast 兜底，
  与剪贴板定时清空提示同口径）。剪贴板标签取**固定通用文案**，绝不把条目名写进系统剪贴板描述。
- 新增 `notification/UnlockedNotificationCopyReceiver.kt`（`@AndroidEntryPoint`，`goAsync()` + 动作结束
  `finish()`；清单 `exported=false`，与 `VaultLockActionReceiver` 同口径）。
- `NotificationGate.shouldShowUnlockedCopyActions(recentEntryId)`（纯函数，新增 2 例用例）——
  无「最近查看条目」即不挂动作（动作必须有作用对象，否则是点了没反应的假入口）。
- `UnlockedNotificationController`：依赖注入 tracker，`merge` 增第四路（条目变化 ⇒ 动作集变化 ⇒ 重发）；
  `post()` 增 `recentEntryId` 形参与两条 `addAction`；`cancel()` 连带清除登记。
  「立即锁定」动作与既有守卫断言（`addAction(` + `lockVaultNow` + 订阅内存快照 + 零 `delay(`）逐条保持。
- `EntryDetailViewModel`：注入 `recentEntryTracker`（可空，纯 JVM 单测不受影响），
  在 `onScreenEntered()` 登记当前条目（该回调由 `EntryDetailLifecycleEffects` 在进入组合时调用）。
- 中英文案 6 条（两动作名 + 两条成功 + 剪贴板标签；「未配置」与「复制失败」复用列表行既有文案，不另造副本）。

  调用方**不得直接导航**；「已询问条目」集合与「本次会话不再询问」标记都活在协调器上
  ⇒ 去重作用域＝列表页 ViewModel 存活期（锁库 / 退栈即复位，不落盘）。

  只改 `URL` 一个字段 ⇒ `Override URL` / 笔记 / 自定义字段（含 `{REF:…}` 原文）逐字保留；
  **不产生历史修订**；落盘仍走会话唯一出口 `persistSession`（既有原子写 / 备份链路）。
  顺带把「收藏 / OTP / URL」三处字段级写入口重复的 12 行三级解析收敛为一份
