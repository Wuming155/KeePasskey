## 1. 原始条目

> 以下为本轮复核时登记的跟进项快照。原整改方案与历史批次状态以各自归档为准；本节记录新增验收缺口及事务边界。

### ISSUE-P2-614：锁定态保存 PendingIntent 缺少目标进程重启后的回归

- **来源 / 严重度**：2026-10-14 复核锁定态 Autofill 保存请求实现与设备验收范围；Medium。
- **核实时间点 + 核实方式**：2026-10-14；检查 `LockedSaveRequestPendingIntent`、`PasswordSaveActivity` 及现有 instrumentation 用例，确认此前用例只在同一进程内发送请求。
- **背景 / 位置**：请求身份由 Android `PendingIntent` 承载；同进程 A/B 逆序发送不能证明进程重建后 token 仍指向各自请求，也不能证明已消费令牌的拒重放状态跨进程保留。
- **触发 / 后果**：系统在应用进程退出后发送旧保存 token，可能错配用户/口令，或重复交付已消费请求。
- **建议 / 验收**：用独立进程持有 A/B 真实 `PendingIntent`，在目标应用进程重建后逆序发送；核对请求身份、明文缓冲销毁及已消费请求拒重放。

### ISSUE-P2-616：设置元数据写入失败时内存候选可能先于磁盘提交发布

- **来源 / 严重度**：2026-10-14 复核设置页写入失败反馈链与数据库会话状态；Medium。
- **核实时间点 + 核实方式**：2026-10-14；逐读 `VaultWriteBoundary.commitMeta`、`DatabaseSession` 与 `SessionPersistence`，并检查现有设置保存失败用例的写入替身。
- **背景 / 位置**：元数据更新若先发布活动数据库候选、再调用 writer，writer 失败时 UI/内存可能呈现未提交值；回滚已发布树还可能与历史裁剪、资源擦除及取消后的提交状态冲突。
- **触发 / 后果**：SAF/provider 或本地 writer 在保存时失败，设置页读到的内存状态与正式文件分离；结果不明时再次写入还可能覆盖已提交数据。
- **建议 / 验收**：在共享会话互斥锁内形成候选、写入并取得提交回执；仅确认提交后发布候选。写入失败保留旧状态；提交不确定时禁止继续写并明确返回错误。通过宿主故障注入、设置反馈和 AVD SAF provider 实测。

### ISSUE-P3-615：自动填充认证链用例缺少语言、干扰库及超时恢复矩阵

- **来源 / 严重度**：2026-10-14 复核 `AutofillAuthChainDeviceTest` 的设备用例参数与运行回执；Low。
- **核实时间点 + 核实方式**：2026-10-14；逐读测试入口、客户端请求隔离、活动库前提及此前设备 XML，确认缺少重复执行与认证超时后的完整恢复路径证据。
- **背景 / 位置**：用例需在中文/英文、存在/不存在不同密码的干扰库等条件下定位认证 UI；首个认证请求超时时还须证明后续恢复确实到达完整填充链。
- **触发 / 后果**：本地化文案变动、旧活动库残留或认证首轮超时可能导致用例错认窗口、命中错误库，或只验证了失败没有验证恢复。
- **建议 / 验收**：隔离客户端请求、活动库与测试设置；覆盖两种语言、干扰库有无、连续重复及 timeout → 完整成功路径，逐份读取 XML 确认非空并通过。

## 2. 实施与验收

- **P2-614（目标进程重建与系统 token）**：新增 `LockedSaveRequestProcessRestartDeviceTest` 和仅 androidTest 使用的 `LockedSaveRequestHolderProvider` / `LockedSaveRequestHolderActivity`。独立 test APK 进程持有由生产工厂创建的 A、B `PendingIntent`；第一阶段退出后，第二次 instrumentation 在不同 PID 恢复状态，经可见 test Activity 逆序发送 B、A，验证 Activity 收到的用户名/口令与令牌一致、已消费 A 不复制口令数组、B 消费后再次发送被拒绝。两个阶段分别回执 `OK (1 test)`；设备读数 `preparePid=25121 consumePid=25177`，说明消费阶段运行于新 app 进程。常规设备套件 XML `tests=1 failures=0 errors=0 skipped=0`。
  - **测试边界**：为避免 Android 在 force-stop/uninstall 时取消该包的 PendingIntent，阶段间不 force-stop 或卸载；用两次 instrumentation 与不同 PID 证明目标进程已重建。发送由独立测试包的可见 Activity 完成，覆盖 Android 平台 PendingIntent 与生产 `PasswordSaveActivity`，不等同于自动化点击 Credential Manager / Autofill 系统保存面板。

- **P2-616（元数据事务）**：`DatabaseSession` 在会话锁内捕获数据库、路径与文件身份；`SessionPersistence.commitDatabaseMeta` 将变更保留为候选，writer 确认后才发布。写入未提交时不发布；提交回执为 UNKNOWN 时会话置只读并返回 `SAVE_WRITE_UNCERTAIN`；活动库或目标文件漂移返回 `SAVE_SESSION_CHANGED`。已确认提交后，即使调用方取消，也先完成非挂起的局部发布再传播取消。替换 KDF 时只擦除未被新 KDF 共享的旧 secret 数组，并将生命周期约束记入 KDoc。`VaultWriteBoundarySafDeviceTest` 用真实 SAF provider 验证打开写入失败、候选不发布、正式文件字节不变、错误映射、取消前原字节保持以及关闭重开后重试成功：AVD XML `tests=1 failures=0 errors=0 skipped=0`。`SessionAdoptIfUnchangedTest` 为 6/0/0/0；设置反馈用例 XML 为 12/0/0/0。

- **P3-615（认证矩阵）**：扩展 `AutofillAuthChainDeviceTest`，加入错误活动库负向断言、认证首次超时后继续完整流程及请求隔离。AVD API 36 共 8 次完整执行：中文/英文 × 有/无干扰库，每组合重复两轮；其中一轮显式触发认证超时后继续完成认证与填充。每份 XML 均为 `tests=1 failures=0 errors=0 skipped=0`。

- **全量 JVM 单测**：`test --max-workers=1` EXIT 0；`count_test_results.py` 读数为 `xml=581 tests=3803 failures=0 errors=0 skipped=15`。首轮及第二轮失败证据已按仓库规则保留，修正静态源码断言和事务清零计数后第三轮全量通过。

- **本轮相关 AVD 回归**：`PasskeyCreationDeviceTest` 5/0/0/0，`PasskeyPersistenceActivityDeviceTest` 1/0/0/0，`SyncSnapshotRestartDeviceTest` 1/0/0/0，`SessionRecoveryDeviceTest` 2/0/0/0。Activity 用例由第三方测试 APK 触发真实 Credential Manager 创建请求，注入生产 Activity 的仓库提交边界，确认持久化失败文案、读取 Android `Activity.mResultCode == RESULT_CANCELED`，调用方没有 `onResult`，且正式测试库字节不变。

- **验收结论**：P2-614 的跨进程 token/重放判据、P2-616 的元数据事务及错误反馈、P3-615 的自动填充矩阵均有实现与通过证据；已整条归档。`ISSUE-P1-590` 的真实 Activity 失败回执补验通过。P1-591/592 的剩余系统级生命周期验收仍单列于 [ACTIVE_ISSUES.md](../../ACTIVE_ISSUES.md) 的 `ISSUE-P1-613`。

## 4. 限制与后续边界

- **P1-591 操作系统进程与生产 WebDAV provider 未覆盖**：当前 AVD 测试以本地 HTTPS 合成服务覆盖上传 A / 本地保存 B / 重建 session 与 coordinator / 外部 client C 合并，验证 A/B/C 均保留；没有执行 app force-stop 后由生产 WebDAV provider 重启同步。
- **P1-592 产品恢复 UI 未覆盖冷进程恢复**：当前设备测试使用真实屏幕熄灭事件触发 `ACTION_SCREEN_OFF`，验证加密恢复副本写出；已有恢复编排测试可读、预览和恢复合成库。仍未在真实进程杀后从产品 UI 完整恢复该副本。
