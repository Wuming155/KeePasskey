# §212 批次：JNI 零拷贝评估批次（ISSUE-P3-187 结案，定案实施另立 P3-198）

> 日期：2026-09-19　|　条目：`ISSUE-P3-187`（**评估项结案**）；新立 `ISSUE-P3-198`（生产化承接）
> 评估正文：[`records/JNI零拷贝评估_2026-09-19.md`](../../records/JNI零拷贝评估_2026-09-19.md)（AC①②④⑤）

## 1. 本批做了什么

1. **AC① 契约定义**（三条候选路线，逐条写明）：
   - **① `GetPrimitiveArrayCritical`**：GC 钉住窗口 + 临界区禁令（禁分配 / 禁其他 JNI / panic
     必须先 Release 再归一）+ in-place 语义变化；与现有 `catch_unwind` 范式可配对（guard Drop）；
   - **② `DirectByteBuffer`**：堆外地址稳定、无 pin 窗口、擦除责任上移调用方（确定性归零）；
   - **③ `CipherSpi` 有状态 Provider**：密钥原生自持（`engineInit` 移交 ⇒ **结构性消除 §147
     全零密钥风险**）、`engineByteBuffer` 重载全零拷贝；代价 = JCE 完整契约面 + Provider 注册拓扑。
2. **AC⑤ 有状态 vs 无状态四维对照**：密钥所有权 / 擦除时点 / 生命周期泄漏防护 / 可测试性
   （评估正文 §6；有状态形态以 Rust `Drop` 担保 + 显式 `dispose()` 证明不削弱 `Zeroizing` 纪律）。
3. **AC② 探针原型**（非生产路径）：
   - Rust：`NativeChaCha20.applyKeystreamDirect`（`GetDirectBufferAddress` 直取堆外切片就地
     `apply_keystream_at`；无拷贝无分配无 `Zeroizing`；`catch_unwind` 保持；失败归一 `-1`）；
   - Kotlin：`NativeChaCha20.applyKeystreamDirect(key, nonce, byteOffset, data: ByteBuffer)`；
   - 探针用例：`probeJni零拷贝DirectByteBuffer_对比_连续10轮`（正确性前置 = 两条路径
     **逐字节一致**；10 轮同载荷对比）。
4. **AC② 真机对比实测**：Pixel_10（x86_64 / API 36.1）10 轮中位——现状 **24.05 ms**
   （与 2026-09-17 基线 24.7 ms 复现一致）vs 直扣 **3.7 ms**（≈**6.5×**）⇒ 拷贝 + 分配
   （占单次 JNI 44%）被消除，残余边界远低于「内核本体 + 20%」 ⇒ **AC② 达标**。
   **真机缺测（如实登记）**：Redmi 4X 本轮 USB 断连未恢复，A53 侧数据缺测——结构性结论
   （拷贝占比是调用形态决定、与微架构无关）不受影响；探针已入库，真机重连后随批补跑。
5. **AC④ 结论入档**：评估正文 §8 五条定案 + 限界表 §15 / §17 的解除条件更新。

## 2. 定案结论（评估正文 §8 摘要）

1. **DirectByteBuffer 路线收益证成**（唯一同时满足「零拷贝 + 无 GC 窗口 + 纪律自洽」的路线）；
2. `GetPrimitiveArrayCritical` 技术可行但劣于 ②（GC 钉住窗口无额外收益）——不采纳；
3. `CipherSpi` 有状态 Provider 为长线演进方向（AC⑤ 核心收益 = 消除 §147 全零密钥风险），
   与 ② 正交，不在本轮实施；
4. **实施另立 `ISSUE-P3-198`**：`ChaCha20CipherEngine` / `CbcStreams` 生产化 + AES 族同构 +
   真机补测；本评估项结案。
