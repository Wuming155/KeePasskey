### ISSUE-P1-631 外部漂移合并伪造共同基线，可能丢失本地新增和编辑

- 核实：2026-10-16（Asia/Shanghai），当前源码与定向调用链；静态确认；置信度：高。
- 问题：mergeAndSave 把当前 localDb 同时传作 base 与 local。合并器因此认为本地从未修改：本地新增条目在磁盘缺失时被推断为远端删除，同 ID 本地编辑则让磁盘版本成为唯一修改。随后采用并保存该结果。分组也受相同基线错误影响。
- 影响与触发：用户选择“合并后保存”仍可能丢失未提交本地条目/分组或恢复磁盘旧值；影响本地文件和 SAF 外部漂移处置，不代表普通三方同步均有此缺陷。 触发序列及反证详见方案。
- 位置：`app/src/main/java/com/keepasskey/app/data/repository/VaultFileDriftResolve.kt`；`sync/src/main/java/com/keepasskey/sync/merge/KdbxEntryMerger.kt`。

## 534.2 进程死亡结论**修正**（撤回错误说法）

- **撤回**：此前聊天报告中「进程被杀时未落盘的裁决丢失后，下次保存会重新触发漂移提示，不产生静默覆盖」
  系**推导而非实测**，与真机读数矛盾，予以撤回；`ACTIVE_ISSUES.md` 第四轮条目中
  「提交仍随进程终止而终止（此时保留待决状态，由会话锁定路径自然清空）」一句同属错误描述
  （进程死亡不经过锁定路径，待决状态随进程消失）。
- **实测真实状态机**（`am force-stop` 于提交前门）：
  1. 本地脏树存在于内存（未落盘）；
  2. 磁盘被外部改写 ⇒ 漂移；
  3. 用户点 `KEEP_LOCAL` ⇒ 受理，UI 在途（`choiceSubmissionInProgress=true`），**未报告成功**；
  4. commit 前进程死亡 ⇒ 内存 session / 待决裁决 / 在途标记**全部丢失**；
  5. 正式文件保持外部版本（与提交前快照逐字节一致，无半写）；
  6. 重启重开 ⇒ 解析磁盘文件（`Disk#1`）；
  7. 打开即登记持久化基线 = 当前磁盘内容 ⇒ `checkDrift=false`；
  8. 无 `pending` / `mergeConflict`；原未提交本地修改（`LocalOnly#1`、本地字段值）**不再存在**；
  9. **只有新的外部改写**才会再次产生漂移，此前的裁决上下文不会重建。
- **定界**：该行为不属于方案 §2/§3/§4/§5 的关闭条件——§2/§3 约束的是「有落盘机会时」
  真实 base 与失败保全（保全的是用户**仍持有**的草稿/恢复材料）；§4 四行不含进程死亡；
  §5 的关闭条件为「原触发路径及失败对照均满足验收」。进程死亡导致的**未提交内存脏树不可恢复**
  属独立问题域，已登记 `ISSUE-P2-661`（P2）与限界 §49，并明确「无 durable draft」的事实，
  不再以「已安全处理」表述。

## 534.3 过程缺陷与测试装置留痕（如实）

- 组合作用域承载数据层提交（第四轮发现并整改）：修复前点击裁决后退出页面即产生
  「选择已被 UI 消费、提示全清、文件未变」的数据丢失第三态（复现用例 A/B 稳定失败，
  读数 `实测=[Disk#1]；pending=null conflict=null`）。整改：提交移至应用级作用域 +
  受理不再先清提示 + 在途状态改由协调器承载。
- `NonCancellable` 曾覆盖保存侧 Argon2 + 序列化（第五轮收口）：已拆为可取消预备段 +
  最小提交临界区；预备与提交之间会话变更 fail-closed（`SAVE_SESSION_CHANGED`）。
- 测试装置缺陷（本轮修正）：① 活动库判定「会话路径优先 + 默认库占位」⇒ 仅 `import`
  不足以切换，`registerAndUnlock` 改为 `selectDatabase` + 有界重试；② 耗时用例用重解析轮询，
  每次 ~1 s 污染读数 ⇒ 改 mtime/长度 5 ms 轮询；③ 进程死亡需外部编排，后置段拆独立类，
  标记改 logcat（`run-as` 在卸载后不可用）；④ AVD 首启 swiftshader 触发 System UI ANR、
  系统语言非 zh-CN 使中文资源串断言失败——分别以 `-gpu host -memory 4096 -cores 4` 与
  `persist.sys.locale=zh-CN` 解决（均为环境侧，非产品缺陷）。
- 已撤回的错误结论：见 §534.2（「下次保存重新触发漂移」）。
