## 2. 实施与验收

- **前提复核（认领时）**：直读确认前提成立——`isModified` 未含 `autoType` / 颜色 / 到期；`MERGED_SCALAR_FIELDS`
  仅图标 / 覆写 URL / 质量检查四项 ⇒ 远端单独改上述三项会被判「未修改」、本地整表覆盖（静默丢失）。

- **改动一（词汇表补齐，`KdbxEntryMerger`）**：`MERGED_SCALAR_FIELDS` 新增 `autoType`（**整体配置对象**）、
  `backgroundColor`、`foregroundColor` 与**联合到期**规格。判定（`isModified`）/ 实际合并 / 上报（`diffFields`）
  三处继续由**同一词汇表**驱动，禁止另写清单。

- **改动二（联合到期语义）**：`expires` 与 `expiryTime` 以**单一规格**原子读写——`read` 归一为
  `Instant?`（禁用到期 ⇒ `null`，不生效的旧日期不参与比较与合并）；`write` 一次性改写两字段，
  杜绝望「逐字段获胜」产生**两端都未选择的混合状态**。`mergeConflictedEntry` 改为先在标量合并结果上
  仅覆盖 `lastModificationTime`（原实现基于 `local.times` 重建会抹掉联合到期结果）。

- **改动三（冲突键与裁决，`KdbxMerger`）**：新增 `CONFLICT_KEY_AUTO_TYPE` / `CONFLICT_KEY_EXPIRES` /
  `CONFLICT_KEY_BACKGROUND_COLOR` / `CONFLICT_KEY_FOREGROUND_COLOR`，并在 `resolveConflictByFields`
  补对应采纳分支（到期整组采用远端）。

- **改动四（界面本地化映射，`ConflictResolutionViewModel`）**：四个新键映射为可裁决界面行
  （AutoType 呈现启用态、到期呈现到期时刻或「（无）」、颜色呈现取值或「（无）」）；
  zh（`strings_ui_messages.xml`）/ en（`values-en/strings.xml`）**成对**新增 4 条文案。
  既有的「词汇外键 → 可见呈现」兜底不变。

- **不动项**：PD-35 的**库级 Meta 本地优先**裁决不变（本项仅条目级语义）；不新增自动输入执行功能。
  四份 KDoc 中「四个标量键」表述同步更新，避免登记漂移。

- **测试（新增 `KdbxEntryMergerSemanticsExpansionTest` 6 例）**：`isModified` 检出三项；本地改标题 + 远端改
  到期/AutoType/颜色 → 三项均保留且**无冲突**；双侧异值改到期 → 冲突键 `expires` 上报且**同侧**取值；
  双侧同值 AutoType 不产生虚假冲突；禁用到期时旧日期差异**不**判为已修改；`resolveConflictByFields`
  对四个新键的远端采纳。既有 `KdbxMergerScalarFieldsTest`（6）/ `KdbxEntryMergerFieldsModifiedTest`（5）/
  `KdbxMergerFieldResolutionTest`（4）/ `KdbxImportMergeSemanticsTest`（4）全绿。

- **改动五（结构收口）**：新增 `EntryScalarVocabulary`（`ScalarFieldSpec` + 8 键词汇表）承接原
  `KdbxEntryMerger` 内联词汇，`KdbxEntryMerger` 仅保留一行引用；`ConflictResolutionViewModel.buildConflictedField`
  的 8 个标量键映射抽为 `buildEntryScalarField`。两处均为**行数分档 / 超长函数**门禁（首轮全量红：
  `tier2=36>35`、`functions_ge_100=1`）所需的等价拆分，行为零变更。

- **全量单测**：`./gradlew.bat test --max-workers=1` EXIT 0；`count_test_results.py` 读数
  **`xml=573 tests=3747 failures=0 errors=0 skipped=15`**（§511 基线 3741 ⇒ +6）。
