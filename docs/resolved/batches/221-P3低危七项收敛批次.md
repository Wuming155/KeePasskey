### ISSUE-P3-202：`SyncCache.writeCache/writeBaseContent` 与 `SyncRollbackGuard` 未按自声明口径做「第一字节即仅属主」权限收敛

- **背景与证据**（2026-09-19 对抗审计存活，定级 Low）：`SyncCacheFiles.kt:38-46`（`writeTmpSynced`）为正确范式并自述不变量
  「密文自落盘第一刻起即为仅属主可见」（ISSUE-P1-07 口径，见 `SyncCache.kt:32-34` KDoc），但 `SyncCache.writeCache`（`:113-121`）与
  `writeBaseContent`（`:196-205`）自建裸 `FileOutputStream(tmp)` 仅 rename 后收敛**目标**；`SyncRollbackGuard.persist`（`:199-209`）与
  `stateDir.mkdirs()`（`:106-110`）**全程不调用**任何收敛原语（自带 `moveAtomically:212-222` 亦无）。
  `SyncCacheAndroidRuntimeTest.kt:45-61` 只断言终态权限，写入窗口与 `filesDir/rollback` 无断言。
  实际暴露接近零（app 私目录 + 每应用 SELinux/FBE + tmp 名含随机 UUID；回滚状态文件仅摘要+Keystore HMAC，无密文）⇒ 属**不变量一致性缺口**，非可利用漏洞。
  **第三轮真机取证（Redmi 4X / Android 17 / API 37，2026-09-19）**：新用例 `RawFileWritePermissionDeviceTest`（`sync/src/androidTest/`）实测——裸 `FileOutputStream` 新建文件**即为 0600**、`mkdirs()` 新建目录**即为 0700**（进程 umask 0077），而平台预置的应用私有目录为 `0771`（others **仅可穿越、不可读亦不可写**）⇒ **「写入窗口期以默认 umask 暴露」在真机上不存在**；本条据此**确定收窄为「不依赖 umask 的自声明口径 vs 实际依赖 umask」的代码一致性/风格问题**，不再是安全暴露面。AC①（改走 `writeTmpSynced` 同法）仍成立，但理由由「防暴露」改为「消口径漂移」。
- **涉及文件**：`sync/.../engine/SyncCache.kt`、`SyncRollbackGuard.kt`、`SyncCacheFiles.kt`、设备侧测试。
- **验收标准**：① 两裸路径改走 `writeTmpSynced` 同法（或 rename 前收敛 tmp）；② 设备侧测试增补 tmp 窗口与 rollback 目录断言；③ 真机 `:sync:connectedDebugAndroidTest`（此面属「只有真机才能证伪」类，宿主恒降级）。

## 2. 整改明细

### 2.1 ISSUE-P3-201（picker 锁定守卫）

- `AutofillPickerActivity.confirmAndFill`：进入交付链路时点（**凭据解密之前**）接入
  `AutofillAuthenticationPolicy.canDeliverAuthResult(vaultRepository.isLocked())`，锁定即 `finish` 放弃本次填充。
- `AutofillPickerActivity.deliver`：**两处**门控——交付入口（先于首次绑定写入与 TOTP 动作，锁定即
  `discardPendingResult()`，副作用零发生）+ TOTP 500ms 窗口之后、`setResult(RESULT_OK)` 与会话授权写入
  之前再次复核（窗口期锁定漏判面）。新增 `discardPendingResult()` 收口（与确认页同口径：双参
  `RESULT_CANCELED` + `authenticationCanceledIntent()`）。
- 守卫测试 `AutofillConfirmDeliveryLockTest` 扩至 picker 源码（4 个新用例）：每处 `setResult(RESULT_OK)`
  前须有同函数内门控；门控覆盖「解密前 + TOTP 窗口后」两时点；`bindCallerForPackageDimension()` 与
  `AutofillSessionGrants.grant(` 必须晚于交付入口门控（锁定态零副作用）；`discardPendingResult` 收口存在。

### 2.2 ISSUE-P3-202（权限口径收敛）

- `SyncCache.writeCache` / `writeBaseContent`：裸 `FileOutputStream` 改走 `SyncCacheFiles.writeTmpSynced`
  （tmp 落盘第一字节起 0600）→ `moveAtomically`（目标收敛）。
- `SyncCache.writeCacheStreaming`：顺手对齐——原实现**写完全量后**才收敛 tmp，改为打开输出流后、
  写第一字节**前**收敛（同窗口缺陷，同批消除口径漂移）。

### 2.6 ISSUE-P3-206（下载流式化）

**契约**：`SyncProvider.download(remotePath): Result<ByteArray>` → `download(remotePath, sink: OutputStream): Result<Unit>`
（实现内经 `SyncDownloadLimits.copyBounded` 强制「声明尺寸预检 + 累计封顶」，只写不关 sink；
半成品清除义务归调用方）。WebDAV / S3 两个实现同步改写。

**新原语**：
- `SyncDownloadLimits.copyBounded(input, declaredLength, maxBytes, label, sink): Long`——边读边写 + 累计封顶，
  堆占用恒为 64 KiB 缓冲；`readBounded` 改为对 `ByteArrayOutputStream` 的委托（**仅保留给 PROPFIND 元数据
  通道**，其 16 MiB 体量整份物化可接受）。
- `SyncCache.receiveRemote(remotePath, receive): ReceivedRemote`——在唯一 tmp 上打开输出流（**第一字节前**
  收敛 0600，P3-202 口径），同步累计 SHA-256 与字节量，完成后 fsync；`receive` 抛任何异常自动清除 tmp 后
  原样上抛（**不遗留半成品文件**，AC①）。回执 `ReceivedRemote` 提供 `digest` / `byteCount` / `readBytes()`
  （唯一 ~1×S 物化点）/ `commit()`（rename + 写 `.version`，幂等）/ `abort()`（弃置，幂等）。

**引擎改造**（4 个下载点）：
- `openUncached`：流式接收 → `isReplay(digest)` 拒绝则读出字节后 abort → 否则 readBytes + commit +
  `advanceBaseAndPersist`（摘要直接复用接收期累计值，不再重算）。
- `RemoteConsistencyProbe`：改持 `cache`，`isRemoteUnchanged()` 走「接收进缓存 tmp + digest 比对」；
  未变 → abort（tmp 用后即弃）；有更新 → 同一回执在决策树内复用（保留原「下载一次」优化）。
- `openCachedWithoutLocalChanges` 刷新 / `openCachedWithLocalChanges` 两处冲突 / `commitLocal` 412 冲突：
  回执裁决后按路径 commit（落地）或 readBytes + abort（仅合并，不落地缓存）；失败路径归一为
  `CouldntSaveToRemote` / `RemoteUnreachable`（携带失败原因，不伪造空字节）。

**AC② 峰值对比（结构化论证 + 用例佐证）**：
- 改造前：`readBounded` 接受路径 = `ByteArrayOutputStream` 累积（1×S 持久）+ `toByteArray()` 复制（瞬态
  +1×S）⇒ **下载期 ~2×S**；chunked（声明缺失）时缓冲倍增 ⇒ **可达 ~3×S**。
- 改造后：下载期堆占用 = 常量（64 KiB 缓冲 + 摘要状态）⇒ **下载期 ~0×S 堆**；交付/合并所需的唯一一次
  ~1×S 物化点为 `readBytes()`（结果契约 `SyncOpenResult` / 三方合并 / 基准快照仍以 `ByteArray` 承载，
  该边界属 `DatabaseSession.parseExternalDatabase(bytes)` 侧，条目已注明可选且未动）⇒ **全链路 ~1×S**。
  copyBounded 单测锁定「声明预检零写入」「中途拒绝 sink 不超上限」「正常搬运逐字节一致 + 返回字节数」。
- **AC③**：`SyncDownloadLimits` KDoc 失实前提（「合法 `.kdbx` 远小于上限」）已更正——附件密文随库体存在，
  上限只承担封顶语义、不承担「合法库远小于此」假设。
- 测试适配：新增仅测试源集的 `SyncProvider.downloadBytes` 便利扩展（`sync/src/test`）供逐字节断言；
  4 个测试 fake（`SyncEngineTest` / `SyncEnginePreferenceBranchTest` / `SyncCoordinatorTest` /
  `SyncConflictMergeLocalTreeEquivalenceTest`）与 2 个设备用例改为 sink 写入；场景 / LiveSync 测试经
  `downloadBytes` 机械换写。**生产引擎无任何调用方走 ByteArray 物化路径。**
