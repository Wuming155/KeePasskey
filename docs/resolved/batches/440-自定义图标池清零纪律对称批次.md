# §440 自定义图标池清零纪律对称批次（2026-10-04）

**来源**：用户 2026-10-03 拍板补齐——本仓敏感清理纪律（密钥 / 凭据缓存 / 二进制池 / 附件缓存）为锁库全路径对称，唯 Meta 级 `customIcons` 的 PNG 字节数组不在任何清零路径内。

## 440.0 任务口径（硬约束）

1. **不可退化为裸擦**：`CustomIcon` 是 data class，其 `data: ByteArray` 会被 `KdbxDatabase.copy()`（共享同一列表）与 `KdbxMerger.mergeCustomIcons`（对单侧独有 / 胜出的图标**复用原实例**）跨库共享。若在收口点写 `customIcons.forEach { it.data.fill(0) }`，会把**活动库仍在引用的图标**清零（`SECURITY_RECHECK_2026-09.md` §9.6 #19 同型），并在下次保存时把全零字节写回库文件。
   ⇒ 擦除一律走**实例身份集合判定**（IdentityHashMap，引用相等），与 `clearBinaryPool` 逐条同形；**不得**用 `CustomIcon.equals`（内容相等，含 uuid / name / 时间 / 字节，用错即漏擦）。
2. **与二进制池同收口点**（清理纪律对称的落实处）：`clearSensitiveData()` / `eraseDiscardedDatabase` / `SessionContentMutations.updateDatabaseMeta` / `adoptDatabaseIfUnchanged`。
3. **图标非凭据材料**：本批不改变任何功能行为，只补清理面。

## 440.1 整改内容

1. `KdbxDatabase.kt`：新增原语 `clearCustomIconPool(liveIcons: Collection<CustomIcon>)`（身份集合判定；`liveIcons` 为空即全量擦除）；`clearSensitiveData()` 增加 `clearCustomIconPool(emptyList())`（存活侧 = ∅，与 `clearBinaryPool` 同点）。类/方法 KDoc 同步。
2. `SessionContentMutations.kt`：`updateDatabaseMeta` 与 `adoptDatabaseIfUnchanged` 两个换库形态各补 `currentDb.clearCustomIconPool(updated.customIcons / replacement.customIcons)`（与 `clearBinaryPool` 同一行组）。
3. `SyncConflictMergeAdjudication.kt` 的 `eraseDiscardedDatabase`：补 `db.clearCustomIconPool(live?.customIcons ?: emptyList())`，KDoc 补图标池口径。
4. **同批修正一处历史遗留（漂移合并点）**：`VaultFileDriftResolve.mergeAndSave` 原直接调 `diskDb.clearSensitiveData()`。但该处 `diskDb` 的**条目与图标均被合并器原实例复用进已采用的活动树**（`KdbxEntryMerger.mergeSurvivingEntries` 的 `le == null && re != null → add(re)` 分支、`KdbxMerger.mergeCustomIcons`）⇒ 裸擦会静默清空活动库仍在用的口令明文与图标字节。已改走 `eraseDiscardedDatabase(diskDb, live = databaseSession.databaseFlow.value)`（存活侧取**当前**会话树——`save()` 可能因历史修剪再换实例）。此修正同时消除本批**新增图标清零**在该点的回归，并修掉该点在口令面上的既有隐患。
