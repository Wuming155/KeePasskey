## 1. 原条目（自 `ACTIVE_ISSUES.md` 原样收录）

- **背景**：`sync/.../merge/KdbxGroupMerger.kt:99-115` 对**每个分组**从自身起上溯父链并用 `mutableSetOf(gid)`

  对照：同仓 `sync/.../webdav/WebDavPropfindParser.kt:94-111` 已用「显式栈 + 深度上限」加固过同一类风险。
- **整改方向**：以「自底向上一次染色」替代逐组上溯（或缓存每组的「到根可达」判定），复杂度降为 `O(G)`；
  装配改显式栈并加分组深度上限（上限值须显式声明依据，超限按既有失败语义处理，不得静默截断）。
- **验收标准**：新增用例覆盖「远端构造的深链 / 环状父链」（现有用例若无此形状须补）；

- **核实时间点与方式**：2026-09-17 读 `KdbxGroupMerger.kt:95-155` 与 `WebDavPropfindParser.kt:94-111` 对照核实。
- **风险提示**：属**解析/合并健壮性**（攻击面）而非纯性能项，与 `P3-155` 同属高回归面，须排在零风险项之后。

## 2. 本批实现（① 父链自愈：逐组上溯 → 一次函数图染色）

`sanitizeParentLinks` 改为「一次染色求出**需挂回根组**的集合 + 单趟产出结果」：

- 染色 `cyclicGroups(...)`：对「分组 → 父组」这张**函数图**单趟遍历，节点状态
  `ON_PATH`（在当前路径上）/ `CLEAN`（已判定不进入环）/ `CYCLIC`（已判定进入环，含在环上）；
  路径上命中 `CYCLIC` 或 `ON_PATH` 都意味着该路径**全体**节点均进入某个环 ——
  与旧算法「重现即判环」（含「父链进入环的链尾」）判据一致。
- 判定口径**逐字保持**：需挂回根组 ⟺ 父链为空 / 指向根 / 指向不存在的分组 / **进入环**；
  各组的判定均基于**原始**链接、互不影响 ⇒ 结论与逐组上溯**逐项等价**。
- 复杂度由 `O(G × 深度)`（最坏 `O(G²)`）降为 **`O(G)`**（每节点至多被走一次，路径复用同一缓冲），
  且不再为每个分组各分配一个 `Set`。

## 3. 刻意不做（② 装配递归深度上限）：**已核实为不可达**，故不加

AC 要求「装配改显式栈并加分组深度上限」。开工复核发现**该递归的输入深度已被上游封顶**：

- 合并的两侧分组树都来自 `KdbxXmlParser`，而该解析器有 **`MAX_XML_DEPTH = 64`** 的嵌套深度封顶
  （`KdbxXmlParser.kt:89-90`：超限抛 `KdbxCorruptFileException`，属 fail-closed 解析炸弹防线）；
  分组嵌套是 XML 嵌套的一部分 ⇒ **解析出的分组树深度 ≤ 64**；
- `assembleGroupTree` 的递归深度由 `subgroupsByParent` 决定，而后者由**净化后**的父链构建
  （净化会把环与失链一律挂回根组，只会**缩短**链）；
- ⇒ 递归深度实际上界为数十层，**不存在可达的栈溢出路径**；此时再加一个已封顶的自有上限，
  属**无靶加固**（既增加一处需维护的常量，又可能在未来与解析器上限不一致而误拒合法库）。

**依赖关系（须登记，供后人判定）**：本条 ② 的「不可达」结论**以 `MAX_XML_DEPTH` 存在且未被放宽为前提**。
若日后放宽或移除该解析器上限（或引入不经该解析器的树来源，如其它格式导入 / 插件通道），
则 `assembleGroupTree` **必须**同步补自己的深度上限或改显式栈。该依赖已就地写进
`assembleGroupTree` 的 KDoc。

## 4. 本批新增用例（5 例；该函数此前**零覆盖**）

`sync/src/test/.../merge/KdbxGroupMergerSanitizeTest.kt`（新）：

| 用例 | 断言 |
|---|---|
| `自环与互环均被判为需挂回根组` | 自环（`a→a`）、互环（`b↔c`）、失链父组（指向不存在的 id）**三类**都必须挂回根组 |
| `父链进入环的分组同样必须挂回根组` | 链尾（自身不在环上，但父链进入环）⇒ 必须挂回根组（**这正是旧算法「重现即判环」语义的关键面**） |
| `健康层级与指向根的分组保持原样` | 健康子分组按**同一实例**透传（`assertSame`）；直接挂根 / 指向根的分组按原口径仍走「挂回根组」分支（内容为 copy、父组仍是根）——**如实记录既有行为**，未顺手改动 |
| `随机图与逐组上溯的判定逐项一致` | **固定种子**随机生成 **300** 张图（每张 1~8 个节点、约 1/6 无父组、其余随机指向含自身与不存在 id），把染色法结果与**参照实现**（改动前算法**逐字抄录**）逐项对拍 |
| `长链上溯不再逐组重复走链` | 200 节点长链下结论正确（**复杂度本身不可由用例证明**，故只锁「长链下结论正确」） |

## 5. 边界如实声明（不得外推）

1. **「最坏 `O(G²)`」是源码结构结论**：本批**未**做运行期计时或计数；`O(G)` 的达成依据是
   「每节点至多被走一次 + 路径复用同一缓冲」这一构造性事实。**不得**宣称耗时下降百分比。
2. **① 的「远端可构造」已如实限定**：链状 / 环状父链要进入本函数，需先经解析器与合并入口，
   故其可行性上界同样受 §3 的解析器封顶约束——本批的收益是**消除平方级退化**（对合法的大库同样
   减少无谓遍历），而**不是**修复一个已被利用的攻击。
3. **`sanitizeParentLinks` 此前的零覆盖已补，但覆盖是「判定面」**：本批用例不覆盖
   `assembleGroupTree`（② 未做、且其输入受下游约束）；`assembleGroupTree` 的行为依据仍是既有合并用例。
4. **随机对拍是等价性证据、不是全域证明**：300 张固定种子的小图覆盖了自环 / 互环 / 链尾 / 失链 /
   多环等形状，但**不构成**「任意图等价」的形式化证明。
5. **未跑设备侧 / `-DliveSyncTest` / `assembleRelease`**；本条不触碰加密与文件面。

## 6. 过程缺陷与留痕

1. **一次断言设计错误（与实现无关）**：首版用例对「父组即根组」的分组断言了
   `assertSame`（期望按同一实例透传），而**既有口径**对该情形本就执行 `g.copy(parentGroupId = rootId)`
   （旧算法同样如此）⇒ 用例假红。修正为「断言父组仍是根组」并把该既有行为**如实记录在用例消息里**，
   未改动生产代码。
2. **一处前提复核改变了做法**：本条 ② 原本被我登记为「须加深度上限」，开工后先去找**上游是否已封顶**
   （而非直接加常量），才发现 `MAX_XML_DEPTH = 64` 已把该递归的输入深度封死 ⇒ 改为**不加 + 登记依赖**。
   这与前几批「AC 写在读实现之前」同源：**先读实现与上游约束，再决定改什么**。
