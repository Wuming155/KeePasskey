# §547 存量问题全量整改第三轮：八项全部实测闭环

> 日期：2026-10-21（Asia/Shanghai）。承接交接文档 [`2026-10-21-存量问题全量闭环任务交接.md`](../../records/2026-10-21-存量问题全量闭环任务交接.md) 与上一轮 [§546](546-存量问题全量整改第二轮闭环批次.md)。
> 本批把 §546 遗留的 **8 项全部推进到关闭条件满足**，逐条给出实测读数与保留边界。

## 1. 本轮新发现的真实缺陷（均已修复并实测）

这些缺陷是执行验收时在**真实设备 / 真实服务端**上暴露的，不属于台账条目本身。

1. **异步水合覆盖用户正在输入的表单草稿**（`CloudSyncScreen`）。
   表单用 `remember(uiState.xxx)` 以字段值为 key，而 `hydrate()` 在页面组合**之后**才从 IO 线程回灌
   已保存配置；回灌一落地，Compose 就把本地状态整段重建。真实表现为「刚敲完端点就变回默认地址，
   保存提交的是旧值」。改为页面级草稿 `SyncFormDrafts`：字段未被用户编辑时接受播种，编辑后晚到播种
   不再覆盖，保存成功后放权。
2. **秘密草稿被列表回收清空**（`CloudSyncScreen` / `SecurePasswordField`）。
   密码 / AccessKey / SecretKey 原以组合内 `remember { CharArray(0) }` 持有；表单 item 滚出视口即被
   `LazyColumn` 回收，`SecurePasswordField` 的 `DisposableEffect.onDispose` 随即擦除显示态。用户填好
   密码、滚到下方看状态卡片再滚回来，密码框已空，提交必然失败。改由页面级草稿持有并在回收重建时
   回灌，只有离页才擦除。
3. **附件超预算与「凭据不匹配」共用同一文案**（`RecoveryEntryContentComparator` / `VaultRecoveryCoordinator`）。
   预算耗尽被 `catch (Throwable)` 折成 `RECOVERY_UNLOCK_FAILED`，UI 显示「恢复副本解锁失败（凭据不匹配
   或缺密钥文件）」。用户按提示去换凭据只会徒劳。新增 `AttachmentComparisonUnavailable` 分型与
   `RECOVERY_PREVIEW_BUDGET_EXCEEDED`，文案改为「附件过大，无法逐字节比较差异；请先另存副本再人工核对」。

## 2. 逐项闭环证据

### ISSUE-P2-636 同步缓存与版本标记分离提交可在重启后误判无修改

- 实现：`hasLocalChanges` 以 `.cache` **实际字节摘要**对照 `.baseversion`（不看 `.version`）；`writeCache`
  与 `updateBase` 按规范键进程内互斥（`SyncCacheFiles.pathLock`），字节与三份标记落在同一临界区。
- **真实进程死亡**（两阶段 + `tools/device/run_p2_636_crash.py`，隔离 AVD）：prepare 段建立基线后写入
  新字节而**不**刷新 `.version`（等价于真实崩溃落在 rename 与写 version 之间），宿主 `am force-stop`
  并核实旧 PID 消失，verify 段在**新进程**核对——
  - `hasLocalChanges` 为 true；`.cache` 整份读回且逐字节等于崩溃前写入；目录内无 `.tmp` 残留；
  - 删除 `.version` 后仍判 true（原缺陷正是此分支直接 false）；基线前移后负对照为 false；
  - `.meta` 的 ETag 仍等于**崩溃前**基线值（新字节属未确认上传的本地修改），基线前移后 ETag 同步更新。
- **真实服务端 ETag 往返**（`LiveS3EtagCrashWindowTest`，隔离 MinIO，已并入 `run_s3_matrix.py`）：
  服务端真值写入基线并逐字读回；崩溃窗口不改写基线 ETag；用崩溃前 ETag 条件上传成功、上传后 ETag
  变化；再用**过期** ETag 条件写必须失败（不静默覆盖）；以远端当前 ETag 前移基线后判据回到干净。
  矩阵 11/11 PASS。反向验证：错误 secret 下该用例必红，证明确实连到服务端。
- 保留边界：跨进程并发写仍依赖各文件的原子替换与 SHA-256 校验（[`已知工程限界.md`](../../architecture/已知工程限界.md)）。

### ISSUE-P2-638 恢复副本差异比较忽略密码和实际附件内容

- 实现：内容比较收敛到 `RecoveryEntryContentComparator`（字段内容等值、自定义字段、附件**逐字节**流式
  比较、历史、条目元数据），不依赖 32 位 `contentHash`，超预算与读取失败 fail-closed。
- 设备侧（`RecoveryPreviewFailureUiDeviceTest` 5/5，真实 `MainActivity` + 真实 `VaultRecoveryCoordinator`）：
  - 正式库不可读 → `officialEntryCount = null`，UI 呈现 `recovery_preview_no_official`，**不**给「修改 0」；
  - 附件字节不同但长度相同 → 判「修改 1 条」，UI 摘要逐字正确；
  - 密码与历史内容变化、条数不变 → 判「修改 1 条」（原缺陷的另两个盲区）；
  - 同一份字节负对照 → 新增/删除/修改全为 0；
  - 附件超预算（预算调到 1 KiB）→ 预览失败、无差异读数、呈现**预算**文案且不等于「凭据不匹配」。
- 保留边界：OTP / Passkey 材料的单独变化仍只有 JVM 覆盖——两者与密码同走 `fieldsContentEquals` /
  自定义字段逐字节路径，设备侧已用密码与受保护自定义字段证明该路径。

### ISSUE-P2-641 CM Passkey与创建保存入口未消费已登记的库代次上下文

- 实现：四类 CM 入口按类型、随机注册身份、库路径与票据受理；实际改树、落盘及成功回传均复核原票据。
- 真实 framework CM 矩阵（`CmSessionMatrixDeviceTest` **5/5**）：A 库断言（计数 17→18，B 保持 71）、
  切 B 库断言（B 71→72，A 保持 17）、A/B 同 UUID 不同密钥互不串账、A 活动时 B 的 `allowCredentials`
  不出候选、**认证中换库**（停在确认页时切库 → `RESULT_CANCELED`，两库计数均不变）。
- **旧 token 跨进程重放**（两阶段 + `tools/device/run_p2_641_token_replay.py`）：新进程里 requestId 仍是
  合法 URI 形态但登记表查不到、`bind` 返回 false；反向对照——同进程内新登记 token 可用。
- 独立 RP 对拍（`tools/passkey-interop/verify_assertion.py`）：A1/B1 断言 `verified=true`，另一库公钥
  验签必须失败。

### ISSUE-P2-651 同步配置保存失败后输入显示与已擦除凭据副本不一致

- 实现：提交走 `SyncFormPersistence`（独立副本交给控制器，所有权转移）；失败时工作副本清零、表单草稿
  保留供只改端点重试；成功才清空草稿并提示。另修「保存成功后控制器仍残留上次失败提示」。
- 设备侧（`CloudSyncFormUiDeviceTest` 4/4，真实 UI 点击 + 真实 HTTPS 接收方）：http 端点被拒 → 上浮
  HTTPS 要求、接收方**零请求**、未置位已验证、失败后 URL 与密码框仍显示用户输入；只改 scheme、
  **不重输秘密**即落盘成功且口令逐字相等。
- 本轮修掉的三个真实表单缺陷见 §1 第 1、2 条。

### ISSUE-P2-652 测试连接忽略配置保存失败，仍验证并同步旧目标

- 实现：测试连接仅在 `persistConfig()` 成功后继续；同一保存回执贯穿「测连」与「同步」，中途改存只影响
  后续轮次，迟到结论不把新配置标成已验证。
- 设备侧：A 的测连 PROPFIND 被接收方挂住 → 在途改存 B → 全程**只触达 A 端点一次**（method/path/用户名
  逐项核对），A 的迟到结论不把 B 标成已验证；未提交草稿离页不残留，在途离页忙态复位。
- 装置修正：接收方 Basic 凭据原由脚本固定、用例却写死另一值，PROPFIND 走 401 分支提前返回、门闩永不
  置位；现由脚本经参数下发，缺参即失败。

### ISSUE-P2-655 S3目录参数先拼原文再拆分，含&前缀导致签名不一致

- 实现：`S3DirectoryList` 与 `S3RequestSigner` 改为结构化键值表，wire URL 与 canonical query 消费同一份
  输出，不再有「先拼串再拆」这一步。
- 关闭条件（方案 §4）两条均已满足：独立 AWS 官方向量逐字节一致（`S3OfficialSigV4VectorTest` 4 例 +
  官方 SDK 6 条整条 Authorization 对拍）；隔离 S3 服务的目录 / 分页回执（`run_s3_matrix.py` 本轮重跑
  **11/11 PASS**，含 `&` 前缀首分页被服务端验签接受、真实续页 token 取到第二页、坏密钥不被伪装成空目录）。
- 保留边界：本仓 signer 固定 `s3` 且附加 `x-amz-content-sha256`，与部分官方向量头部集合不同（已按向量
  原文适配比较，未硬凑整签名）；**未**对 AWS 真实 S3 服务做端到端（无 AWS 凭据）——该条不在方案 §4 的
  关闭条件内。

### ISSUE-P3-642 原生Passkey候选在请求RP不匹配时仍走包名回退

- 实现：`PasskeyRequestRpBinding` 保留请求 `rpId`，候选与最终签发要求归一化后**精确相等**；仅 RP 缺失
  时才允许按已绑定包名回退（PD-77）。
- 设备侧（`PasskeyRpBindingDeviceTest` **7/7**，真实 framework CM 的 public-key 请求，读
  `hasCredentialResults`）：RP 精确相等 → 发布；RP 不匹配 / 子域 → **不发布**；`allowCredentials`
  不含 → 不发布、命中 → 发布；缺 RP → 包名回退发布。
- 场景 2「正常 RP 成功回执」：完整签发后导出断言交独立验签器，`verified=true`、`signCount=18`、
  UP=true、UV=false，challenge / origin / rpIdHash / credentialId / userHandle 逐项通过。
- 保留边界：浏览器与 native 两个入口形态未分别构造独立客户端；两者在候选层走同一
  `matchesPasskey`（`browserFlow` 仅影响「缺 RP 时是否回退」，已由缺 RP 用例覆盖）。

### ISSUE-P3-643 重复选择自定义图标会清掉其它未保存编辑的脏标记

- 实现：重复选择图标保留既有表单脏标记，只有「此前未脏且图标未变」才保持 clean。
- 设备侧（`EntryEditDirtyConfirmationDeviceTest` 2/2）：载入未改动时全局登记表不报脏、改标题后报脏；
  连续两次选当前图标后返回仍弹丢弃确认、「继续编辑」不离页且未保存标题不落盘；编辑页销毁后登记表
  不残留陈旧脏态（`onCleared` 注销配对生效）。
- 装置缺陷（该用例此前**一直为红**）：`setTitleText` 的 `ACTION_SET_TEXT` 会返回 true 但文本未落入编辑态
  （Compose 语义节点被外部状态重播种），原实现一次性写入即断言。改为写入后回读校验、不一致即重试。

## 4. 本轮修掉的装置缺陷（非产品缺陷）

1. **`run_p2_651_652_ui.py` 接收方凭据与用例不一致** → 见 §2 P2-652。
2. **点击驱动过于脆弱**（`CloudSyncFormUiDeviceTest`）：原「点一次即认为生效」；改为「点后校验、未生效
   重试」，滚动改为单调向下（周期性回顶部会把已越过的目标反复跨过），并在滚动/点击前收起软键盘
   （键盘遮挡曾把滑动整个吞掉）。
3. **字段定位依赖树序**：曾观察到密码节点被排到首位，导致「写入 URL」实际写进密码框。改为按语义定位
   （唯一 `password()` 节点 + 其余自上而下），并要求四字段同时在视口内才映射。
4. **CM 矩阵的 `userHandle` 契约不符**：fixture 把 `userHandle` 塞成明文，与 WebAuthn base64url 契约不符
   （独立验签器直接报 `Only base64 data is allowed`）。生产创建路径取 RP 下发的 `user.id`，本就正确。
5. **系统选择器定位**：呈现的是 userName 而非条目标题，且候选行文字分散在子节点、子树匹配会命中多层
   祖先（`awaitActiveNode` 要求恰好一个匹配，永远等不到）；改为子树文本 + 取最深节点。
6. **跨用例遗留 sheet**：上一用例的系统选择器会让新请求排队（连跑必红、单跑必绿）；`prepare()` 先退场
   并等待 sheet 消失。
7. **源码扫描断言随重构变红**（`RemoteBrowseCredentialFallbackWiringTest`）：按旧变量名匹配，改为匹配
   页面级草稿入口 `drafts.secret(...).copyOf()`；断言原意（browse 前必须传副本）不变。

- P2-636：跨进程并发写依赖原子替换与 SHA-256 校验。
- P2-638：OTP / Passkey 材料单独变化只有 JVM 覆盖（同路径已由密码与受保护自定义字段在设备侧证明）。
- P2-655：未对 AWS 真实 S3 做端到端（无凭据），该条不在关闭条件内。
- P3-642：浏览器 / native 两入口未分别构造独立客户端（候选层同一判据，缺 RP 分支已覆盖）。
