## 1. 本轮新发现的真实缺陷（均已修复并实测）

这些缺陷是执行交接清单时**在真实设备上**暴露出来的，不是既有台账条目本身。

1. **`isLocked()` 把 `DIRTY` 误判为已锁定**（`VaultLifecycleCoordinator`）。
   判据原为「`state != OPENED`」，而 `DIRTY` 是「已解锁且有未落盘修改」的正常态。后果：逐条落库的
   批量路径（明文导入）在第一条保存后把后续条目全部判成「库已锁定」，整批失败。实测症状：
   `ImportProductSessionMatrixDeviceTest` 4/4 失败、`uiState=Failed(PERSIST)`、`locked=true`。
   已改为「仅 `CLOSED` / `LOCKED` 为锁定」。
2. **凭据请求续用判据过严导致导入整批失败**（`DatabaseSession` / `VaultImporter` / `VaultWriteBoundary`）。
   批量路径在同一次受理内会多次建立请求对象（票据相同、实例不同），原嵌套检查按**实例**判定，
   于是抛 `IllegalStateException("禁止嵌套覆盖已受理凭据请求")`。已新增
   `withCredentialRequestScope`（续用语义，按**票据代次**判定）与 `currentRequest()`，并把导入与
   写边界改走续用入口；新入口对「上下文里存在另一票据」仍然 fail-closed。
3. **分组图标投影恒为 `folder`**（`VaultGroupCoordinator.groupsFlow`）。
   投影把 `iconName` 写死成 `"folder"`（仅回收站写 `"delete"`），与写侧的 `VaultIconMapping.idOf` 不互逆。
   后果两层：用户选过的分组图标重进列表即回退；下一次改名/改图标按旧投影写回，把已落盘的
   `iconId` 覆盖回 48。已改为 `VaultIconMapping.nameOf(iconId)`（与写侧同一对互逆映射）。
4. **图标选择器缺少独立可聚焦语义**（`IconPickerDialog`）。每个图标格原只有 `contentDescription`，
   读屏只能聚焦整个网格；已补 `role = Button` + 选中态 `stateDescription`（新增
   `icon_picker_selected` / `icon_picker_not_selected`）。
5. **调试宿主未复用同一 Provider 解析装配**（`CloudSyncDeviceHostActivity`）。
   `buildSetup` 构造 `SyncCoordinator` 时未注入 `syncProviderResolver`，协调器自建默认实例，
   与用例装配的凭据库不是同一份。已改为显式注入。
6. **`run_p2_651_652_ui.py` 接收方缺 `do_POST`**。控制端点 `reset/hold/release` 走 POST，
   `http.server` 未实现时直接回 501，设备用例 `setUp` 整体失败。已补 `do_POST`（控制端点 + 405 兜底）。
7. **测试装置自身的悬挂与误判**（`SyncSavedConfigFailureAndCancelTest`）：门闩 `await` 无界（作用域取消后
   永久悬挂，整包卡死 >8 分钟）、夹具未解锁/未关闭自动锁、成功后草稿语义断言与实现不符。均已修正为
   有界等待或按真实语义断言。
8. **`ForegroundIdleLockTimerTest` 跨类时钟污染**：`runTest` 继承 `Dispatchers.Main` 上残留调度器的
   虚拟时钟，`lastInteraction = 0L` 在时钟已推进的全量运行里被判成「早已闲置超时」（单类绿、全量红）。
   已按用例自身时钟播种。
9. **`ResumeSyncProbeCoordinatorProductionTest` 用虚拟时间等真实 IO**：探测走 `Dispatchers.IO`，
   `runTest` 的虚拟时间推不动，改为在 `Dispatchers.Default` 上真实等待。
10. **同步缓存并发写交叉污染**（`SyncCache.writeCache` / `SyncCacheMaintenance.updateBase`）：
    两者各自原子替换 `.cache` 与 `.version`，但两步之间无互斥；并发写同一路径时可能留下
    「A 的字节 + B 的标记」，`hasLocalChanges` 随后按错配摘要判定。新增
    `SyncCacheFiles.pathLock` 按规范键进程内互斥，字节与标记纳入同一临界区。
    `SyncCacheCrashRecoveryTest` 连跑 5 次 0 失败（修复前 3 次中 1 次偶发红）。
11. **`DependencyResolutionDeterminismTest` 钉版线约束过窄**：Dependabot 把 material3 由
    `1.5.0-alpha29` 推进到同线 `1.5.0-beta01`（未跨 minor），守卫仍只接受 `1.5.0-alphaN`。
    已把判据扩为 `1.5\.0-(alpha|beta)\d+`，并同步更新 `libs.versions.toml` 的约束注释与
    [`退役依据承接-ISSUE-P3-09.md`](../../records/退役依据承接-ISSUE-P3-09.md)；**跨 minor / 跨线仍禁止**。
