## 2. 语义保持点（以及一处**如实登记**的所有权变化）

1. **选择器仍在段落、不在对话框内**：原注释的理由是「对话框在 SAF 交互期间保持组合，表单输入不丢」——
   段落本身**无条件组合**，故该性质**不弱于**改动前；
2. **子库对话框关闭时三口径同做**（清 source / 清 mountKeyFile → 关父级态 → 反馈复位），顺序保持；
3. **导入两步式中间态**：`pendingImportSource` 与选择器同处一段，回调内**先捕获再置 null** 的写法逐字保留；
4. **所有权变化**：四项中间态由「整页持有」改为「段落持有」。因段落无条件组合，其存活期与整页一致；
   **不**等价的情形是「段落被条件包裹」——那会让 SAF 往返期间的重组丢状态，故由 §3 的判据②钉死。
5. `rememberLauncherForActivityResult` 的**注册位置随搬家而变**（默认 key 由组合位置派生）：
   唯一受影响的是「跨本次升级、恰好有一次 SAF 往返在飞行中」的极端场景，属可接受面（无数据写路径）。

## 3. 为本次搬家新增的接线守卫：`DatabaseSettingsSectionWiringTest`（4 例）

结构性搬家若无判据，退化只会以「用户丢输入」的形式在未来某次改动中出现。故补：

| # | 判据 | 防的退化 |
|:--:|---|---|
| ① | 子库三个选择器的声明必须出现在 `if (showDialog)` **之前**（无条件组合区） | 选择器被挪进门控块 ⇒ SAF 往返期对话框关闭即丢表单 |
| ② | 整页对 `ChildDatabaseSection(` / `VaultImportSection(` 的调用必须**不在任何 `if` 块内**，且不得残留 `if (showChildDbDialog)` / `if (showImportDialog)` 直调对话框的旧形态 | 「条件包裹段落」悄悄回退（§2.4 的唯一不等价情形） |
| ③ | 子库关闭 lambda 内必须同时含 `childDbSourceUri = null`、`childDbMountKeyFileUri = null`、`onDialogDismiss()`、`onFeedbackDismiss()` | 三口径被拆开（尤其漏 `onFeedbackDismiss` ⇒ 反馈条滞留） |
| ④ | 导入段内 `pendingImportSource = source` 必须先于 `importFileLauncher.launch(`，且回调内「先捕获、后置 null」 | 选完文件回不来来源（导入静默失败） |
