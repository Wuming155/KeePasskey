## 2. 根因链与整改（四层 + 两项，逐层实证）

### 2.1 `ISSUE-P2-314`：device-gate 的四层缺陷 + connected 步骤 YAML 缺陷

| 层 | 实证（run / 日志读数） | 根因 | 整改 |
|---|---|---|---|
| ① | #351（2026-09-24）：`19:08:47` `emulator: command not found`，job 挂满 120 分钟被强杀 | ubuntu-24.04 镜像不把 `$ANDROID_SDK_ROOT/emulator` 放入 PATH（`adb`/`avdmanager` 均可用，仅 `emulator` 缺位） | 全路径 `${ANDROID_SDK_ROOT}/emulator/emulator` 调用 + 启动前 `test -x` 断言 |
| ② | 同 #351：裸 `adb wait-for-device` 无限阻塞，20 分钟启动兜底循环写在其后**执行不到** | 兜底结构不可达 | 删除裸等待；getprop 探测循环（120 × 10s）同时覆盖设备上线与启动完成两阶段；读数侧 `|| true` 降级适配 `set -euo pipefail` |
| ③ | #352：`Unknown AVD name [ci-device]`，ini 不在 `$HOME/.android/avd` | avdmanager 与 emulator 对 AVD home 各自解析，新镜像 / emulator 37.1.11 下落位不一致 | 显式 `export ANDROID_AVD_HOME="$HOME/.android/avd"`（两侧共用）；创建后硬断言 ini 落位，不一致则连同 `.avd` 目录迁移并留痕，未产出则秒级报错 |
| ④ | #353：`ProbeKVM: This user doesn't have permissions to use KVM (/dev/kvm)`（`/etc/group` 的 kvm 行无用户名） | `/dev/kvm` 存在但 runner 用户不在 kvm 组（镜像近期变更） | 启动前 `/dev/kvm` 存在断言 + `sudo chmod 666`（一次性 runner 环境无持久化风险） |
| ⑤ | #354：模拟器 55s 启动成功、`emulator-5554` 上线，但 gradle 报 `Task ' -Pandroid…notClass=…' not found` | connected 步骤为「行内 plain scalar + 反斜杠续行」——YAML 把「反斜杠+换行」**折叠为「反斜杠+空格」**，bash 将 `\ ` 解释为转义空格，gradle 收到带前导空格的伪任务名 | 改块字面量 `run: \|`，反斜杠+换行成为真实续行 |

**核心如实声明**：⑤ 意味着该步骤自 notClass 过滤写法引入起，**connected 在 CI 从未真正执行过**
（每轮必在 gradle 参数解析处失败 2 秒退出）——与 #351 的挂死形态叠加，构成「门禁存在 ≠ 门禁被执行」
在 CI 面的又一实锤（与 `ISSUE-P3-305` 本地闸门同型）。①~④ 每层修好后由下一轮 push 触发的 CI
逐层证伪/证实，未做任何跳过或吞错（`timeout-minutes` 与 fail-closed 语义全程未动）。

### 2.2 `ISSUE-P2-315`：OWASP Dependency-Check 的结构性超时

- **实证**：run 36045541019 中 `dependencyCheckAggregate` 自 `19:05:34` 进入 NVD 阶段后一小时零输出，
  `20:05:02` 撞 `timeout-minutes: 60` 被取消；fail-closed 断言按设计报「报告不存在」（该链路正常）。
- **根因**：插件把 NVD H2 库默认落 `${GRADLE_USER_HOME}/dependency-check-data/<ver>`
  （dependency-check-gradle 插件 `DataExtension.groovy` 源码实证），而 `gradle/actions/setup-gradle`
  缓存只覆盖 caches / wrapper 子目录 ⇒ **每次推送全量重下 NVD**，数据源慢日必然撞 60 分钟顶。
  workflow 头注释「首次 NVD 缓存被 runner 缓存吸收后增量扫描耗时可控」属声明漂移，已一并更正。
- **整改**：①`timeout-minutes` 60 → 90；②新增周粒度 `actions/cache@v6.1.0`（SHA 钉死）缓存
  `~/.gradle/dependency-check-data`（ISO 周 key + 前缀 restore-keys，命中后由插件按 `validForHours`
  增量更新）；③CVSS 硬断言 / 报告 artifact / SARIF 上传三步语义一字未动（不得以放宽换绿的纪律原样保留）。
