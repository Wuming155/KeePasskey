# §415 冷启动首帧闪系统语言：引入「启动语言种子」（ISSUE-P3-459 续）

## 1. 原文收录（触发本批的原话）

> 「冷启动最初一帧可能闪一下系统语言，解决」

这条是 §414 主动登记在「遗留与下一步」的那条取舍项（当时按「宁可一帧、不可 ANR」把主线程
等 DataStore 冷读的口子留着），用户要求把它补掉。

## 2. 根因（先取证，不拍脑袋）

语言偏好的真源是 `SettingsRepository` 的 **DataStore**，首值是**异步冷读**（磁盘 IO +
protobuf 解析，真机数十至数百毫秒）。三条消费通道在首值到达前只能拿到默认值 ⇒ 冷启动先按
**系统 locale** 渲染一帧（系统 locale 是 `zh-CN`，用户选的是 `EN_US`）⇒ 先闪一帧中文再翻英文。

| # | 通道 | 首值到达前的取值 | 结果 |
|---|---|---|---|
| 1 | Compose（`KeePasskeyApp` 的 `targetLocale`） | `SettingsUiState()` 的 `appLanguage` 硬编码 `SYSTEM` ⇒ `localeFor(SYSTEM) = null` ⇒ 按系统 locale 渲染 | 首帧中文 |
| 2 | `StringsProvider`（`AppLocaleTracker.locale`） | 初值 `null` ⇒ `localizedResourcesFor` 回落 `context.resources`（系统 locale） | 首帧中文 |
| 3 | 非 UI 装配点（`localizedContextForAppLanguage`） | 同 2 | 首帧中文 |

**决定性取证（这一步暴露了我第一版整改的漏洞）**：首版只加了「SP 镜像 + 冷启动灌种」，真机
冷启动后 `adb shell run-as com.keepasskey.debug cat shared_prefs/keepasskey_launch_seed.xml`
⇒ **`No such file or directory`**。

原因不是代码没跑，而是**镜像的写入时机错了**：镜像只在用户切语言（`setAppLanguage`）时写，
而用户切 English 是在**旧版本**上切的（当时还没有镜像）⇒ SP 文件从未生成过 ⇒ 快路径恒读不到值。

这条取证同时说明：光靠「用户改语言时顺手写一份」是补不回来的，必须有一条**从真源回灌**的路径。

## 3. 整改

新增 `app/.../ui/AppLaunchLanguageSeed.kt`——应用内语言的**启动种子**：进程内首个渲染帧即可
拿到、且**零 IO** 的语言值。

- **快路径（常驻）**：`Application.onCreate` 主线程同步读 SP（mmap 小文件，冷读 1~5ms，
  早于任何首帧渲染）→ 灌进内存 `volatile` 字段；此后所有语言读取退化为一次 volatile 读。
  **刻意不**在 onCreate 里等 DataStore 冷读（主线程阻塞 → 启动期 ANR，`§414` 的口径不变）。
- **慢路径（一次性）**：`AppLocaleTracker` 构造时若种子无值（`readOrNull() == null`），
  `seedFromSettingsSync()` **限时 200ms** 同步等一次 DataStore 首值，**拿到即回灌 SP**；
  超时/任何异常一律落 `SYSTEM`（与 DataStore 缺省口径一致，**绝不**回落到某个具体语言，
  否则首帧会闪一帧*错误*语言）。回灌后该分支永不复现，此后恒走零 IO 快路径。
  §414 刻意回避的「主线程等 DataStore 冷读」这次之所以可做：①限时 200ms 封顶；②仅首次。
- **写入点唯一**：`RealSettingsRepository.setAppLanguage` 同步 `store`（内存 + SP），
  否则镜像与真源漂移（表现为「切了语言重启又变回去」）。
- **Compose 首帧**：`SettingsUiStateProjection` 的 `initialValue` 由 `SettingsUiState()`
  改为 `SettingsUiState(appLanguage = AppLaunchLanguageSeed.read())`。
- **机检（防回潮，AC 要求）**：新增 `tools/audit/check_launch_language_seed.py`，五条接线
  逐条 fail-closed——E1 `MainApplication.onCreate` 灌种 / E2 Compose 首帧 `initialValue` 取种 /
  E3 `AppLocaleTracker.init` 取种 / E5 慢路径补种 / E4 语言写入点镜像；`--selftest` 造 6 种
  「逐条通断」样本（全通 0、单断各 1、tracker 连慢路径断 2、全断 5）验证判据真能分辨。
  **不把这项并入 `check_user_visible_cjk`**——那条判的是「字面量有没有中文」，
  与「通道跟不跟语言」是两个正交口径，混在一起会让两边判据都变糊。
- **CI 化**：`.github/workflows/build.yml` 的 `hygiene-gate` 由八条扩到**九条**（新增本脚本）。

### 3.1 过程缺陷留痕（如实记录，便于后来者复盘）

1. `locale = AppLaunchLanguageSeed.read()` 直接类型错（返回 `AppLanguage`、目标是 `Locale?`）。
2. `seedFromSettingsSync()` 声明返回 `AppLanguage` 时，`init` 里的三元赋值被推断成
   `Serializable?`（`UserSettings` 平台类型穿透 `first()` 的推断），报
   `Assignment type mismatch`；改「`if/else` 两条语句 + 函数返回 `Locale?`」后干净通过。
3. 自校首版样本设计错：造「缺 install + 缺 store」时把 E2/E3 一并打坏了，报 4 而不是 2；
   **判据没错、样本错**——改为逐点可控通断（`make_tree(install=, initial=, tracker=, store=)`）。
4. 第一版整改（只做镜像写入、不做真源回灌）在真机上**完全没生效**，是靠「SP 文件不存在」
   这条取证抓出来的；若只跑本地机检与环境无关的单测，会得到一次漂亮的假绿。

## 5. 真机取证（`adb` 实测，非推断）

设备 **M332BF**（`warsaw`），最新 Debug 包 `lastUpdateTime=2026-10-03 08:56:02`。

| 取证项 | 命令 | 实测结果 |
|---|---|---|
| 启动种子回灌 | `run-as com.keepasskey.debug cat shared_prefs/keepasskey_launch_seed.xml` | `<string name="app_language">EN_US</string>`（**修复前该文件不存在** ⇒ 证慢路径確实跑过一次并回灌） |
| 二次冷启动种子仍在 | force-stop → 起 → 再读该文件 | `EN_US`（此后恒走零 IO 快路径） |
| 冷启动耗时 | `am start -W -n com.keepasskey.debug/com.keepasskey.app.MainActivity` | `TotalTime=1015ms`（慢路径 200ms 封顶一次性代价，含在内） |
| 界面语言 | `uiautomator dump` | 本次取证时设备灭屏 + 焦点停在 `NotificationShade`，`cmd statusbar collapse` 与 `screencap` 均取不到 App 屏（截图全黑）——**这一条没能独立取证**；界面英文由 §414 的 `Sync failed: Cannot decrypt the cloud conflict database` / `Vault` / `Settings` 同通道延续支撑 |

**结论**：首帧能稳取值这件事，由「种子文件里确有 `EN_US`」+「五条接线机检 + CI 兜底」共同保证；
界面那一帧的肉眼确认受设备状态限制，如实标注为未完全独立取证。

## 6. 遗留与下一步

- **首帧那 1~2 帧的肉眼取证**：`uiautomator` / `screencap` 都是**事后**快照（dump 执行时首帧早已
  过去），抓不到「闪」。若要硬取证，需要 `Surface` 层按帧抓取或`reportFullyDrawn` 埋点，
  成本高且本项目无该设施；当前以「种子值正确 + 接线机检 + 冷启动耗时未恶化」作为闭环依据。
- **SP 与 DataStore 双写**：种子是**镜像不是真源**，任何绕过 `setAppLanguage` 直接改 DataStore 的
  写法都会让镜像陈旧（表现为切语言后重启回落旧值）。回灌路径已把首次冷启动补上，
  但「用户手动清 DataStore 文件而不清 SP」属极小概率，不额外处理。
- **冷启动 200ms 上限**：若后续真机测试显示首帧仍有闪，先把 `SEED_TIMEOUT_MS` 调到 100 试，
  **不要**改成无上限阻塞（口径见 `AppLocaleTracker` KDoc）。
