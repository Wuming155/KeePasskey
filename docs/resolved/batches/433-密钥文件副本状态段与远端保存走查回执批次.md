## §2 `ISSUE-P3-448` 走查续整改（**条目保留**，待再走查后归档）

### §2.1 问题

原实现的「导入密钥文件」只有**一次性回执**（`dbset_keyfile_import_memory_done`），设置页
**没有任何常驻状态**回答「此刻本库到底有没有私有目录副本」——用户无从判断收编是否真的发生。

### §2.2 参考核实（规则 3 口径：`docs/references/` 直读结论）

[`docs/references/UI与操作体验的竞品对比报告.md`](../../references/UI与操作体验的竞品对比报告.md) §4.4
三家源码直读结论：**KeePassDX 的密钥文件 URI 只落在 Room `file_database_history.keyfile_uri` 列，
解锁时现读外部文档、应用私有目录不落副本**；kp2a 同理现读；仅 Monica 有内部副本（按 SHA-256 指纹命名）。
⇒「私有目录副本路径」这块 **KeePassDX 无直接先例**，用户所点名的「参考 KeepassDX」按
**交互风格**对齐（可读名称 + 显隐按钮）理解，本项属本应用独有增强。

### §2.3 用户拍板（2026-10-03）

- **呈现位置**：**导入行下方常驻状态**（未选「导入前确认弹窗」「导入成功提示」两处）；

  须在文案里说明磁盘上实际按库标识哈希命名）。

**关键取舍（行数闸门倒逼）**：副本摘要**并入既有 `MasterKeyChangeTaskState`**、经既有
`masterKeyChangeState` 输入流投递，而**非**新增第十路 `combine`——`SettingsViewModel.kt` 恰在
tier2 上限 **500 行**（`tier2 budget=36` 已满），新增一路必须改该文件即越界（tier1 >500 恒 0）。
语义上自洽：本控制器即「改密 / 改绑 / 导入密钥文件」三位一体的状态宿主，副本正是这三条动作的直接产物。

**探测量守恒**：`refreshKeyFileCopyName` 只在**确有副本文件时**才解封（`load` 先查文件存在即返回），
解出的字节**就地 `fill(0)`**、不向任何调用方外泄；文案面只显示**原始文件名**（非密钥元数据）。

**预览覆盖**：`ImportExportSettingsScreenPreview` 传非 null 显示名，使新增状态段（遮蔽＋眼睛按钮）
进入导出预览——该段仅在确有副本时渲染，默认参数下预览看不到它（ISSUE-P3-340 口径）。
