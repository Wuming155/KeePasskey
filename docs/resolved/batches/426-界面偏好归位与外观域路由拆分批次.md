## §1 两件走查项的取证与处置

### §1.1 「常驻通知栏里没有立即锁定」——核实为**动作已挂上、仅被折叠态隐藏**（零代码改动，落 `PD-71`）

取证（`adb -s a7eb933d shell dumpsys notification --noredact`，2026-10-03）：

```
NotificationRecord(0x022e0fe5: pkg=com.keepasskey.debug ... id=1001 tag=null importance=2
  key=0|com.keepasskey.debug|1001|null|10456 bbbc=0: Notification(channel=keepasskey_unlocked_status
  ... flags=ONGOING_EVENT|ONLY_ALERT_ONCE|SILENT ... actions=1 vis=SECRET ...))
      actions={
          [0] "立即锁定" -> PendingIntent{... com.keepasskey.debug broadcastIntent ...}
        }
            android.title=String (KeePasskey 密码库已解锁)
            android.text=String (自动锁定倒计时进行中，点击返回应用)
```

即：**「立即锁定」动作确实挂在通知上**（`[0] "立即锁定" -> broadcastIntent`，指向 `VaultLockActionReceiver`），
`VISIBILITY_SECRET` / `IMPORTANCE_LOW` / `SILENT` 与 §425 的设计口径逐项一致。
同批截图（`screencap`）显示：常驻通知在**折叠态**只渲染标题 + 正文，**不渲染动作按钮**。

结论：这是 **Android 12+ 通告栏的折叠语义**——动作按钮随**展开态**渲染，而非本仓漏挂动作。
竞赛对照报告 G6 与竞品（keepass2android）在此点无差异，不构成缺陷。
**不为此自造第二入口**（常驻前台服务 / 悬浮球 / 自定义通知布局），故本批**零代码改动**，口径落 `PD-71`。

- **复核手法（给用户）**：在通知栏内对该条通知**下拉展开**，动作按钮（「立即锁定」，以及存在
  「最近查看条目」时的「复制用户名 / 复制验证码」）在展开态呈现。
- **重开条件**：用户按上述手法展开后**仍不可见**时重开——届时候选手段为
  ① 给通知补 `NotificationCompat.BigTextStyle` 展开态样式（换取展开可供性）；或
  ② 另立 `IMPORTANCE_DEFAULT` 的新通道 id（旧通道重要度一经创建不可改，§425 的 `NotificationChannelSpec` KDoc 已载明该约束）。

### §1.2 「界面偏好应收缩到二级页面」——**已整改**（本批唯一代码改动面）

走查口径：§425 把「界面偏好」做成了设置主页上的**第四个独立分组**；用户要求它**收进「界面与显示」组**，
作为该组的**第三个二级入口**（该组原有「主题」「列表与导航」两项）。属信息架构归位：三项同属
「应用长什么样」，平铺成两块会把同一族外观入口拆成不相邻的两段。条目层面属 `ISSUE-P3-444` AC⑤ 的口径修订。

  界面偏好）**逐字搬迁**出 `KeePasskeySettingsNavGraphRoutes.kt`；门面 `keepasskeySettingsNavGraph` 的装配顺序不变。
  外迁缘由见 §5（tier2 棘轮转红）。
- 字符串 zh / en 成对 +2（`settings_interface_sub`、`interface_section_fields`）。
- 既有守卫同步：`InterfacePreferencesWiringTest` 的「开关落点」改指新页面、并新增
