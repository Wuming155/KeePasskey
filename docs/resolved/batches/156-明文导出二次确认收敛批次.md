## 2. 顺带修掉：静态守卫「剥注释」不认识字符串 ⇒ 一处安全守卫假阴性

**现象**：新写的「三类调用点计数 = 3」断言首跑报 `expected:<3> but was:<1>`，而文件里明明有三处。

**根因**（`ExportTicketSinkGuardTest` 原 `stripComments` = 块注释正则 + 行注释正则）：块注释正则只看字符序列，
本仓 SAF 通配过滤器字面量（`arrayOf` 里那串「星、斜杠、星」）同时含「斜杠星」与「星斜杠」两个子串，
于是**从前一处该字面量的开注释符到后一处该字面量的闭注释符之间的全部真实代码被当成注释抹掉**。

**为什么这不只是「断言数不对」**：该守卫的第一条判据是**全仓 `app/src/main` 扫有无第二处 `ExportTicket` 实现**
——它正是走这套剥离。被吞区间内的任何伪造令牌实现都会**看不见** ⇒ 守卫存在**假阴性**。

**修法**：新增 `app/src/test/java/com/keepasskey/app/testutil/SourceTextSanitizer.kt`
（口径：**字符串字面量 → 块注释 → 行注释**），`ExportTicketSinkGuardTest` 的 `stripComments` 改为委托它。
**未**同步改 `AlgoHotPathGuardsTest`：实测其 27 个扫描目标**不含**该字面量（当前无假阴性），
不无端改动一份正在工作的守卫的语义；工具已就位，待其真被命中时再统一。
