### §355.2 安全面裁定（AC②「按既有排序合并」的实施口径）

条目立规时预设 AC② 为「按域/包名既有排序合并」，实施时发现该口径对卡 / 地址条目**自相矛盾**：
卡条目通常不含目标电商站点的 URL，走 `AutofillCandidateRanker` 必然 score=0 落选，供给恒空。
按条目「含对应自定义字段即候选」的本意裁定为：

- **供给正交于域匹配**：结构化候选 = 含全部所需字段的条目（`StructuredFieldPolicy.selectCandidates`，
  时间降序、上限 4）——与 Monica 同型（卡是跨站点上下文）。域匹配语义**一字未改**，
  只对登录候选继续生效；
- **安全面不降级**：结构化数据集**恒挂确认页认证**（`attachConfirmationAuth`，不读会话授权跳过）——
  每次交付都过「调用方归属展示 + 生物识别 / 受保护窗口手动确认」；纯结构化表单锁库时不下发
  （解锁链交付面为 U/P，见 §355.4 边界）；`AutofillAccessPolicy` 自我排除 / 黑名单 / 通道开关
  三道前置闸门对结构化同样生效（它们在 `resolveTargetFields` 之前）；
- **字段级屏蔽不扩权**：`AutofillFieldBlockPolicy` 的签名维度是「包名 + 域 + U/P 角色」，
  结构化目标不属该模型；纯结构化表单亦不得被 `blocksEntireForm`（U/P 双空即 true）误杀
  ——闸门改为「整表拒绝仅当无任何结构化目标」。

### §355.3 整改内容

1. **AC① 三源识别**：新增 `StructuredFieldPolicy`（纯函数）——8 角色枚举
   （卡号 / 安全码 / 有效期月 / 年 / 街道 / 城市 / 地区 / 邮编）+ 字段名单点映射
   （`creditCardNumber` 等，Android hint 惯例）；`detectFillableTargets` 只采信
   **autofillHints 与 html autocomplete** 两源（归一化查表，可见性 + `importantForAutofill`
   同登录口径）；`labelRoleOf` 承载 label 术语源——**只识别不放行**（日常词误触面，
   置信不足不填，有关系断言用例锁定「label-only 节点不进 detect」）。
   结构树投影补 `autocomplete`（`AutofillStructureScanner.htmlAutocomplete` 读 `htmlInfo`，
   落 `ParsedAutofillNode` → `ScanNode`，`toString` 脱敏面同步只出布尔）。
2. **AC②③ 供给与取值**：`selectCandidates`（全字段齐备 + 时间降序 + 上限 4，缺字段的卡不入选）

  不在本批范围——扩角色是纯枚举 + 词表增量，另立条目评估。
- **结构化零候选无手动兜底**：选择器交付链为 U/P 通道（`resolveCredentials`），
  纯结构化表单不挂「搜索全部条目…」（挂了也无字段映射）——零候选即如实空响应。
- **保存捕获不含结构化**：`SaveInfo` 仍只注册 U/P（`applySaveInfoIfNeeded` 对结构化-only
  返回 null），不捕获卡字段——保存面另立条目评估。
