> 日期：2026-10-02。P3 1→2→**1**。
> 起因：用户装机走查 §403 debug 包反馈「更改密钥文件后，杀掉应用重新进入之后，它默认选择的密钥文件还是旧版本的，而不是新修改的」。

## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-434：改绑/解绑密钥文件后「记住的密钥文件位置」不更新——冷启动恢复与指纹现读仍指向旧文件

- **核实时间点**：2026-10-02；**核实方式**：用户装机走查（§403 debug 包）反馈「更改密钥文件后，杀掉应用重新进入，默认选择的密钥文件还是旧版本的」；代码链路复核（HEAD `db2b6d89`）：记忆记录（`lastKeyFileUri/Name`）唯一写入点＝解锁页 `KeyFileSessionCoordinator.rememberKeyFileOnSuccess`（解锁成功后按偏好记忆）；改绑通道 `ChangeKeyFileIntent.Use` 只携带字节（`VaultRepositoryTypes.kt`），`SettingsMasterKeyChangeController.submit` 成功后只重封印（P2-398），不触碰记忆记录。
- **影响**：改绑新密钥文件后——① 冷启动解锁页 `restoreRememberedKeyFile` 恢复**旧**文件（用户所见现象）；② 指纹解锁链（`BiometricUnlockCoordinator.completeBiometricUnlock` 第③步经记忆 Uri 现读，P1-431）读到旧文件 → 组合密钥不匹配 → 落 Failure 分支清陈旧封印回落密码模式（可恢复但每次必败）；③ 解绑（Remove）后旧记录同样残留。冷启动对「已不可读」的旧记录会 `forget()` 降级，但旧文件仍可读时不自我纠正——陈旧记录稳定存在。
- **整改方向**：`ChangeKeyFileIntent.Use` 扩展携带来源 SAF Uri + 显示名（非密钥元数据；缺省参数保既有构造点兼容）；改绑/解绑**提交成功后**由 `SettingsMasterKeyChangeController` 同步记忆记录——`Use`：偏好开启且对来源 Uri 取得持久化读授权 → `remember(新)`，否则 `forget()`（陈旧记录绝不保留）；`Remove` → `forget()`；`Keep` → 不动；偏好关闭 → `forget()`（与解锁页 `rememberKeyFileOnSuccess` 同口径）。提交管线其余零改动。
- **验收标准**：
  ① 改绑成功后记忆记录指向新文件（Uri + 显示名），冷启动恢复与指纹现读链读到新文件；解绑成功后记录清除；
  ② 偏好关闭 / 持久授权不可得 / Uri 缺失时一律清旧记录（fail-safe，绝不留陈旧指向）；改密失败路径不动记忆；
  ③ 密钥文件字节擦除链（P3-428）与既有提交语义零变化；新增控制器单测覆盖上述分支；
  ④ 全量 `test` 绿 + 门禁全 PASS；真机复测：改绑新密钥文件 → 杀进程 → 重进，恢复与指纹解锁使用新文件（用户走查）。

## 2. 整改内容

1. **`ChangeKeyFileIntent.Use` 扩展元数据**（`VaultRepositoryTypes.kt`）：新增 `sourceUri` / `displayName` 两个缺省空串字段——SAF 来源定位与文档显示名，**非密钥元数据**（可持久化，同 P3-04 口径），缺省参数保既有构造点（单测 / `CreateKeyFileFactor` 语义无涉）零改动兼容；字节借用语义与擦除契约一字未动。
2. **改密对话框随行**（`MasterKeyChangeDialog.kt`）：`PickedKeyFile` 增加 `sourceUri` 字段（SAF 选定回调处随 `uri.toString()` 落位）；`intentOfChoice()` 的 `Use` 分支把 `sourceUri` / `displayName` 随意图上行。
3. **控制器记忆同步**（`SettingsMasterKeyChangeController.kt`，123→163 行）：新增可空注入 `keyFileAccess: KeyFileAccess?`（生产 = `SafKeyFileAccess`，单测注入假实现）与 `syncRememberedKeyFile()`——**成功后**（先于重封印，纯偏好层 IO 不阻塞 BiometricPrompt）：偏好关闭 → `forget()`；`Use` 来源非空且取得持久化读授权 → `remember(新)`，否则 `forget()`（陈旧记录绝不保留）；`Remove` → `forget()`；`Keep` → 不动。与解锁页 `rememberKeyFileOnSuccess` 的偏好/授权口径逐条对齐。失败路径不进同步（改绑并未发生）。
4. **接线**（`SettingsViewModel.kt`）：控制器构造补第 4 参 `keyFileAccess`（单行构造，行数分档闸门内——该文件恰在 tier2 上限 500）。
5. **冷启动链受益**：解锁页 `restoreRememberedKeyFile`（P3-04）与指纹现读链（`completeBiometricUnlock` 第③步，P1-431）均读同一记忆记录——记录指向新文件后两条链自然读到新密钥文件，无需另改。
