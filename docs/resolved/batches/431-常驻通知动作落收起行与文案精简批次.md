# §431 常驻通知「动作落收起行 + 文案精简」批次（`ISSUE-P3-440` 五轮回执）

> 批次日期：2026-10-03。
> 触发＝第五轮装机走查回执（用户原话：「有箭头了，但是点一下箭头，没有看到立即锁定、复制用户名或者
> 复制验证码。还有就是通知栏里的信息过于冗余了，精简一些。」）。
> 性质＝**缺陷修复 + 文案整改**（承接 §430）：箭头已到位，但**动作没有落点**；同时精简冗余文案。
> 装机形态＝debug 版（`com.keepasskey.debug`）；设备＝Xiaomi M332BF / HyperOS OS4.0 / Android 17。

## §1 根因：`MediaStyle` 的展开视图**不渲染普通动作行**

§430 只设了 `setStyle(MediaStyle())`（刻意避开 `setShowActionsInCompactView`，因 KeePassDX 源码自注
「Won't work with Xiaomi」）。但 `MediaStyle` 的**展开视图是媒体版式**（大图 / 播放控制），
它**不像普通样式那样带一条动作行**；动作在这套样式里的唯一落点是**收起行的按钮位**——
正是官方文档那句所要求的：

> **`MediaStyle` 还允许您通过指定三个操作按钮（这些操作按钮也应在收起的视图中显示）
> 修改收起尺寸的内容视图**——为此，请向 `setShowActionsInCompactView()` 提供操作按钮索引。

⇒ 不调用它，动作就**无处可显**（点开箭头也看不到），与走查现象完全一致。

## §2 整改

1. **动作落进收起行**：`MediaStyle().setShowActionsInCompactView(*IntArray(actionCount) { it })`
   （`actionCount` 随动作集变化：仅「立即锁定」时为 1，存在「最近查看条目」时为 3）。
2. **补三个单色动作图标**（收起行按钮位需要图标，否则按钮位空白）：
   `res/drawable/ic_notif_lock.xml` / `ic_notif_account.xml` / `ic_notif_totp.xml`（24dp 白色实心矢量），
   经 `IconCompat.createWithResource(context, …)` 挂到对应动作（顺序与 `addAction` 一一对应）。
3. **文案精简**（用户「过于冗余」）：

   | 资源 | 改前 | 改后 |
   |---|---|---|
   | `notification_unlocked_title` | `KeePasskey 密码库已解锁` | `密码库已解锁`（通知面已显示应用名，前缀冗余） |
   | `notification_unlocked_text` | `自动锁定倒计时进行中，点击返回应用` | `自动锁定倒计时进行中`（倒计时数值已由 Chronometer 呈现；「点击返回应用」是点按的固有语义） |
   | `notification_unlocked_text_idle` | `密码库已解锁，点击返回应用` | `点击返回应用`（与标题重复的部分去掉） |

   英文同批对齐（`Vault unlocked` / `Auto-lock countdown running` / `Tap to return to the app`）。
4. `UnlockedNotificationWiringTest`：守卫扩为 `常驻通知必须以MediaStyle提供收起行动作位`——
   同时断言 `MediaStyle()` 存在、`BigTextStyle` 不得回退、**`setShowActionsInCompactView(` 存在**、
   **`IconCompat.createWithResource(` 存在**。

安全面（`PD-69`：字段子集 / `VISIBILITY_SECRET` / 固定通用文案 / 跨 `PendingIntent` 只带字段名 /
后台复制不展开明文 UI / 剪贴板擦除链）**逐条未动**；本批只改「动作落在通知的哪一格」与文案长度。
