# §541 非设备依赖存量问题整改与部分实施记录

## 范围

本批闭环 10 项已有独立整改方案、其计划验收可由 JVM / 模块边界完成且不要求真机的存量问题：

- P2：636、638、640、651、652
- P3：643、644、646、648、654

另对 P3-653 完成核心代码整改并通过状态转换/接线 JVM 用例，但真实 DataStore 落盘后重新读取未验收，故仍保留在 `ACTIVE_ISSUES.md`，不计入闭环数。

本批未触及需要系统 Credential Manager、设备 UI / 生命周期、SAF、扫码相册或实体网络路径的条目。P2-655 已有实现并通过本次离线 S3 JVM 用例，但仍要求隔离 S3 服务分页回执和 ListObjectsV2 canonical-query 独立签名向量，故继续保留在 `ACTIVE_ISSUES.md`。

## 实际整改

| 问题 | 改动与验收 |
|---|---|
| P2-636 | 冷启时用缓存文件实际 SHA-256 与基线比较；缓存/版本标记分步提交中断、缺失或损坏标记均不再误判 clean。`SyncCacheTest` 定点覆盖交付前、交付后、完成后及坏标记。 |
| P2-638 | 恢复预览改为比较标准字段、受保护/自定义字段、附件字节及递归历史；密码、OTP、受保护字段、Passkey 材料、附件和历史分别单独变化均计为修改。附件采用固定 8 KiB 缓冲并在退出清零；不可读正式库仍返回未完成比较。 |
| P2-640 | 导入启动时捕获会话票据并贯穿批次；数据库共享 mutex 内每次树修改校验票据，最终保存再次校验。barrier 用例确认 A 首条完成后切换 B 时余下两条拒绝且报告部分结果。 |
| P2-651 | WebDAV / S3 保存只消费独立凭据副本，所有权明确并在结束时清零；失败保留有效草稿与界面值，成功后清理控件状态。 |
| P2-652 | 同一保存边界返回密封配置快照；连接测试和同步周期分别从该快照构造并释放 Provider。A 测试挂起时保存 B，A 的测试和同步仍只请求 A，迟到结果不把 B 标记为已验证。 |
| P3-643 | 重复选择当前自定义图标不会覆盖已有 dirty 标记；含标题更改、重复新图标和未改负对照。 |
| P3-644 | 分组图标反馈跟随真实保存结果；只读分组及批量写入口禁用/隐藏并说明原因，控制器保留底层只读保护。 |
| P3-646 | KDBX 解密探针、GZip 解压累计容器、读取缓冲和副本在扩容、失败及正常路径清理；附件有效输出保持可读。 |
| P3-648 | 生成器按代次发布结果；过期结果在慢快乱序、锁定和 ViewModel 销毁交错中丢弃并清零。 |
| P3-654 | PRF 编码、Base64 空白压缩及 CBC 堆尾部拼接的独占工作副本在成功/异常路径清零，不擦除移交结果。 |

## 部分实施

P3-653 新增原子 `switchToBrandPalette`，关闭 dynamic、清除自定义 seed，并保留已选 palette；路由/SettingsViewModel/偏好控制器已接线，fake 状态转换与生产源码接线 JVM 用例通过。尝试在 Windows JVM 中运行真实 DataStore 重读测试时，Preferences DataStore 文件替换报 `Unable to rename ...preferences_pb.tmp`，因此撤掉了不可靠的测试 harness；没有将该失败当作实现通过或产品缺陷。真实持久化重新读取验收仍待完成，问题继续开放。
