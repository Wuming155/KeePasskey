## 1. 原条目（自 `ACTIVE_ISSUES.md` 原样收录）

- **背景**：`ISSUE-P3-176` ② 的转登项：`app/.../ui/KeePasskeyApp.kt:61` 的根组合读取**整个**
  `SettingsUiState`（100+ 字段）并在 `:243` 传给 `keepasskeyNavGraph(appSettings = …)`；
  而 `NavHost` 以 `remember(route, startDestination, builder) { navController.createGraph(...) }` 建图 ⇒
  **builder 是新 lambda 时整张图重建**，而 builder 捕获的 `appSettings` 在任一字段变化
  （同步状态文案、健康扫描进度、调试开关……）时就是新实例（`SettingsUiState` 含 `List<String>`、
  未标 `@Immutable`）⇒ 任一**无关**偏好变化都会 `createGraph` + `setGraph`，重建全部 `NavDestination`。
- **整改方向**：根只读**真正需要的窄字段**，`keepasskeyNavGraph` 改接收窄参数，
  或用 `remember(navController, 窄参数)` 把 builder 包一层。
- **验收标准**：导航图不因**无关**设置字段变化而重建（结构断言或计数）；既有导航 / 页面用例全绿；
  预览与截图基线经复核（涉及全仓导航调用点）。
- **核实时间点与方式**：2026-09-17 读 `KeePasskeyApp.kt:55-70/235-250`、`navigation-compose:2.10.0`
  的 `NavHost` 建图实现核实。
- **风险提示**：属 **Compose 状态宽度 + 导航建图**面，改动会触及 `keepasskeyNavGraph` 形参与
  全仓导航调用点；**不得**以「用 `remember` 包一层」掩盖真实依赖。

## 2. 关键侦察结论（决定了本批的最小改法）

`keepasskeyNavGraph` 虽然接收整个 `SettingsUiState`，但**实际只用到其中的 `themeMode` 两处**
（`:39` 解锁页与 `:66` 列表页的 `currentTheme`）——这是三条 `appSettings` 用法中的全部
（其余是 KDoc 提及）。⇒ 收窄形参即可，**无需**改动图内任何路由定义。

**为何「收窄形参」在此确实能止住整图重建**（推理，非实测）：`NavHost` 的建图 key 含 `builder`；
Kotlin lambda 无 `equals` 覆写 ⇒ 每次重组的新实例都会让 `remember` 失效，**除非**该 lambda 被
Compose 编译器**记忆化**——而记忆化的前提是它所捕获的值**全部稳定**。`SettingsUiState` 含
`List<String>` 且未标 `@Immutable` ⇒ 不稳定 ⇒ 原实现每次设置变化都重建图；
`AppThemeMode` 是**枚举**（稳定）⇒ 收窄后的 builder 只捕获该枚举 ⇒ 仅主题变化才重建。

## 3. 本批实现

1. **`KeePasskeyNavGraph.kt`**：形参 `appSettings: SettingsUiState` → **`themeMode: AppThemeMode`**；
   两处 `currentTheme = appSettings.themeMode` → `currentTheme = themeMode`；
   导入由 `…settings.SettingsUiState` 换成 `…ui.theme.AppThemeMode`；
   类 KDoc 补「为何收窄」的说明（含上述记忆化前提）。
2. **`KeePasskeyApp.kt`**：调用点由 `appSettings = appSettings,` 改为 **`themeMode = appSettings.themeMode,`**
   ——根组合其余字段的读取（`themePalette` / `showAuthenticatorTab` / `lockWhenNavigateBack` 等）
   **一律未动**（它们各自的 `remember(...)` 本已按字段为 key）。
3. 图内**任何路由定义未改**（收窄只发生在形参与传参）。

## 5. 边界如实声明（不得外推）

1. **「不再整图重建」是结构性推理，不是运行期断言**：本批**未**用 Compose 运行时测试
   （如 `ComposeTestRule` 计数 `createGraph`）证明；证据是「形参收窄 + builder 捕获值变为稳定枚举」+
   源码守卫。**不得**读作「已在运行期验证导航图不再重建」。
2. **依赖编译器的 lambda 记忆化行为**（strong skipping / 自动记忆化）：若该优化在某配置下关闭，
   收窄形参仍会因「每次重组新建 lambda」而失效——本批**未实测**该编译器开关状态，
   也未改用「`remember(navController, themeMode)` 包一层」这一 AC 备选方案。
3. **根组合仍读取整个 `SettingsUiState`**（`KeePasskeyApp.kt:61`）：因此**根函数体仍会**在任一设置
   变化时重组（其内部各 `remember` 已按字段为 key，故不会连带重算）。AC 的「根只读窄字段」
   本批以**另一个等价选项**（图收窄形参）满足；若要彻底消除根重组，须把根改成读 10 个左右窄流，
   属独立改动、本批**不做**。
4. **未复核预览 / 截图基线**（AC 要求「涉及全仓导航调用点」须复核）：本批未跑
   `updateDebugScreenshotTest` 或预览导出，故**未更新任何视觉基线**。
5. **未跑设备侧 / `assembleRelease` / `lint`**。
