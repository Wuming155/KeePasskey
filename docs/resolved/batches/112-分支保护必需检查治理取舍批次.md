### 112.3 决策与依据（**新增 `PD-04`**）

**口径**：`main` 不设分支保护规则 ⇒ 供应链闸门维持**「检测」**语义（工作流在 `push{main}` 与 `pull_request` 上照常运行、CVSS ≥ 7.0 硬断言 fail-closed、SARIF 进 Code Scanning，但**不阻断**）。`P2-54` 的 AC② 据此判为**「有意不实施」**。

**依据（官方文档 [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) + 本次核实）**：

1. **单人仓库下保护规则对唯一行为者几乎不起约束**："By default, the restrictions of a branch protection rule **don't apply to people with admin permissions**"——不勾「Do not allow bypassing the above settings」时管理员不受约束；勾上则连自己的紧急直推也被挡。
2. **要真「阻断」必须引入 PR 流程，与本仓工作流冲突**：官方对「必需检查是否也约束**直推**」的措辞**含糊**（同一段里既有 "before collaborators can make changes to a protected branch"，也有 "…**or pushed directly to the protected branch**"）；**唯一不含糊**的阻断机制是「Require a pull request before merging」，而它会使 `AGENTS.md` 规则 6.4 的「整改后**立即** `git commit & push` 到 main」**不再可行** ⇒ 属**流程改造**而非加一个勾。
3. **闸门的实质价值已由工作流本身获得**：「检测」层已在位且同时在 push 与 PR 上运行；分支保护额外买到的仅是「阻断」，而在单人仓库上（理由 1）这层额外收益经不起理由 2 的代价。
4. **不是受计划限制**：仓库为**公开仓库** ⇒ 分支保护在计划层**可用**（官方：public 仓库在 GitHub Free 即可用）。**不得**把本取舍读作「做不到」。
