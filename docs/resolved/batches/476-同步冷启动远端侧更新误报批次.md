## 2. 整改

- **新增 `SyncLocalFileCheckpoint`**（`@Singleton`，进程内）：「本地库**文件**自上次成功同步以来是否被
  重写过」的检查点——记录**本地库文件字节的流式 SHA-256**（64 KiB 块，不整份物化；密文摘要，无明文无凭据，
  不触 `P1-07`）。`isUnchangedSinceSync(remotePath, file)`：记录缺失 / 远端路径不符 / 文件不可读一律
  **false（保守）**；摘要天然自证，换库 / 换远端路径不会误命中。**刻意不随锁库销毁**（销毁即令机制失效；
  与 `P1-07` 要销毁的密文快照不同类）——KDoc 明写口径。
- **记录点唯一判据**：新同包扩展 `SyncOutcome.isInSyncWithRemote()`（`UpToDate` / `UploadedLocal` /
  `MergedAndUploaded` 为真）。记录统一收口在 `SyncCycleRunner.runSyncCycle` 锁外（决策体整体更名为
  私有 `runCycleUnderLock`，函数体逐行未改）；**`ConflictNeedsUser` 一律不记**——冲突待决期本地可能正持有
  未上传编辑，记了会让下一轮把「本地未动」判真并据此静默丢弃它（用例 ② 锁定）。
- **决策接线**：`SyncCycleSetup` 仅在占位态（`BASELINE_MISSING`）读检查点（其余态证据已足，省一次整库
  读+哈希），产出 `SyncCycleContext.localFileUnchangedSinceSync` 并贯穿 `RemoteSyncContext`；装配期 verbose
  取证行增列 `本地文件自上次同步未变=`。
- **`handleRemoteSynced`**：新增 `remoteOnlyDifference = !ctx.isDirty && ctx.localFileUnchangedSinceSync`；
  为真时**不进合并上传**，落入既有「远端接管」尾段（该尾段随本批切出为同包私有扩展 `adoptRemoteBytes`，
  函数体逐行未改），并在接管前经既有六事件通道 emit `SyncCacheEvent.UpdatedCachedFileOnLoad`——
  列表页既有映射随之呈现「检测到云端已有更新，本地数据库已刷新」，**替代**误导性的「本地修改已上传至云端」。
- **接线**：生产经 Hilt 自动注入 `SyncCycleRunner`（新参可空默认 null，手工装配路径同批显式传入）；
  `SyncCacheEvictor` 在锁观察者之列（`DatabaseModule`）的前提经复核确认。
- **边界红线（未触碰）**：锁库清缓存安全设计原样保留；F1「已落盘未同步」与「内存未落盘」两类本地修改的
  合并 / 上传语义原样保留（用例 ② 锁定）；§372 的「两端一致」臂与其两条用例原样保留。

## 4. 过程留痕

1. **排查副产品（另立 `ISSUE-P3-542`，本批不修）**：第一支探针顺带发现 `KdbxContentComparator` 的等值
   判据对 `ProtectedString.isProtected` 敏感，而该标志对**标准五字段**不参与序列化往返（写侧
   `KdbxXmlEntrySerializer.resolveProtectedFlag` 以库级 `MemoryProtection` **无条件覆盖** per-value，
   读侧从 `Protected="True"` 属性派生）——探针读数：同一份字节两次解析 `changed=false`（判据在「两侧皆
   解析产物」时正确，这正是 §372 真机通过的原因），内存树 vs 自身序列化的解析 `changed=true`
   （`Title`/`UserName`：内存 `prot=true` vs 解析 `prot=false`）。生产写入面对标准五字段硬编码的标志
   **恰与库级默认 `MemoryProtection` 一致**，故默认配置库不现形；非默认配置库（导入自其它客户端）或任何
   以构造默认值造字段的路径会**恒判有变化**。已按边界如实登记（见 `ACTIVE_ISSUES` `ISSUE-P3-542`）。
2. **长函数门禁红一次**：`handleRemoteSynced` 增补后达 105 行（`functions_ge_100=1`，fail-closed 红）——
   顺手把远端接管尾段切出为同包私有扩展 `adoptRemoteBytes`（函数体逐行未改）回绿，非逻辑改动。
3. **用例断言错序修正一次**：首版 ① 例的「远端字节逐字节不变」比对基线取在**注入远端更新之前**，
   必红（注入本身就该改变远端字节）——修正为「注入后」基线；属用例自错，非被测行为缺陷，未进构建留痕。

## 6. 边界与残余（不得读作已验证）

1. **保守回退面（如实登记）**：以下组合下检查点失配 / 缺失 ⇒ 维持整改前的合并 + 上传路径（可能再次出现
   误导性文案，但**数据面保守、不丢内容**）：①本地两次同步之间发生过**任何落盘写**（含「触碰但内容等同」
   的保存——文件字节因随机 IV 必然变化）；②**进程被杀且缓存同时被系统回收**（证据双失）；③SAF 通道
   （`currentFile == null`，无本地文件可比，机制整体旁路）。解除条件：把检查点升级为内容级指纹
   （需规范化序列化层，§372 批次已论证其改动面），或记录点改为「逐 save 挂钩」。
2. **行为口径变化（产品可见）**：锁库后冷启动遇「远端侧更新」从「合并 + 上传 +『本地修改已上传』」改为
   「远端接管 + 零上传 +『检测到云端已有更新，本地数据库已刷新』」。前提由检查点**证明**本地自上次同步
   以来未被重写 ⇒ 接管不丢弃任何本地内容，非取舍性放宽。
3. **`KdbxContentComparator` 的 `isProtected` 等值敏感性**（§4.1）未在本批修——默认配置库不现形，
   修法（标准五字段按内容比较 / 自定义字段保留 per-value）须以 `ISSUE-P3-542` 的取证为前提，防「顺手对齐」
