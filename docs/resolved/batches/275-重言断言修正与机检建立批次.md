## §2 整改内容

### 2.1 AC① 断言改走生产判据（[`SecurityTest.kt`](../../../app/src/test/java/com/keepasskey/app/security/SecurityTest.kt)）

判定式与秒→毫秒换算**全部交回生产代码**，测试体只保留注入的时钟样本与原「70 秒 / 20 秒」场景：

```kotlin
val now = 100_000L
val backgroundTimestamp = 30_000L
val timeoutSeconds = 60

// 离开 70 秒，超时 60 秒 -> 生产判据必须判为已超时
val elapsedMillis = now - backgroundTimestamp
assertTrue(AutoLockTimeoutPolicy.isExpired(timeoutSeconds, elapsedMillis))

// 离开 20 秒，未超时 -> 生产判据必须判为未超时
val recentBackground = 85_000L
val elapsedShort = now - recentBackground
assertFalse(AutoLockTimeoutPolicy.isExpired(timeoutSeconds, elapsedShort))
```

- 被删的只有 `timeoutMillis = timeoutSeconds * 1000L` 与两处自造比较（**用例未删、场景未减**）。
- **顺带订正（同处陈旧注释）**：原注释把第二档写作「离开 20 秒」，而 `now − recentBackground`
  ＝ `100_000 − 85_000` ＝ **15 000 ms（15 秒）**——注释与样本不符，本批一并订正为 15 秒
  （禁把错误注释原样搬进新版本）。
- 用例 KDoc 补齐来龙去脉：本条的问题、同行为的既有正确覆盖点（`AutoLockTimeoutPolicyTest` /
  `AutoLockSessionGuardTest`）、以及「改本文件后必跑」的机检出口。
- AC② 履行：**用例数不变**（见 §4 读数 `tests` 持平），属「修正为真断言」而非删除。

### 2.2 AC③ 机检出口（新建 [`check_tautological_assertions.py`](../../../tools/audit/check_tautological_assertions.py)）

**前提核实（如实留痕）**：仓内此前**无**「永远为真的断言」机检出口——`tools/`（`doc/` 8 脚本 +
`audit/` 1 脚本）与 `docs/` 全量检索「永远为真 / 恒真断言」**零命中**，条目 AC③ 所称「沿用……检测口径」
在仓内无既有载体。故本批**建立**该出口，口径如下（已写进脚本文档串）：

1. 判定单位＝带 `@Test` 的函数体（大括号配平切块）；
2. 「纯局部值」＝`val NAME = EXPR` 且 `EXPR` 仅由字面量 / 已判定纯局部值 / 同文件纯字面量 `const val` /
   白名单类型转换（`toInt`…`toString`）经算术 · 比较 · 逻辑 · 范围运算符组合而成——**出现任何其它调用
   或属性访问即出局**（那才可能触到生产代码）；
3. 断言实参可全部按此口径求值 ⇒ 判「不经生产代码」⇒ 退出码 1。

**`var` 豁免（本批最重要的一处口径修正，属实测纠偏）**：首版把 `var` 也算纯局部值，
全仓跑出 **65 处命中 / 433 个测试文件**，抽查后确认绝大多数是**误报**——`var calls = 0` 这类
**观测通道**由**生产代码经回调写入**（`guard.register { calls++ }` 后 `assertEquals(1, calls)`），
恰恰是最有鉴别力的断言形态。故口径改为 `var` 一律不判（只认 `val` 一次性赋值），
并把该负样本固化进 `--selftest`。修正后全仓命中降到 **2 处**，且**恰为本条的两个断言**。

   该边界已写进脚本文档串。
