  返回 `Failure` 被忽略，症状同一）；行号随历次重排漂移，对象与事实全部在案。

- **改动一（新增 `SettingsDatabaseWriteState.kt`，119 行，写盘过程态与失败分型单点）**：
  - `DatabaseConfigWriteState(isSaving, feedback)`：UI 态（正在保存 + 一次性反馈，反馈语义与
    `MasterKeyChangeTaskState.feedback` 同源）；`isSaving` 由 `AtomicInteger` **计数**维护（布尔量会被
    先完成的那次提前熄灭）；`trackSave { … }` 包住一次真实落盘：进入置 busy、退出 `finally` 必释放，
    且关键提交段以 `withContext(NonCancellable)` **不可取消**（见改动五的退出语义），完成后结果如实落状态流；
  - `libraryWriteFailureFeedback(failure)`：**纯错误码映射**（`KdbxErrorTexts.resIdFor(code)`，绝不拼接异常
    `message`）；`DRIFT_SAVE_ABORTED` 返回 `null`（漂移由既有三选提示承载，不叠加一次性反馈）；
  - `rejectInvalidKdfParameters()`：参数无效（未落盘、未改会话）如实回执，为绕过 UI 的程序化调用兜底。

- **改动二（类型化漂移错误码，`core` / `security` / `ui.model` 三处）**：`KdbxError` 新增
  `DRIFT_SAVE_ABORTED = "kdbx.drift.save_aborted"`；`VaultFileDriftGuard.driftedFailure` 为该失败**标注此码**
  （文案仍走 `userText`）；`KdbxErrorTexts` 映射到既有 `ext_mod_save_aborted` 资源。**不再靠文案比对**识别漂移
  ——上层据 `code` 分型，可断言、不随翻译漂移。

- **改动三（`SettingsPreferencesController.kt` 485 → 498 行）**：新增 `databaseWriteState` 字段、对外
  `databaseConfigWriteState` 与 `clearDatabaseConfigWriteFeedback()`，并把四个 setter 的
  `scope.launch { commitDatabaseMeta { … } }` 收口为**单一私有助手** `commitLibraryConfig(transform)`
  （`scope.launch { databaseWriteState.trackSave { vaultRepository.commitDatabaseMeta(transform) } }`）——
  四个 setter 各减 4 行（新增的状态字段 / 对外通道 / 私有助手另计，全文件合计 485 → 498）；
  `setArgon2Parameters` 两个非法分支改走 `rejectInvalidKdfParameters()`。
  **回显仍只由 `databaseSession.databaseFlow` 头映射通道下发**（单一真相源）：失败不落盘 ⇒ 不重发 ⇒ 回显保持
  磁盘真值（不做假应用），用户重开对话框即为重试入口。

- **改动四（`SettingsDatabaseMetaController.kt` 111 → 117 行）**：新增构造参数 `writeState`（与算法 / KDF /
  Argon2 / 回收站**共用**同一写盘状态）并改经 `trackSave` 提交 `commitDatabaseMeta`——`Failure` 不再被吞。

- **改动五（`SettingsViewModel` / 导航 / 设置页接线 + 退出语义）**：`SettingsViewModel` 将**原死代码**
  `databaseMetaFeedback` / `clearDatabaseMetaFeedback`（全仓无消费方）替换为 `internal databaseConfigWrite` /
  `clearDatabaseConfigWriteFeedback()`（`SettingsIssueWiring` 同步删除该死通道，62 → 55 行）；`settingsDatabaseRoute`
  收集该状态流并传入 `DatabaseSettingsScreen`；该页把一次性反馈经 `AppSnackbarChannel` 转发（**与换密反馈同口径**：
  外壳唯一宿主呈现、切页不丢），并在 `isSavingDatabaseConfig` 时渲染 `DatabaseSavingRow`（进度行）。新增
  `DatabaseSettingsScreenSavingPreview`（新增可见性开关同批补态预览，满足 `ISSUE-P3-340`）。
  **退出语义**：写盘关键提交段不可取消——用户退出设置页（`viewModelScope` 随导航销毁）不会把整库重序列化 /

  随页销毁的状态流上（无观察者）⇒ **不产生可见的迟到 UI 更新**（同批成例锁定，见测试）。

- **改动六（文案 zh + en 成对）**：`values/strings.xml` 与 `values-en/strings.xml` 同批新增
  `dbset_save_in_progress` / `dbset_save_applied` / `dbset_kdf_params_rejected` 三条；**写失败文案不新增英文残片**

- **测试（新增 1 个用例类 / 12 例；`--max-workers=1` 定向 + 回读 XML）**：
  `com.keepasskey.app.ui.screens.settings.SettingsDatabaseWriteFeedbackTest`（XML 实测
  `tests=12 skipped=0 failures=0 errors=0`），以**真实 `DatabaseSession`** + 只改 `commitDatabaseMeta` 返回值的
  仓库替身驱动：
  - **每类库设置各一条普通 `Failure` 注入**（加密算法 / KDF / Argon2 / 回收站 / 库 Meta）：断言失败回执为
    错误样式且按码映射（`err_save_failed` / `err_save_read_only` / `err_save_no_writer`）、**已应用回显不变**、
    **磁盘字节逐字节原样**、状态不停留 `DIRTY`（KDF 例并断言会话头参数不变）；
  - **漂移失败不叠加一次性反馈**：注入 `DRIFT_SAVE_ABORTED`，等「提交已发生且 busy 释放」后再断言 `feedback == null`

  - **参数无效**：256 MiB × 50 轮（> `2^33` 联合预算）拒收并回执 `dbset_kdf_params_rejected`，会话头 / 磁盘 / 状态全不变；

  - **并发交错**：先失败（回执失败且不落盘）→ 放开替身再提交新算法 → 磁盘落定第二次的新值（旧失败**不**回滚覆盖新编辑）；

    （会话树落定新值 + 如实回执成功 + busy 释放），即「不取消已进入关键提交的事务」。

## 4. 限制与后续边界

- **未做真机 / SAF 通道实测**：本批以本地 `File` 通道 + 真实 `DatabaseSession` 覆盖「失败不落盘 / 不回显 / 不回滚」
  与成功落盘重开；SAF（`content://`）通道与真机写回按既有 `VaultFileDriftMetadataTest` 的限界声明另行走查
  （宿主无 Robolectric，不模拟 `ContentResolver`）。方案 §5 要求的「AVD 验证真实写错提示」未在本批执行。
- **「换库」交错未成例**：并发用例覆盖「先失败后成功」的交错（旧事务不回滚覆盖新编辑），但**切换活动库**
  期间的交错（会话被替换）未构造——`DatabaseSession` 的换库语义由既有生命周期用例覆盖，本批不新增。
- **成功后的「同步失效」未新增动作**：本批写盘经统一边界 `persist()`，成功即刷新**文件漂移基线**（既有）；
  这些改动不改凭据（与换密不同），故**不**调用 `markLocalVaultRecrypted` 一类封印失效。同步侧对本地内容变化的
  采纳由既有内容变化检测 / `ISSUE-P1-591` 承担，本批不越界改动。
- **失败后对话框不保留输入**：算法 / KDF / Argon2 对话框仍在「应用」时关闭；失败后用户重开对话框再应用即为重试
  （「可保留用户输入供重试」之实现口径）。**待应用输入值**与**已应用文件配置**已分离（回显单一真相源为
  `databaseSession.databaseFlow`），但未做「失败时对话框驻留并回填上次输入」的增强。
- **参数无效反馈为兜底**：Argon2 非法组合在 UI 侧已被对话框禁用「应用」，`rejectInvalidKdfParameters()`
  只对绕过 UI 的程序化调用生效；其文案不含具体边界原因（原因文本仍由对话框 `Argon2AcceptanceReasonText`
  以判据同源文案呈现，属 §514 既有面）。
- **关键提交段不可取消的取舍**：进入写盘后即不可取消（`withContext(NonCancellable)`），保证整库重序列化 /
  KDF 重派生不被页面退出截断；**代价**是该写入若长时间阻塞（异常慢的提供方），其协程须等它返回才结束，
  **未加超时熔断**（本批不引入，避免正常慢写被误杀）。
- **未做官方实现（KeePass / KeePassXC）对拍**：本批不改 KDBX 格式、头部字段与写出字节布局（仅新增失败反馈与
  写盘收口），互操作面零变化，故未新增对拍。
- **未触达原生绑定 / JNI / Rust**：改动仅 `core` 错误码常量、`app` 层仓库边界 / 设置控制器 / UI 与文案，不触发四层
  设备测试与原生验证义务；`*/src/androidTest/**` 零新增、零修改（设备侧源集编译门禁仍已通过）。
- **行数分档**：新增 `SettingsDatabaseWriteState.kt`（119 行）；`SettingsPreferencesController.kt` 485 → 498
  （仍 < 500）；`SettingsViewModel.kt` 维持 500（以死代码等量替换，零净增）；`SettingsIssueWiring.kt` 62 → 55；
