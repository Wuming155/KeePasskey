# §282 文档地图分册登记补齐与索引重登机检批次

> 本批次由 2026-09-23 全仓工程卫生梳理触发（**非** `ACTIVE_ISSUES.md` 既有条目整改），
> 收口「`docs/README.md` 分册登记仍只链 `BATCH_01_30.md`『等 5 册』」——其余 4 册文件名未登记。
> 施工中顺带揭出并收口：分册索引 **2 条重复 `§280`**，且 `check_resolved_index_sync.py`
> 旧判据用 `setdefault` 静默吞重登、**不校验** `RESOLVED_LOG` 漏登——两条真实缺口一并机检化。
> 本批**零测试增减**、**零生产代码改动**。

## §1 背景

`docs/README.md` 是文档地图的唯一登记表（`AGENTS.md` §4 索引纪律）。其 `resolved/` 分区
原先行写成「`resolved/BATCH_01_30.md` 等 **5 册**」（只链分册 01）：册 02~05 的**文件名**
无法从该表跳达或检索，与「新增文档必须归入分区并登记该表」的精神不一致
（`RESOLVED_LOG.md` 文首与 `resolved/README.md` 分册表早已五册齐列，唯地图缺登）。

同一轮核对 `BATCH_158_PLUS.md` 末尾发现 **3 条 `| §280 |`**（行 142/144/145，正文内容相同）。
而 `check_resolved_index_sync.py` 报 `OK`——因其 `registered.setdefault(...)` 对重复编号
**只保留首次**，「双向一致」三条判据（漏登 / 陈旧行 / README 口径）都挡不住**重登**。
`RESOLVED_LOG.md` 是否漏登亦不在判据内（§270 曾实际漏登 §269 的全量索引行，分册却已有）。

## §2 整改内容

### 2.1 `docs/README.md` 分册登记拆为五册逐行

| 原 | 现 |
|---|---|
| 一行：`BATCH_01_30.md` 等 **5 册** | **五行**：`BATCH_01_30` / `BATCH_31_45` / `BATCH_46_57` / `BATCH_58_PLUS` / `BATCH_158_PLUS`，各注覆盖范围与封卷/滚动状态 |

与 `RESOLVED_LOG.md` 文首五册链、`resolved/README.md` 分册表三方对齐；`check_md_links.py` 覆盖新链可达性。

### 2.2 `check_resolved_index_sync.py` 判据 3 → **5**

| # | 判据 | 状态 |
|---|---|---|
| 1 | 批次正文 → 分册（防漏登） | 原有 |
| 2 | 分册 → 批次正文（防陈旧行） | 原有 |
| 3 | `resolved/README.md` 最大编号口径 | 原有 |
| 4 | **分册登记不得重登**（同一 `§N` 在全部 `BATCH_*.md` 至多一行） | **新增** |
| 5 | **批次正文 → `RESOLVED_LOG` 且该表不得重登** | **新增** |

实现：`scan_index_rows` 保留 `编号 → [文件:行号, …]` 全量位置；重登即列出全部命中处。
`index_numbers()` 不再 `setdefault` 吞行。OK 读数增加「全量索引 N 条」。

### 2.3 去重现存缺陷

删除 `BATCH_158_PLUS.md` 行 144、145 两条重复 `§280`（保留行 142 首次登记）。
`RESOLVED_LOG.md` 的 `§280` 仅 1 条，无需处置。

### 2.4 索引描述同步

`AGENTS.md` §5 与 `resolved/README.md` 机检说明改为五判据口径（漏登 / 陈旧 / 口径 / **重登** / **全量索引**）。
