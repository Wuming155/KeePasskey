# §370 同步凭据全零串拒封与导入器入口快照批次（`ISSUE-P2-403` 整条闭环）

- **触发**：2026-09-30 用户定位 §369 遗留失败的真机观察：「登录上去之后，同步设置里面的密码全是 0，
  也因此导致了鉴权失败。但是明明登录之前是输入的正确的密码，并且也成功的登录」——即云端打开
  （下载成功 = 所填 WebDAV 密码正确）之后，存储里的密码变成了**整串 '0'**。
- **开放项变动**：P2 区 0 → **1** → **0**（本批闭环）。

## 0. 原文收录（登记即闭环，同会话完成）

> **ISSUE-P2-403**（核实时间点 2026-09-30；核实方式 = 用户真机观察 + 设备存储取证
> （`run-as` 读 `sync_credentials_prefs.xml`：密文解码 32 字节 = 16 字符内容 + 16 字节 GCM tag，
> 与「等长 '0' 串」及用户所见整串 0 一致）+ 全量写入方审计）：
> **同步凭据封印入口不校验全零串**——借用语义的 `fill('0')` 擦除指纹一旦在封印前落到待存数组
> （下载窗口期竞态 / 任何未知的调用侧时序），会被原样封进存储，静默顶掉可用凭据，
> 后续同步 401、设置页预填整串 0。整改＝封印入口 fail-closed（非空全 '0' 拒绝封印）
> + 导入器入口快照（关闭下载窗口期竞态）+ 行为级复现器测试。

## 1. 排查过程（证据链）

1. **存储取证**：`webdav_password_cipher` 解码 32 字节 ⇒ 封印内容 16 字符——与用户所见
   整串 0 的长度一致；`webdav_url` / `remote_path` / `sync_provider=WEBDAV` 均为导入器写入的
   期望值 ⇒ 写入方就是云端打开导入链路。
2. **全量写入方审计**：`saveWebDavConfig` 仅两个调用方（导入器 / 设置页保存）；两条链路的
   复制（对话框确认 `copyOf()` → 提交载荷 → 导入器）与擦除（`wipeCredentials` 在 finally、
   store 封印后自擦）逐行核对，静态时序封闭；既有单测往返（`CloudVaultImporterTest`）**恰好
   未断言密码本身**的往返——本轮补上后 JVM 路径全绿 ⇒ 擦零发生在**单测覆盖不到的设备侧时序**
   （主线程重组 / 离场收口与秒级下载并发的窗口）。
3. **结论**：与其继续追杀不可静态证明的竞态触发点，不如让封印入口对「擦零指纹」**fail-closed**，
   并把导入器改为**入口快照**——无论擦除从哪里来、何时来，都不可能再被封进存储。

## 2. 整改

- **全零串拒封（fail-closed）**：`SyncCredentialsStore.saveWebDavConfig` / `saveS3Config`
  在封印前校验——非空但全 '0' 的凭据（借用语义擦除指纹；空串不算，空 = 保留既有语义）
  一律 `debugLog.warn` + 返回 false，**绝不**把垃圾密文落盘顶掉既有可用凭据；
- **导入器入口快照**：`RealCloudVaultImporter.import` 入口即对请求侧凭据 `copyOf()` 快照，
  Provider 构造 / 下载 / 提交封印全部改用快照，快照随函数 finally 统一擦除——下载是秒级
  网络操作，窗口期内任何外部路径对请求侧数组的擦除都不再影响封印内容；
- 恢复 §369 归档脚本误删的 `ACTIVE_ISSUES.md` P2 区注释行（同批留痕）。

## 3. 验收

- AC① 全零串拒封：WebDAV 密码全零 → 保存 false 且存储零写入；S3 AK/SK 全零 → 同

- AC② 行为级复现器：下载期间请求侧凭据被外部擦成 '0' → 导入仍成功且存储往返为**原密码**

- AC③ 密码往返断言补齐（WebDAV 密码 / S3 AK/SK 原样往返，此前仅断言非敏感字段）；
