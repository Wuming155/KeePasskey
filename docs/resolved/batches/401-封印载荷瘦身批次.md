# 批次 401：封印载荷瘦身（密钥文件不进 Keystore 载荷）批次（ISSUE-P1-431 整条闭环）

> 日期：2026-10-02。P1 0→1→**0**。
> 起因：用户真机走查 §400 装机反馈「没有卡死，但转圈转了半天（密码 + 选密钥文件解锁后弹生物识别验证，最终进去了但耗时过长）」，密钥文件 ~700 KB。

## 1. 调研与方案裁决（用户 2026-10-02 指示「先调研参考项目再动手」，二选一拍板方案一）

### 1.1 参考调研结论（docs/references/ 优先，参考项目源码定点查证）

| 项目 | Keystore 载荷 | 密钥文件因子恢复 |
|---|---|---|
| 🥇 KeePassDX | 只封主密码（几十字节）；封印密钥文件是 TODO（`MainCredentialActivity.kt:452-455`） | 开库时从原 URI 重读（`LoadDatabaseRunnable.kt:56`） |
| 🥈 keepass2android | 只封主密码字符串（`FingerprintSetupActivity.cs:179-185`） | 解锁时从磁盘重读再组合（`PasswordActivity.cs:981-989`） |
| ⚖️ Monica | 只封 32B 数据密钥（`SecurityManager.kt:902-917`） | 不进快速解锁体系 |

**无一家把密钥文件字节放进 Keystore 载荷**——本仓 ISSUE-P2-23 的复合封印（主密码 + 整个 keyfile，上限 1 MiB）属三家皆无的极端做法；StrongBox 分块处理 700 KB 载荷实测数十秒（ANR 期单次 binder `update` 5.28s）。

### 1.2 裁决

**方案一（KeePassDX/kp2a 口径）**：封印载荷只装主密码；指纹解封后经「记住的密钥文件位置」（ISSUE-P3-04 基建）重读组合；重读失败清陈旧封印回落密码模式。不采用双层 DEK 封装（协议改动大，用户裁决不做）。

## 2. 整改内容

1. **封印侧卸载密钥文件**：`BiometricEnrollmentCoordinator`（登记）与 `BiometricResealCoordinator`（改密/仅改绑重封印）的载荷改为 `BiometricSealedPayloadCodec.encode(passwordChars, null)`；`keyFileBytes` / `sessionKeyFileBytes` 提供者参数及 `SettingsBiometricGate` → `SettingsViewModel` 的接线（`exportKeyFileBytes` 通道）退役。
2. **解封侧重读链**（`BiometricUnlockCoordinator.completeBiometricUnlock`）：密钥文件因子解析链 = ① 存量复合载荷自带（P2-23 兼容）→ ② 会话驻留字节（冷启动记忆恢复）→ ③ 经 `restoreRememberedKeyFile` 现读一次（ISSUE-P3-04 SAF 通道，`KeyFileSessionCoordinator.restoreRememberedKeyFile`）→ ④ 仍没有则以仅主密码尝试（密码-only 库正常）；需要密钥文件的库落入既有 Failure 分支——清陈旧封印回落主密码模式。
3. **存量迁移**：复合封印（大载荷）解锁成功后**清除封印**，下次主密码解锁以仅主密码小载荷重新登记（一次性过渡，杜绝存量永远慢）。
4. 编解码器 `BiometricSealedPayloadCodec` 帧格式零改动（v1 帧 + 不带魔数回落语义原样，天然承载新口径）。

## 4. 如实声明

- 「记住密钥文件位置」成为指纹解锁的**可用性前提**：文件被移动/删除或 SAF 持久授权失效时，指纹解锁回落密码模式（既有恢复通道），与 KeePassDX 行为一致；用户侧表现为一次密码解锁后自动重新登记。
- 存量复合封印在迁移前仍会经历一次慢速解封（大载荷解密），迁移后恢复秒级。
- 快速解锁偏好关闭（无封印凭据）的用户完全不受本批影响。
