### 1.1 各条 AC 落地要点

#### P2-381（WebDAV MOVE 409/423 兜底）

- `WebDavMoveOverwritePolicy`：409/423 判定、文案与 ProtocolError 构造收敛为纯策略（可 JVM 断言）。
- `WebDavSyncProvider.uploadAtomic`：MOVE 收 409/423 → DELETE 目标（404 容忍）→ **无预条件** + `Overwrite:T` 单次重试；
  412 仍走 ConflictError（文案区分）；最终失败文案含 HTTP 状态码。
- mock：`StatefulDavDispatcher.failMoveOnExistingTarget409` 模拟「覆盖已有目标恒 409」服务器。
- **AC③（与 P2-382 同一真实服务器覆盖写链路验证）**：本批仍无真实 DAV 环境，**未执行**；登记为遗留验证项（不伪造完成）。

#### P2-384（认证回传复检字段屏蔽）

- 新增 `AutofillAuthDeliveryBlockPolicy.filter`：复用 `AutofillFieldBlockPolicy.decide`，只收紧不放宽；fail-closed。
- 选择器 `deliver` 与确认页 `resolveAuthResultIntent` 均在构造 Dataset **之前**调用；全屏蔽 + 无结构化目标 → 按取消回传。
- AC②：`TargetFields.blockedIds` 投影到 `FillResponse.Builder.setIgnoredIds`（Monica `c854ef2a` 同型）。
  **setClientState 评估结论**：本仓填充服务无「按 FillResponse 会话跟踪 clientState 并主动失效」的既有管道，
  引入会扩大状态面且 AC② 已由 setIgnoredIds 覆盖主路径，**本批不实施** setClientState。
- 确认页 Dataset 构造收口 `AutofillConfirmAuthDelivery`（规模闸门拆分，内部仍委托 `buildAuthenticationResultDataset`）。

#### P2-386（同名附件编辑保存折叠）

- `AttachmentMergePolicy.merge`：UI 附件 `data==null` 时按 `UiAttachment.refIndex` 身份匹配既有
  `attachments` 列表下标（ISSUE-P3-295 同口径）；refIndex 缺失/越界时回退名称匹配**尚未被消费**的既有项。
- 用例：既有条目含两份同名附件（不同字节），UI 以 refIndex=0/1 投影后保存，断言仍为两份且字节不丢。
- 口径：UI 列表即期望最终态——UI 未列出的既有附件视为用户有意删除，**不**保留余份（AC① 采 refIndex 主路径）。

#### P3-386（通知「立即锁定」动作）

- `VaultLockActionReceiver`（清单 `exported=false`）→ `AutoLockManager.triggerLock`（与自动锁同收口）。
- `NotificationIntents.lockVaultNow` + 通知 `addAction`；锁定后会话态变化 → 控制器自动 `cancel` 撤销通知。
- 中英文案 `notification_unlocked_lock_now`（立即锁定 / Lock now），零插值。
- 设置页「解锁状态常驻通知」文案同步更新（原文案曾注明「不含 action」，现已含立即锁定）。

#### P3-392（原生 KDF 回落可观测）

- 二选一裁决：**采纳 AC① 的 AppLog 一次性日志**（未接受静默降级）。
- `NativeKdfFallbackLog`：AtomicBoolean 一次性闸门；仅记「探活失败已回落」事实，**不含** KDF 参数 / 主机标识。
- `Argon2KdfEngine`：仅在 `!NativeArgon2.available` 时记日志（版本不支持 / AD 超限 / 参数越界属有意走 JVM，不记）。
- `AesKdfEngine`：`!NativeAesKdf.available` 时记一次。

### ISSUE-P2-381：WebDAV MOVE 覆盖已有目标普遍 409 无兜底——保存永久失败且错误不可区分

- **状态（2026-09-29 登记）**：开放。源自参考项目对照双源（keepass2android 注释标注 + git 提交 `9c8ee243`）。
- **背景与整改依据**：`WebDavSyncProvider.kt:349-389`（快照行号）的 `uploadAtomic` 以
  「PUT 临时名 → MOVE 覆盖」提交，MOVE 仅带 `Overwrite:T` + `If` ETag 预条件且只特判 412；
  409/423 落入 else 分支后第二次尝试同错，最终抛 `ProtocolError(500)`「WebDAV 原子写入 MOVE 失败，
  已清理临时文件」。keepass2android `WebDavStorage.java:235` 注释 + 提交 `9c8ee243`（2025-11-09）实证：
  多台服务器对 MOVE 覆盖已有目标报 409，仅靠 `Overwrite:T` 不可靠；其修复 = 先 DELETE 目标
  （容忍 404）再 MOVE 并对 409 重试。本仓遇该类服务器时保存永久无法收敛且错误文案无法区分该场景。
- **核实时间点 + 核实方式**：2026-09-29 参考项目对照工作流：排查子代理定位后由独立复核子代理
  （上下文隔离）实读 `:349-389` 确认无 409/423 分支（`rg -n "409|423"` 全文件零命中，exit=1 复跑证实）；
  《产品裁决登记》《已知工程限界》无本面取舍。证据见
  [`references/参考项目Git历史对照/02-keepass2android.md`](../../references/参考项目Git历史对照/02-keepass2android.md)。
- **涉及文件**：`sync/src/main/java/com/keepasskey/sync/webdav/WebDavSyncProvider.kt`。
- **AC**：①MOVE 收到 409/423 时先 DELETE 目标（404 容忍，`:408` 已有同语义）再单次重试并留日志；
  ②409/423 与 412 分开报错文案；③不采纳兜底则按规则 6.1 在《已知工程限界》登记
  「MOVE 覆盖遇 409 服务器不可用」并写明触发面。

### ISSUE-P2-386：同名附件经编辑保存被折叠——mergeAttachments 按名称匹配丢数据
