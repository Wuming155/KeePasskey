## 4. 踩到并修掉的三个坑（留给后续搬家）

1. **剪枝脚本的 fall-through**：`for l in lines: if l.startswith("import ") and 保留: out.append(l)`
   后面又有一句**无条件** `out.append(l)` ⇒ 所有保留下来的 import 被写成两份
   （两份文件各重复 25 行）。已用「连续重复 import 折叠」修回，并在修好后重跑编译器与套件确认；
   教训：**脚本里 `if/else` 分支处理过的元素，末尾不得再无条件追加**，写完脚本先跑一次并看产物。
2. **只去注释的长函数度量会失真**：第一版计数脚本照搬「括号配平 + 去注释」，
   结果 `placeholder = { Text("content://... 或 /path/to/vault.kdbx") }` 里的 `//...` 被当行注释吃掉，
   连带删掉该行的引号与右括号 ⇒ 配平永久失配，函数「测不到」（同一脚本把 226 行的本体漏报为 0）。
   修正为**先去字符串字面量、再去注释**（即 `AlgoHotPathGuardsTest.stripStringsAndComments` 的口径），
   修正后 BEFORE 值与 §175 表内 226 逐字吻合 ⇒ **度量脚本本身要用已知值反校**。
3. **编辑锚点覆盖不全把函数签名截断**：想在 `OpenVaultSourceChips` 前插入内容，却把
   `old_string` 取成「注释 + 签名 + 形参 + `) {`」而 `new_string` 只写了「注释 + 签名 + `(`」⇒
   形参与 `) {` 一起被吃掉，文件当场不可编译。修法与既有教训一致：**整块新增一律锚在文件尾**，
   或让 `old_string` / `new_string` **覆盖被触碰行的完整边界**。
