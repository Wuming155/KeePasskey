## §2 整改与验证纪实

### 2.1 AC 逐条落点

**AC① 搜索空态（双出口 + 一次性预填）**

- `vault_empty_title` 值「暂无内容」→「**无搜索结果**」（`values/` 与 `values-en/` 同步，
  en 由 "Empty Directory" → "No search results"）。原值唯一消费点即 `VaultEmptyState` 搜索分支，
  改值不留死键、不动非搜索态（仍显 `vault_empty_desc`）。
- `VaultEmptyState` 搜索态加双出口：`Button(R.string.vault_new_entry)`（新建凭据条目，复用既有键）
  + `OutlinedButton(R.string.vault_search_clear)`（新增「清除搜索」）；
  `onCreateEntryFromSearch == null`（只读会话 / 回收站内，由 `VaultListScreen` 按
  `isReadOnly || isInsideRecycleBin` 传 null）时不呈现新建出口，清除搜索恒在。
- 预填链路（**不走路由参数**——搜索词可能被粘贴任何内容含口令形态文本，nav route 会落
  `SavedStateHandle` 持久化，属 P2-105 同源红线的延伸）：
  `CreateEntryPrefillHost`（`@Singleton` 内存一次性，`publish`/`takeTitle`）→
  列表页出口先 `viewModel.beginCreateEntryFromSearch()` 发布当前搜索词、再导航 →
  `EntryEditViewModel` init `takeTitle()`：**新建形态**套用（`title`；搜索词含 `://` 时同步落
  `url`，与 `PasswordDraftActivity` 的 URL 预填同向）；**编辑 / 模板形态只取不用**
  （取与用分离 ⇒ 陈旧预填既不串进下一次无关新建、也不覆盖既有条目标题——由
  `EntryEditSearchPrefillTest` 4 例锁定）。
- `@Preview` 覆盖：`VaultListSearchEmptyPreview`（双出口态）与
  `VaultListSearchEmptyReadOnlyPreview`（null 出口态），浅 / 深各一。
  包装重生成 `generate_screenshot_test_wrappers.py`：`locale=zh-CN promoted=90 wrappers=90`，
  其中 `PasswordDraftScreen` 三个 preview `private→internal` 属生成器既有约定，随批入库；
  `:app:compileDebugScreenshotTestKotlin --rerun` 绿。
- 普查读数 `23 / 3 / 8` 与 §346 基线**逐项持平** ⇒ AC「不新增漏态」成立
  （新增参数为可空 lambda 而非字面量 Boolean 开关，不在普查口径内）。

**AC② 域名感知匹配（加性，红线零触碰）**

- `VaultSearchMatching.domainTierMatches`：子串未命中时的**加性 OR 层**——
  复用 `DomainMatcher.extractDomain` / `isDomainMatch` 做**双向父子域**判定
  （查询为条目父域、或条目为查询父域）+ `www.` 前缀剥离（Kp2a `SearchForHost` 同型）。
- **红线核验**：`git diff -- app/src/main/java/com/keepasskey/app/passkey/` 对
  `DomainMatcher.kt` **零 diff**（唯一 diff 是 §2.2④ 的 preview 可见性）——本档**只复用不改动**，
  凭据供给 / 签名侧判定链路原样；全量 test 中 `CredentialProviderLookalikeMatchTest` 等域判定
  用例全绿（AC「既有域判定测试全绿为证」）。
- 三重守卫（成本与误报面）：查询含空白或**不含 `.`** ⇒ 短路不求值（普通词语零 PSL 开销）；
  `android://` 形态的查询与条目两侧跳过 host 维度（Kp2a 对 `androidapp://` 同样跳过；
  包名维度仍归子串档与 autofill 的 `isAndroidPackageMatch`）；`isDomainMatch` 自带**严格点号边界**
  与**可注册域名下限**（单标签 `com` / 公共后缀、`evilexample.com` 粘连一律拒）。
- 新增 `VaultSearchDomainTierTest` **13 例**，负向全部配同源正向：父域查询命中子域条目 /
  子域查询命中父域条目（配「URL 子串不含该查询」反证，证明命中只能来自域名档）/ `www` 两侧 /
  带协议查询 / `passkeyRpId` 参与判定；异 eTLD+1（example.org vs example.com）/
  粘连（evilexample.com）/ 单标签（com、org）/ 含空白语句 / `android://` 双侧 负向；
  ALL_TERMS 逐词走域名档；子串档既有口径回归（大小写不敏感、无命中仍假）。

**AC③ 剪贴板清空可见反馈**

- `ClipboardSecurityManager.scheduleClear` 到期且 `performClearIfMatching(...) == true`
  （**实际清掉**才提示）→ Toast `R.string.clipboard_auto_cleared`「剪贴板已自动清空」/
  "Clipboard cleared automatically"，文案口径参照 Kp2a "Clipboard cleared."。
- **通道选型偏离说明（AC 草案提及 Snackbar / 通知通道）**：十个 Screen 各持 `SnackbarHost`、
  仓内**无全局宿主**，清空时刻可能落在任意界面 ⇒ 选 Toast——与 Kp2a 同型（其
  `ClearClipboardTask` 即 toast）、零接线成本；`scope` 恒 `Dispatchers.Main` 满足线程要求。
- **刻意不提示**的路径：熄屏 / 切后台 / 锁库 / 冷启动对账（用户不在场；且 Android 12+ 对
  后台应用文本 Toast 有系统抑制，正好合「不在场不打扰」）。
- 不误报边界：覆盖写或无残留时 `performClearIfMatching` 返回 false ⇒ 不提示；
  用户关闭自动擦除 ⇒ `ClipboardClearPolicy.resolveScheduledTimeoutSeconds` 返回 null 不调度
  ⇒ 永不提示（`ClipboardSecurityManagerScheduledClearTest` 8 例全绿）。
- 复制时既有倒计时三态文案（`EntryDetailStateAssembler`）**零改动**（AC「不回退」）。
