## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-436：设置页导入导出卡缺「导入密钥文件」对称入口（导出有、导入无）

- **核实时间点**：2026-10-02；**核实方式**：用户走查设置页「数据导入与导出」卡（`DatabaseImportExportCard` 仅三行：导入密码库 / 导出密码库 / 导出密钥文件），指出缺「导入密钥文件」。
- **背景**：密钥文件改绑能力 §399/§430 已进**改主密钥对话框**（三态 KEEP/USE/REMOVE），但入口埋深；导入导出卡「导出密钥文件」与「导入密钥文件」不对称，用户找不到为当前库换绑第二因子的直达入口。
- **整改方向**：导入导出卡新增第四行「导入密钥文件」——SAF 选取外部密钥文件（读取强制走全仓唯一通道 `KeyFileAccess`）→ **显式确认弹窗**（改绑＝全库 Argon2 重派生并保存，旧密钥文件此后无法独立开库）→ 经 `SettingsMasterKeyChangeController.submit(空密码, Use(...))` 走既有仅改绑分支 `changeKeyFileOnly`（含忙守卫、字节 `finally` 清零、§434 记忆位置同步、§430 会话快照重封印）；行数闸门要求渲染面下沉新文件（`DatabaseSettingsScreen.kt` 现处 tier2 以下）。
- **验收标准**：卡内四行对称；未读到文件禁提交（fail-closed）；取消路径字节就地擦除；busy 期间入口禁用；单测覆盖待选密钥文件持有态的擦除/移交语义；全量 test 绿 + 门禁全 PASS；zh/en 文案成对。

## 2. 整改内容

1. **新文件 `DatabaseImportExportCard.kt`**（subscreens 包）：`DatabaseImportExportCard` 自 `DatabaseSettingsComponents.kt` **整卡迁出**（三行导出装配逐字未改；迁出缘由＝本文件行数闸门余量），并承载第四行「导入密钥文件」的完整闭环：
   - **SAF 选取 → 读取**：`OpenDocument` 选取后经宿主透传的 `onReadKeyFile` 读取——生产即全仓唯一通道 `KeyFileAccess`（读取上限 / 流关闭 / 缓冲擦除 / 持久化授权全部由该通道承担，§405 后无上限）；`Empty` / `Unreadable` 显式弹窗反馈（复用 `unlock_keyfile_read_failed` 文案），绝不静默当成功（fail-closed，P3-04 口径）；**未读到文件不渲染确认弹窗（禁提交）**；
   - **显式二次确认弹窗**：列出所选文件名 + 改绑后果（重派生并保存 / 旧密钥文件此后不再能开库 / 先验证再处置旧文件）；确认才构建 `ChangeKeyFileIntent.Use`；
   - **提交**：`onKeyFileImport(intent)` → 路由层调 `SettingsMasterKeyChangeController.submit(CharArray(0), intent, hostActivity)`——空密码即走既有仅改绑分支 `changeKeyFileOnly`（§430），忙守卫、字节 `finally` 清零（§399 口径）、记忆位置同步（§434）、会话快照重封印（§430）全部既有零改动；
   - **敏感数据铁律**：待确认字节仅以 `ByteArray` 驻留 `PendingKeyFileImport`（不进任何 String / UiState / StateFlow）；确认＝所有权随意图移交（借用语义，`assertSame` 锁定无副本），取消 / 换选＝就地清零，卡片离开组合＝`DisposableEffect.onDispose` 兜底清零；
   - **忙禁用**：改绑任务进行中（`keyFileImportBusy`）导入行禁用（`DatabaseActionRow` 新增可选 `enabled` 形参，禁用降透明度且不可点击）；控制器忙守卫同步兜底（并发提交被拒并入参当场清零）。
2. **`PendingKeyFileImport`**（同文件 internal 类）：`toIntent()`（产出 `Use` 意图、携带来源 Uri + 显示名——非密钥元数据，§434 记忆同步用）+ `erase()`（就地清零）。
3. **`DatabaseSettingsScreen.kt`**：新增五个透传形参（`onReadKeyFile` / `onKeyFileImport` / `keyFileImportBusy` / `keyFileImportFeedback` / `onClearKeyFileImportFeedback`，全部带默认值——既有调用点零改动）；卡调用点扩传；导入反馈以 `DatabaseFeedbackItem` 呈现在卡内（复用改主密钥任务回执 `masterKeyChangeFeedback`，点击清除）。
4. **`KeePasskeySettingsNavGraphRoutes.kt`**（`settingsDatabaseRoute`）：接线五参——`onReadKeyFile = settingsViewModel.keyFileReader`（全仓唯一 SAF 通道）、`onKeyFileImport` 调 `masterKeyChangeController.submit(CharArray(0), intent, hostActivity)`（宿主经 `LocalActivity` 直取，与 `SettingsScreen` 同口径）、busy 与反馈读自既有 `SettingsUiState`（`isChangingMasterKey` / `masterKeyChangeFeedback`），**主密钥变更与导入共用同一忙态**（同一临界写）。
5. **文案**（zh/en 成对 5 条）：`dbset_keyfile_import_title` / `_sub` / `_warn_title` / `_warn_message` / `_confirm`。
6. **测试**：新增 `PendingKeyFileImportTest` 3 例（`toIntent` 产出 `Use` 并携带 Uri / 显示名；**按原引用借用字节不产生副本**；`erase` 就地清零且借用中的意图字节同样归零）。
7. **主密钥对话框路径零变化**：`MasterKeyChangeDialog` 三态入口（§399/§433）原样保留，与本卡互为深浅两个入口、共用同一提交管线与忙态。
