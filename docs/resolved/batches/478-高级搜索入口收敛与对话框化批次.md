## 1. 排查过程（取证链）

### 1.1 为何先怀疑「接线断裂」又被证伪

`VaultListSearchTopBar` 的图标钮 `onClick = onToggleAdvanced` → `VaultListScreen` 的
`showSearchAdvanced = !showSearchAdvanced` → `VaultListContent` 的展开态传入，**链路完整**；
离线渲染证据（`@Preview` 导出图 `preview-exports/secondary/light/VaultListSearchTopBarPreview…png`）
显示图标布局正常（搜索胶囊右边缘约在 74% 宽处，未压住操作区），`@Preview` 的展开态图
（`VaultListContentSearchAdvancedPreview…png`，§462 补）也证明「给了 true 就画得出面板」。

### 1.2 真机实测（决定性取证）

环境：AVD `kp-256`（`-no-window -gpu guest`，用户 0 `RUNNING_UNLOCKED`；`Pixel_10` 与 `kp-192`
两盘位在「用户未解锁（`RUNNING_LOCKED`）」下 `am start` 恒 `START_CLASS_NOT_FOUND`，与
`tools/device/check_connected_device_results.py` 文首记录的历史现象一致，故改用 `kp-256`）。
取证手段：`uiautomator dump`（应用窗口带 FLAG_SECURE，`screencap` 全黑 ⇒ 层次树是唯一可用读口）。

| 步 | 操作 | 读数 |
| :-- | :-- | :-- |
| 1 | 空库 + 列表在顶部，点「Advanced search」图标 | 面板**出现**（`Advanced search` / `Title` / `URL` / `Exclude expired entries` / `Case sensitive` 均在层次树内） |
| 2 | 再点一次图标 | 面板**消失**（单向可逆 ⇒ 状态机本身正常） |
| 3 | 建 8 个分组 → 列表可滚动 → 向下滚 3 屏 → 点图标 | **视口内文本零变化**（`Fld04…Fld08 / Vault / OTP / Generator / Settings`，与点击前逐字相同） |
| 4 | 不再点击，直接滚回顶部 | 面板**已在展开态**（`Exclude expired entries` 出现） |

⇒ 结论：**点击有效、反馈落在屏外**——「点了没反应」的成因是**展开面的位置**，不是接线。

### 1.3 同族对照

同槽的「排序」「扫码」都是 `AlertDialog`（模态），与列表滚动位置无关；页内 item 形态在
**已滚动**列表上的失效是结构性的（用户不会为了确认「点了有没有用」先滚回顶部）。

## 2. 整改

1. **入口收敛**（AC①）：`VaultListTopBars.kt` 删除独立 `Tune` 图标钮与 `advancedActive` /
   `onToggleAdvanced` 两个形参，改为溢出菜单第 2 项「高级搜索」(`search_advanced_title`) →

   原页内面板 `VaultSearchAdvancedPanel.kt` **整文件删除**（`git rm`），职责由对话框承接。
3. **语义零变化**（AC③）：对话框只做选择与回传，改动**即时生效**（无「确认 / 取消」的草稿语义，
