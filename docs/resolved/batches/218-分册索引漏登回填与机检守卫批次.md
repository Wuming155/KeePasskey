# §218 批次：分册索引漏登回填与「分册 ↔ 批次正文」机检守卫（文档面批次，无条目变动）

> 日期：2026-09-19　|　条目：无（文档面批次，沿用 §202 先例：零代码改动、无条目变动）
> 关联纪律：`AGENTS.md` §4「索引纪律（`ISSUE-P3-81` 立规）——**不得脱离索引与工作流入口**」；
> `ISSUE-P3-205` 教训「**散文承诺 ≠ 机检**」。

## 1. 发现的缺陷（真实发生，非假设）

`docs/resolved/` 是两层索引：`RESOLVED_LOG.md`（全量索引，逐批追加）与 `BATCH_*.md`（5 册分册级索引，
分册 04 已封卷、05 自 §158 滚动）。2026-09-19 发现：

- `docs/resolved/BATCH_158_PLUS.md`（滚动分册 05）**止于 §202**，而 `docs/resolved/batches/` 下
  已有 **§203~§215 共 13 份批次正文** ⇒ **这批正文无法从任何分册跳达**；
- `docs/resolved/README.md` 的维护规则第 2 条仍写「当前最大为 **§202**，下一批次从 **§203** 起」
  ⇒ 按该口径派号将**直接重号**（§203 已被占用）。

**为何此前无任何机检发现**：`python tools/doc/check_md_links.py` 只校验**已登记链接是否可达**，
**不校验是否漏登**——同 `ISSUE-P3-205`（豁免 regex 宽度只有散文承诺、无守卫测试）是同一类盲区。

## 2. 本批做了什么

1. **回填**：把 `RESOLVED_LOG.md` 中 §203~§215 的**权威摘要行原样搬运**（仅做链接路径变换
   `](resolved/batches/` → `](batches/`）插入 `BATCH_158_PLUS.md` 的 §202 行之后。
   **未新写任何摘要文字**——避免以复述代替原文（`RESOLVED_LOG.md` 是单一真相源）。
2. **更正口径**：`docs/resolved/README.md` 的「当前最大编号」由 §202 更正为 **§217**（下一批次 §218），
   并在维护规则第 3 节补一句指向本批新增的机检守卫。
3. **补机检守卫（本批核心产出）**：新增 `tools/doc/check_resolved_index_sync.py`，三条判据：
   - **正向**：`batches/*.md` 的文件名编号必须**全部**出现在某个 `BATCH_*.md` 的 `| §N |` 行
     （否则该批次无法从分册跳达）；
   - **反向**：分册登记的编号必须有对应正文文件或落在**显式豁免表**（当前仅 `§42` / `§43`——
     依 `docs/README.md` 注记已归入 `docs/security/`）；
   - **口径**：`resolved/README.md` 的「当前最大为 **§N**」必须等于批次正文最大编号（防重号）。
4. **接入命令索引**：`AGENTS.md` §5 命令清单新增该脚本（改任何批次 / 分册 / README 后必跑）。

## 4. 边界（如实声明）

- 本守卫**只覆盖「是否漏登」**，不校验分册摘要行的**内容准确性**（那属 `RESOLVED_LOG.md` 与批次正文的职责）；
- 守卫依赖 `resolved/README.md` 的固定措辞「当前最大为 **§N**」；若该措辞被改写，判据 3 会
  退化为「未找到口径」并**报红**（fail-closed，不静默放行）；
- 豁免表 `{§42, §43}` 是**唯一权威定义**（写在脚本 docstring 与常量注释中）；新增豁免必须
  同时在批次文档说明理由（防「豁免表成为新的散文承诺」）。
