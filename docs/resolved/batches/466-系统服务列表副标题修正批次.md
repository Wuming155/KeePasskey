## §1 条目与整改

### ISSUE-P3-527：系统「首选服务」列表里本应用一行的副标题与应用名重复（等于没有说明）

**条目原文（登记入 `ACTIVE_ISSUES.md` 后本批整条剪切归档，文字逐字）**：

> - **核实时间点**：2026-10-07；**核实方式**：用户提供真机截图（Xiaomi `M332BF`，系统页
>   `com.android.settings/.applications.credentials.CredentialsPickerActivity`）——同一列表内 KeePassDX 行显示
>   「KeePassDX / 通行密钥、自动填充凭据提供程序」两行，本应用行两行均为「KeePasskey」；随后
>   `grep -rn settingsSubtitle app/src docs` 现查定位到唯一来源。
> - **背景**：该页是用户选择「首选服务（凭据提供者 / 自动填充）」的入口（本应用设置页的
>   `SystemSettingsNavigation.credentialProviderIntent` 即跳此页）。每行两段：**标题＝服务名**、
>   **副标题＝`credential-provider` 元数据的 `android:settingsSubtitle`**。本条是**文案缺陷**：
>   `app/src/main/res/xml/credential_provider_service.xml` 的 `settingsSubtitle` 指向 `@string/app_name`，
>   于是副标题与标题逐字相同 —— 位置被占用却没有传递任何信息（用户须靠外部知识才知道这行是干什么的）。
> - **涉及文件**：`app/src/main/res/xml/credential_provider_service.xml`、
>   `app/src/main/res/values/strings.xml`、`app/src/main/res/values-en/strings.xml`；
>   同源注释更正见 `app/src/debug/res/values/strings.xml` 与 `app/build.gradle.kts`（debug 变体说明）。
> - **验收标准**：① 该列表中本应用行的副标题显示**说明性文案**（不再是应用名），且中文 / 英文各一份；
>   ② 不影响 debug / release 两版在该列表中的可分辨性；③ 全量 `test` 全绿 **且**
>   `python tools/doc/gate_readings.py` 全 PASS，读数块原样入本档。

**机制核实（开工前，2026-10-07，两条独立证据）**：

1. **框架侧**（AOSP `core/java/android/credentials/CredentialProviderInfo.java`）：`getLabel()` 走
   `mServiceInfo.loadSafeLabel(context.getPackageManager())`（服务 `android:label`，未声明则回落应用名），
   `getSettingsSubtitle()` 由 Builder 注入 —— 即副标题只来自 `credential-provider` 元数据。
2. **镜像侧**：`<autofill-service>` 元数据**没有**同名属性（AOSP `AutofillServiceInfo.java` 只解析
   `settingsActivity` / `passwordsActivity` / `supportsInlineSuggestions`）⇒ 副标题**只有这一处可设**，
   改自动填充侧的 XML 不会有效果。
3. **对照项目**：KeePassDX `app/src/main/res/xml/provider.xml:5` 即
   `android:settingsSubtitle="@string/credential_provider_service_subtitle"`（zh-rCN 值＝
   「通行密钥、自动填充凭据提供程序」）—— 与本应用同机制，故其行有说明行。
   （**只读了该 XML 一行 + 对应字符串**，未翻其源码；许可约束见 `AGENTS.md` 规则 3。）

**整改（整改点 4 处，逐处列出）**：

| 文件 | 变更 |
|---|---|
| `app/src/main/res/values/strings.xml` | 新增 `credential_provider_settings_subtitle`＝「通行密钥、自动填充凭据提供程序」（含「只在系统 UI 渲染、应用内不出现」的注释） |
| `app/src/main/res/values-en/strings.xml` | 同键英文＝`Passkeys, autofill credential provider` |
| `app/src/main/res/xml/credential_provider_service.xml` | `android:settingsSubtitle` 由 `@string/app_name` 改指新键；KDoc 增第 4 条（副标题语义 + 「`<autofill-service>` 无同名属性」+ 不得再指回 `app_name`） |
| `app/src/debug/res/values/strings.xml`、`app/build.gradle.kts` | **同源注释更正**：两处原称「`settingsSubtitle` 也引用 `@string/app_name`，资源覆盖两处一次生效」——该前提自本批起不成立；改为说明「debug / release 在该列表里的区分由**上一行应用名**（`android:label`）承担」 |

> **文案口径**：与 KeePassDX 逐字同款（「通行密钥、自动填充凭据提供程序」/ `Passkeys, autofill credential provider`）。
> 理由＝该文案描述的是**服务能力**（本应用确实同时提供通行密钥与自动填充凭据），且用户是在同屏对比后提出的
> 需求，同款文案可读性最好；若后续要改口径，改 2 个字符串即可（零结构影响）。

## §3 如实声明

1. **设备上 release 包那一行仍是旧文案**：`com.keepasskey` 是设备上既有的旧构建，本批**未重装 release**
   （release 签名需 `keystore.properties` / `KEYSTORE_*`，本机未配置 ⇒ `assembleRelease` 不可产出可升级包；
   且它是用户日常在用的包，不在本批改动范围）。判据不靠它承载：**同屏内 debug 新包行已显示新文案**即证机制生效；
   release 侧下次随版本构建自然一致。
2. **本批未动**：`android:settingsActivity` 仍指 `com.keepasskey.app.MainActivity`。官方对该属性的口径是
   「点击列表中提供程序名称时打开应用自己的设置屏幕」，KeePassDX 指向的是其 Passkeys 设置页；本应用指向主界面
   （**可进入设置页但多一跳**）。**本条不改**（无用户反馈、属取舍而非缺陷），仅此登记，避免日后被当成漏项。
3. **未跑**：`connectedDebugAndroidTest`（本批无设备侧代码面）、`lint`、`assembleRelease`、
   `check_installed_build.py`（本批无新增代码符号，`--expect-symbol` 不适用；改以 §2.1 的资源 id 与 §2.2 的真机读数取证）、
   KPEX 对拍（未触碰 KPEX 字段 / 编解码）。
4. **过程坑留痕**：Git Bash 下 `adb shell uiautomator dump /sdcard/x.xml` 的远程路径会被 MSYS 转义成
   `C:/Program Files/Git/sdcard/x.xml` ⇒ 必须 `export MSYS_NO_PATHCONV=1`（§414 已记，本次再次踩到）；
   另 `adb shell am start -a android.settings.CREDENTIAL_PROVIDER` 在该 ROM 上**解析不到**（`unable to resolve Intent`），
   改用组件名 `com.android.settings/.applications.credentials.CredentialsPickerActivity` 直达同一页。应用内
   `SystemSettingsNavigation.credentialProviderIntent` 走 `resolveActivity` 前置门，不受此影响（其跳转能力另有真机记录）。
