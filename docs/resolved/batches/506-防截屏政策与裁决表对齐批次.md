本项为纯文档整改，仅更正现行承诺，不改任何生产代码，不触发设备测试。

- **前提复核（认领时）**：直读 `FlagSecurePolicy.kt:23`（`shouldApplySecure(userEnabled) = userEnabled`）、
  `FlagSecureGuard.kt:16-47`（「只由用户开关决定」，首帧保守遮蔽 + Flow 修正）与 `SecureDialog.kt:76-85`
  （四类敏感对话框无条件强制遮罩、TOTP 扫码取景跟随开关）确认现行实现；核对批次
  [`411`](411-真机走查第三轮热修复批次.md) §1.3（2026-10-02 用户裁决推翻 2026-09-12「锁定态无条件强制」半环）。
  原登记前提成立：政策与裁决表确仍写「锁定态强制遮蔽」。

- **改动一（现行政策承诺）**：`docs/security/Privacy-Policy.md:99`「防截屏」条由
  「锁定态强制遮蔽，解锁态随开关真实生效」改写为「**窗口截屏防护全程由该开关决定**（含解锁页），
  首帧保守遮蔽保留但不构成全程保护，关闭期间产生的截屏 / 录屏 / 相册副本无法追溯擦除」，
  并如实列出**例外**：建库向导 / 主密钥修改 / 子库凭据 / 附件预览四类敏感对话框**始终强制遮罩**，
  TOTP / 通行密钥扫码对话框**跟随开关**（PD-47 / PD-48）。

- **改动二（现行裁决登记）**：`docs/architecture/产品裁决登记.md` 的 `PD-47`（不变边界第 3 项）与
  `PD-48`（不变边界首句）两处「锁库态强制遮蔽（`FlagSecureGuard` 的「锁定态强制 ∨ 开关」模型）不变」
  以删除线标记为**已被 2026-10-02 用户裁决替代**（引用批次 411 §1.3 与 `FlagSecurePolicy` KDoc），
  其余子裁决（扫码对话框跟随开关、反 overlay / 遮挡触摸过滤两层不随开关、四类敏感对话框清单一字不改、
  风险声明与重开条件）逐字保留。

- **不动项（历史原文保持原样）**：`docs/resolved/batches/29`、`39`、`338`、`411` 等归档正文与
  `docs/security/退役审计承接-42`、`待复核区IPC与SUPPLY项重合声明核实.md` 作为核实时点的历史引述保持原样，
