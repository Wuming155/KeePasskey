## 452.2 前提复核（2026-10-06 直读）

- **前提全部成立**：`maybeProbe` 原实现（`ResumeSyncProbeCoordinator.kt:81`）**先**写 `_lastProbeAtMillis = System.currentTimeMillis()`，**后**调 `probeRemote`；三处 `classify(...)` 传的 `lastProbeAtMillis = _lastProbeAtMillis.value` 都是刚写入值。`classify`（`ResumeSyncProbePolicy.kt:66`）内先复核 `shouldProbe`，`nowMillis - last < 30_000` ⇒ 恒 `Skipped`。全仓 grep 确认 `notice` / `lastOutcome` / `clearNotice` 零订阅者；`sync_probe_*` 三键仅协调器 `describeOutcome` 自引。
- **方向**：取 AC② **接线分支**（不取移除分支）——「开关可拨、结论永不呈现」由「设置页状态行消费 `notice`」消除；`lastOutcome` / `clearNotice` 两个**冗余**成员（`notice` 已承载结论，且开关关闭即隐藏状态行，无须显式清除）一并移除，使协调器不再留有零消费者成员。理由：接线可让开关承诺的结论真实可见，移除分支则等于取消该功能面。**排除「不可行故走移除」的判断**——接线不需要新增 `Manager` 类或并行状态源，仅沿既有 `SettingsUiStateFlows` 九→十路 combine 追加一路即可，非「不成比例的新管道」。

## 452.3 整改

### `ResumeSyncProbePolicy`：把「该不该探测」与「用哪个基线分类」抽成纯函数

- **新增** `data class ProbePlan(val shouldProbe: Boolean, val classifyBaselineMillis: Long?)` 与 `fun planProbe(probeEnabled, isLocked, lastProbeAtMillis, nowMillis = …): ProbePlan`——`classifyBaselineMillis` **恒等于**调用时传入的 `lastProbeAtMillis`（探测**前**基线），而不是 `nowMillis`。该函数把「自败节流」的根因（用刷新后的时刻当基线）在**纯函数层**表达为可断言契约。
- `shouldProbe` / `classify` 语义与签名**未变**（既有 `HostPolicyBatchTest` 用例逐字保留）。

### `ResumeSyncProbeCoordinator`：基线快照 + 时间戳后置回写 + 结论有真实出口

- `maybeProbe()` 改调 `planProbe(...)` 取计划；`if (!plan.shouldProbe) return` 后把 `plan.classifyBaselineMillis` 传入 `probeRemote(...)`；`_lastProbeAtMillis` 在探测**完成后**才回写（原实现先写后探）。
- `probeRemote(probeEnabled, isLocked, classifyBaselineMillis)` 三处 `classify(...)` 一律消费 `classifyBaselineMillis`，不再读 `_lastProbeAtMillis.value`。
- `_notice.value = describeOutcome(outcome).takeIf { it.isNotEmpty() }`——`Skipped`（`describeOutcome` 返回空串）不再写入空串，改写 `null`（无可呈现结论）。
- **移除** `lastOutcome` / `_lastOutcome` 与 `clearNotice()`（全仓零消费者；结论只经 `notice` 单一出口）。`notice` 仍是 `StateFlow<String?>`，成为设置页状态行的唯一真相源。

### 设置页接线（AC② 接线分支）

- `SettingsUiState` 新增字段 `syncProbeNotice: String? = null`（默认 null = 无可呈现结论，不谎报）。
- `SettingsUiStateFlows` 新增 `syncProbeNotice: Flow<String?>`；`settingsUiStateFlow` 的九路 combine 追加为**十路**（子 combine 由 `Pair` 升 `Triple`），`buildSettingsUiState(...)` 新增 `syncProbeNotice: String? = null` 形参并映射入状态。
- `SettingsViewModel` 注入 `ResumeSyncProbeCoordinator`（null 仅纯 JVM 单测，生产 Hilt 注 `@Singleton`），把协调器 `notice` 流经 `SettingsUiStateFlows.syncProbeNotice` 下发。
- `SecuritySettingsScreen` 在「回前台探测远端变化」开关**下方**新增常驻状态行：`syncProbeOnResumeEnabled && syncProbeNotice != null` 时渲染该文案（复用既有 `sync_probe_unchanged` / `sync_probe_remote_changed` / `sync_probe_failed` 三键，`describeOutcome` 已本地化）；**非弹出式**（符合条目「设置页或同步页展示结论」，不用 Snackbar）。开关关闭即隐藏状态行。
