## 1. 原条目（`ISSUE-P2-528`，本轮登记）

### 换密后云端副本不被替换：旧主密码对云端副本持续有效，且回执承诺落空

- **背景（用户报告）**：用户改主密码后本地文件未及时同步，杀掉后台重进时发现「两份文件密码不一样」，
  并在冲突处置面找不到「保留副本」类出口（该面的缺口另立批次）。
- **根因（2026-10-07 代码直读核实）**：换密只改**文件头凭据**（KDBX4 重生成 masterSeed / IV / KDF salt），
  **不改条目树**（`SessionPersistence.changeCredentials`：`serializeToBytes(db, 新凭据, …)` 用的仍是同一棵树）；
  而同步的「本地内容是否变过」判据**只比树**（`KdbxContentComparator.changed`），
  装配期判「无变化」时**直接复用旧缓存字节**当本地侧（`SyncCycleSetup.buildCycleContext` 的 `localBytes` 分支）
  ⇒ 换密后的同步判「与云端一致（`UpToDate`）」，**一次上传都不发生**。另：`changeCredentials` 成功分支把会话态置回
  `OPENED`（非 `DIRTY`）、不失效同步缓存、也不触发同步（`SettingsMasterKeyChangeController` 仅做「记忆密钥文件 + 重封印」）。
- **后果**：① 换密回执里「云端旧版本副本将在下次同步后被替换」（`strings.xml:757`）**不成立**——
  只有发生真实内容改动的那次同步才会替换；② **旧主密码对云端副本长期有效**，而换密的本意正是让旧口令失效。
  本条**不在** `已知工程限界.md` 已登记范围内（§1.4 只覆盖「`.bak` + 在应用外改密」这一型）。
- **验收标准**：AC① 换密（含改绑密钥文件）成功后的下一次同步必须**重新以当前凭据序列化并上传**，
  远端副本不再能用旧主密码解开；AC② 该行为须在进程被杀 / 冷启动后**仍成立**（不得只靠内存态）；
  ③ 无换密时不得引入「每次同步都重传」的另一面回归；④ 接线须被用例钉住（机制正确而接线断掉即静默失效）。
- **核实时间点与方式**：2026-10-07 主控**代码直读**（`SessionPersistence.changeCredentials` /
  `SyncContentChangeDetector` / `KdbxContentComparator` / `SyncCycleSetup` / `SyncCycleRemoteOutcomes` 五处），
  并由本批新增用例 `SyncCredentialRotationUploadTest` **实测坐实**（无标记对照组判 `UpToDate` 且零上传）。

## 2. 整改

1. **新增 `SyncCredentialRotationStore`**（`app/src/main/java/com/keepasskey/app/sync/`）：
   持久标记「本地库已用新主凭据重新加密、云端副本待替换」。
   键 `recrypted_vault_<SHA-256(remotePath)>`，**与 `SyncCredentialsStore` 共用同一 prefs 文件**
   （同步关系终止时 `clear()` 连带销毁 ⇒ 换服务器 / 退出同步不残留意图）；
   键内**不含远端路径明文**（WebDAV 路径常含邮箱等 PII）。
2. **装配期消费**（`SyncCycleSetup.buildCycleContext`）：标记置位时把本地内容变化三态**强制**为
   `LocalContentChangeState.CHANGED` ⇒ 本地侧按**当前会话凭据**重新序列化；
   远端未变时引擎走「本地赢 + `If-Match` 预条件上传」（`SyncCycleEngine.openCachedWithLocalChanges`），
   远端已变时 412 ⇒ 正常进冲突裁决（不静默覆盖他端改动）。
   **读后即清**；上传失败（离线等）时的重投由本地缓存版本号承担（装配期已 `writeCache(updateVersion = true)`）。
3. **登记点**：`SyncCoordinator.markLocalVaultRecrypted()`（解析远端路径；未配置同步 / 解析失败 ⇒ 空操作；
   任何异常不上抛——事实登记失败**不得**改写「换密已成功」这一结果）；
   `SettingsMasterKeyChangeController` 新增 `onCredentialsRotated` 钩子，在**写盘成功之后、重封印之前**调用
   （重封印可被用户取消，登记不得随之丢失）；`SettingsViewModel` 装配为
   `{ syncCoordinator.markLocalVaultRecrypted() }`。
4. **下沉**：`SettingsViewModel` 的改密控制器装配点移入 `masterKeyChangeControllerOf`
   （`SettingsMasterKeyChangeController.kt` 尾部的同包工厂，装配口径随之下沉）——
   本批新增行曾使该文件达 **503 行**（`count_line_tiers` 的 `tier1(>500)` 恒 0 被打破），下沉后回到 498 行。

**代理裁决（可逆）**：不做「换密后立即强制上传」（`commitLocalForce` 无预条件，会静默覆盖他端期间改动），
而选「持久标记 + 下次周期走常规带预条件上传」；不做「只写同步工作缓存」——该目录按设计可被系统回收
（`SyncCache` 自声明「只放锁库即可丢弃的密文快照」），无法承担 AC② 的跨进程义务。
