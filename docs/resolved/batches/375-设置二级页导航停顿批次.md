# §375 设置二级页导航停顿批次（`ISSUE-P2-406` 整条闭环）

> **批次性质**：用户直报体验缺陷整改（同轮登记并闭环）。
> 用户命题（2026-09-30）：「有个问题，点击某个选项，设置里面的选项，然后我点击在进去的这个过程中会有停顿，就感觉好像卡了一下。」

---

## 1. 根因

设置二级页**任一入口**（密码库 / 安全 / 自动填充 / 主题 / 同步 / 健康 / 调试 / 关于）都走同一条导航链：

`SettingsScreen` 点击 → `KeePasskeySettingsNavGraphRoutes` 各 `composable` → `hiltViewModel<SettingsViewModel>()` 同步构造 VM。

构造期在**导航组合线程**上做了两件与该页无关的 Keystore 级重活：

| 位置 | 动作 | 成本 |
|---|---|---|
| `SettingsSyncController` 初值 | `probeSealHardwareBacked()` → `syncSealSecurityLevel()` | Keystore `getKeySecurityLevel` |
| `SettingsViewModel.init` | `syncController.restoreSyncCredentials()` → `loadWebDavConfig` / `loadS3Config` | **Keystore AES-GCM 解密** + SharedPreferences |

只有「云端同步」二级页需要凭据预填与封印硬件声明；其余设置页为此付出同一笔主线程停顿。Keystore 操作在低端机 / 首次访问密钥时可感知为「点进去卡一下」。

工程规则亦禁止在 `Dispatchers.Main` 做解密（`.codebuddy/rules/engineering-rules.md` §协程与并发规则）。

---

## 2. 整改内容

### 2.1 控制器构造期不再探测 Keystore

- `SettingsSyncController.syncStateFlow` 初值 `syncSealHardwareBacked = false`（不再构造期调用 `probeSealHardwareBacked()`）。
- 实测值仍由 `refreshSealHardwareBacked()` 刷新（hydrate / save / restore 路径）；`SecurityClaimWiringTest` 所锁的
  `syncSealHardwareBacked = probeSealHardwareBacked()` 字面量与 `syncSealSecurityLevel()` 消费点**仍在源码中**，ISSUE-P2-285 实测声明链路不断。
- 新增 `SettingsSyncController.hydrate()`：`scope.launch(Dispatchers.IO) { updateWifiOnlySync(...); restoreSyncCredentials() }`。

### 2.2 VM init 去掉同步 Keystore / 偏好回填

- 删除 `init` 内 `updateWifiOnlySync(loadWifiOnlySync())` 与 `restoreSyncCredentials()`。
- 新增门面委托（PD-23 单语句）：`fun hydrateSyncUi() = syncController.hydrate()`。

### 2.3 同步页路由触发水合

- `settingsSyncRoute` 在 `composable` 内 `LaunchedEffect(Unit) { settingsViewModel.hydrateSyncUi() }`。
- 其余设置页路由零改动：**不再**支付 Keystore 成本；同步页表单可在水合完成后回填预填通道（短暂空表单可接受，优于全设置域主线程阻塞）。

### 2.4 安全语义不变（验收红线）

| 面 | 处置 |
|---|---|
| 凭据 `CharArray` 一次性预填 | 仍由 `restoreSyncCredentials` 下发；锁定即擦除（`SessionLockGuard`） |
| 全零串拒封（ISSUE-P2-403） | 未触碰 `SyncCredentialsStore` 封印入口 |
| 封印等级按实测渲染（ISSUE-P2-285） | 探测点从「构造期」改为「hydrate / save 路径」，字段与文案链路未断 |
| 冷启动自动同步 | `SettingsColdStartSyncGate` 仍触发；`syncNow` 自行加载凭据，不依赖 UI 预填 |
