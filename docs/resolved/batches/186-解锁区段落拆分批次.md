# §186 解锁区段落拆分批次（`ISSUE-P3-188` 一批双降：第二档 **29 → 28**、≥100 项 **26 → 25**）

> **起因**：`ui/screens/unlock/UnlockContentSections.kt` 是**同时挂在两个维度**上的目标——
> 文件 430 行（第二档）、其内 `UnlockStandardUnlockContent` 158 行（第 3 目 ≥100 清单）。
> §185 的实测还确认了它的唯一守卫 `UiMd3AlignmentWiringTest` **已经是「文件清单的清单」结构**
> （§175 立的并集形态）⇒ 扩扫只是往内层列表加一个路径，改动面极小。一次搬动同时削两个数。

## 2. 主密码链路刻意不搬

`SecurePasswordField`（29 行）**留在原函数内**：它的 `onPasswordChanged` 直连 ViewModel 的
`CharArray` 通道、`wipeToken` 承接 ISSUE-P1-04 的「失败/锁定后擦除显示态」，与 §179 对向导主密码
管线的判断同一口径——**秘密处置保持单一现场**，不为凑行数外迁。

## 3. 守卫扩扫（只放宽定位，不降强度）

`UiMd3AlignmentWiringTest.禁用态主按钮必须走共用组件而不是各自写 MD3 默认色`：
两条断言（`disabledPrimaryButtonColors()` / `disabledPrimaryButtonBorder()`）的**原文一字未动**，
只把内层列表由 `["UnlockContentSections.kt"]` 扩为
`["UnlockContentSections.kt", "UnlockStandardUnlockSections.kt"]` 并集；
测试输出的定位串由 `joinToString(" + ")` 自动生成 ⇒ 失败信息仍指向两处。
同一条测试里的**全仓扫描**部分（`uiSourceFiles()` 找 `alpha = 0.12f` 直写）未受影响。
另：`UnlockContentSections.kt` 顶部一条**既有死 import**（`androidx.compose.ui.unit.sp`，
实测原文件非 import 出现次数 **0**）随本批剪除，共 7 条 import 因搬动失效。

### 4.1 顺带收紧一处会误导的判定语（`logic_lines.py`，§184 工具）

首版对「逻辑行 <5」的函数直接打印 `PD-11 判定：装配表（PD-11 豁免）`——但 PD-11 的**边界①**
写明豁免只覆盖 `NavGraphBuilder` 扩展函数。本批拿它量 `UnlockStandardUnlockContent`（逻辑行 1）时，
这行输出就成了一条**错误的豁免暗示**。已改为只报「重开条件是否触发」，
并明写「是否属豁免范围须按 PD-11 边界①自行判定」；§184 批次正文的同句措辞同步更正。
