## 1. 切分的依据

母文件里三族代码的耦合性质不同：

| 族 | 内容 | 依赖 | 结论 |
|---|---|---|---|
| 生命周期与凭据落库 | `onCreate` / `createAndReturn` / 候选与既有凭据处理 | `CredentialManager`、Keystore、`viewModelScope` 无关的 Activity 状态、`callerTrustStore.trust(…)` | **留在母文件** |
| 注册响应材料 | `buildRegistrationJson` + `buildPrfClientExtensionResults` | 只用到实例的 `rpId` / `origin` **两个字符串**，其余全是入参 | **本批下沉** |

⇒ 新文件 `PasskeyRegistrationPayload.kt`（`internal object`，133 行）承接第二族；
`rpId` / `origin` 由实例字段改为**显式入参**（母文件 `buildRegistrationJson` 变为一行委托，15 行）。
母文件 **460 → 359 行**，两文件均低于 400 阈值。

## 2. 随代码同迁、未放宽的安全语义（`PasskeyData` 与凭据材料的处置）

1. `clientDataJSON.androidPackageName` **只写系统背书**的调用方包名，取不到即**省略该字段**
   （ISSUE-P2-72：回退成本应用包名等于把归属伪造成我们自己）；
2. `authData` / `attestationObject` 两块字节缓冲在 `finally` 中显式擦除，**含早退路径**；
3. `clientExtensionResults.prf`：注册侧 `enabled = true`、有 `eval` 才回传 `results`；
   断言侧「算不出即回空对象，绝不谎报」；`PasskeyPrf.computeValue` 的中间值 `first` / `second`
   同样 `finally` 擦除。

## 3. 过程留痕

1. 首版忘记给新对象的 `build` 补 `rpId` / `origin` 两个形参、且新文件 import 只写了三条猜测路径 ⇒
   编译期 8 处报错（`No parameter with name 'rpId'` / `Unresolved reference 'PasskeyData'` 等）。
   **处置**：形参补齐 + 直接沿用母文件的 import 全集再按编译器结果剪枝（母文件 −4、新文件 −17），
   一次编译通过。**未入库**；
2. import 剪枝沿用 §161 的白名单（`getValue` / `setValue` / `provideDelegate` 类不剪）——
   本批两处 Compose 无关，但白名单保留以免同类失误复发。
