## 3. 过程中发现并当场修正的缺陷

1. **sync 测试 APK 无 INTERNET 权限**（结构性缺口）：library 主清单不声明权限（正确形态），测试 APK 需自备 ⇒ 新建 `sync/src/androidTest/AndroidManifest.xml` 声明 INTERNET。
2. **targetSdk 37 测试 APK 进程平台默认禁明文**：传输层用例的回环 MockWebServer 请求被平台拦（`CLEARTEXT communication to 127.0.0.1 not permitted by network security policy`）——**该失败本身就是平台明文禁令生效的直接证据**；测试 APK manifest 加 `android:usesCleartextTraffic="true"`（仅测试进程）放行回环，app 层策略用例依赖的禁令不受影响。
3. **API 37 真机对回环明文的平台内置豁免**（实测，非缺陷）：`NetworkSecurityPolicy` 在 Redmi 4X 上 `default=false loopback=true localhost=true`——回环豁免与全局禁令分裂；API 36.1 模拟器则回环同样被拦。故 `CleartextPolicyDeviceTest` 的回环断言设计为「请求结果必须与策略读数一致」（两代平台均稳定），并以**设备 LAN IP（非回环）被平台拦截**作为判别性最强的形态。该平台差异已登记限界表 §4.1。
4. **`WorkInfo` 无 `workerClassName` 属性**：初版用例误用（凭 API 印象未查文档）⇒ 改由 `TestListenableWorkerBuilder` 直接构建执行 `PeriodicSyncWorker` 承载「注册执行体确为该类」的断言。

## 4. 模拟器专有差异（如实登记，新立条目跟进）

`AutofillAuthChainDeviceTest` 在 **Pixel_10 模拟器上两轮稳定失败**于阶段 0 自检「本进程未打出完整性扫描留痕」
（`RuntimeIntegrityDetector` 的 `运行完整性扫描完成` 留痕 15 秒轮询未捕获）；**Redmi 4X 真机同轮两轮全绿**。
该用例 KDoc 明示「不使用 AssumptionViolatedException；未达成的阶段显式失败」——维持其判定口径，未改。
**成因候选**（未定位，不猜结论）：① `detectSignals()` 在模拟器上某信号读取抛异常 → `scanScope.launch` 协程静默终止（`refresh()` 无 try 包裹）；② 模拟器 logcat dump 形态差异。
已补登 `ISSUE-P3-197`（P3）跟进；不得把真机结论外推到模拟器，反之亦然。
