## 2. 整改

### 2.1 写侧真实落库（AC① / AC③）

`SettingsPreferencesController` 两个 setter 由「仅 `databaseConfigStateFlow.update`」改为
与 `setArgon2Parameters`（P2-22）/ `setRecycleBinEnabled`（P2-270）同口径：

- `setEncryptionAlgorithm`：经新增的 `CipherLabels.cipherUuidForLabel`（显示标签 → 算法 ID 反查，
  与 `databaseConfigFromHeader` 正向映射共用同一常量，杜绝正反两向漂移）得到 `KdbxUuid`，
  `updateDatabaseMeta { db.copy(header = db.header.copy(cipherUuid = ...)) }` + `session.save()`。
  落盘时 `KdbxFile.save` 按**保存时** cipherUuid 生成**该算法官方长度**的全新 EncryptionIV
  （ChaCha20 12B / AES、Twofish 16B，P0-4 契约）并以新 IV / 新 MasterSeed 重派生写出；
- `setKdfAlgorithm`：按显示标签构造**参数齐备**的目标变体（AC②，口径见 §2.2）后
  `updateDatabaseMeta { db.copy(header = db.header.copy(kdfParameters = ...)) }` + `session.save()`。
  落盘时以保存时 kdfParameters（全新随机 salt / seed）重派生加密密钥。

两者回显**均不再自持状态**：会话 `databaseFlow` 重发后由 init 的头映射通道
（`databaseConfigFromHeader`）统一下发（P2-19 单一真相源），消除「用户选择值 vs 文件头真值」分叉。

如实 no-op 边界（AC③）：无活动会话 / 库未就绪（`databaseFlow.value == null`）/
未知标签（反查返回 null）/ 与现行形态相同（cipherUuid 相同；KDF 同型同 variant——避免无谓
重派生与整库重写）时直接返回，不触碰会话状态。

### 2.2 KDF 变体参数补齐口径（AC②）

| 换入方向 | 参数补齐 |
|---|---|
| Argon2id ↔ Argon2d | `copy(type = ...)` 携带现行 I / M / P（换型不改强度） |
| → AES-KDF | 新构造 `KdfParameters.Aes`，rounds 取官方缺省 `KdbxConstants.Kdf.DEFAULT_AES_KDF_ROUNDS`（6 000 000） |
| → Argon2（自 AES-KDF） | 新构造 `KdfParameters.Argon2`，I / M / P 取类型缺省（2 轮 / 64MB / 并行 2）——自 AES-KDF 换入时 Argon2 参数无处映射（rounds ≠ I·M·P），与官方 KeePass「换 KDF 取新参数缺省值」口径一致，换回后可经 Argon2 参数对话框重调 |

salt / seed 占位无需随机：`KdbxFile.save` 换新后才参与派生，占位值从不落盘。

### 2.3 词汇表收敛（KdfLabels）

KDF 三个显示字面量（`Argon2id` / `Argon2d` / `AES-KDF`）此前在头部投影
（`databaseConfigFromHeader`）与选择对话框两处独立硬编码；本批新增第三处消费方
（写侧反查），故按 ISSUE-P3-92 对 `CipherLabels` 的同一纪律收敛为 `KdfLabels` 常量，
投影 / 对话框 / 控制器三处共用。UI 绑定与字符串资源无需改动（对话框文案本就
只描述算法本身，现为真）。
