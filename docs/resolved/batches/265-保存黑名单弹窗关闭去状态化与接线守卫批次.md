- **背景与影响**：本条的确认缺陷不是「接线断了」，而是**「关闭语义与一个单向状态耦合」＋「零守卫」**，落到用户侧有两种可复现观感：
  1. **非手工模式（默认态）**：全弹窗只有一颗「关闭」且接线正确 ⇒ 在此态若真机复现「点了不关」，只可能是构建落在 §205 纠偏之前，或存在本条目范围外的干扰项（须真机取证，见 AC⑤）。
  2. **手工输入模式**：`manualEntry` 是**单向闩锁**（`AutofillBlocklistDialogs.kt:143-146` 的 `onToggleManual` 只置 `true`，无回退到名单模式的路径），一旦点过「手工输入」，右下角即由「关闭」**变为**「新增」；空输入时 `enabled = pendingPackage.isNotBlank()` 为假 ⇒ **灰掉且点之不动**，真正的「关闭」被挤到其左侧。用户按「右下角那颗按钮」的既有印象点击，观感即「右下角按钮无响应 / 关不掉」（`submit` 成功还会清空 `pendingPackage` ⇒「新增」随即再次变灰，极易踩中）。
  影响面：设置页 → 自动填充 →「智能识别、凭证保存与兼容策略」→「不再提示保存的应用」（`ISSUE-P3-43 ③` 的保存侧黑名单）。**不阻断使用**（返回键 / 点弹窗外部 / 左侧「关闭」三条路仍可关），无数据风险 ⇒ **定级 P3**；**升档条件**：若在**非手工模式**下真机复现「点关闭不关」，即为功能性阻断，须升 **P2** 并先定位真因。
- **正确的方式（整改方向）**：
  1. **关闭语义去状态化**：把「关闭」**无条件**放回 `dismissButton` 槽（与全仓 13 处同形，`PackageBlocklistDismissButton` 删掉 `manualEntry` 分支），confirm 槽只在 `manualEntry == true` 时承载「新增」（`enabled = pendingPackage.isNotBlank()` 保持不变）⇒ 顺带消灭 `onConfirm` 里 `if (manualEntry) … else …` 这一**全仓唯一**的状态相关关闭语义。
  2. **补回退路径**：手工输入模式提供回到名单模式的方式（或新增成功后自动回落），使界面不存在「右下角长期停在禁用按钮上」的态。
  3. **补接线守卫**：比照 `SettingsSubscreenScaffoldWiringTest` / `OneTapInteractionWiringTest` 的静态源码比对形态新增用例——断言该弹窗 `dismissButton` 槽存在 `TextButton(onClick = onDismiss)`，且 confirm 槽**不得再出现** `btn_close`；须含**防空扫**断言（§77 口径：扫不到目标即失败）。
- **验收标准**：
  - AC① 非手工模式下「关闭」由 `dismissButton` 槽承载，且其**存在与可点性不依赖任何状态**（`manualEntry` 取何值都不影响）；
  - AC② 手工输入模式补回退路径，界面**不存在**「右下角恒为禁用按钮」的态；切换/回落后按钮文案与动作一致（界面声明 == 实际行为）；
  - AC③ 新增接线守卫用例（含防空扫），并以下述方式**证明其区分力**：把 §205 的历史坏形态（confirm 槽无条件 `submit`）代入谓词须报红（`git show <回归态>` 代入法，§199 先例），不得只以「现态通过」自证；
  - AC④ 若裁决「保留现形态」（不重构），须在 [`architecture/产品裁决登记.md`](../../architecture/产品裁决登记.md) 登记取舍与重开条件，**不得静默留白**；
  - AC⑤ 若真机在**非手工模式**下复现「点关闭不关」，本条目升 P2，并先取真机留痕（设备 / 构建号 / 复现步骤 / 录屏或日志）再定因。

### 1.2 前提勘误（2026-09-23 评估揭出，开工前修正）

条目「核实方式」自陈「逐跳接线完整：**未发现**监听缺失、空 lambda、`onDismiss` 错挂……」**不成立**——
`AutofillBlocklistDialogs.kt:155` 的 `onConfirm = { if (manualEntry) submit(pendingPackage) else onDismiss }`
中 `else onDismiss` **缺调用括号**：`onDismiss` 是 `() -> Unit` 变量，此处只对函数引用**求值随即丢弃**
（lambda 期望返回 `Unit`，Kotlin 静默接受、不自动调用）⇒ **非手工模式（默认态）下全弹窗唯一的「关闭」是死按钮**。

三处连带更正：

1. 用户原始报告「默认态点右下角『关闭』无响应」已被静态解释，**不是**「构建落在 §205 纠偏之前或范围外干扰项」；
2. 影响面论述「返回键 / 点弹窗外部 / 左侧『关闭』三条路仍可关」在默认态**只剩两条**——非手工模式下
   `PackageBlocklistDismissButton` 整段不产子项，左侧根本没有「关闭」，即默认态**没有任何可见的关闭按钮**；
3. 按条目自身升级条件（非手工模式复现「点关闭不关」须升 P2），现在**静态即可证实** ⇒ 本条按 **P2** 严格度整改
   （真机留痕未前置，见 §4 如实声明）。

## 2. 整改

### 2.1 关闭语义去状态化（AC①）

`PackageBlocklistDialogSections.kt`：

- `PackageBlocklistConfirmButton` 删 `manualEntry` 参数与 else「关闭」分支，恒渲染「新增」
  （`enabled = pendingPackage.isNotBlank()` 不变）；confirm 槽自此**只**在手工输入态被调用；
- `PackageBlocklistDismissButton` 删 `manualEntry` 参数与 `if (manualEntry)` 分支，恒渲染「关闭」绑 `onDismiss`
  （与全仓其余 13 处同形）。

`AutofillBlocklistDialogs.kt`：

- confirm 槽改为 `if (manualEntry) { PackageBlocklistConfirmButton(pendingPackage, onConfirm = { submit(pendingPackage) }) }`
  ——状态相关转发与死接线**一并消灭**（名单模式下整槽不产子项，M3 `confirmButton` 为必填槽、空实现即不渲染）；
- dismiss 槽无条件 `PackageBlocklistDismissButton(onDismiss = onDismiss)`；
- 对话框 KDoc 与槽内注释补「关闭无条件落 dismiss 槽」口径与历史教训（死按钮成因），锚点 `ISSUE-P3-264` 可检索。

### 2.2 手工输入真双态回退（AC②）

- `onToggleManual` 由单向闩锁（`manualEntry = true`）改为**真双态切换**（`manualEntry = !manualEntry`，同时清 `showAddError`）；
- 手工输入分支补「返回名单模式」入口（`TextButton(onToggleManual)`），新文案键 `autofill_blacklist_manual_back`
  （zh「返回名单模式」/ en "Back to list mode"）⇒ 界面不存在「右下角恒为禁用按钮」的滞留态（可一键退回名单模式 + 选择器）。

### 2.3 接线守卫（AC③）

新增 `app/src/test/java/com/keepasskey/app/ui/screens/settings/PackageBlocklistDialogWiringTest.kt`（**4 例**），
判据形态比照 `SettingsSubscreenScaffoldWiringTest`（静态源码比对，不依赖运行时）：

- 谓词 `wiringViolations(dialogSource, sectionsSource)` 五项判据：① confirm 槽组件不得承载 `btn_close`、
  不得再吃 `manualEntry`；② dismiss 槽组件必须承载 `btn_close` 且不得状态化（出现 `manualEntry` / `if (` 即旧形态）；
  ③ 调用点必须把 `PackageBlocklistDismissButton(onDismiss = onDismiss)` 直挂；④ 全文件不得出现 `else onDismiss`
  （死按钮形态，无论是否补了括号——状态相关关闭语义整类禁止）；**锚点缺失一律计违反项**（§77 防空扫）；
- 区分力证明（§199 代入法）：§205 历史坏形态文本（confirm 槽吃 `manualEntry` 并承载「关闭」、else 分支引用未调用、
  dismiss 槽随状态消失）代入**同一谓词**必须逐项报红（≥2 类）——不得只以「现态通过」自证；
- 反向哨兵例：切片锚点被人改名 / 挪走时首例必须因防空扫报红而非静默通过；
- 双语例：`autofill_blacklist_manual_back` zh / en 双语在位、`manualEntry = !manualEntry` 双态切换在位。

**施工留痕**：守卫首跑把对话框内新写的历史教训注释里的字面量 `else onDismiss` 也扫中报红——谓词敏感度属实，
遂改写注释避开该字面量（坏形态字面量只由测试用例内的代入文本承载）。
