# §422 云同步配置按库隔离批次：同步凭据 / 远端路径按 dbId 命名空间（ISSUE-P2-465 整条闭环）

## 1. 原文收录（原样迁移自 `ACTIVE_ISSUES.md`，未删改）

### ISSUE-P2-465：云同步配置全局单份不随库切换——按库隔离（参考 KeePass2Android）

- **核实时间点**：2026-10-03；**核实方式**：用户走查回执「云同步的配置不会随着文件的不同而改变，依然还是老配置」+
  代码直读（`SyncCredentialsStore` 以 `KEY_WEBDAV_REMOTE_PATH` 等**全局扁平键**存 SharedPreferences——
  全部库共用一份配置）+ logcat 时序（12:06–12:07 两轮切库后同步仍指向老库远端：`库身份绑定拦截：remotePath
  归属另一库` → `库身份改绑确认：整库覆盖上传`——绑定拦截是目前防错传的唯一闸门）。
- **竞品依据（先读文档再借鉴，竞品报告 §4.4 / §8）**：keepass2android 每库一行（`FileTable` 行内含同步配置，
  按库读写）；KeePassDX `file_database_history` 表主键即 `database_uri`——两家的云同步配置都**归属库行**，
  无全局层。
- **整改方向**：同步凭据 / 远端路径按 `dbId` 命名空间存储（键带 dbId 摘要或每库独立记录），设置页同步组
  与同步周期读写**当前活动库**自己的记录；存量全局配置一次性迁移到迁移时的活动库名下；`VaultBinding`
  绑定拦截 / 防回滚机制保持不变（与 `同步层记录级完整性威胁建模` 对齐）。
- **验收标准**：  
  ① 同步设置页读写当前活动库自己的配置，切库后配置页与同步周期跟随；  
  ② 旧全局配置一次性迁移（迁移到迁移时点的活动库名下），其余库初始为未配置；  
  ③ 绑定拦截 / 改绑确认 / 防回滚全链回归；全量 test 绿 + 门禁全 PASS；真机走查「两库两远端两配置」留痕。
- **关联**：`ISSUE-P3-447`（SAF 库同步）同触同步层；本条是配置归属维度，整改须与绑定/防回滚机制同批自洽。

## 2. 前提复核（开工前，规则 6.1②）

- **键形态前提成立**：`SyncCredentialsStore` 的 17 个键（协议 / WebDAV 五项 / S3 十一项）确为**全局扁平键**，
  无任何 dbId 维度；本次以「dbId 摘要后缀」命名空间化（`<基名>_<SHA-256(dbId) hex>`）。
- **消费面复核（逐点列出，防漏改）**：读写方共 6 处——设置页水合与保存（`SettingsSyncController`）、
  同步周期装配与远端路径解析（`SyncProviderResolver`）、库列表自动同步判定与探活（`SyncCoordinator`）、
  设置页远端浏览的已保存凭据回退（`SettingsViewModel` → `RemoteBrowseController`）、
  云端打开导入提交（`CloudVaultImporter`）、库选择器「打开已有库」预填（`DatabasePickerCloudAccountController`）。
  **全部经 store 的同一批公开方法**，故命名空间解析收口在 store 内部即可，调用点零改写（仅云端导入显式指定库）。
- **「当前活动库」判据复核**：会话侧 `DatabaseSession.currentPathIdentifier`（SAF 为 `content://`，本地为
  绝对路径；`lock()` 不清、`close()` 才清）与库列表侧 `VaultDatabaseCatalog.loadActiveDbId()`
  （外部登记库 = 路径 / `content://`，**沙盒内扫描条目 = 裸文件名**）。两者对**同一物理文件**给出不同字符串形态
  ⇒ 必须归一，否则「解锁前 / 锁屏中」与「解锁后」会落到两个命名空间。
- **既有按库命名空间范式（直接沿用，不另造）**：`KeyFileVaultCopyStore`（SHA-256(dbId) 作文件名）、
  `RealSettingsRepository.keyFileMemoryDigest`（dbId 摘要作键段）、`SyncVaultBindingStore.keyFor`
  （SHA-256 摘要）+ `SyncCache.vaultScope`（根分组 UUID 作缓存键前缀）。

## 3. 整改

### 3.1 命名空间标识（新 `ActiveVaultSyncNamespace.kt`）

依次回退并归一：**① 会话路径标识 → ② 会话本地文件绝对路径 → ③ 库列表活动库 ID**；
`content://` 与绝对路径原样保留，**裸文件名归一为 `filesDir/<名>` 的绝对路径**
（与库列表对沙盒扫描条目的登记形态互补，使同一库在会话内外恒得同一个键）。三者皆空 → `null`
（= 旧全局键命名空间，存量兼容与迁移来源）。另提供 `idFor(rawId)` 供无会话路径显式指定库。

> 与同步层既有 `vaultScope`（根分组 UUID）**刻意并存、互不替代**：`vaultScope` 只存在于
> 「库已解锁且内存树在场」，用于缓存 / 基线 / 防回滚的物理隔离；本命名空间标识必须**在解锁前也可解析**
> （云端打开导入要先落凭据、库选择器要先预填）。KDoc 已写明该区别，防后续混用。

### 3.2 键清单与一次性迁移（新 `SyncCredentialKeys.kt`）

- 17 个键的基名集中于此（原 `SyncCredentialsStore` 私有 companion 搬出，顺带让该文件回落规模档）；
  `scoped(base, dbId)` 生成按库键，`removeScoped(prefs, dbId)` 供单库清理，`ALL_BASES` 供迁移与清理共用。
- `adoptLegacyInto`（AC②）：**仅当已知活动库**且**存在存量全局键**时执行——把存量键按类型（String / Boolean /
  Long）搬到该库命名空间、**随后物理删除全局键**（一次性语义：不留下可被后续任意库「捡走」的无主配置）。
  若该库自己已有记录（锚点键 `webdav_url` / `s3_endpoint` 命中）则**不覆盖**，但全局键照样清除。
  无活动库时不动作（归属未定，留待有库时迁移）。日志只记布尔与计数，绝不记命名空间标识（路径 / URI）。

### 3.3 存储层（`SyncCredentialsStore.kt`）

- 构造注入 `DatabaseSession?`（可空 + 默认 null，沿用本仓测试缝范式）；**全部**读写先经内部
  `resolveScope(dbId)` 解析命名空间（显式 `dbId` 优先且**不触发迁移**——新库不该继承旧配置）。
- `saveProvider` / `saveWebDavConfig` / `saveS3Config` 新增可选 `dbId` 形参（默认走当前活动库）；
  其余方法（含 S3 时钟偏移、旧明文 AccessKey 转加密、废弃证书锁定键清理）一律改走按库键。
- 新增 `clearFor(dbId)`：删库时清该库的配置（与按库密钥文件副本 / 记忆同批）；`clear()` 保持整文件清空语义。
- 两处结构性搬出（守 `tier2` 棘轮，见 §5 过程留痕）：凭据值对象 → `SyncCredentialModels.kt`（同包同全限定名）。

### 3.4 接线（两处，均属 AC 内含面）

- `CloudVaultImporter.commitCredentials`：以**即将落盘的本地文件绝对路径**作显式 `dbId`——该路径随后即由
  `importExternalDatabase` 登记为库 ID、并成为解锁后的会话路径标识 ⇒ 解锁后同步页 / 同步周期读到的正是这一份，
  不会落到别的库头上（KDoc 写明该等价关系）。
- `DatabasePickerViewModel.removeDatabase`：删库成功同批 `syncCredentialsStore.clearFor(id)`。
  **同一路径重建新库**的最坏情形仍由既有绑定闸门兜底（`VaultBindingMismatch` 在任何网络写之前中止）。
- `ActiveDatabaseIdStore.kt`（新）：活动库 ID 的持久化单点（自 `VaultDatabaseCatalog` 私有实现抽出，
  prefs 名 / 键名单点定义）——库列表与同步命名空间读**同一份记录**，杜绝两处键名漂移。
  `VaultDatabaseCatalog.loadActiveDbId/saveActiveDbId` 改为纯转发（容错语义逐字不变）。

## 6. 残余与取舍（如实登记）

- **同步缓存 / 防回滚 / 绑定登记的命名空间不变**（AC③ 明令）：缓存与防回滚键仍为
  `根分组 UUID + remotePath`（`SyncCache.vaultScope`），绑定登记仍按 `remotePath` 存根分组 UUID。
  由此带来两点**既有**行为（本批刻意不改，非本批引入）：① 锁库触发 `SyncCacheEvictor.evictAll()`
  **清空全部库**的同步缓存（下一次同步重新下载即自愈，不产生错传或数据丢失）；② 删库只清该库**配置**，
  绑定登记因值无从反查而保留——错传方向仍由绑定闸门拦死。
- **库文件「换身份」即视为另一个库**：命名空间键 = 库文件登记身份（与按库密钥文件记忆 / 副本同源）。
  沙盒内文件未经 root 无法被改名；SAF 文档改名 **URI 不变**（命名空间不变）；经 SAF 重选同一文件会得到
  新 URI 并生成新的库卡片（对用户而言本就是「另一个库」）。⇒ 判**不属**限界表口径的残余风险，
  不新增 `已知工程限界.md` 条目；此判断留痕于此。
- **删库清理的边界**：`clearFor` 只删该库命名空间下的键；缓存与绑定登记不清（技术理由见上）。
- 未新增字符串 / 未新增 `@Preview` / 未触原生面与 `androidTest` ⇒ 无截图编译门禁义务、无设备侧必跑项
  （规则 §「测试资产纪律」② 的触发面未触及）。
