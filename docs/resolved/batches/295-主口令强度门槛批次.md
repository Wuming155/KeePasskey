## 2. 整改

### 2.1 AC①：单一判据 `MasterPasswordPolicy`（纯函数）

`app/ui/components/MasterPasswordPolicy.kt`：`verdictOf(passwordLength, strengthBits)` 三态（`TOO_SHORT` / `WEAK_REQUIRES_CONFIRM` / `OK`）。阈值登记 **`PD-38`**：长度 < **8** 阻断；强度 < **40 bits**（即 `PasswordStrengthBar` 较弱 / 中等分界，读数同源）显式二次确认；强度评估不可用（null）**不按弱**（不谎报）。强度评估经共享 Composable `rememberMasterPasswordStrengthBits`——内核评估快照用毕即擦，CPU 段 `Dispatchers.Default`（§3 规则 2），明文不进任何状态流。

### 2.2 AC②：两道闸接入（建库 + 改密，处置 = 阻断 + 二次确认 + 留痕）

- **建库向导**：`isFormValid` 加长度下限（短口令**阻断** + 输入框红字提示）；确认按钮前加弱口令闸——`MasterPasswordWeakConfirmDialog`（共用组件，文案含当前 bits 与建议值，中英成对），用户「仍要使用」⇒ `onWeakPasswordConfirmed` 留痕（`DatabasePickerViewModel.noteWeakMasterPasswordConfirmed` → `DebugLogBuffer`，不落明文）。
- **改密对话框**：同一判据、同一确认对话框；`enabled = passwordsMatch && size >= MIN_LENGTH`；留痕经 `SettingsViewModel.noteWeakMasterPasswordConfirmed`。

### 2.3 AC③／AC④：登记分支

取「写明理由并登记限界」：限界表新增 **§31**——主口令不纳入条目健康检查与在线泄露检测（理由：会话凭据缓存无挂载点 + 敏感现场引入网络依赖与明文创面 + 门槛判据已覆盖主要风险；残余风险与解除条件随条）；AC④ 的约束同步写入 §31（未来实施须沿用 k-匿名 + fail-closed，禁明文入日志 / 缓存 / 请求体）。
