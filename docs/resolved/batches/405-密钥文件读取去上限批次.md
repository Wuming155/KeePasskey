## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-435：密钥文件读取 1 MiB 上限把合法大密钥文件（如 2.28 MB）拒之门外——参考项目均无此上限

- **核实时间点**：2026-10-02；**核实方式**：用户装机走查（§404 debug 包）反馈「密钥文件稍微大一点，比如到 2.28 MB 时，就会提示无法读取密钥文件」；代码复核（HEAD `1b86de8b`）：全仓唯一 SAF 读取通道 `SafKeyFileAccess.readKeyFileBytesCapped` 以 `KEY_FILE_MAX_BYTES = 1 shl 20`（1 MiB，`KeyFileAccess.kt:72`）超限即 `TooLarge` 拒读（fail-closed 不截断），解锁页 / 改密对话框 / 子库挂载共用该通道。
- **参考调研（2026-10-02，定向查证）**：**KeePass 官方**（`KeePassLib/Keys/KcpKeyFile.cs`）与 kp2a（同源 `KeePassLib2Android/Keys/KcpKeyFile.cs`）对密钥文件**无任何大小上限**（仅拒「误选了数据库文件」的签名检查）；KeePassXC `keys/FileKey.cpp` 仅拒空文件、整文件读入。1 MiB 上限属本应用自设策略（P3-04 引入时的防御口径「密钥文件惯例 32~128 字节」），与三家参考皆不一致。
- **危害定性**：密钥文件内容是密钥材料本身（KDBX4 为整文件 SHA-512），一旦某库以 >1 MiB 文件作为密钥文件创建，本应用**永久无法读取该密钥文件**——除非降上限前该库已不可创建；等于「自伤型误拒」（同 §29 附件 1 MiB 误拒的形态）。P1-431 封印载荷瘦身已不再把密钥文件字节放进 Keystore，大文件的主要代价只剩一次整读内存（MB 级，可承受）。
- **整改方向（用户 2026-10-02 二次拍板：彻底去上限）**：**删除** `KEY_FILE_MAX_BYTES` 上限与 `KeyFileReadResult.TooLarge` 分型（不再有生产者），`readKeyFileBytesCapped` 改为**整流读入**（更名去「capped」）——与 KeePass 官方 / kp2a / KeePassXC 完全对齐（整文件读入，最多拒空文件）；字节擦除链与「绝不截断半截密钥」纪律保留；OOM 残余风险（恶意/异常 SAF 提供方返回超长流）按用户裁决登记进限界表。
- **验收标准**：
  ① 2.28 MB（及旧 1 MiB + 1 边界）密钥文件经 SAF 通道读取成功、解锁与改绑链路可用；仓内不再存在任何密钥文件大小上限；
  ② 字节擦除链语义零变化；`TooLarge` 分型及其穷尽分支随删除同步迁改，无死代码残留；
  ③ 全量 `test` 绿 + 门禁全 PASS；真机复测 2.28 MB 密钥文件解锁（用户走查）。

## 2. 整改内容

**过程留痕**：登记时整改方向为「上限提至 16 MiB」（保留 OOM 防御工程上限的折中案）；实施中被用户中途叫停并二次拍板「没必要做这个限制」——按终版口径（彻底去上限）实施，折中案从未进代码。

1. **`KeyFileAccess.kt`**：删除 `KEY_FILE_MAX_BYTES` 常量与 `KeyFileReadResult.TooLarge` 分型（生产者已不存在，不留死分型）；`KeyFileReadResult` KDoc 记录裁决与依据（密钥内容即密钥材料，任何截断都产出错误密钥）。
2. **`SafKeyFileAccess.kt`**：`readKeyFileBytesCapped` → **`readKeyFileBytes`**（整流读入，删超限判定与返回可空性）；`read()` 删 `TooLarge` 分支；分块读取 + `finally` 双清零（分块缓冲 / 可擦除内部缓冲）的擦除纪律一字未动；空文件 → `Empty`、流异常 → `Unreadable` 的 fail-closed 分型不变。
3. **消费点随删**（穷尽 `when` 分支，编译器强制——漏改即红）：`DatabaseKeyFileFactorResolver`、`KeyFileSessionCoordinator`（解锁页）、`MasterKeyChangeDialog`（改密对话框）各删 `TooLarge` 一行；`SettingsChildDatabaseController` 的 `else` 分支仅注释留痕分型名同步。
4. **限界表**：`已知工程限界.md` 新增 **§37**（【有意取舍】）——密钥文件读取无上限的 OOM 残余风险（触发前提＝用户主动选定该来源，无远程无交互触发面）、擦除纪律与空/不可读分型不变的边界、解除条件。
5. **测试**（`KeyFileByteReaderTest`）：原「恰好等于上限可读」「超限返回 null 绝不截断」两用例随被删对象（上限闸门）**退役**（测试资产纪律①：被测生产对象已不存在，退役理由本批留痕）；新增「旧 1 MiB + 1 边界整流读出」「用户实测 2.28 MB 级整流读出」两回归，断言逐字节完整读出。
