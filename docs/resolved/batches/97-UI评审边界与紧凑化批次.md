|---|---|---|
| 滑动条是「一侧粗指示条 + 一侧细线」的非标准样式，应换 M3 `Slider`/`RangeSlider` | **不成立且已满足**：`SliderTokens.ActiveTrackHeight == InactiveTrackHeight == 16.0.dp`，`SliderDefaults.Track` 以同一 `trackStrokeWidth` 画两条轨；生成器预览图取样，活动段与非活动段出现在**同一批行**（y 1418–1459 = 42px ≈ 14dp，抗锯齿内缩）⇒ 无粗细分段。`ValueSlider` 本就是标准 `Slider`（§96 已加数值气泡 + 跨档触感；气泡只在拖拽中出现） | M3 源码 + 预览图取样 + 独立视觉复核 |
| 字符开关是裸按钮、需补 48×48dp 热区 | **不成立且已满足**：调用点本就是 `FilterChip`；其内部经 `Surface(onClick)` 施加 `Modifier.minimumInteractiveComponentSize()` ⇒ 容器高 32dp 而**触控热区 48dp**。可采纳的只有「选中态无标记」⇒ 已按 97.2⑥ 补勾选图标 | `Chip.kt` + `Surface.kt`（1.5.0-alpha27） |
| 调试代码块 `[INFO]`/`[WARN]` 对比度可能不过 WCAG AA | **不成立**：实测对 `#0F172A` 底——`[ERROR] #F87171` **6.45:1**、`[DEBUG] #38BDF8` 8.33:1、`[INFO] #4ADE80` 10.25:1、`[WARN] #FBBF24` 10.69:1、普通行 14.48:1、空态 `#94A3B8` 6.96:1 ⇒ **全部 ≥ 4.5:1**。独立视觉复核亦为「对比度极佳、完全清晰可读」 | 逐色 WCAG 计算 + 预览图复核 |
| 顶部 SearchBar / FAB 缺 16dp 外边距 | **不成立**：FAB 由 `Scaffold` 默认 `FabPlacement` 给 16dp 边距；搜索胶囊位于 `TopAppBar` 标题槽，标题内缩本就是 16dp。可采纳的只有列表内容水平内缩与网格不一致 ⇒ 已按 97.2⑦ 统一 16dp | M3 `Scaffold` / `AppBar` 源码 + 调用点 |
| 弹窗遮罩是「无模糊的纯深灰」，应加模糊 | **不采纳**：M3 的 scrim 规范即**纯色**（`colorScheme.scrim`），本仓未自造遮罩；`CredentialFillConfirmScreen` 已是完整 Modal Bottom Sheet 形态（28dp 顶部圆角 + drag handle + `navigationBarsPadding`），§95 刚收紧过底部 padding。加模糊属非规范改动，且与「受保护窗口内最小化合成开销」无正面收益 | M3 规范 + 调用点 |

**另有一项报告未提但同批处置**：`AutofillPickerScreen` 请求方身份块中的包名 / 签名摘要长文本会折行——
**有意保留**：那是签名证书 SHA-256 摘要，用户需**逐位比对**才能完成首次绑定授权，
截断（即便中段省略）会把「可核验的锚点」变成「不可核验的装饰」，属安全语义降级，故不做省略。

## 97.5 如实声明

- 本批为**代码 + 宿主单测 + 静态源码守护 + 改动后预览图重新导出实测**（见 97.8）；
  **未**上真机渲染比对，触感 / 动效未做设备侧实测。
- 97.8 的重新导出是在**工作区含另一会话遗留未提交界面改动**的树上执行的（该部分改动不由本批署名，
  亦不在本批 commit 内）；本批取样的四处元素（编辑页输入框边框、解锁页禁用按钮、详情页快捷操作、
  密码库选择弹窗）与那些改动**不在同一界面区域**，取样结论不受其影响。
- `outline` 令牌改为不透明会**全局**影响取该角色的 14 处次要图标（如未选中 Switch 图标、条目删除图标）
  与全部 `OutlinedTextField` 未聚焦边框——这是本批**影响面最大**的一项，属「回到 MD3 名义对比度」，
  但观感变化不局限于报告点名的页面。
- `outlineVariant` 维持原值（1.24:1），故 FilterChip 未选中边框仍然**刻意含蓄**（M3 令牌表即
  `FlatUnselectedOutlineColor = OutlineVariant`）；本批只补了选中标记，未改其边框色。
- 报告 ⑤「列表项应成组进连续圆角卡片」**未采纳**：选择器候选行是 M3 标准 `ListItem` + `HorizontalDivider`
  列表形态，改为分组卡片属设计偏好，且该页为安全敏感入口（§89 已用不变量用例锁定其入口语义），
  不做无收益的布局改动。
- 报告 ⑤ 的「长路径折行」在 `AutofillPickerScreen` 请求方身份块中确实存在（包名 / 签名摘要折行），
  但那是签名证书 SHA-256 摘要，用户需**逐位比对**才能完成首次绑定授权，截断会把「可核验的锚点」
  变成「不可核验的装饰」，故**有意保留折行**，不纳入中段省略。
