## 2. 迁移与存根规则

1. **逐字、逐行原样搬移**：迁出节体的**每一行连同原折行**整行复制到新文档（**未重排、未重新折行**）——`check_verbatim_move.py` 比的是行多重集，重排会让它失效。实测读数见 §3.1（`MISSING_KINDS=0`）。
2. **原表保留存根**：`### <原编号与标题逐字不变>` + **该节全部规范句逐字保留** + 一行指针。
   - 规范句判定：把被软换行拆开的**逻辑块先合回一行**，再按 `。` 切句，取含「**不得 / 刻意不改 / 已接受 / 已裁决 / 刻意不做 / 刻意未**」的句子——**合行是为了保证句子完整**（首版未合行时出现「…省下的只是每 30 s 一次的文件探测（IO 线程），」被截断的残句，已修正）。
   - 指针形态：`> **非限界（2026-09-21 §255 迁出）**：本节属「说明 / 约定 / 验证现状」…，**不是**已接受的残余风险；完整正文见 [实现约定与验证现状.md](实现约定与验证现状.md#s3-5)。`
3. 存根里**不再复述**被移走的事实叙述——只留规范句 + 指针。
4. **两个新文档**按原编号组织（`## §1.2 …` / `## §7 …`），文首写明「本文件承接自 `已知工程限界.md` §255 批次迁出的内容（逐字原样）」；
   每节前加显式锚点 `<a id="s1-2">` / `<a id="s12">`（§x.y → `s` + 编号以 `-` 连接；单编号直接用 `s7` / `s12`），供存根指针直达。
5. 文首块**增补一段**（§255 立规，**4 行**）：本表只登记「客观限界」与「已裁决且不打算整改的工程取舍」两类；说明 / 约定 / 验证现状与宿主环境现象**不属本表**，去向见各节存根与 `docs/README.md`。
