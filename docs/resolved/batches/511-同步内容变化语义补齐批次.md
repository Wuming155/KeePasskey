## 2. 实施与验收

- **前提复核（认领时）**：直读 `KdbxContentComparator.entryChanged`（只比 `history.size`，无 `expires`）与 `changed`
  （仅 `deletedObjects` + 分组树），并核对编辑页已具备有效期写入口 ⇒ `PD-20` 重开条件 ① 成立。

- **改动一（条目到期语义）**：新增 `expiryChanged(times, times)` —— `expires` 翻转即变更；
  仅在**生效**（`expires == true`）时比较 `expiryTime`，避免禁用到期时陈旧日期误报。
  **仍不**纳入 `lastModificationTime` / `lastAccessTime` / `usageCount`（使用性字段，原口径保留）。

- **改动二（历史内容级）**：`entryChanged` 的 `history.size` 判据改为 `historyChanged(list, list)`
  ——先比条数，再逐条复用 `entryChanged` ⇒ 等条数原地改写同样判为变更。递归有界（历史快照自身历史通常为空）。

- **改动三（库级 Meta / 头部语义）**：`changed` 新增 `metaChanged`（名称 / 描述 / 默认用户名 / 回收站开关与
  UUID / 模板组 / 自定义图标 / MemoryProtection / Meta customData / 历史预算）与
  `headerSemanticChanged`（加密算法 / 压缩 / KDF 语义参数）；**排除随机材料**（`masterSeed` / `encryptionIv` /
  KDF `salt` / `seed` / `secretKey` / `associatedData`）与会话定位字段（`lastSelectedGroup` / `lastTopVisibleGroup`）。

- **裁决同步（主代理收口）**：`产品裁决登记.md` `PD-20` 增「补记（2026-10-14）」标记重开条件 ①② 已满足并实施，
  核心裁决（两侧口径刻意不同）不变；`已知工程限界.md` §10（已迁出 stub）补一行指向该补记。
  比较器类 KDoc 的「不覆盖历史内容 / 无 expires 写入者」过时陈述一并改写。

- **测试（`KdbxContentComparatorTest` 8 → 14 例）**：新增到期语义正反例（翻转 / 生效期比较 / 禁用期不比）、
  历史等条数改写、库级 Meta 逐字段、会话定位与时间戳不误报、随机头部材料不误报而同语义参数（算法 / KDF 迭代）
  判为变更；原「仅 times 不判变更」用例**收窄**为只余使用性字段（原含 `expires` 项已按新口径移出）。

- **全量单测**：`./gradlew.bat test --max-workers=1` EXIT 0；`count_test_results.py` 读数
  **`xml=572 tests=3741 failures=0 errors=0 skipped=15`**（§510 基线 3736 ⇒ +5）。
