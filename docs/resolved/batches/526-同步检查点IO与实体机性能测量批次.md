# §526 同步检查点 IO 与实体机性能测量批次

<a id="s526"></a>

## 1. 闭环范围

本批关闭 ISSUE-P2-626。问题是前台同步收尾时对正式 KDBX 求 SHA-256，曾在调用线程遍历整库，可能占用 UI 主线程。

## 2. 实施与验收

- 正式文件类型检查和 SHA-256 读取均在 Dispatchers.IO 执行；读取仍由 DatabaseSession 的会话锁保护，保持摘要对应活动库和正式文件版本。
- app JVM 全量通过：2522 项，0 失败、0 错误。
- API 37 Redmi 4X 实体机运行 SyncCheckpointIoDeviceTest：2 项通过，0 失败、0 错误，StrictMode 未发现 Main 磁盘读取。
- 大库样本为应用实际序列化的合成 KDBX，文件 8,392,727 字节。实测摘要耗时 55 ms；哈希期间 Main 队列回调延迟 2 ms，首个 vsync 回调延迟 17 ms，均早于摘要完成。数据来自实体机 logcat 的测试专用度量输出。
- 非空设备 XML：app/build/outputs/androidTest-results/connected/api37-evidence/TEST-SyncCheckpointIoDeviceTest-API37.xml；XML 内设备序列号为 1c859bcc7d24。

## 3. 限制

- 本批只测一台 API 37 实体机和一个约 8.4 MB 的合成库；该读数不外推到低速存储或更大的库。
- 本项关闭的是主线程整库读取问题。跨写入可信回执与竞态正确性仍由 ISSUE-P2-624 单独跟踪。
