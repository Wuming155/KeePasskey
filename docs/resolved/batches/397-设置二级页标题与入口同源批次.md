# §397 设置二级页标题与入口同源批次（用户截图反馈：入口与页首标题不一致，会话内整改随批归档）

> **触发**：2026-10-01 用户截图（设置 → 安全页）反馈：「这个选项明明是从设备解锁与安全策略点开，
> 但是上方显示的却是安全防护。请你纠正一下这个问题，并且排查一下有没有类似的问题，如果有请你解决。」
> **结案条目**：会话内整改（未占 ISSUE 编号），随本批次文档归档。

---

## 0. 根因与全量排查

- **根因**：二级页脚架 `SettingsSubscreenScaffold(titleRes = …)` 的标题字符串与设置页入口行
  `ModernSettingsRow(title = …)` **各自持有独立字符串资源**，文案演进不同步——用户从
  「设备解锁与安全策略」（`settings_security`）点入，页首却显示 `sec_screen_title`「安全防护」。
- **全量排查（核实 2026-10-01，逐入口比对 `SettingsScreen.kt` 入口行与各二级页 `titleRes`）**：
  设置页全部二级入口中**三处不同源**：

  | 入口（SettingsScreen） | 二级页页首（整改前） | 二级页 |
  |---|---|---|
  | `settings_security` 设备解锁与安全策略 | `sec_screen_title` 安全防护 | `SecuritySettingsScreen` |
  | `settings_sync` 云端同步 | `sync_screen_title` 同步与云备份 | `CloudSyncScreen` |
  | `settings_health` 健康度检查与审计 | `health_screen_title` 密码健康检查 | `HealthCheckScreen` |

  其余入口均同源无此问题：密码库与加密（`settings_database`）、双重认证 TOTP
  （`set_totp_entry_title`）、自动填充与 Passkey（`settings_autofill`）、外观（`settings_theme`）、
  调试（`debug_title`）、关于（`settings_about`）、特权浏览器（`settings_passkey_privileged_browsers`，
  父级入口在 `AutofillSettingsComponents.kt` 亦同源）。

## 1. 整改

| 文件 | 变更 |
|---|---|
| `SecuritySettingsScreen.kt` | `titleRes` 改指 `R.string.settings_security`（与入口同源） |
| `CloudSyncScreen.kt` | `titleRes` 改指 `R.string.settings_sync` |
| `HealthCheckScreen.kt` | `titleRes` 改指 `R.string.settings_health` |
| `strings.xml`（zh / en 成对） | 退役 3 条仅剩零消费者的标题串：`sec_screen_title` / `sync_screen_title` / `health_screen_title` |

**统一口径**：二级页页首标题一律与用户实际点入的入口行**同一字符串资源**，从机制上杜绝
再漂移（而不是逐处对齐文案——对齐文案仍是两份资源，还会再漂）。

**行为不变式**：三个页面各自的分区标题、行文案、回调与状态逻辑零改动；`values-en` 英文入口
串（Device Unlock & Security / Cloud Synchronization / Health Check & Audit）成对生效。
