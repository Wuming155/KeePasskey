## §111 自动填充「二次确认」路径凭据交付修复批次（2026-09-17，app）：ISSUE-P2-88

> **批次性质**：闭环 `ISSUE-P2-86` 的**同源兄弟路径**——库**已解锁**时自动匹配候选的「二次确认」路径，
> 用户点「确认填充」后**目标输入框始终为空**。
>
> 本批的做法是**先取官方契约、再由契约推出缺什么**，而不是试错：官方 `Dataset.Builder#setAuthentication`
> 明写两条要求，而该路径**两条都违反**；补上缺失的另一半后真机通过，并以**负向对照**把「只补一条不够」钉成回归。
>
> 同时取得一条**比推断更细**的实测结论：框架对回传数据集是 **replace 语义**（按返回内容原样填），
> **不会**复用服务端候选数据集里已带的值。该结论只在「回传数据集不完整」时才暴露——而它恰恰在本批**第一轮真机上暴露了**。

### 111.2 官方契约（本批的定位依据，**取代** 111.1 的就地更正所指的判断）

`android.service.autofill.Dataset.Builder#setAuthentication`（**数据集级**认证，即本条路径所用形态）原文两条：

> "Once you complete your authentication flow you should set the activity result to `Activity.RESULT_OK` and
> **provide the fully populated dataset or a fully-populated response by setting it to the
> `AutofillManager.EXTRA_AUTHENTICATION_RESULT` extra**. **If you provide a dataset in the result, it will
> replace the authenticated dataset and will be immediately filled in.**"
>
> "Note: **Do not make the provided pending intent immutable by using `PendingIntent.FLAG_IMMUTABLE` as the
> platform needs to fill in the authentication arguments.**"

⇒ 确认路径**同时违反两条**：① PI 不可变；② 结果**未**携带数据集（返回的是 `Bundle.EMPTY`，其语义是「没有东西可填」）。
**上一轮只修 ① 因而无效**——`FLAG_MUTABLE` 是平台强制、**必要但不充分**。

> **一句必须留痕的口径陷阱**：官方那句「可以用 `Bundle.EMPTY` / null 以避免 Android 12 崩溃」出自
> **`FillResponse.Builder#setAuthentication`（响应级）**，原文是「set the extra with the fully populated response
> (**or null if the screen cannot be autofilled**)」。它是**崩溃规避**条款，**不是**「可以不回传数据集」的许可。
> 把响应级的 `null/Bundle.EMPTY` 允许套用到**数据集级**，正是本条缺陷的成因。

### 111.5 **比推断更细的实测结论**：框架对回传数据集是 **replace 语义**

第一轮（契约已补、但回传数据集**不完整**）的真机**原始留痕**：

```
09-17 10:19:50.165 21810 21810 I AutofillClientTest: 客户端状态 #1 AC3-STATUS username=[] passwordLength=12 usernameFilled=false passwordFilled=true
```

即：**口令被写入、用户名框为空**——因为那一轮回传的数据集里**只有口令字段**。
⇒ **框架按回传内容原样填（replace），不会复用服务端候选数据集里已带的值**。
官方那句 "it will **replace** the authenticated dataset and will be **immediately filled in**" 与实测吻合，
且实测给出了官方文字未明说的推论：**回传数据集必须完整**——只回传部分字段就只填部分字段。

**与既有实现的两点连带（已在本批一并守住）**：

1. **不得摘掉候选数据集自带的真实值**：`ISSUE-P3-42` 会话授权宽限（`skipRepeatConfirmation == true` 时**不挂**认证 PI）
   **依赖数据集自带值**；摘掉会让「30 秒内免二次确认」直接填不出值。
2. **交付载荷构造收敛为单一实现**（`AutofillAuthResultDelivery`）：选择器与确认页共用，
   避免两处各写一份而再次漂移。

### 111.6 过程中暴露的第二个缺陷：**认证 Activity 不得假设任何异步缓存已就绪**

第一轮之所以回传了不完整的数据集，根因不在框架，而在**取数**：`AutofillPickerViewModel` 的条目缓存是
`init` **异步**填充的，而确认页是**按需创建**该 ViewModel（`by viewModels()` 首次访问发生在用户点「确认」那一刻），
那时缓存尚未就绪 ⇒ 用户名取到空串 ⇒ 数据集里只剩口令字段。
修法：`resolveCredentials` 的用户名改为「缓存命中即用缓存，**未命中回退仓库快照**」；**锁定态仍是 fail-safe**
（空用户名降级，`ISSUE-P2-52` 语义不变），并新增 `AutofillPickerViewModelCredentialLookupTest` 回归该坑。

> **可复用的工程教训**：认证 Activity 可能是在用户点确认的**那一刻**才被创建的对象，
> 它**不能**假设任何 `init` 期异步加载已完成。这条与 111.5 的 replace 语义合起来，才是「契约已满足却仍填不出」的完整解释。
