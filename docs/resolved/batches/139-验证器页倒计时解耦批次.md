## 1. 原条目（自 `ACTIVE_ISSUES.md` 原样收录）

### ISSUE-P3-182 验证器页倒计时与列表内容未解耦（整页每秒重建）

- **背景**：`ISSUE-P3-175` ② 的**后半**（§132 批次转登）：该页把秒级 tick 并入整页 `combine`
  （`app/src/main/java/com/keepasskey/app/ui/screens/authenticator/AuthenticatorViewModel.kt:58-115`），
  tick 的**唯一作用是触发重算**（变换体内该参数被丢弃为 `_`，剩余秒数由 `OtpEngine.getRemainingSeconds(period)`
  现算）⇒ 每拍都会新建整份 `items`（`List<TotpCardItem>`）并带动全部卡片重组。
  `§132` 已把该页的**逐条挂起调用**换成批量通道（每拍 T 次 → 1 次），但**整页每秒重建未消除**。
- **整改方向**（`ISSUE-P3-175` AC ② 原文口径）：列表内容只在**周期边界**重建；倒计时由卡片内读
  共享刻度现算（照抄列表页 `EntryTotpBadge` 的窄通道模式）。具体需要：
  ① `TotpCardItem` 去掉 `remainingSeconds`；
  ② `AuthenticatorScreen` 三处（`isUrgent` 判据 `/ 进度环分母 / 倒计时文本`）改为按卡片收到的刻度 +
  `item.periodSeconds` 经 `OtpEngine.getRemainingSeconds` 现算；
  ③ 验证码刷新走与列表**同构**的「周期序号变化才重算」通道（`§114` / `§120` 已确立该口径）。
- **验收标准**：`ISSUE-P3-175` 的两条运行期判据在此条落地——「1 Hz 刻度不触发整页状态新建」
  与「同拍内批量取码只调用一次」；`§120` 的周期口径用例（任一条目自身周期序号变化才算翻转）全绿；
  倒计时相位与进度环分母逐项不变（含 `period != 30` 的条目）。
- **核实时间点与方式**：2026-09-17 读 `AuthenticatorViewModel.kt:58-115`、
  `AuthenticatorUiState.kt:8-22`、`AuthenticatorScreen.kt:231/308/315` 核实（§132 开工期一并读得）。
- **风险提示**：属**状态形状 + UI 三处联动**的改动，回归面集中在**宿主不可渲染的 UI**
  （须以接线守卫 + 编译期契约承担，并核对预览 / 截图基线）；`§120` 已把「全局 30 秒」这一错误前提
  从分母中移除，**不得**在解耦过程中把它带回来。

## 2. 开工复核结论（含两条 AC 未写、必须自己发现的前提）

1. **AC 前提成立**：`timerSecondsFlow` 确为 `combine` 的占位参数（变换体内 `_` 丢弃），其唯一作用是驱动重算；
   `TotpCardItem.remainingSeconds` 每拍都变 ⇒ 整份 `items` 每拍新建。复核方式：逐行读
   `AuthenticatorViewModel.kt` / `AuthenticatorUiState.kt` / `AuthenticatorScreen.kt`（本批开工期全读）。
2. **可复用的同构通道已存在**：`VaultListTotpTracker`（§114 拆出，§120 定为「下发秒级刻度 + 按条目自身周期判边界」
   + §132 的周期集合快照缓存）正是 AC ③ 要求的形态，**且 AC 明确写「与列表同构」**。
3. **本批新决策：把它提升为跨页共享协作者（更名 + 迁移）**。直接 `import` 会引入本仓**首个 `screens → screens`
   依赖**（列表页包 → 验证器页包的兄弟耦合），且类名/KDoc 绑定「密码库列表页」即陈述不实。
   故 `ui/screens/vault/VaultListTotpTracker.kt` → `ui/model/TotpCountdownTracker.kt`（`ui/model` 已是
   `EntryDisplayDispatcher` / `EntryIconPresenter` / `IconBitmapCache` 等**展示层协作者**的归处）。
   **同样重要的反面理由**：本仓 P1 整改已把「三份逐字重复的秒级节拍」收敛为一份，**再复制一份即为回归**。
4. **复核发现的关键语义差异（AC 未写，照抄会做出错行为）：HOTP 卡片不得取窄通道之码**。
   `liveCodes` 是**时间驱动**之码，只在周期边界重算；而 HOTP 之码由用户**显式推进计数器**决定
   （`advanceEntryHotpCounter` 先算码 → 计数器 +1 落库 → 返回该码）。改善前的实现里，推进成功后
   `userMessageFlow` 变更会令 `combine` 重跑并重算，卡片显示的是**推进后**投影之码；
   若照抄列表页徽标的 `liveCodes[id] ?: fallbackCode`，卡片会一直显示**刚被消费掉的那个码**
   （该码正是用户刚复制走的），直到某个条目的周期边界才被覆盖 —— 属**新增缺陷**。
   既有口径支持按 `isHotp` 分流：详情页 `EntryDetailTotpTicker` 的取码前置条件即为
   `it.totpCode != null && !it.isHotp`，显示侧取 `liveTotpCode ?: entry.totpCode`。
   ⇒ 验证器页取码判定为 `if (item.isHotp) item.codeRaw else liveCodes[id] ?: item.codeRaw`。
5. **`codeFormatted` 一并移除（超出 AC ① 字面，理由）**：AC 只要求去掉 `remainingSeconds`；但显示文本必须改为
   由**实时码**格式化，若继续在状态里另存一份「格式化后的投影之码」，就会出现同一信息的两个来源
   （实时码 / 兜底码）与两处格式化实现，必然漂移。故格式化提为 `internal fun formatTotpCode(raw: String?)`
   （**单一实现**：卡片显示与用例断言共用，ViewModel 不再产出格式化文本），`TotpCardItem` 只留 `codeRaw`
   （已归一：剔除空格，与窄通道之码同形态）。
6. **搜索框回显仍直接接 `searchQueryFlow`**：内容流 `totpEntriesFlow` 已按搜索词过滤，但若把回显也交给它，
   键入到回显之间要多等一次「条目过滤流水」。故 `uiState` 的 `combine` 保留 `searchQueryFlow` 作为回显参数
   （与 `VaultListViewModel` 把 `filterParamsFlow` 与内容流并列的既有结构同形）。

## 5. 边界如实声明（不得外推）

1. **无任何性能实测**。本批结论全部是**源码结构**结论；**不得**宣称百分比收益，**不得**推断真机帧率 / 耗电。
2. **AC 的两条运行期判据未按原文落地**（「1 Hz 刻度不触发整页状态新建」与「同拍内批量取码只调用一次」）：
   宿主侧无「整页状态被新建了几次」的计数通道（需引入测试替身与订阅编排），故与 §129 / §132 同口径，
   以**源码文本守卫**替代。**不得**读作「已用运行期计数证明」。
   （「单拍内批量取码只调用一次」的**部分**行为面依据取自迁移后的 4 例：它们以计数型仓库断言
   每拍 / 每周期边界的 `calculateEntryTotps` 调用次数。）
3. **设备侧渲染未核对**：Compose 组件只能在设备侧渲染，本批**未跑** `connectedDebugAndroidTest`、
   未跑截图 / 预览渲染、未跑 `lint` / `assembleRelease`。UI 侧证据＝**编译期契约 + 接线守卫 + 预览夹具同形改写**。
   预览夹具的数值口径刻意保持与改动前一致（剩余 18 秒、`"123 456"`），但**未渲染比对像素**。
4. **倒计时相位来源发生变化**（如实记录，非缺陷）：改前由 `combine` 每拍用**真实墙钟**现算，改后取**窄通道的
   1 Hz 刻度**（`tickerFlow` 自订阅起点计时）；两者在周期边界处**可能存在 ≤1 拍的相位差**，与列表页徽标
   现有口径一致（§120 已采用同一形状）。**未做设备侧逐帧核对**。
5. **`liveCodes` 命中前显示的是投影兜底之码**：条目刚出现、尚未等到下一次周期边界刷新时取
   `item.codeRaw`（投影层即时计算之码）——与列表页徽标 `liveCodes[id] ?: 投影之码` 同一语义，
   是**首帧兜底**而非过期码。若查询词变化使条目集合变化，新出现的条目同样先取投影兜底之码。
6. **会话锁定后实时码的驻留（新登记）**：`TotpCountdownTracker.liveCodes` 是内存 `StateFlow`，**未**注册
   `SessionLockObserver`；锁库后节拍停表、无人订阅，其值会留到 ViewModel 被销毁或下一次刷新覆盖。
   该驻留自 §114 起由**列表页**持有（本批只是让验证器页复用同一对象），本批未改其擦除语义，
   已登记 [`../../architecture/已知工程限界.md`](../../architecture/已知工程限界.md) **§13**（含解除条件）。
7. **`isHotp` 取投影之码的前提**：依赖「HOTP 计数器写回会触发条目流重新投影」。
   `RealVaultRepository.advanceEntryHotpCounter` 经 `entryWriter.updateEntryOtpConfig` 落库
   （不产生历史修订），改动前该页同样依赖重投影 + 重算；本轮**未在设备侧实测**该链路的界面表现。
8. **迁移的机械面**：更名涉及 6 处引用（2 个守卫测试的路径常量 / KDoc、1 个用例文件、2 处 KDoc 注释）。
   编译器覆盖了全部代码引用；**KDoc / 注释引用无编译器保障**，已用全仓 `grep` 复核（含 `docs/` 下
   仅历史归档文件保留旧名——归档正文按约定**只搬迁不改写**）。
9. **变异验证 1 项**：把 `AuthenticatorScreen` 的取码回退为 `item.codeRaw`（即「不接窄通道」）⇒
   `AlgoHotPathGuardsTest > 验证器页卡片状态不得随秒级节拍重建` **FAILED** ✔（随后已还原，全量复跑绿）。
