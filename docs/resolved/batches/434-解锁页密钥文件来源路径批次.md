## §1 过程留痕：首次「真机核验不通过」实为过期二进制（**非缺陷**）

**回执现象**＝状态段完全不出现，而导入回执（`dbset_keyfile_import_memory_done`）正常显示。
该组合在 §433 代码里**自相矛盾**——产生该回执的两条分支在同一次 `copy(...)` 内同时写
`keyFileCopyDisplayName`（`SettingsMasterKeyChangeController.importRememberedCopy`），
**不可能只出现前者**。此自相矛盾正是未被误判为「实现写错」的原因。

三条独立证据坐实「设备跑的是旧包」：

| 项 | 值 |
|---|---|
| 本地 `app-debug.apk` 构建时间 | `19:45:39` |
| 设备 `lastUpdateTime` | `19:45:42`（同一份包） |
| 该 APK 内 `KeyFileCopyStatusSection` / `refreshKeyFileCopyName` | **0 / 0**（不含 §433 代码） |
| §433 源码最后改动 / 提交 | `19:53~19:54` / `20:03:40` |

⇒ 走查跑在**早于本批改动**的二进制上，实现从未被执行过。

**辅助确认（只读）**：`adb shell run-as com.keepasskey.debug ls -l files/keyfiles` 显示副本
`08f8c3ef…fd7c9.kfc`（346 B，16:28 已落盘），且 `sha256("phellords.kdbx")` 与该文件名**完全一致**
——即副本早已存在，只是旧包没有渲染它的代码。

**教训（建议升格为流程规则，待用户裁决后落 `AGENTS.md` 规则 6）**：装机走查前须核对
设备包时间与 APK 构建时间（`adb shell dumpsys package <pkg> | grep lastUpdateTime` ×
APK 文件 mtime）。「回执显示成功、新 UI 不存在」与真缺陷在观感上**完全一致**。

| 预览 | `UnlockContentErrorWithKeyFileInfoPreview` 补 `keyFileSourcePath`（真机同形副本路径、折叠态） |

**关键取舍①（手势冲突）**：来源行刻意落在**可点击行之外**——原来整行点击是「清除密钥文件」，
若把来源行纳入同一手势，用户想看全路径就会把密钥文件清掉。

**关键取舍②（安全口径）**：来源路径不含密钥材料（副本文件名是库 id 的 SHA-256 摘要），
且**不参与任何派生**；「默认折叠、按钮才展开」是**呈现层选择**，不承担保密职责
（同一屏的库卡早已明文显示同类绝对路径），故不按敏感数据铁律走。

**状态卫生**：来源路径随「取消选择 / 读取失败 / 活动库切换」三处一并归零，绝不残留陈旧指向
（切库后显示上一库的路径会直接误导因子归属）。

## §4 装机回执修正：展开态改为**换行铺满**（同批追加，2026-10-03）

**回执**（用户原话）：「完整的路径在当前空间根本看不全」。

**根因**＝§2.2 的展开态仍是**单行 + `Ellipsis`**——固定行宽下 118 字符的真实路径必然截尾，
「展开」等于没展开。**该态此前没有任何 `@Preview`**（`expanded` 内持 `remember`），于是又一次
落入「新态只能靠真机撞见」的同一形态（ISSUE-P3-340 / P3-457）。

**整改**：

- `KeyFileSourceRow` 拆为「状态包装 + `KeyFileSourceRowContent(path, expanded, onToggle)`」，
  状态外提使展开态**可被预览覆盖**；
- 展开态：`maxLines = Int.MAX_VALUE` + `softWrap = true` → **换行铺满**（路径含 `/`，系统排版
  在斜杠后断行，天然可读）；折叠态保持单行中间省略；
- 补两态预览（折叠 / 展开，各浅深两档）至 `UnlockScreenPreviews.kt`；包装已重生（113 枚）。

**读数**：全量 test 绿 `xml=514 tests=3351 failures=0 errors=0 skipped=13`（与 §2.2 持平——
纯布局态无 JVM 可测断言，判据落在预览导出图）；门禁 9/9 PASS；截图包装编译门禁绿。

**过程留痕（并发工作线）**：本批实施期间另一工作线在**同一工作区**并发提交 / 重置，先后产生
`0c7ab8ae`（把本线的在途回退一并卷入，提交信息未能反映）与 `cd69de70`（将该回退整体撤销，
即**复活用户已裁定移除的设置页段**）。本线以「`git checkout origin/main -- .` 无损还原 + 在其上重做」
收口，**未做任何历史改写**。另：一次全量 `--rerun-tasks` 曾在并发构建干扰下于
