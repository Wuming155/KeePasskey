# §393 空状态入口就地弹框批次（用户裁决变更：废除 §392 直达路由口径）

> **触发**：2026-10-01 用户在 §392 实现态装机后继续反馈：「弹出打开已有 KDBX 密码库这个框，
> 从背景上就能看到，后面还有个新建密码库什么的」——即 §392 的「直达路由 + 自动展开」虽然
> 消除了二次点击，但对话框弹出时**背景仍是库管理页**，该页自带的「新建密码库 / 导入已有库」
> 入口与来源页（解锁页空状态两枚卡片）同义并列，嵌套重叠的观感依旧。
> **形态裁决（用户二选一拍板）**：a) 直达时隐藏库管理页自带入口；b) **弹框直接在首页弹出**。
> **用户选 b**——此裁决**推翻** §392 §1.1 的「对称化（直达路由）」选择。
> **结案条目**：本批为用户即时反馈的会话内整改（未占 ISSUE 编号），随本批次文档归档。

---

## 0. 根因与核实

- **核实（2026-10-01）**：直读代码——§392 后解锁页空状态两枚卡片经
  `createRoute(openCreate/openImport = true)` 导航到库管理页，`DatabasePickerScreen` 收到
  `autoOpenImport/autoOpenCreate` 后自动展开对话框；**对话框之下就是库管理页自身的
  「新建（实心主）/ 导入（描边次）」两枚全宽按钮**（§391 AC② 的产物），用户从弹框背景
  直接看见同义入口。
- **根因**：§392 只把「跳页 + 二次点击」压缩成「跳页 + 自动弹框」，但**宿主页面选错了**——
  对话框的业务宿主（库管理页）与视觉宿主（同一页）天然带着自己的同义入口，
  「入口嵌套」在页面层级上无解。
- **结论**：要彻底消除嵌套，对话框必须挂在**不含**同义入口的页面上，即解锁页本身。

| 层 | 变更 |

**建库 / 导入成功后的落点**：对话框由 ViewModel 内部关闭（与库管理页同一路径）；登记生效后
`UnlockViewModel` 对 `getDatabases()` 的既有观察把空状态切换为解锁表单——全程零导航，
不存在「取消后落在哪」的问题（本会话早前曾以「取消后 popBackStack」修补直达路径，
随宿主更换一并作废）。

## 3. 如实声明

1. **裁决变更留痕**：§392 §1.1 用户曾三选一拍板「对称化（直达路由）」，本批经用户二选一
   拍板「弹框直接在首页弹出」将其推翻——两次均为用户本人真机体验后的主动选择，
   非代理代裁；§392 批次文档按「只搬迁、不改写」纪律保持原样。
2. **真机走查不完整**：装机后用户正当面使用设备，冒烟中断——已证实「打开已有库」对话框
   就地弹出；「新建密码库」向导弹出、取消后停留解锁页、建库后空状态切解锁表单三条
   待用户自然核验（组合结构上取消 = 关窗留在解锁页，无任何导航）。
3. **非导航宿主行为面扩大**：自动填充解锁 / 凭据创建窗口等非导航宿主的空状态两枚入口
   此前是空响应（回调默认空），现也可就地弹框建库 / 导入——属顺带的能力补齐而非回归；
   如需收窄须显式传空回调，本批不加防御性分支。
4. 未触 `androidTest` / 原生面；`lint` 未单独跑（无 CI 强制点）。
