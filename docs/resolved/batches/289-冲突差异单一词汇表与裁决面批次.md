## 2. 整改

### 2.1 AC①：`modifiedFields` 机读词汇表（单一真相源）

词汇常量化于 `KdbxMerger`（产出 / 消费共用）：标准字段＝KDBX 标准字段键（`KdbxConstants.Fields.*`）；自定义字段＝`CUSTOM_FIELD_CONFLICT_PREFIX`（`"custom:"`）+ 字段名；标量＝`CONFLICT_KEY_ICON_ID / CUSTOM_ICON_ID / OVERRIDE_URL / QUALITY_CHECK`（与 §287 `MERGED_SCALAR_FIELDS` 同表外显）。三处产出统一切换：`KdbxEntryMerger`（标准 / 自定义 / 标量三通道）、`BothModifiedEntryCollector`（`differingStandardFields` → `differingConflictFields`，补齐自定义与标量比对）。界面（`ConflictResolutionViewModel.buildConflictedField`）与裁决（`resolveConflictByFields`）均消费同一份键——两处各算一份 diff 的形态拆除。

### 2.2 AC②：自定义字段可见可裁决 + 整条兜底入口

- **可见**：界面差异行 100% 由 `modifiedFields` 驱动（含自定义字段与四个标量）；自定义字段行标签＝字段名，`isProtected` 值与密码同型掩码（敏感数据铁律）；标量行取值如实呈现（iconId 数字 / 自定义图标 UUID / overrideUrl / 是否）。
- **可裁决**：`resolveConflictByFields` 扩展词汇——`custom:` 键按名替换自定义字段（远端缺失为安全 no-op），四个标量键逐项 `copy` 覆写；未选字段保留本地底版（语义不变）。
- **兜底入口**：条目卡片新增裁决方式选择行（`EntryResolutionMode`：**按字段裁决**（默认）/ **整条取本地** / **整条取云端** / **双方保留（云端存副本）**）；非逐字段时字段行停用并呈提示，决策走 `resolutions` 整条通道（`fieldResolutions` 不再含该条目——这正是此前「恒真吞掉整条分支」的结构性根因，本批从装配侧解除）。

### 2.3 AC③：`DUPLICATE_BOTH` 真实可达

选择「双方保留」⇒ `resolutions[entry.id] = DUPLICATE_BOTH` ⇒ `KdbxMerger.resolveConflict` 的副本分支（新 UUID + 「(云端冲突副本)」改名）真实落库。整条取本地 / 取云端同理恢复可达。

### 2.4 波及面适配（词汇改键）

既有断言随之对齐（非行为回归，属词汇更正）：`KdbxMergerV2Test` 三处（`"密码 (Password)"` → `Fields.PASSWORD`；`"自定义字段: OTP"` → `"custom:OTP"`）、`KdbxMergerTest` 一处、§287 `KdbxMergerScalarFieldsTest` 一处（`contains("图标")` → `CONFLICT_KEY_ICON_ID`）、`ConflictResolutionViewModelTest` 的夹具键。**测试资产纪律①**：只改期望，未删用例。
