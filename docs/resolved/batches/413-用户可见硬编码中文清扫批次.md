## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-453：用户可见文案硬编码中文清扫——KdbxResult message 通道等致英文界面残留中文

- **核实时间点**：2026-10-02；**核实方式**：用户真机走查「英文界面时有的提示依然有中文」；语料审计（代码引用键 vs `values-en` 全量比对）证明资源键**无缺失**（`cancel`/`ok` 为框架 R 误报）——残留根因是**代码硬编码中文**绕过资源通道，典型如 `SessionOpener` 的 `KdbxResult.Failure(t, "解锁密码库失败: …")`：message 直通 `UiMessage(R.string.op_failed, listOf(result.message))` 拼进用户可见提示。
- **背景**：`KdbxResult.Failure(message)` 的 message 形参在 database / sync / app 三层有大量硬编码中文（含内嵌异常细节），既不可本地化，也存在把异常细节（可能含路径 / 端点内容，ISSUE-P3-311 同源红线）透出到 UI 的信息面问题。
- **验收标准**：
  ① 盘点三层 `KdbxResult.Failure` / `UiMessage` 硬编码中文清单（审计脚本化，防回潮），按「类型化错误码 → 资源键映射」收敛（message 仅留日志面，UI 面只出资源文案）；
  ② 英文界面走查解锁失败 / 保存失败 / 同步失败三类高频提示零中文；异常细节不再透出 UI（进日志）；
  ③ 文案双语；全量 test 绿 + 门禁全 PASS；真机走查留痕。

### 2.3 过程缺陷（本批真实踩到，逐条留痕）

1. **KDoc 里的 `*/` 会提前关闭注释**：`if...else` 注释写 `res/values*/strings.xml`（`values*/` 中的 `*/`）导致整个 KDoc 块提前终结、下游 200+ 行报 "Expecting a top level declaration"。已改为「`res/values` 下的 strings.xml」。**同类写法（注释里出现 `*/`）全仓排查一遍**。
2. **顶层 `@Composable val`（无 backing field）在本仓 Kotlin 版本不合法**——编译器判定「注解不适用于 top-level property without backing field」；而在 getter 上标 `@Composable` 又会把每个调用点逼进组合上下文。**改为 `@Composable fun`**。
3. **非 Composable 上下文不能用 Composable 扩展**：首轮把 `result.textArg` 定为 Composable 属性后，`AuthenticatorViewModel` / `MasterPasswordUnlockSession` 等 8 处（都在 `viewModelScope` 里）全部编译失败。**补同名重载 `textArg(strings: StringsProvider)`** 供注入侧使用。
4. **Kotlin 扩展跨包必须显式 import**：18 个调用点逐个补 `import com.keepasskey.app.ui.model.textArg`（脚本批量插入 + 剔除自引用）。
5. **位置传参被打乱**：`strings` 参数插在 `SettingsMasterKeyChangeController` 构造中段，导致 `SettingsViewModel:155` 把 `StringsProvider` 传给 `activeDbId: suspend () -> String?`；同类隐患在 `MasterKeyChangeTaskTest` 的 10 处位置调用里。**新参数一律置于末位**（`EntryEditViewModel` 改用全限定 `KdbxErrorTexts.resIdFor(code)` 以省 import 行）。
6. **属性 → 函数调用，括号数变化**：`(result as KdbxResult.Failure).textArg))` 改成函数调用后**少一个 `)`**（属性不消耗括号，函数调用消耗）→ 3 处 "Expecting ')'"。
7. **`tier1` 红线被自己顶穿**：`SettingsViewModel` 502 / `EntryEditViewModel` 501（HEAD 基线均为 500）⇒ 门禁 `[1/8]` 转红。已按「行数净变化归零」对账（命名参数 +1 行 ↔ 合并两行注释 −1 行），**回到 500 / tier1=0 / tier2=36/36**。

### 2.4 测试侧同步

- `core/KdbxResultTest`：兜底语义由「固定中文通用文案」改为「错误码」——断言 `code == KdbxError.UNKNOWN` + `userText == null` + 敏感串（主机/邮箱）不出现在兜底值里；`onFailure` 回调第二参同步改为错误码断言。
- `CustomIconDeleteTest`：断言目标由 `.message` 改为 `.userText`（显式提供文案的语义更准）。
