# §366 云端打开全凭据自洽链路批次（`ISSUE-P2-399` 整条闭环）

- **触发**：2026-09-30 用户报告「初始化 APP 后，打开云端数据库时，输入的 WebDAV 和 S3 有关信息不足，
  根本无法打开对应的远端内容；但是如果先在本地打开，然后同步配置里面可以输入完整信息后同步到云端」。
- **开放项变动**：P2 区 1 → **0**（P3 仅剩搁置项 `ISSUE-P3-339`）。

## 1. 根因

两层缺陷叠加：

1. **入口假桩**：「打开已有 KDBX 密码库」对话框的云端表单只收集展示名与 URL/Bucket
   （源码注释自认「凭据统一在同步设置中配置」），WebDAV 缺用户名 / 密码 / 远端路径，
   S3 缺 Region / AccessKey / SecretKey / ObjectKey / path-style——恰是
   `WebDavSyncProvider` / `S3SyncProvider` 构造的必需参数；且登记链路
   `importExternalDatabase` 只把 URL 字符串存为 `KnownDatabaseEntry`，**从不写
   `SyncCredentialsStore`、从不构造 Provider**，后续 `SyncProviderResolver.resolveProvider()`
   查无凭据返回 null，同步报 `sync_error_test_no_credentials`。
2. **解锁侧数据丢失级隐患**（登记时发现，随批堵住）：`unlockActiveDatabase` 对远端登记条目
   （path 为 URL）走 `File(url).exists() == false` 分支时落入「文件缺失即**新建空库**」兜底——
   空库顶替云端库；一旦同步凭据在位，还会被「解锁后自动同步」整库上传**覆盖云端真库**。

## 2. 方案取舍

同步引擎的全部路径都以「已解锁会话 + 本地正式文件」为前提（`SyncCycleRunner` 需要
`databaseSession.databaseFlow.value`），不存在也不宜新造「未解锁先下载」的远端主存模式。
故本批不把凭据塞进解锁链路，而是让云端打开入口**复用已被用户手工验证的同构链路**
（「本地打开 → 同步配置补全 → 同步」）：登记时用所填凭据**直接下载远端库到应用私有目录**，
成功后凭据封印落盘、远端条目按**本地文件路径**走既有单一登记出口——此后解锁、自动同步、
远端目录浏览全部复用既有机制，云端打开成为一条自洽可通的链路。

## 3. 整改

- **新增 `CloudVaultImporter` / `RealCloudVaultImporter`**（app/sync 包 + `RepositoryModule` 绑定），
  编排顺序即安全口径：端点 HTTPS 归一化（见下）→ **先下载后落凭据**（下载失败即整体失败，
  **绝不**先写凭据存储——错凭据不得覆盖用户既有可用同步配置）→ 下载成功才提交凭据
  （`saveWebDavConfig` / `saveS3Config` 封印落盘 + `saveProvider` 置当前 Provider）→
  临时件 `.importing` 原子改名为目标库文件；本地同名库文件已存在时 fail-closed 拒绝
  （覆盖既有库文件是数据丢失级动作）；凭据 `CharArray` 借用语义全路径收口（外层 `finally`
  兜底擦除 + S3 Provider `clearCredentials()`，与 `SyncCycleRunner` 同口径）；
- **新增 `HttpsEndpointPolicy`**：`SettingsSyncController.normalizeHttpsEndpoint` 抽出为共享单点
  （空串放行 / 无 scheme 补 https:// / 显式非 https 拒绝），控制器改委托，行为零变化；
  导入器的凭据落盘同过该归一化，保证与同步配置页保存口径一致；
- **对话框补齐字段**（`OpenExistingVaultDialog` + 新文件 `OpenExistingVaultDialogForm.kt` +
  `OpenExistingVaultDialogSections.kt`）：WebDAV 补用户名 / 密码（`SecurePasswordField`，
  CharArray 直达状态）/ 远端路径（URL 与路径分离，占位改坚果云根地址）；S3 补 Region /
  AccessKey / SecretKey / ObjectKey / path-style 开关（凭据双字段与开关行按 §209 先例下沉）；
  字段增多后快照状态收拢为对话框本体 `remember` 持有的三个状态类（§178「状态留对话框本体」
  口径不变），敏感数组离开组合即擦除、提交传副本（导入失败时表单保留可直接重试）；
- **登记链路**：`DatabasePickerViewModel.importDatabaseFromSource` 改收 `OpenVaultSubmission`
  （本地 / 云端载荷分型）；云端路径 = 导入器下载成功后以**本地文件路径**走原登记出口，
  `syncType` 仍按来源落「WebDAV 云存储 / 兼容 S3 对象存储」标签（卡片云徽章与解锁页
  「云端库」状态照常呈现）；`DatabasePickerScreen` 重授权路径同步改包 `OpenVaultSubmission.Local`；
- **解锁 fail-closed 守卫**（`VaultLifecycleCoordinator.unlockActiveDatabase`）：`isRemote` 条目
  本地文件缺失时显式失败（`repo_cloud_vault_not_downloaded`），**先于**新建空库兜底裁决——
  堵住 §1.2 的空库顶替与云端覆盖隐患；
- **文案**：`picker_cloud_remote_missing` / `picker_cloud_download_failed` /
  `picker_cloud_local_conflict` / `repo_cloud_vault_not_downloaded` 中英成对；
  `picker_webdav_url_label`（去「完整路径」）、`picker_s3_bucket_label`（去「及路径」）随模型改写；
- **退役**：`WebDavDefaults.NUTSTORE_URL_PLACEHOLDER`（旧「完整 URL 占位」模型）无消费方后随批删除。

## 4. 验收

- AC① 导入编排：WebDAV 成功路径下载落地 + 凭据封印落盘（含 URL 归一化）+ 远端路径补根斜杠；
  S3 成功路径按 objectKey 下载且 path-style 落盘（`CloudVaultImporterTest` 5 例，假 Provider 行为级）；
- AC② 失败分型：下载失败不写凭据存储任何键（预置旧配置原样保留）且不留半成品文件；
  同名冲突不触碰网络与存储；封印失败整体失败（同上 3 例）；
- AC③ 借用语义：请求侧凭据 `CharArray` 任何结果路径（含全部早退失败分支）擦除（贯穿上列用例）；
- AC④ 解锁守卫：`isRemote` 早退先于空库兜底、显式文案落库（`RemoteVaultUnlockGuardWiringTest`
  2 例，静态源码比对——失效形态静默且数据丢失级，行为级证据只有真机可给）；
- AC⑤ ViewModel 接线：云端成功后按本地路径登记且保持云端标签、失败如实上浮不登记
  （`DatabasePickerViewModelTest` 新增 2 例）；
- AC⑥ 全量 `test --rerun-tasks --max-workers=1` 绿 `xml=492 tests=3185 failures=0 errors=0
  skipped=13`（§365 基线 489/3172 ⇒ +3 xml/+13 例：本批新增 `CloudVaultImporterTest` 5 +
  `HttpsEndpointPolicyTest` 4 + `RemoteVaultUnlockGuardWiringTest` 2 + `DatabasePickerViewModelTest` 2 +
  `WebDavDefaultsTest` 改造净 +1〔旧占位常量用例随常量退役，拼接等价用例顶替〕）+ 门禁 8/8（§6）。
