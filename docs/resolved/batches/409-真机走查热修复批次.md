## 1. 原文收录（`ACTIVE_ISSUES.md` 条目正文，原样剪贴）

### ISSUE-P3-449：应用内语言热切换崩溃循环——`LocalContext` 为 `ContextImpl` 致 `hiltViewModel()` 恒炸（P0）

- **核实时间点**：2026-10-02；**核实方式**：用户真机走查「切换英文会闪退且无法再次打开APP」；`adb logcat -b crash` 取得现场：`java.lang.IllegalStateException: Expected an activity context for creating a HiltViewModelFactory but instead found: android.app.ContextImpl`，栈顶 `KeePasskeySettingsNavGraphRoutes.settingsThemeRoute`。
- **背景**：`KeePasskeyApp` 在应用内语言 ≠ 跟随系统时以 `localizedContextOf` 派生上下文并 `LocalContext provides`——旧实现 `context.createConfigurationContext(...)` 的产物以 **ContextImpl 为基座**，无法沿 ContextWrapper 链解回宿主 Activity；设置页全部 `hiltViewModel()`（经 `androidx.hilt.lifecycle.viewmodel.compose`，强校验 Activity 上下文）即抛。语言偏好落盘 ⇒ 冷启动同样崩 ⇒ **崩溃循环**。跟随系统语言（默认态）从不派生包装，故潜伏至今未暴露。
- **验收标准**：
  ① 本地化包装保住 ContextWrapper 链（基座 = 宿主 Activity），`stringResource` / `getString` 仍按目标语言解析；
  ② 切换中文 ↔ 英文热切换无崩溃；语言非跟随系统时冷启动正常；自动填充 / 凭据解锁页（同一助手的另两处调用点）不受影响；
  ③ 全量 test 绿 + 门禁全 PASS；真机复验留痕。

### ISSUE-P3-450：编辑页口令生成器产出不回显密码框——模型已持有而显示态不更新

- **核实时间点**：2026-10-02；**核实方式**：用户真机走查「点击闪电图标生成的密码不会出现在密码框内」；代码直读——`SecurePasswordField` 显示用 String 内聚于组件（安全设计，P1-04），外部程序化改密只有 `onPasswordChangeSecure`（模型侧）与一次性 `initialPassword/initialKey` 预填（组合期消费）两条通道；生成器走前者 ⇒ 显示态恒空、模型已有值。
- **背景**：用户无法看到生成结果（强度条有值而输入框为空），只能盲存；属可用性缺陷（非凭据丢失——模型侧 CharArray 已持有）。历史潜伏：P3-342 拆分「行为逐字不变」，生成回显自首版即缺。
- **验收标准**：
  ① 点击闪电（或改长度 / 字符池开关）后，生成密码即时回显密码框（掩码态）；
  ② 回显走既有一次性预填通道（不新增敏感数据驻留面），模型侧持有与脏标记语义不变；每次生成都能重新回显（连续生成不失效）；
  ③ 全量 test 绿 + 门禁全 PASS；真机复验留痕。

### ISSUE-P3-451：SAF（自选位置）库每一次保存都被「磁盘文件已被外部修改」中止——漂移基线占位假值

- **核实时间点**：2026-10-02；**核实方式**：用户真机走查「保存失败并提示磁盘文件被修改，返回上级界面内出现了之前新建的条目」；代码直读——`VaultFileBaselineHolder.capture` 对无本地 File 的 SAF 通道落 `fromMetadata(path, 0, 0)` **占位假基线**，保存时 `current`（`DatabaseSession.currentFile` = null ⇒ `currentFromLocalFile` = null）按 `VaultFileDriftPolicy.isDrifted` 的 `current == null ⇒ 漂移` 分支**恒判漂移** ⇒ `persistSession` fail-closed 中止（`ext_mod_save_aborted`）。真机取证：debug 私有目录无 `.kdbx`，走查库为 SAF 自选位置通道。
- **背景**：P2-378 的文档口径是「元数据不可读 ⇒ 基线为 null ⇒ 宁可不提示」，占位假基线违背该口径，把「不可知」变成了「必漂移」。「返回上级界面出现条目」为 P2-378 既有语义（保存中止后内存态保留），非数据丢失，但可感知性缺位（已随 `ISSUE-P3-447` ③ 登记）。
- **验收标准**：
  ① SAF 库保存不再被漂移误报中止（`file == null` 时不落基线，回归「元数据不可读 ⇒ 无基线 ⇒ 不提示」文档口径）；
  ② 本地 File 通道漂移防护零变化（既有用例全绿）；
  ③ 全量 test 绿 + 门禁全 PASS；真机 SAF 库保存复验留痕；SAF 真实元数据管道随 `ISSUE-P3-447` ② 立项恢复。

## 2. 整改内容

### 2.1 ISSUE-P3-449：本地化上下文保住 ContextWrapper 链

`AppShellLocalization.localizedContextOf`（一处修复覆盖外壳 `KeePasskeyApp` 与自动填充 / 凭据解锁页三处调用点）：`locale != null` 分支由直接返回 `createConfigurationContext` 产物改为返回**包住 base（Activity）的 ContextWrapper**，仅覆写 `getResources()` 返回本地化 Configuration 的 resources——`stringResource` / `getString` 仍按目标语言解析；`hiltViewModel()` 沿 ContextWrapper 链可解回 Activity。`localizedConfigurationOf` 纯函数与 `LocalConfiguration provides` 既有口径零改动。

### 2.2 ISSUE-P3-450：生成结果经既有预填通道回显

- `EntryEditUiState` 新增 `passwordPrefillToken: Any?`（非敏感标记对象，无凭据材料）。
- `EntryEditViewModel.generatePassword`：`generator.generate()`（模型侧持有 + 脏标记，原有）之后，把生成结果副本推入既有一次性预填通道 `_loadedPassword`，并换新 `passwordPrefillToken`——`SecurePasswordField` 组合期同步消费（ISSUE-P3-320 口径），显示态即回显；连续生成逐次换键重新消费，副本清零沿用预填通道既有生命周期（用户编辑 / 销毁时擦除）。
- `EntryEditFormSections`：`initialKey = uiState.passwordPrefillToken ?: (uiState.entryId ?: "new-entry")`；`loadEntry` 载入条目时重置 token 回退既有按 entryId 消费口径。

### 2.3 ISSUE-P3-451：SAF 通道不落占位基线

`VaultFileBaselineHolder.capture`：`file == null`（SAF / content://）时 `baseline = null`（不创建 `fromMetadata(path,0,0)` 占位），按 `VaultFileDriftPolicy` 文档口径「元数据不可读 ⇒ 无基线 ⇒ 宁可不提示」；`checkDrift` 的 `base == null ⇒ return false` 随之放行。本地 File 通道（`fromFile` 真实元数据）漂移防护零变化。SAF 真实元数据管道随 `ISSUE-P3-447` ② 立项恢复防护强度。
