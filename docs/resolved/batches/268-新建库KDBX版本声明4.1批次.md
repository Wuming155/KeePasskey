## §1 背景与前提核实（开工前按条目维护规则 2 逐项复核，2026-09-23 直读 HEAD）

条目五项前提**全部成立**，无漂移：

1. `core/src/main/java/com/keepasskey/core/model/KdbxConstants.kt:32` 仅
   `VERSION_4_0 = 0x00040000`，全仓无 `0x00040001` 版本常量；
2. 新建库路径 `database/src/main/java/com/keepasskey/database/session/SessionOpener.kt:69`
   → `KdbxHeader.createDefault()`，而 `KdbxHeader.kt:48` 数据类默认 `version = VERSION_4_0`
   （`createDefault` 不传 version，取数据类默认）；
3. 写出侧 6 处 4.1 字段逐一在位：`KdbxXmlMetaSerializer.kt:30-32`（`SettingsChanged`）、
   `:63-65`（`MasterKeyChangeForceOnce`）、`:77-89`（CustomIcon `Name` / `LastModificationTime`）、
   `:128-131`（CustomData Item `LastModificationTime`）、`KdbxXmlEntrySerializer.kt:46-47`
   （Entry `QualityCheck`），各处 KDoc 均自陈「KDBX 4.1 追加字段」；
4. 边界澄清成立：反序列化路径经 `KdbxHeader.deserialize` → `toHeader(sig1, sig2, version)`
   **原样传入读到的 version**，`KdbxFile.save` 的 `database.header.copy(...)` 不重置 version
   ⇒ 既有 4.0 / 4.1 库往返均保留原版本，缺陷面仅限新建库；
5. `SettingsUiState.kt:237` 注释「写侧恒为 4.0」表述不精确（只对新建场景的整改前成立）。

规格依据：keepass.info/help/kb/kdbx.html「For KDBX 4.1, the format version value is
`0x00040001`」。声明 4.0 却夹带 4.1 元素的文件对严格客户端无宽容承诺（规格仅对 minor
**更大**的文件建议「可忽略未知项」），经 4.0 严格客户端往返时 4.1 元数据可能被静默丢掉。
