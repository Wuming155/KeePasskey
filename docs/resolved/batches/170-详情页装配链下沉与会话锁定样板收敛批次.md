## 3. 刻意**不做**的两处（各有已记录的边界）

1. **`exportAttachment` 的确认判定不下沉**到 `EntryDetailAttachmentExporter`：该类 KDoc 明写
   「用户确认（`ExportConfirmationPolicy` 的 fail-closed 判定）**仍在调用方**完成——本类只在已获授权后
   执行写出，绝不自行放行」。移动它等于推翻一处已记录的放行边界，属**语义变更**而非搬家；
2. **详情页明文导出确认框不与设置页 `ExportConfirmationDialog` 合并**（理由见 §169 §3：无 `ExportTicket`
   签发环节且文案不同）。

## 4. 守卫与判据（只放宽定位，不降低强度）

`AlgoHotPathGuardsTest.秒级节拍不得常驻且不得逐条重建`：
- **正向**两条（句柄声明 + `.onCompletion { totpTickJob?.cancel() }`）改按「ViewModel + 装配器」**并集**扫描，
  判据文本逐字保留；
- **反向**「`init` 里不得常驻启表」**刻意仍只扫 ViewModel 本体**，并把探针由 `totpTicker.run` 收紧为
  `totpTicker`（更强）。原因：并集里装配器 *legitimately* 含节拍启动代码，扩扫会把合法实现读成违规。

行为等价要点逐条核对：装配器构造期拿到的 `scope` 就是 `viewModelScope` ⇒ 启停时机与取消传播不变；
`start()` 内部仍是 `Dispatchers.Default` 上的同一 `run` 循环；修订簇两个入口的 `?: return` 提前返回、
`showMessage` 写入的仍是同一 `userMessageFlow`；`SessionLockGuard` 用的是同一 `SessionLockObserver`
SAM 构造，且注册/注销仍分别落在 `init` 与 `onCleared`。

## 5b. 本批暴露的证据缺口（已登记，未在本批补足）

该项属宿主层可测面，已登记为 `ACTIVE_ISSUES` 的 `ISSUE-P3-188` 剩余清单第 5 项，
