## 2. 整改内容

### 2.1 数值核实（改动依据）

- **material3 1.5.0-alpha27**（`tokens/ExpressiveMotionTokens.kt`，本机 Gradle 缓存 sources jar 解包直读，
  与项目在用 alpha28 同代）：
  `defaultSpatial = damping 0.8 / stiffness 380`、`fastSpatial = 0.6 / 800`、
  `slowSpatial = 0.8 / 200`、`defaultEffects = 1.0 / 1600`、`fastEffects = 1.0 / 3800`——
  即整屏滑动现值 380 偏急、视差 800/0.6 偏快且带欠阻尼过冲、列表 fastEffects 3800 近乎瞬完。
- **navigation-compose 2.8.8**（`NavHost.kt` 同法直读）：默认转场＝
  `fadeIn / fadeOut(tween(700))` 纯**同时**交叉淡化——用户「默认好用」的观感来源即
  同时淡化、无空窗（不是 700ms 本身值得抄）。
- `AppNavigationMotion.kt` 现状逐行核对：顶层 Tab 出向仅 `fadeOut(90ms)`、入向延迟 90ms，
  构成「瞬消 → 空窗 → 淡入」。

### 2.2 方案一：导航空间段降档（`AppNavigationMotion.from()`）

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `fullSlideSpec`（整屏滑动） | `defaultSpatialSpec`（380/0.8） | `slowSpatialSpec`（200/0.8） | 官方 slow 档语义即「页面级、更从容」；expressive default 档定位是「强调 / hero 交互」，用在每一次全页导航感知过快 |
| `parallaxSpec`（视差位移） | `fastSpatialSpec`（800/0.6） | `defaultSpatialSpec`（380/0.8） | 0.6 欠阻尼在小位移上过冲「弹」一下；与大滑动同族 |

### 2.3 方案二：顶层 Tab / 解锁页改双向同时交叉淡化（`PD-44` 有意偏离）

- 原 fade through 顺序淡化（出向 90ms 瞬消 + 入向延迟 90ms）改为**双向各 300ms 同时淡化**
  （新常量 `TOP_LEVEL_FADE_MS = 300`，与官方 shared axis 同档总时长同源、无延迟），
  保留 `0.92f` 入口涨入——空窗消除，观感与 NavHost 默认交叉淡化同族而无其 700ms 拖沓。
- **共享轴（下钻 / 返回）的 90 / 210+90 顺序淡化维持不变**（`PD-26` 效果段口径原样）：
  空间滑动放慢后淡化伴随滑动，无空窗观感问题；`AppNavigationMotionTest` 的三条顺序淡化
  不变式原样保留并通过。
- 预测性返回（全屏表面规格，`PD-28`）与顶层路由 popEnter 例外（`ISSUE-P2-260`）均未触碰。

### 2.4 方案三：列表 `animateItem` 降档 + 顺手清理

- `VaultListScreen` / `AuthenticatorScreen` 的 `itemFadeSpec` `fastEffectsSpec` →
  `defaultEffectsSpec`（3800 → 1600，增删不再近瞬消）、`itemPlacementSpec`
  `fastSpatialSpec` → `defaultSpatialSpec`（800/0.6 → 380/0.8，重排不再过冲）；
  FAB 维持 fast 档（覆盖式小控件，快即语义）。
- 删除 `EntryDetailCards.kt` 未使用的 `import androidx.compose.animation.core.tween`（死 import）。
