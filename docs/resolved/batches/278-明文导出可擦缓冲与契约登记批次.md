## 2. 整改

### 2.1 AC①：两个明文导出器改用可擦缓冲 + `finally` 收口

**`KdbxCsvExporter.export`**：

```kotlin
val buffer = WipableByteArrayOutputStream()
return try {
    val writer = BufferedWriter(OutputStreamWriter(buffer, Charsets.UTF_8))
    try {
        writeRow(writer, HEADER)
        writeGroup(writer, database.rootGroup, ArrayDeque())
        writer.flush()
    } finally {
        writer.close()
    }
    buffer.toByteArray()
} finally {
    buffer.wipe()
}
```

**`KeePassXmlExporter.export`**：同型——`WipableByteArrayOutputStream` 承载、`toByteArray()` 交出**复制**交付（R2）后于外层 `finally` 调 `buffer.wipe()`。

**所有权与擦除分层**（对齐契约 R2 / R4）：

| 层 | 缓冲 | 类别 | 擦除责任 | 钩子 |
|---|---|---|---|---|
| 导出器内部 | `WipableByteArrayOutputStream.buf` | O | 导出器 | `finally { buffer.wipe() }`（成功与失败均擦） |
| 调用方 | `toByteArray()` 交出的 `bytes` | O（调用方） | `SettingsExportController` | 既有 `finally { bytes?.fill(0) }`（晚于 `os.write`） |

`SettingsExportController` 注释就地补记该两层责任（ISSUE-P3-296 指针），**行为一行未改**。

**「提为共用可见性」的落地说明**：`WipableByteArrayOutputStream` 为 `database` 模块 `internal`，`DatabaseSession` 与两个导出器**同属本模块** ⇒ `internal` 已是三处调用方的共用可见性；无跨模块消费者，**不扩为 `public`**（避免无谓扩大模块 API）。类 KDoc 补记共用范围与契约指针。

### 2.2 AC②：契约表登记明文导出缓冲 + `readString()` 明文化面

`docs/architecture/敏感缓冲所有权契约.md` §4：

1. **#10 扩展**——由「整库序列化缓冲（`buf`）｜`wipe()`（写盘后由 `DatabaseSession` 调用）」改为覆盖三处调用方（加密序列化 + **两个明文导出器**），擦除钩子写明「`finally` 收口：加密序列化写盘后；明文导出 `toByteArray()` 交出副本后——成功与失败路径均擦」；守卫用例列补「含明文导出接线守卫」。
2. **新增 #19**——导出侧 `readString()` 明文化面（`KdbxCsvExporter` 的 `entry.password?.readString()`、`KeePassXmlExporter` 的 `password.readString()` / `field.value.readString()`）按**覆盖限界**登记（类别栏如实标「不可擦残留（RC-01 同类）」，**不**硬塞进 O/B/S/P）：无确定性钩子（JVM `String` 不可清零）；进程内取证在信任边界外（限界 §2.2 / §2.4 已接受同类）。摘除条件＝日后改走 `useChars` 路径。
3. **§8.1** 机检表补 `WipableByteArrayOutputStreamTest` 明文导出接线守卫一行。

**为何取「登记」而非「改 `useChars`」**：条目 AC② 给的是二选一；本批取登记，理由＝① 该 `String` 残余已被限界 §2.2 / §2.4 明示接受（进程内取证在信任边界外），与 `ProtectedString.readString()` 既有限界同型，**不是新缺陷**（条目核实方式原话）；② 改 `useChars` 须连带改 `writeField` / `KdbxXmlWriteUtil.textElement` 的 `String` 形参，变更面超出条目「涉及文件」四件套，且 CSV 的 `writeRow(List<String>)` 整条链都要动；③ 契约表的可收敛点本就是**一致性**（禁「只记加密序列化」），登记即达成 AC② 的字面要求。**AC④ 纪律**：未以「参考项目也不擦」为由免登记——契约表已如实收录两器与 `readString` 面。

### 2.3 AC③：二次确认保持不变

`ExportConfirmationPolicy.Risk.PLAINTEXT` / `ExportTicket` / `exportPlaintextTo` 的令牌闸门**一行未改**；`ExportConfirmationPolicyTest` 既有用例原样通过。

## 3. 用例（只加不删，+1 例）

### `WipableByteArrayOutputStreamTest` +1

**两个明文导出器必须用可擦缓冲并在 finally 收口 wipe**（静态接线守卫，口径同既有 `DatabaseSession` 三条路径守卫）：

1. 必须出现 `val buffer = WipableByteArrayOutputStream()`；
2. 必须以 `finally { buffer.wipe() }` 收口（正则锚定，成功与失败路径均擦）；
3. `buffer.toByteArray()` 的源码位置必须**早于** `buffer.wipe()`（「只清交出副本」正是本条缺口）；
4. 不得回退 `(?<!Wipable)ByteArrayOutputStream\(`（不可擦内部 `buf`）。

对 `KdbxCsvExporter.kt` / `KeePassXmlExporter.kt` 两文件循环断言。

**既有用例未动**：`wipe` 逐字节清零 / 幂等、`DatabaseSession` 三路径接线、`KdbxCsvExporterTest` 4 例逐字节产物断言（回归护栏：改缓冲后产物不变）。

## 5. 如实声明

1. **`readString()` 的不可擦 `String` 残余仍在**（AC② 取「登记」分支）：口令 / 自定义字段明文化后以 `String` 驻留至 GC，与限界 §2.2 / §2.4 已接受同类。契约 #19 已登记；**不得**读作「导出路径已无明文 `String`」。摘除条件＝改走 `useChars`（本批未做，理由见 §2.2）。
2. **「提为共用可见性」未改 Kotlin 可见性修饰符**：三处消费者同在 `database` 模块，`internal` 即共用；不扩 `public` 的理由见 §2.1。若日后出现跨模块消费者，再按需提升。
3. **行为面零变化**：产物字节与整改前逐字节等价（`KdbxCsvExporterTest` 4 例逐字节断言原样通过）；`ExportConfirmationPolicy` 闸门一行未改（AC③）。
4. **未跑** `lint` / `assembleRelease` / 截图门禁 / KPEX 对拍 / 真机冒烟；未触原生面 / `androidTest` / `参考项目/` / 构建脚本 ⇒ 无设备侧必跑项。
5. **判别力实验的坏样本形态**＝`wipe()` 换 `reset()`（只复位计数、不清内容，恰是 `ISSUE-P3-118` 原缺陷形态）；首次尝试「删掉 `finally`」因留下 `try` 无 `catch/finally` 的语法错误无法编译，已换可编译坏样本并如实留痕。
