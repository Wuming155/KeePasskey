# 文档体系与入口

文档分为使用入口、开发规则和维护资料。每类事实只有一个维护位置，其它文件用链接引用。本文只维护目录与职责；新增、更新和退役流程统一见 [工程规则](../.codebuddy/rules/engineering-rules.md#文档维护流程)。

## 固定职责

| 位置 | 读者与内容 | 更新时机 |
|---|---|---|
| [根 README](../README.md) | 用户和新开发者：产品能力、环境要求、构建测试命令与使用入口 | 能力、运行要求或常用命令变化 |
| [AGENTS.md](../AGENTS.md) | 编码代理：必读入口、操作约束和验证要求 | 代理工作方式变化 |
| [工程规则](../.codebuddy/rules/engineering-rules.md) | 贡献者：编码、测试及文档维护流程 | 开发约束或维护流程变化 |
| 本页 | 维护者：文档目录、职责与定位 | 文档新增、合并、迁移或删除 |
| [当前问题](ACTIVE_ISSUES.md) | 维护者：尚未解决的问题、影响、核实方式与关闭条件 | 发现问题、关键事实变化或验收关闭 |
| [架构](architecture/ARCHITECTURE.md) | 开发者：模块职责、依赖和稳定边界 | 模块或跨模块职责变化 |
| [产品与设计约定](architecture/产品裁决登记.md) | 开发者：仍有效的范围、选择与必要理由 | 产品或设计取舍变化 |
| [工程边界](architecture/已知工程限界.md) | 维护者：已接受的限制、前提与残余风险 | 限制、接受前提或验证范围变化 |
| [敏感缓冲所有权](architecture/敏感缓冲所有权契约.md) | 开发者：秘密缓冲交付、共享与清理责任 | 所有权或擦除契约变化 |
| [同步威胁模型](security/同步层记录级完整性威胁建模.md) | 开发者：攻击者能力、信任边界和安全保证 | 同步协议、信任边界或攻击者假设变化 |
| [隐私政策](security/Privacy-Policy.md) | 用户：数据收集、网络流向、权限与留存 | 用户数据处理行为变化，发布前核对 |

`architecture/` 保存跨模块设计与约束，`security/` 保存安全模型与用户数据政策。普通开发不按日期、问题编号或迭代批次建立新目录。

## 其它资料放在哪里

- 实现细节、接口参数和默认值由代码、配置及必要的就地注释维护；测试场景和预期由测试维护。
- `tools/<工具>/README.md` 只说明该工具的用途、前提、命令、产物与退出码；测试资源旁只保留来源、生成方式及复用所需说明。
- 临时计划、排查笔记和本地报告放在已忽略的 `build/` 下；共享运行日志、截图及报告使用 CI artifact 或明确的外部附件，不提交永久流水。需要长期复现的最小公开样本随测试保存。
- 已提交的旧文档通过 Git 历史查询；未提交的本地材料不会被 Git 自动保存。需要保留的结论归入上表，证据注明实际保存位置与适用环境。

修改涉及哪类事实，就更新对应文件；无需为了完成一次任务同步改写所有文档。当前缺陷不能只放进“已接受边界”，问题关闭也无需新建归档文档。
