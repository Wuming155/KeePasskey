## §7 目录枚举噪声与其派生残余（`ISSUE-P3-142`）


- **事实**：本机（Windows/NTFS）`File.listFiles()` / `File.list()` **偶发返回「大写拼写、磁盘上并不存在」的目录条目**（本仓实测命中率约
  **3%–6.5%**；四路交叉取证一致否认其存在：`exists`/`isFile`/`canRead`/`length` 全为 false/0、NIO `readAttributes` 与
  `DirectoryStream` 读不到、原生 `cmd dir /b` 看不到）。
- **边界**：① **不得**以 `File.listFiles()` 的**原始返回值**作为「目录已清空 / 无残留」的判据——须先以**实体**复核（`File(dir, name).isFile` 或
  NIO）；② 该口径**不是放宽断言**：`isFile == true` 的**真残留仍必红**；③ 即便按上述口径，仍有约 **3%** 的**假阳性残余**（`isFile` 非百分百可靠）。
  更强判别式为**同路径短时有界重枚举**（15 ms × 4 次，实测在 380 例假阳性上 **0 命中**）——**刻意未采纳**（避免引入时序依赖断言），可按需启用。
- **派生残余（产品代码）**：`SyncCache.deleteOrphanTmpFiles` 的匹配**大小写敏感**（
  `file.name.startsWith(key) && file.name.endsWith(SUFFIX_TMP)`，
  `sync/src/main/java/com/keepasskey/sync/engine/SyncCacheFiles.kt:109`（2026-09-18 §188 拆分后迁址；
  `SyncCache.kt` 现仅转发）），对**大写拼写**的孤立 tmp 不匹配。当前所有写入者均为小写，**不构成缺陷根因**；**刻意未改**（无根因依据不动产品代码）。解除条件：
  引入大写命名写入者或外部工具落临时文件时再改（改法：小写归一化后比较）。
- **观测点登记（第四处，§239 全量跑命中，2026-09-21）**：`SyncCacheEvictorTest > 关闭密码库后同步缓存目录为空`（断言已按实体口径写）被鬼影条目
  `490A5659…C77A1.BASEVERSION.tmp` 以 `isFile` **返回 true** 命中 ⇒ 落进「边界 ③」自陈的约 **3% 假阳性残余**。
- **同口径未覆盖处（2026-09-21 补，见 `ISSUE-P3-246`）**：`sync/src/androidTest/.../SyncCacheAndroidRuntimeTest.kt:76`
  仍以**原始 `listFiles()` 返回值**判定「清理后不得残留」，与本节边界 ① 相冲；该处属设备侧用例，处置见该条目。
- **刻意不改**：为迁就宿主鬼影而在产品代码里改用「实体复核后计数」，等于把**测试侧口径**下沉进产品代码；
  且按实体口径仍有约 **3% 假阳性残余** ⇒ 换不来确定性，只换来「看起来修好了」。
  **解除条件**：平台 / 文件系统不再出现无实体枚举条目（无法主动解除）；或采纳更强判别式，把假阳性降到可忽略。
- **依据**：`RESOLVED_LOG.md` §107；[`docs/records/SyncCache大写CACHE临时文件定位记录.md`](../records/SyncCache大写CACHE临时文件
  定位记录.md)。

## §12 宿主侧 Windows 原子 rename 偶发 `AccessDeniedException`（**平台现象，非产品缺陷**）


- **事实**：`SyncRollbackGuard.persist` 走「写 `<hash>.rollback.<uuid>.tmp` → 原子 move 覆盖 `<hash>.rollback`」
  的安全写盘序列；在**本机 Windows/NTFS** 上，该 move **在全量单测负载下偶发**抛 `java.nio.file.AccessDeniedException`（2026-09-17
  §133 批次观测 1 次：`SyncRollbackGuardTest` 的 `摘要重载与字节重载的裁决逐项一致`；**定向复跑 9/9 绿**（该类现有 9 个用例），随后全量复跑绿）。
- **边界（如实声明，勿外推）**：① 这是**宿主侧测试可靠性**现象，**不是终端用户可见缺陷**——Android 侧不存在该拒绝语义；② **不得**据此在产品代码里加「rename 重试」以为修复：
  那会把宿主侧口径下沉进产品，且 Android 上该重试永不触发（**无靶加固**）；同理**不得**据此放宽任何断言；③ 触发条件：**全量并发 / 高文件 churn 下偶发，隔离运行全绿**——与 §7
  记录的「文件系统 churn 放大」同类环境依赖。
- **解除条件**：宿主侧不再复现（换 Linux/macOS 宿主，或 Windows 侧消除句柄竞争来源）。**维持现状**：不改产品代码、不改断言，复现时按「定向复跑确认 + 全量复跑」处置并留痕。
- **依据**：`docs/resolved/batches/133-WebDAV首传重复探测收敛批次.md` §5.2（含异常原文与复跑计数）。复跑计数更正见[附二](限界表证据与实测数据汇录.md#附二更正留痕按日期) §12。
