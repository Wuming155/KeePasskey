### (f) 设备侧工具链约束（2026-09-16 实测，后续设备侧用例须遵循）

1. 系统 `UiAutomation` 是**每用户单槽位**——若 `com.android.cli.interact.instrumentation`（Android CLI 自带的交互辅助 APK）
   在跑，instrumented 进程再取 `uiAutomation` 会抛 `IllegalStateException: UiAutomationService … already registered!`，
   框架随后在「连接中」状态调用 `disconnect()` **直接崩溃进程**（连断言都执行不到）。规避：运行前确认该辅助 APK 未运行
   （`dumpsys accessibility` 中无 `Ui Automation[...]` 条目），并**在用例运行期**（而非构造期）经 `by lazy` + `runCatching`
   获取 `uiAutomation`。
2. **锁屏（Doze）下任何 Activity 都无法真正进入前台** ⇒ 认证类 Activity 始终不出现在无障碍树中；
   设备侧 UI 驱动类用例须先**唤醒并解锁屏幕**。
依据：[`docs/records/自动填充认证链路真机实测记录.md`](自动填充认证链路真机实测记录.md) §7.3 / §7.4。

## §7 目录枚举鬼影的派生残余与观测点原始记录

### (a) 派生残余（产品代码 · 第二处，2026-09-17 新增证据，**该处此前只有「偶发红」的现象、没有根因**）

`SyncCacheEvictor.evictAll()` 的**残留计数**同样受该鬼影影响——它以
`dir.list()?.count { !SyncCache.isRollbackStateFileName(it) }` 清点「应清理项」，鬼影会让该计数**多出 1**，于是：
① 返回 `false`（调用方据此认为清理未完成）；② 落一条**误报** WARN「同步缓存残留 N 项，锁定后密文可能仍可恢复」；
③ 使 `SyncCacheEvictorTest` 的 `F23 锁库清理缓存不得删除防回滚状态文件` **偶发红**——该项目**早已观测并留痕**
（用例注释记「观测 **3 次全量 / 1 次失败**，独立复跑 4 次全绿」），并**刻意**在断言消息里带上「销毁器日志 + 实际目录内容」以待定位。
**2026-09-17 一次全量跑的失败信息恰好完成了该定位**：断言消息给出
「目录索引条目 = 磁盘上真实存在的文件 = **仅** `<hash>.rollback`」，而销毁器日志为「同步缓存残留 **1** 项」——
由于 `isRollbackStateFileName` **确实**排除了该文件名，这个 `1` 只能来自 `dir.list()` 返回的**无实体条目**
⇒ 鬼影已从「**测试侧**目录索引」扩展到「**生产代码的清点**」。该次定位后单独复跑该类**绿**，与「偶发」一致。

`SyncCacheEvictorTest > 同步凭据清空时连带销毁同步缓存`

## §22 凭据拒绝页：无自动化覆盖的具体缺口与理由（原始条目）

- **为什么不采用「跳转设置页」方案（已在方案演进中被否决）**：
  1. `MainActivity` 是唯一无权限保护的导出组件，`ExportedComponentHygieneTest` 锁定了
     「不得消费任何外部 intent 数据」这一安全不变式，跨 Activity 传递目标路由无法走标准 Intent；
  2. 凭据窗口具有「不提供本应用内导航」的加固取向（`CredentialUnlockPresenter` 等三处 no-op）；
  3. 用户命题明确要求「减少跳转和操作」——就地完成授权使操作步数由「跳去设置 → 找开关 → 找应用 → 切回浏览器」
     骤降为「点一次添加 → 回浏览器重试」。
- **无自动化覆盖的具体缺口（需真机核验的项）**：
  ① 真实系统拉起下，按钮点击后的 `CircularProgressIndicator` 转圈与状态刷新流程度；
  ② 写入偏好后回到浏览器再次发起 passkeys.io 注册，是否确实直接放行且不再弹拒绝页；
  ③ 读不到签名证书（例如特殊沙箱环境）时的 `STATUS_FAILED` 失败文案呈现。
