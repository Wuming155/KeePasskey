1. 两侧均为**先预热、再多轮采样取中位数**（与 `NativeArgon2InstrumentedTest` 先例一致）；

2. **Rust 侧无 JNI 开销**：整库流场景按 64 KiB 分块投递，生产集成（经 JNI 桥每块一次调用）的

   相对毫秒级签名耗时同样可忽略。**该差异不改变「数量级差距」级别的结论。**
3. Rust 探针的依赖（`chacha20 0.9` / `p256 0.13` / `ed25519-dalek 2` / `rsa 0.9`）**仅为评估引入**，
   未过 `crypto/src/main/rust/deny.toml` 与供应链 CVSS 闸门——若立项下沉，须按 ISSUE-P3-153
   风险提示先走该闸门。
4. 复跑两次的 ChaCha20 Rust 数据（84.5 / 85.0 ms）与 RS256 keygen（2756.2 / 2106.5 ms，素性搜索
   随机性所致宽离散）在 §1 / §2 表内并列，不取平均、不择优。

## 1. ISSUE-P3-155：AES-256-CBC 现状 512 B 流 vs 候选 64 KiB 分块（真机）

载荷 10 MiB；预热 1 次 + 采样 5 次取中位数（logcat `PERF-PROBE|` 原样摘录，2026-09-17 22:02）：

| 路径 | median | min | max | 吞吐 |
|---|---|---|---|---|
| **解密** · 现状（生产 `AesCipherEngine` 流 = `CipherInputStream` 内部 512 B） | **653.8 ms** | 648.9 | 899.3 | **15.3 MB/s** |
| **解密** · 候选（64 KiB 分块直投 `Cipher.update`） | **89.9 ms** | 89.2 | 99.0 | **111.2 MB/s** |
| **解密** 加速比 | **7.3×** | | | |
| **加密** · 现状（生产流 = `CipherOutputStream`） | 98.6 ms | 94.7 | 132.1 | 101.4 MB/s |
| **加密** · 候选（64 KiB 分块） | 97.4 ms | 95.8 | 101.8 | 102.6 MB/s |
| 加密 加速比 | 1.0×（无收益） | | | |
| 参照 · 一次性 `doFinal`（10 MiB 整块，加密侧） | 31.4 ms | 31.0 | 33.4 | 318.7 MB/s |

**正确性前置（设备侧已断言）**：现状流与候选路径密文逐字节一致；两条路径解密往返逐字节还原明文。

### 结论

1. **瓶颈在解密侧且量级确凿**：`CipherInputStream` 内部 512 B 缓冲把解密吞吐压到 15.3 MB/s，
   64 KiB 分块即恢复到 111.2 MB/s（7.3×）。ISSUE-P3-155 的前提与量级在真机上**成立**。
2. **加密侧无收益**（1.0×）：`CipherOutputStream` 对 ≥512 B 的写入已直通 `Cipher.update`，
   与条目「512 B 瓶颈」的表述相比，**整改范围应收窄为解密侧**（`createDecryptingStream` 一侧）。
3. **采纳建议**：值得采纳（复用 `CbcStreams` 分块骨架、仅解密侧），收益约 7× 且无新依赖；
   触及主数据面，按条目原 AC 走互操作与流语义对拍后另行开批实施。

## 2. ISSUE-P3-153：BC 现行 vs Rust 候选真机吞吐（同一设备）

### 2.1 ChaCha20 整库流（外层 cipher 候选，10 MiB，BC 用完整 `BouncyCastleProvider` 实例）

| 实现 | median | 吞吐 | 备注 |
|---|---|---|---|
| BC（完整 provider）一次性 `doFinal` | 3712.5 ms | 2.7 MB/s | min 3705.0 / max 3718.8 |
| BC（完整 provider）64 KiB 分块 `update` | 3779.4 ms | 2.6 MB/s | min 3754.1 / max 3788.3 |
| **Rust `chacha20` crate**（64 KiB `apply_keystream`） | **84.5 ms**（复跑 85.0 ms） | **117.6~118.4 MB/s** | min 84.0 / max 85.2 |

加速比 ≈ **44×**（保守取 BC 分块值 3779.4 / 85.0 = 44.5×；若取 BC 最优 bulk 值为 43.9×）。

### 2.2 Passkey 三算法（keygen 与「生产 `signAssertion` 路径」sign）

| 操作 | BC（真机，5 轮均摊中位） | Rust 候选（同法） | 加速比（BC/Rust） |
|---|---|---|---|
| ES256 keygen | 18.389 ms（16.9~21.8） | 0.900 ms（0.899~0.903） | **20.4×** |
| ES256 sign | 17.681 ms（16.1~27.3） | 1.066 ms（1.065~1.069） | **16.6×** |
| Ed25519 keygen | 5.099 ms（1.9~9.1） | 0.167 ms（0.166~0.168） | **30.5×** |
| Ed25519 sign | 3.816 ms（2.8~4.7） | 0.171 ms（0.169~0.172） | **22.3×** |
| RS256 keygen（2048, certainty=80） | **992.987 ms**（677.4~2451.7） | **2106.5 ms**（599.2~3813.2） | **0.47×（Rust 慢）** |
| RS256 sign | **10.869 ms**（10.5~11.0） | **17.804 ms**（17.797~17.808） | **0.61×（Rust 慢）** |

### 结论（评估定案）

1. **ChaCha20 下沉收益确凿**：BC 纯 Java 实现真机仅 2.6~2.7 MB/s（AES 硬件路径的 ~1/118），
   Rust 候选 44×；若产品保留 ChaCha20 外层 cipher 选项，下沉是唯一现实的性能出路。
2. **ES256 / Ed25519 下沉收益明确**（keygen 20~30×、sign 17~22×），属用户可见时延
   （每次通行密钥断言都要签名）。
3. **RS256 否定下沉**：`rsa` crate 在真机上 keygen 慢 2.1×、sign 慢 1.6×（纯软件大整数 vs BC
   的 CRT/Montgomery 优化），**不得**以「Rust 更快」为由下沉 RSA。
4. **是否立项待裁定**：三处候选均需**新增 Rust 依赖**，须先过 `crypto/src/main/rust/deny.toml`
   （`wildcards = "deny"`、依赖树无重复密码学实现）与供应链 CVSS ≥ 7.0 闸门；结合用户既有
   供应链口径（拒绝低 star / 单维护者加密库），立项决策**留给用户裁定**，数据已备齐。

## 3. ISSUE-P2-92（新发现）：平台剥离版 BC 抢占 provider 名，真机 ChaCha7539 不可用

> **闭环注记（同日 §143）**：整改中核对 `bouncyCastleProvider()` 全部调用点发现 **Twofish 路径
> 同样踩中且更隐蔽**——`NativeTwofish.available` 探活的 BC 对照抛异常被
> `catch (Throwable) { false }` 吞掉 ⇒ 真机上原生 Twofish 被静默弃用、JCE 兜底再挂。
> 修复与验证（宿主 `BcProviderCollisionTest` 1 例 + 真机 `BcProviderDeviceTest` 3 例全绿）见
> [`resolved/batches/143-真机BCProvider抢占解耦批次.md`](../resolved/batches/143-真机BCProvider抢占解耦批次.md)。

- **现象（真实失败，2026-09-17 22:04 真机 instrumented 首跑）**：
  `javax.crypto.Cipher.getInstance("ChaCha7539", <Security.getProvider("BC")>)` 抛
  `java.security.NoSuchAlgorithmException: Provider BC does not provide ChaCha7539`
  （logcat：`crypto/build/outputs/androidTest-results/connected/debug/Redmi 4X - 17/logcat-...probeChaCha20...txt`）。
- **根因**：Android 平台自带**剥离版** BC provider（注册名同为 `"BC"`，不含 `ChaCha7539` 等
  轻量算法）。`ChaCha20CipherEngine.ensureBouncyCastle()` 以
  `Security.getProvider("BC") == null` 判定是否注册完整 BouncyCastle——真机上该判定恒为
  「已注册」，完整版**永远不会被注册**；`bouncyCastleProvider()` 随后返回的正是剥离版平台
  provider。
- **影响面**：真机上**任何**经 `ChaCha20CipherEngine` 的加解密路径（选 ChaCha20 为外层 cipher
  的建库 / 保存 / 读取）必然 fail-fast；读取他人创建的 ChaCha20 KDBX 同样失败。
  宿主 JVM 无平台 `"BC"`，`ensureBouncyCastle` 会注册完整版，故宿主单测全绿——**经典「仅真机失败」**。
  旁证：`AesCipherEngine` 不指定 provider（走平台 AndroidOpenSSL）与 `PasskeyCryptoEngine`
  （直接用 BC 轻量 API 类，不经 JCE provider）均不受影响。
- **整改方向**：完整 BouncyCastleProvider 以**独立 provider 名**注册（如 `"BC/keepasskey"`——
  `new BouncyCastleProvider().getName()` 不可改时用 `BouncyCastleProvider` 子类化或
  `insertProviderAt` 新名），或引擎内**不查注册表、直接传实例**
  （`Cipher.getInstance("ChaCha7539", BouncyCastleProvider())`，本批探针已实证该形态在真机可用）。
  注意勿 `removeProvider("BC")`（平台组件可能依赖）。
- **核实时间点与方式**：2026-09-17 真机 instrumented 探针首跑的真实异常 + 复跑（传完整实例）
  通过；`grep app/src` 确认无任何 `removeProvider` / 完整版注册点。

`crypto/build/rust-probe/src/main.rs`（全文留档如下；§2 所有 Rust 数字即由此版本二进制产出）：

```rust
// ISSUE-P3-153 评估专用探针：Rust 候选算法真机吞吐（chacha20 / p256 / ed25519-dalek / rsa）。
// 方法学与 BC 侧 DeviceThroughputProbeTest 对齐：先预热、再多轮采样取中位数，输出前缀
// `PERF-PROBE-RUST|`。独立二进制直跑于设备 shell（无 JNI / 无 JVM）——方法学差异在记录文档声明。

use rand::rngs::OsRng;
use rand::RngCore;
use rsa::pkcs1v15;
use rsa::signature::{Signer, Verifier};
use sha2::Sha256;
use std::hint::black_box;
use std::time::Instant;

const PREFIX: &str = "PERF-PROBE-RUST|";
const PAYLOAD_BYTES: usize = 10 * 1024 * 1024;
const CHUNK_64K: usize = 64 * 1024;
const WARMUP: usize = 1;
const SAMPLES: usize = 5;
const OPS_PER_SAMPLE: usize = 50;
const RSA_SIGN_OPS_PER_SAMPLE: usize = 20;

fn median(v: &mut Vec<f64>) -> f64 {
    v.sort_by(|a, b| a.partial_cmp(b).unwrap());
    v[v.len() / 2]
}

fn fmt(v: f64) -> String {
    format!("{:.1}", v)
}

fn fmt3(v: f64) -> String {
    format!("{:.3}", v)
}

fn main() {
    println!(
        "{}环境|target=aarch64-linux-android,profile=release,opt-level=3,lto=true",
        PREFIX
    );
    probe_chacha20();
    probe_es256();
    probe_ed25519();
    probe_rs256();
}

fn probe_chacha20() {
    use chacha20::cipher::{KeyIvInit, StreamCipher};
    use chacha20::ChaCha20;

    let mut payload = vec![0u8; PAYLOAD_BYTES];
    OsRng.fill_bytes(&mut payload);
    let key = [0x42u8; 32];
    let nonce = [0x24u8; 12];

    // 与候选实现等价的投递粒度：64 KiB 分块（流式位置随块推进）
    fn run_once(key: &[u8; 32], nonce: &[u8; 12], payload: &[u8]) -> Vec<u8> {
        let mut buf = payload.to_vec();
        let mut cipher = ChaCha20::new(key.into(), nonce.into());
        for chunk in buf.chunks_mut(CHUNK_64K) {
            cipher.apply_keystream(chunk);
        }
        buf
    }

    // 正确性前置：往返一致
    let encrypted = run_once(&key, &nonce, &payload);
    let round_trip = run_once(&key, &nonce, &encrypted);
    assert_eq!(round_trip, payload, "ChaCha20 往返必须还原明文");

    for _ in 0..WARMUP {
        run_once(&key, &nonce, &payload);
    }
    let mut samples = Vec::new();
    for _ in 0..SAMPLES {
        let start = Instant::now();
        let out = run_once(&key, &nonce, &payload);
        samples.push(start.elapsed().as_secs_f64() * 1000.0);
        black_box(&out);
    }
    let m = median(&mut samples);
    println!(
        "{}ChaCha20(rust)加密|64KiB分块apply_keystream|payload=10MiB|median={}ms|min={}ms|max={}ms|throughput={}MB/s",
        PREFIX,
        fmt(m),
        fmt(samples.iter().cloned().fold(f64::MAX, f64::min)),
        fmt(samples.iter().cloned().fold(f64::MIN, f64::max)),
        fmt(PAYLOAD_BYTES as f64 / 1024.0 / 1024.0 / (m / 1000.0))
    );
}

fn probe_es256() {
    use p256::ecdsa::signature::Signer as _;
    use p256::ecdsa::{Signature, SigningKey, VerifyingKey};

    let sk = SigningKey::random(&mut OsRng);
    let data = vec![0x5Au8; 64];

    // 正确性前置：签名可验
    let sig: Signature = sk.sign(&data);
    let vk = VerifyingKey::from(&sk);
    vk.verify(&data, &sig).expect("ES256 签名必须可验");

    // keygen：随机标量 + 公钥点计算（与 BC ECKeyPairGenerator 口径对称）
    let mut keygen_per_op = Vec::new();
    for _ in 0..SAMPLES {
        let start = Instant::now();
        for _ in 0..OPS_PER_SAMPLE {
            let k = SigningKey::random(&mut OsRng);
            let _pub: VerifyingKey = VerifyingKey::from(&k);
            black_box(());
        }
        keygen_per_op.push(start.elapsed().as_secs_f64() * 1000.0 / OPS_PER_SAMPLE as f64);
    }
    let kg = median(&mut keygen_per_op);
    println!(
        "{}ES256(rust)|keygen(随机标量+公钥点)|n={}轮均摊|median={}ms|min={}ms|max={}ms",
        PREFIX,
        keygen_per_op.len(),
        fmt3(kg),
        fmt3(keygen_per_op.iter().cloned().fold(f64::MAX, f64::min)),
        fmt3(keygen_per_op.iter().cloned().fold(f64::MIN, f64::max))
    );

    for _ in 0..WARMUP {
        let s: Signature = sk.sign(&data);
        black_box(s);
    }
    let mut per_op = Vec::new();
    for _ in 0..SAMPLES {
        let start = Instant::now();
        for _ in 0..OPS_PER_SAMPLE {
            let s: Signature = sk.sign(&data);
            black_box(s);
        }
        per_op.push(start.elapsed().as_secs_f64() * 1000.0 / OPS_PER_SAMPLE as f64);
    }
    let m = median(&mut per_op);
    println!(
        "{}ES256(rust)|sign|n={}轮均摊|median={}ms|min={}ms|max={}ms",
        PREFIX,
        per_op.len(),
        fmt3(m),
        fmt3(per_op.iter().cloned().fold(f64::MAX, f64::min)),
        fmt3(per_op.iter().cloned().fold(f64::MIN, f64::max))
    );
}

fn probe_ed25519() {
    use ed25519_dalek::{Signer, SigningKey};

    let sk = SigningKey::generate(&mut OsRng);
    let data = vec![0x5Au8; 64];

    let sig = sk.sign(&data);
    sk.verify(&data, &sig).expect("Ed25519 签名必须可验");

    // keygen：种子生成 + 公钥推导（与 BC Ed25519KeyPairGenerator 口径对称）
    let mut keygen_per_op = Vec::new();
    for _ in 0..SAMPLES {
        let start = Instant::now();
        for _ in 0..OPS_PER_SAMPLE {
            let k = SigningKey::generate(&mut OsRng);
            black_box(k.verifying_key());
        }
        keygen_per_op.push(start.elapsed().as_secs_f64() * 1000.0 / OPS_PER_SAMPLE as f64);
    }
    let kg = median(&mut keygen_per_op);
    println!(
        "{}Ed25519(rust)|keygen(种子+公钥)|n={}轮均摊|median={}ms|min={}ms|max={}ms",
        PREFIX,
        keygen_per_op.len(),
        fmt3(kg),
        fmt3(keygen_per_op.iter().cloned().fold(f64::MAX, f64::min)),
        fmt3(keygen_per_op.iter().cloned().fold(f64::MIN, f64::max))
    );

    for _ in 0..WARMUP {
        black_box(sk.sign(&data));
    }
    let mut per_op = Vec::new();

        black_box(signing.sign(&data));
    }
```
