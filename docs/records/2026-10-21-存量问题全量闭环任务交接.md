## 6. P2-661 已选方案的详细接续设计（尚未实施）

### 6.1 复用现有安全能力

- `SessionRecoveryCoordinator.onSaveFailedBeforeLock` 已可用当前复合凭据导出标准 KDBX；`VaultRecoveryStore` 已有 filesDir/recovery 下版本载荷、长度/SHA-256 索引、fsync/原子提交和冷启动发现/验证恢复。
- 当前 `VaultRecoveryStore` 只有每库一类副本。新增 durable draft 时必须按 **purpose + vault + version** 分离常规崩溃草稿与锁定失败副本，不能让普通保存清理掉用户尚未处置的旧恢复材料。
- 普通保存只条件删除该次确认的草稿版本；凭据轮换成功清该库全部旧凭据可解材料；明确放弃/恢复成功删除对应目的/版本。
- 恢复列表与 `RecoveryViewModel.keyOf` 当前以路径作为键；同库多 purpose 会冲突，应改为唯一载荷/目的身份，并保持预览的 payload 摘要绑定。

### 6.2 会话锁内快照 API

推荐新增 `captureEncryptedSnapshot(): KdbxResult<SessionEncryptedSnapshot>`，由 `SessionPersistence` **只取一次** session mutex，原子取得路径、票据、库名与当前脏树以复合凭据序列化后的独占密文字节；快照提供 wipe，不交出密码/密钥文件。

- 现有 `exportToBytes()` 在内部已拿 mutex，但只返回 bytes，不能在外面另读 path/ticket 后假设它们属于同一会话。
- **禁止** `useCredentialTicket { exportToBytes() }`，会对同一非重入 mutex 重入死锁。
- `writeIntents.captureSnapshot()` 返回的 database 是借用引用，解锁后可能被换库清零，不能随后拿它离锁序列化。
- `persistedBaselineSnapshot()` 只代表已持久化版本，不是 dirty tree。
- 草稿慢写/加密在会话锁外阶段化，最后以票据保护的短本地提交确认；条件删除防旧保存清掉较新草稿。
