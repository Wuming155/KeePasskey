**数据完整性结论**：本仓的云端并发正确性由**三道服务端条件写**保证：S3 首传 `If-None-Match:*` / 覆盖 `If-Match`（服务端原子校验，HEAD 预检只是快速失败优化）；WebDAV 生产写路径由 MOVE 的 tagged-list `If` 头作用于**目标**资源、首传 `Overwrite:F` 保持创建竞争保护（§324 实测 Overwrite:F 在 mod_dav/nginx 上被真实尊重）。条件写构不出来（ETag 空白/弱形态）一律 fail-closed 拒发（P2-244），412 后元数据重探失败如实上抛不折空串（P2-501），409/423 兜底重试不带 If（P2-500）——两个旧缺陷已于 8dd4f872 闭环：其一为「先删远端目标→必败」（P2-500：409/423 兜底重试仍带 `If`，在按 RFC 4918 评估 `If` 的服务器上重试必 412，兜底退化为删目标后必败）；其二即「空串剥除乐观锁静默覆盖他端写入」（P2-501：MOVE 412 后的元数据重探**瞬时失败**被折算为空 etag，沿 commitLocal 冲突分支流入合并上传后折为 null ⇒ 以无 `If` 预条件的 MOVE(Overwrite:T) 覆盖远端，剥除合并窗口的乐观锁）。

**在案残余（均有登记，如实声明）**：① 少数 S3 兼容存储忽略 `If-Match`，语义退化为「HEAD 预检 + 无条件 PUT」（限界 §1.3）；② 防回滚摘要链只留最近 32 条，更早的历史版本重放判 Accept 被应用（限界 §5）；③ 无 ETag 的 WebDAV 服务器覆盖上传退化为最后写入者胜（`WebDavSyncProvider.kt:336-339`）；④ 防回滚状态文件缺失/不可解析 fail-open，存在一次重放窗口（威胁建模 §3.3）。云端不可信前提下，①③④ 的最坏后果被 KDBX4 头部/块 HMAC 兜底——任何密文篡改 fail-closed 拒解（威胁建模 §3.1/3.2）。

**证据边界**：五服务矩阵中**仅 MinIO 有本机真实服务证据**；标【领域知识】的格子来自外部检索与通用知识，**未在仓内核实，不得当事实引用**；§28 边界①明令矩阵实测只允许证实/证伪服务器行为假设，不推翻本仓已锁定的形态契约。在真服务实测完成前，任何文档不得声称这四类服务上的条件写/兜底行为「已验证」。

**数据丢失风险总评**（限定措辞）：本地 filesDir 通道的数据完整性工程化程度高（原子写+双层 fsync+滚动备份+目录项固化，且每一环有机检用例）。云端防回滚在**四场景中相对而言**宿主测试覆盖与用户提示链最完整（guard 裁决层 `SyncRollbackGuardTest` / 引擎层 `SyncEngineTest` / app 提示信号层 `SyncFailureSignalTest` 三层宿主测试——「三端」为本报告按 §4.2 实测清单的归纳，非源文档定义，且 SyncFailureSignalTest 本轮未列入运行清单；前台 snackbar + 后台通知双提示链有代码指针），**但其在真实服务层（LIVE）覆盖为零**（§1.1「回滚✗」、§9.3 草稿 1），故「闭环最完整」仅限上述相对口径，不得读作端到端已验证。真正的薄弱面集中在三处：**① SAF 自选位置库**——非原子写+无备份+不同步三重降级（限界 §24），是唯一「断电可真实损坏且无兜底」的主路径，产品已用建库警告对冲但无运行期补救；**② 换密后的旧密文残留窗口**——.bak 删除失败静默、云端旧版本无提示，属低概率但零告知的暴露面；**③ 密钥文件单点**——应用侧副本（files/keyfiles）已把「误丢」风险显著收敛，剩余风险是卸载/换机这类「副本与本体同灭」的场景，只能靠用户导出习惯对冲。自动化测试对「逻辑正确性」覆盖扎实，四个场景的「真实持久性/系统级行为」（断电 fsync、卸载、服务端回滚）全部只能真机/AVD 注入，且全部须走 AVD 以遵守 §263 数据保全铁律。
