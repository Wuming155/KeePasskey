### ISSUE-P2-548｜同步失败通知「先发后撤」——鉴权 / 协议失败被伪装成离线且无告警残留

**证据链**（逐行复核）：

```
sync/.../webdav/WebDavSyncProvider.kt:163-164   401/403 → throw SyncException.AuthenticationError
sync/.../webdav/WebDavSyncProvider.kt:150-151   getMetadata 用 runCatching → Result.failure（不抛出）
sync/.../engine/SyncEngine.kt:220-224           recoverFromMetaFailure 的 else 分支：非 FileNotFound
                                                一律 emit CouldntOpenFromRemote + RemoteUnreachableUsingCache
app/.../sync/SyncCycleRunner.kt:354             RemoteUnreachableUsingCache → SyncOutcome.Offline
app/.../sync/SyncFailureNotifier.kt:33-42       isEngineFailure(CouldntOpenFromRemote)=true → post()
app/.../sync/SyncFailureNotifier.kt:89-103      lastOutcome.collect：非 Error → cancel()
```

**机理**：同一次同步周期内，`CouldntOpenFromRemote` 事件**先**触发 `post()`（发通知），
周期收尾写入 `lastOutcome = Offline` **后**触发 `cancel()`（撤通知）。`posted` 标记被 `cancel()` 清掉，
净效果＝**通知从未出现过**。

**与代理原始结论的差异（重要）**：代理报「`Offline` 不发通知 ⇒ 静默失败」。
该表述**只说对一半**——事件通道**确实会** `post()`，真正的问题是**同一周期内的撤销覆盖**。
仅按代理结论去改 `shouldNotifyOutcome` 会**误修**（把 `Offline` 也纳入通知，网络断线时刷屏）。
正确修法在事件通道与结论通道之间定序：**结论为非 `Error` 时不得撤销本周期已发出的引擎级失败通知**。

**影响**：WebDAV 密码填错 / 服务端 5xx → UI 显示「离线，已保留本地副本」，用户误判为没网；
通知栏不留痕 ⇒ 库可长期未同步成功而用户无感知。该缺陷**部分抵消** `ISSUE-P3-298` 立项目标（修复静默失败）。

**AC**：① 鉴权 / 协议错误下发的周期结束后，失败通知**仍在通知栏**；② 真实网络不可达（`NetworkError`
抛出路径）不得因本次整改而变成常驻通知；③ 增补单测覆盖「事件 + 结论同周期」的定序。

## 4. 已排除（经反证，本报告不立项）

- **敏感数据落 `String`**：全链 `ProtectedString` / `CharArray` / `ByteArray`；`PasskeyKeyCodec.kt:151-166`
  已重构掉 `BigInteger(String(...))` 的不可擦中间量。
- **Rust 侧清零**：Argon2 / AES-KDF / Twofish / passkey JNI 的 `Zeroizing` 覆盖含 `?` 提前返回路径。
- **原子写盘**：`AtomicFileWriter.kt:96-128` tmp → `flush` + `fd.sync()` → `ATOMIC_MOVE`；
  任何 `Throwable` 均删 tmp；降级分支**拒绝**无备份的无保护覆盖。
- **HMAC 校验**：全程 `MessageDigest.isEqual`（常时比较）；`HmacBlockStream.kt:216-224` 用
  `terminalValidationFailed` 重放，防 `CipherInputStream` 吞异常伪装 EOF。
- **原生回落静默吞错**：7 个内核均在**回落决策点**登记留痕，非静默。
- **强制 HTTPS / SSRF / 路径穿越 / 无限重试 / 裸 `GlobalScope` / Dispatchers.Main 跑重活**：全部已有守卫，
  逐项取证见四路代理报告，此处不重复。
- **日志脱敏**：`AppLog.kt:44-55` release 下 `e/w` 只落 `"$message <${t.javaClass.name}>"`；
  `ProtectedString.kt:368` / `ClearableByteArray.kt:69` 的 `toString()` 均已覆写。
